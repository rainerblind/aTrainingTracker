## 3. Architectural Strategy & Scope Grounding (`ATT-1250`)
* **In-Scope**:
  1. Track per-connection `availableAccRates: Set<Int>` and `activeAccSampleRateHz: Int?` in `PolarOnlineStreamingBridge` / `PolarPmdStreamCoordinator` (cleared on disconnect/`shutDown()`).
  2. Compute `desiredAccRateHz` from `!isVeritySense`, `runActive`, and cached `availableAccRates` (`200 Hz` for H10 in `RUN` when advertised, `100/50 Hz` otherwise; `52 Hz` unchanged for Verity Sense).
  3. Add single-flight, non-reentrant `renegotiateSlot(...)` in `PolarPmdStreamCoordinator.kt` (keeping `PolarOnlineStreamingBridge.kt <= 1,500` LoC!) triggered from `syncCadenceSensorRegistration()` (and `MULTISPORT_TRANSITION_INTENT`) whenever `StreamSlot.ACC` is active and `activeAccSampleRateHz != desiredAccRateHz` while connected & `!isOfflineGattYielded()`: cancels current `ACC` collector, invokes `stopStreaming(ACC)`, resets `runningDynamicsEstimator` only (keeping `cadenceEstimatorInstance` & `mStridesSensor` intact), and restarts `startAccCollection(api)` with `collectBounded(..., DROP_OLDEST)`.
  4. Reset `avgDtMs = DEFAULT_DT_MS` inside `PolarH10RunningDynamicsEstimator.resetForGap()` so transient packet timing anomalies cannot permanently poison `isHighRate200Hz`, and verify end-to-end `MySensorManager` -> `WorkoutSamples.db` -> CSV/FIT wiring via regression tests.
* **Out-of-Scope**: Forcing `mHaveUserSelectedSportType = true` in `TrackerService.applyResumedState()` (would break Tier-3 auto-sport/multisport unlocking when user never locked sport), Verity Sense VO/GCT, UI/strings, DB schema changes, or Polar SDK upgrades.
