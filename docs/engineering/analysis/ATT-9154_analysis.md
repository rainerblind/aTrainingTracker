## 1. Problem Statement & Motivation
On Pixel 10 (`5.0.0-dev-906504b8`, workout `_id = 2414`, Polar H10 + Verity Sense both connected & armed), tapping Stop stalled navigation to `EditWorkoutScreen` for tens of seconds. While `ATT-8969` (`REQ-SET-119`) fast-fails *disconnected* Polar sensors, connected armed sensors still execute PFTP offline readout + HRV/ERTS recomputation synchronously on `TrackerService.mDbExecutor` **before** `TRACKING_FINISHED_INTENT` is broadcast.

## 2. Independent Peer Review & Verification
Audited live `sprint/2026-11-20_02_Spät` @ `392e312c` (`Rule 68` side-effect trace):
1. **Verified Blocking Stop Chain (`TrackerService.java:2467-2555`)**: `endWorkout()` synchronously invokes `PolarH10OfflineController.stopAndBackfillWorkoutBlocking` (`L2475`, <= 30 s), `PolarVeritySenseOfflineController.stopAndBackfillWorkoutBlocking` (`L2482`, <= 45 s), `HrvPostWorkoutRecomputer.recomputeWorkoutBlocking` (`L2492`), `ErtsPostWorkoutRecomputer.recomputeWorkoutBlocking` (`L2495`), and `ExportManager.workoutFinished` (`L2522`) **before** broadcasting `TRACKING_FINISHED_INTENT` (`L2528-2550`). Navigation strictly waits on `TRACKING_FINISHED_INTENT` -> `TrainingApplication.trackingStopped()` (`L2091`) -> `WorkoutNavigationEvents.triggerEdit(mWorkoutID)` -> `MainActivityWithNavigation.kt:533-539` -> `WorkoutSummariesTabbedScreen.kt:261-267, 429-457` (`EditWorkoutScreen`).
2. **Hidden Side-Effect A — Premature Export Race on Early User Save (`WorkoutRepository.kt:4549-4560`, `ExportManager.java:184-226`)**: `ExportManager.workoutFinished(baseFileName)` only flips `ExportStatus` rows from `TRACKING` -> `WAITING`; actual `WorkManager` file/cloud exports & Health Connect sync launch inside `WorkoutRepository.saveWorkout()` -> `exportManager.exportWorkout(userEditedWorkout)` (`L4560`). With instant Stop -> Edit navigation, a user tapping **Save** while background Polar backfill/HRV/ERTS is still running would trigger exports with un-backfilled/un-smoothed data and race on SQLite. **Fix**: `WorkoutPostProcessingCoordinator.deferExportIfPostProcessing(workoutId)` lets `saveWorkout()` immediately persist metadata (`summariesManager.updateWorkoutData`) and update `_allWorkouts` (also fixing missing `rpe`/`feel` in-memory copy at `L4589-4607`), while deferring `exportManager.exportWorkout(freshWorkoutFromDb)` until Polar backfill -> HRV -> ERTS -> `workoutFinished()` complete so exports contain **both** backfilled/smoothed telemetry and saved user edits.
3. **Hidden Side-Effect B — Edit-Safe Reactive Refresh (`EditWorkoutViewModel.kt:125-193`)**: `EditWorkoutViewModel` currently only collects `repository.initialWorkoutLoaded` (`L128`, never emitted by `refreshWorkout(workoutId)` which updates `_allWorkouts`), and its merge branch (`L134-145`) only guards `workoutName`, overwriting sport/equipment/cluster on re-emission. **Fix**: observe `repository.allWorkouts` filtered to `workoutId` and merge strictly **telemetry/derived fields** (distance, speed, ascent/descent, altitudes, polyline/streams, HR/HRV stats, `polarSyncPending`, `recordingErrors`) while preserving **all** user-editable fields (`workoutName`, sport, equipment, cluster, `rpe`, `feel`, `description`, `goal`, `method`, `commute`, `trainer`, `race`, `uploadToStrava`, `syncToHealthConnect`).
4. **Hidden Side-Effect C — Android 14+ FGS Rules (`REQ-TRK-022`), `WorkManager` Unavailability (`ATT-621`), and Pocketed-Phone Survival**: `MergedManifestFgsAuditTest.kt` strictly forbids `FOREGROUND_SERVICE_CONNECTED_DEVICE` / `"connectedDevice"`; `WorkManager` can be disabled (`TrainingApplication.isWorkManagerAvailable()`); hosting post-processing inside `TrackerService` collides with `TRACKING_NOTIFICATION_ID` (cancelled in `TrainingApplication.trackingStopped()` at `L2092`) and `mSessionGeneration`. **Fix**: dedicated thin `WorkoutPostProcessingService` declared with `android:foregroundServiceType="shortService"` (`ServiceInfo.FOREGROUND_SERVICE_TYPE_SHORT_SERVICE` on API 34+, `onTimeout()` clean stop, **zero new manifest permissions**, 180 s budget >> worst-case ~85 s pipeline), with `ForegroundServiceStartNotAllowedException` fallback to in-process coroutine + `NotificationManagerCompat`. Verified `MainActivityWithNavigation` keeps `BANALService` bound for `WAITING_TIME_BEFORE_DISCONNECTING = 5 min` (`L191`) after `onPause()`, and `PolarOfflineGattCoordinator` acquires its own ref-counted `PolarBleApi` singleton lease (`L956-965`).
5. **Hidden Side-Effect D — Armed-State Snapshot, Raw Recorder Stop & Duplicate Notifications (`8045`/`8046`)**: Capture `h10Armed`, `verityArmed`, `h10StartMs`, `verityStartMs` and close `PolarRawTelemetryRecorder.stopActiveSession()` synchronously inside `endWorkout()` before broadcasting `TRACKING_FINISHED_INTENT` so a subsequent workout start cannot race with armed metadata. Add default `showOwnNotification: Boolean = true` to `PolarH10OfflineController.stopAndBackfillWorkout()` and `PolarVeritySenseOfflineController.stopAndBackfillWorkout()` (passing `false` from coordinator) to suppress overlapping notifications `8045`/`8046` under unified progress notification `8047`.
6. **Target File LoC Audit (`ArchitectureConformanceContractTest.kt`)**: `TrackerService.java` (`3,539/3,559` -> `~3,505`, net `-34` LoC), `WorkoutRepository.kt` (`4,931/5,117` -> `~4,946`, `+15` LoC), `PolarVeritySenseOfflineController.kt` (`1,473/1,500` -> `~1,477`, `+4` LoC — strictly `< 1,500`), `PolarH10OfflineController.kt` (`757` -> `~761`), `EditWorkoutViewModel.kt` (`554` -> `~600`), `DeviceManager.java` (`1,707/1,708`, **0 edits**), `DevicesDatabaseManager.java` (`1,669/1,671`, **0 edits**).

## 3. User Scope Grounding (`ATT-1250`)
- **In-Scope (`3 SP` confirmed; no split)**: (1) Move Polar H10 backfill, Polar Verity Sense backfill, HRV & ERTS recomputation, and `ExportManager.workoutFinished()` out of synchronous `TrackerService.endWorkout()` into async `WorkoutPostProcessingCoordinator.kt` enqueued immediately before/alongside `TRACKING_FINISHED_INTENT` so `FINISHED = 1`, summary/sensors persistence, and Edit Workout navigation complete in `< 1 s`; (2) Foreground-safe `WorkoutPostProcessingService.kt` (`shortService`) + `WorkoutPostProcessingNotificationManager.kt` (`ID 8047`, channel `NOTIFICATION_CHANNEL__EXPORT`, API 33+ `POST_NOTIFICATIONS` guard, localized 9-language stage updates, clean dismiss/completion/failure handling) + suppress duplicate `8045`/`8046` notifications when orchestrated; (3) Edit-safe telemetry-only merge in `EditWorkoutViewModel.kt` + `rpe`/`feel` in-memory parity and deferred-export coordination in `WorkoutRepository.saveWorkout()` so exports strictly run after backfill + HRV + ERTS with user-saved metadata; (4) `SYSREQ-TRK-005` / `SYS-IF-04` documentation sync.
- **Out-of-Scope**: No changes to Polar PFTP/BLE protocols or timeout constants (`REQ-SET-119`), no `EditWorkoutScreen` visual redesign, no DB schema migrations, no changes to `DeviceManager.java` / `DevicesDatabaseManager.java`, no new Android manifest permissions.

## 4. Requirement Archaeology & Chesterton's Fence Audit (`REQ-PRO-022`)
- **Original Requirement ID & Target**: `REQ-TRK-030` / `REQ-TRK-033` (`TrackerService.java`), `REQ-TRK-022` (`AndroidManifest.xml`, `MergedManifestFgsAuditTest.kt`), `REQ-SET-105` (`PolarH10OfflineController.kt`), `REQ-SET-109` (`PolarVeritySenseOfflineController.kt`), `REQ-SET-119` (`PolarOfflineGattCoordinator.kt`), `REQ-UI-211` (`EditWorkoutViewModel.kt`).
- **Historical Origin & Commit Trace**: `ATT-3986`/`ATT-4006`/`ATT-4099` (`aa0e9097`) moved `endWorkout()` onto FIFO `mDbExecutor` with isolated `FINISHED = 1` commit; `ATT-3567` purged `FOREGROUND_SERVICE_CONNECTED_DEVICE` (`REQ-TRK-022`); `ATT-7918` (`60ec5c3b`) and `ATT-7924` added synchronous Polar H10/Verity stop backfill & HRV/ERTS recompute before `ExportManager.workoutFinished()`; `ATT-8969` (`8e44039d`) added disconnected fast-fail & `5 s` connect timeout.
- **Root Reason for Existing Formulation**: Synchronous ordering in `endWorkout()` was the simplest way to guarantee Polar backfill and HRV/ERTS smoothing completed before `ExportManager` serialized FIT/TCX/Strava/Health Connect exports.
- **Preservation of Core Invariants**: Preserves minimal dedicated `FINISHED = 1` commit first (`REQ-TRK-030.1`), zero-gap Polar fast paths & `5 s` connect timeout / disconnected fast-fail (`REQ-SET-105.1`, `REQ-SET-109.1`, `REQ-SET-119.3`), optical Verity Sense `WorkoutRr.db` isolation (`REQ-SET-109.2`), strict export ordering AFTER backfill + HRV + ERTS (`REQ-SET-105.5`), strict omission of `FOREGROUND_SERVICE_CONNECTED_DEVICE` (`REQ-TRK-022`), and `EditWorkout` hidden-field preservation (`REQ-UI-211`).

## 6. Architectural Strategy & Localization Parity
1. **`WorkoutPostProcessingCoordinator.kt`**: Holds process-wide `SupervisorJob + Dispatchers.IO` serialized queue, per-workout `activeWorkouts` & `deferredExportWorkouts` sets, ordered pipeline execution (`H10 -> Verity -> HRV -> ERTS -> refreshWorkout -> ExportManager.workoutFinished -> optional deferred ExportManager.exportWorkout(freshFromDb)`), and state/progress listener callbacks.
2. **`WorkoutPostProcessingService.kt` & `WorkoutPostProcessingNotificationManager.kt`**: Thin Android `Service` (`shortService`, `onTimeout()` safe stop) promoting `NOTIFICATION_ID_POST_PROCESSING = 8047` on `NOTIFICATION_CHANNEL__EXPORT` with stage-specific progress (`setProgress`), Android 13+ `POST_NOTIFICATIONS` check, and clean completion/failure cleanup.
3. **`TrackerService.java`, `WorkoutRepository.kt`, `EditWorkoutViewModel.kt`**: `endWorkout()` commits `FINISHED = 1`, sensors, auxiliary metadata, `finalizeLiveSession()`, `PolarRawTelemetryRecorder.stopActiveSession()`, enqueues `WorkoutPostProcessingCoordinator.enqueue(...)` (capturing armed flags synchronously), and immediately broadcasts `TRACKING_FINISHED_INTENT`; `WorkoutRepository.saveWorkout()` defers export while active; `EditWorkoutViewModel` merges telemetry-only updates from `allWorkouts`.
4. **Localization Parity**: New notification strings (title, Polar H10 sync stage, Polar Verity Sense sync stage, HRV/track recompute stage, export finalization stage, completion/failure copy) MUST be added with 100% parity across all 9 locales (`values/`, `values-de/`, `values-es/`, `values-fr/`, `values-it/`, `values-ja/`, `values-nl/`, `values-pl/`, `values-pt/`).
