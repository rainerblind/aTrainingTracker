# Stage 1 Analysis: ATT-9159 — Persist Actual Lap Start Timestamp in `TrackerService.saveLap`

- **Ticket**: `ATT-9159` (`1 SP`, Minor Bug, Epic `ATT-826: Laps`, Branch `feature/ATT-9159` from `sprint/2026-11-20_01_Früh` @ `d555c4f9`)
- **Problem**: `Laps.db` records `timeStart` as the lap **completion** timestamp instead of its start timestamp (e.g. `workoutID=2414` started `2026-11-19 17:49:53` UTC, ended `18:34:07` UTC, Lap 1 persisted `timeStart='2026-11-19 18:34:07'`).

## 1. Forensic Root Cause & Timestamp Format Audit
- **Call-Site Chain**: `TrackerService.saveLap(workoutId, lapNr, lapTime, lapDistance, averageSpeed)` (`TrackerService.java:2226-2231`) calls 5-arg `WorkoutRepository.saveLap(...)` (`WorkoutRepository.kt:437-439`) -> 5-arg `LapsDatabaseManager.saveLap(...)` (`LapsDatabaseManager.java:186-188`), which passes `timeStart = null` to 8-arg `saveLap` (`:135-171`). When `timeStart == null`, `Laps.TIME_START` is omitted from `ContentValues` (`:153-155`), triggering SQLite `DATETIME DEFAULT CURRENT_TIMESTAMP` (`:558`) at **insert/lap-end time**.
- **UTC Format Contract**: SQLite `CURRENT_TIMESTAMP` writes **`yyyy-MM-dd HH:mm:ss` in UTC**. `FitFileWriter.parseUtcTimestamp(lap.timeStart)` (`FitFileWriter.kt:129-135, 829`) and `TCXFileWriter.dbTime2XMLTime()` (`TCXFileWriter.kt:69-83`) parse `yyyy-MM-dd HH:mm:ss` strictly as **UTC**. `MultisportLapCoordinator.formatUtcTimestamp(epochMs)` (`MultisportLapCoordinator.kt:66-78`) already formats canonical UTC `yyyy-MM-dd HH:mm:ss`. Using local-TZ `SimpleDateFormat` would shift lap timestamps by the device UTC offset.
- **Target File LoCs & Ceilings**: `TrackerService.java` `3,538 / 3,559` (**21 LoC headroom**), `MultisportLapCoordinator.kt` `526`, `LapsDatabaseManager.java` `612`, `WorkoutRepository.kt` `4,931 / 5,117`, `FitFileWriter.kt` `1,153`, `TCXFileWriter.kt` `442`.

## 2. Independent Peer Review & Verification
- **Confirmed**: Ticket RCA at `TrackerService.java:2230` & `LapsDatabaseManager.java:153, 558` is accurate.
- **Blind Spots & Refinements Identified**:
  1. `MultisportLapCoordinator` **already tracks** `currentLapStartAnchor.timestampMs`: initialized at `START_NORMAL` (`TrackerService.java:1260`), restored at `applyResumedState` (`TrackerService.java:1906`), and updated per non-pause `LAP_SUMMARY` (`MultisportLapCoordinator.kt:201-206`). However, `onLapSummaryIntent()` (`:222-231`) and `saveFinalLap()` (`:255-261`) only pass `timeStart` when `activeLegStartTimeUtc != null` (multisport transitions), dropping `currentLapStartAnchor.timestampMs` into `saveUnnamedLap` for all single-sport/manual/final laps.
  2. **LoC Budget & Test Subclasses**: `TrackerServiceLapTest` (`:49-55`), `TrackerServiceFinalizationTest` (`:163-172`), and `TrackerServiceStateMachineCharacterisationTest` (`:438, 442`) override/invoke 4- and 5-arg `TrackerService.saveLap`. Resolving lap start UTC via `MultisportLapCoordinator` (and passing `formatUtcTimestamp` from `TrackerService.saveLap` -> `WorkoutRepository.saveLap(..., startTime, ...)`) keeps `TrackerService.java` delta minimal (`<= 4` LoC) without breaking test overrides.
  3. **Other 5-arg `saveLap` Callers**: `WorkoutRepository.recalculateSwimWorkout()` (`WorkoutRepository.kt:1634`) and `PolarVeritySenseOfflineController` (`:1061`, mocked in `PolarVeritySenseOfflineControllerTest:991`) invoke 5-arg `saveLap` with `prevLapMs` / `prevTimeMs` available; `LapsDatabaseManager.saveLap()` fallback (`now - lapTime * 1000L` in UTC when `timeStart == null && lapTime > 0`) protects all legacy/unmodified 5-arg callers without breaking mock signatures.
  4. **Lap Readers**: `FitFileWriter.kt:827-837` reads `lap.timeStart` via `parseUtcTimestamp`; `TCXFileWriter.kt:225` reads `sample.time` (UTC); `GCFileWriter.java:160` uses relative seconds.
- **Scope & Complexity**: In-scope (`1 SP`, `LOW` risk): `MultisportLapCoordinator`, `TrackerService.saveLap`, `LapsDatabaseManager.saveLap` fallback (plus optional `WorkoutRepository.recalculateSwimWorkout` / `PolarVeritySenseOfflineController` explicit UTC `prevMs` if low-risk). Out-of-scope: `Laps.db` schema migration, historical backfill, `TCXFileWriter` refactor.
