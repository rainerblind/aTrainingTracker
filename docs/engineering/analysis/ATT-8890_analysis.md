# Stage 1 Analysis: ATT-8890 - Classify Activity and Phone Carriage Modes from IMU & Barometer Signatures, Persist at 1 Hz, and Adapt Live EKF & Offline ERTS Filtering

## 1. Problem Statement & Motivation
* Pixel 10 cycling (`Zum Bäcker #57`/`#56`, front jeans pocket) and running (`Kurze Runde var 2 #52`) telemetry shows static EKF/barometer parameters cannot simultaneously optimize rigid handlebar mounts, pockets, arm/handheld running, dismount walks, and indoor stops.
* Currently neither `PhoneCarriageMode` classification nor 1-Hz diagnostic persistence in `WorkoutSamples.db`/`CSV` exists, leaving live (`SpeedAndLocationDevice_ATTFused`, `AltitudeAndSlopeDevice_ATTFused`, `BarometricAltitudeFilter`) and offline (`ErtsPostWorkoutRecomputer`, `ExtendedRtsOdometrySmoother`, `ExtendedRtsAltitudeSlopeSmoother`) filters unaware of carriage regime transitions (`Ride -> Walk -> Stationary -> Ride`).

## 2. Root Cause Analysis & Independent Hypothesis Verification
* **Live Sensor Ingestion & Architecture Gap**:
  * `SpeedAndLocationDevice_ATTFused` (`:178-186`) subscribes to `TYPE_GYROSCOPE` + `TYPE_GAME_ROTATION_VECTOR` (`TYPE_ROTATION_VECTOR` fallback) at `SENSOR_DELAY_GAME`; `QuaternionGyroProjector` (`:71-73`) computes $R_{20..22}$ (body-up projection -> pitch/roll) and $\omega_{\text{ENU},z}$.
  * `AltitudeAndSlopeDevice_ATTFused` (`:215-294`) aggregates `TYPE_PRESSURE` (~5 Hz) into 1-Hz buckets for `BarometricAltitudeFilter.filterSlewOnly()` and `KinematicAltitudeSlopeEkf`.
* **Independent Peer Review & Verification**:
  1. **`TYPE_STEP_DETECTOR` Permission & Hardware Fallback (`AndroidManifest.xml`, `TrackerService.java:1134-1141`)**: `AndroidManifest.xml` currently lacks `ACTIVITY_RECOGNITION` (required on API 29+ for `Sensor.TYPE_STEP_DETECTOR`, whereas `TrackerService.hasHealthPermission()` already safely gates `FOREGROUND_SERVICE_TYPE_HEALTH` on runtime grant and `OnlineUserGuideContractTest.kt:193` only bans `"ACTIVITY_RECOGNITION"` in `docs/guide/`). Emulators or devices without `TYPE_STEP_DETECTOR`, permission grant, `TYPE_PRESSURE`, or `TYPE_GAME_ROTATION_VECTOR` must fall back cleanly to gyro/rotation/barometer/GNSS/wheel signatures without `SecurityException`, `Process.myPid()` JVM test crashes (`Coding Standards §5.9`), or permanent `UNKNOWN` lockout.
  2. **`SensorType` Storage vs. UI Formatting & Monolith LoC Guardrails (`ArchitectureConformanceContractTest.kt:118-133`)**: `TrackerService.sampleAndWriteToDb()` (`:2725-2752`) casts sensors to `SensorData<Number>` and writes `INTEGER` via `.intValue()`, `CSVFileWriter` (`:138-145`) exports `Integer.toString(...)`, and `MySensor.getStringValue()` formats via `SensorType.myFormatter`. Appending `ACTIVITY_AND_CARRIAGE_MODE` at the **end** of `SensorType.java` (ordinal `67`, preserving `0..66`) with `SensorValueType.INTEGER`, `filteringPossible = false`, `internalUnit = "dimensionless"`, `'Internal unit:'` Javadoc (`verify_sensor_type_javadocs()`), and `PhoneCarriageModeFormatter` yields integer DB/CSV persistence + localized UI labels with **0 LoC added** to `TrackerService.java` (`3,559`), `DeviceManager.java` (`1,708`), `WorkoutSamplesDatabaseManager.java` (`1,533`), `CSVFileWriter.java`, or `WorkoutRepository.kt` (`5,048 <= 5,117`).
  3. **Reachability & Contract Parity (`Rule 81`)**: `ActivityType.getSensorTypeArray()` (`:223-226`) must append `ACTIVITY_AND_CARRIAGE_MODE` alongside `WORLD_YAW_RATE_radps`; `DeviceType.getDeviceTypeList()` (`:158`) maps it to `SPEED_AND_LOCATION_ATT_FUSED`. `SensorCategoryAndSelectorContractTest.kt:70,138` (`67->68`), `docs/architecture/sensor_units.md`, and `docs/architecture.md:354` enforce strict 100% enum parity.
  4. **Smooth Parameter Adaptation & Device Decoupling**: `UnicycleOdometryEkf.predict()` (`:178`) already accepts `gyroNoiseScale`, and `KinematicAltitudeSlopeEkf.updateBarometer()` (`:262`) accepts `varBaro` (keeping `DEFAULT_VAR_BARO = 0.25`, `MIN_DOPPLER_SPEED_MPS = 3.0`). However, `BarometricAltitudeFilter` (`:34-38`) hardcodes immutable `medianWindowSize = 7` / `maxSlewRateMps = 1.2` and `SpeedAndLocationDevice_ATTFused` (`:71`) hardcodes `YAW_RATE_WINDOW_SEC = 1.0`. Resizing windows must retain active buffers without resetting `lastSlewAltitude`, EKF state, or sample-1 `mWorldYawRateSensor` emission (`SpeedAndLocationDevice_ATTFusedTest:126-139`). `AltitudeAndSlopeDevice_ATTFused` can observe `ACTIVITY_AND_CARRIAGE_MODE` via `mMySensorManager` (falling back to neutral defaults when `SPEED_AND_LOCATION_ATT_FUSED` is unpaired).
