# Stage 1 Analysis: ATT-8723 — BLE DIS (`0x2A29`/`0x2A24`/`0x2A25`) Reconnect Backfill & Deduplication

**Ticket**: `ATT-8723` (`2 SP`, `tier-a`, Epic `ATT-5910`) | **Target Release**: `V5.0.0` | **Branch**: `feature/ATT-8723` | **Date**: 2026-11-24

## 1. Problem Statement & Post-`ATT-8717` / Post-`ATT-8996` Scope Alignment
`ATT-8723` originally covered three BLE Device Information Service (`0x180A`) gaps: (1) NUL-byte stripping, (2) `0x2A24`/`0x2A25` Model/Serial discovery reads, and (3) reconnect backfill on regular `MyBTLEDevice` connections. Two of those three gaps are already merged on `sprint/2026-11-24_02_Spät` (`27436048`):
- `ATT-8717` (`9f9e5967`): Added `0x2A24`/`0x2A25` reads in `BTSearchForNewDevicesEngine.java` and `BTLEHeartRateDevice.java` + `PolarOfflineCapabilityStore.kt`.
- `ATT-8996` (`27436048`): Added shared pure-JVM `BleDisStringSanitizer.kt`, sanitized all existing BLE GATT/GAP/Polar DIS read sites, self-healed `PolarOfflineCapabilityStore`, and migrated `Devices.db` v14->v15.

**Remaining gap owned by `ATT-8723` (per Ceremony 1 Scope Alignment)**:
1. **No `0x2A29` Manufacturer Name Reconnect Backfill Across `MyBTLEDevice`**: Paired BLE sensors whose `Devices4.manufacturerName` is missing (`NULL`/blank — e.g., paired before DIS read succeeded, timed out during discovery, restored from legacy backup, or cleared from NUL-only `"\u0000"` by v15 migration) or NUL-dirty never backfill `0x2A29` on reconnect across any `MyBTLEDevice` subclass (`BTLEHeartRateDevice`, `BTLERadarDevice`, `BTLEBikeDevice` speed/cadence, `BTLEBikePowerDevice`, `BTLERunSpeedDevice`). By contrast, ANT+ (`MyANTDevice.java:248,301`) backfills missing `manufacturerName` on reconnect.
2. **Unconditional Polar `0x2A24`/`0x2A25` Re-Reads**: `BTLEHeartRateDevice.configureServices()` (`L260-274`) enqueues `0x2A24` and `0x2A25` on *every* reconnect even after `PolarOfflineCapabilityStore` already holds clean `modelNumber` and canonical 8-hex `polarDeviceId`, adding 2 unnecessary GATT round-trips before HR CCCD (`0x2A37`).

## 2. Forensic Root Cause Analysis & Independent Peer Review / Verification
Auditing `sprint/2026-11-24_02_Spät` (`27436048`) verifies all call sites and surfaces four critical architectural constraints:
1. **`BTLERadarDevice.configureServices()` Bypasses `super.configureServices()`**: `BTLERadarDevice.java:258-360` completely overrides `configureServices(gatt)` without calling `super.configureServices(gatt)` and reads `0x2A24` (`L309-317`) per connect for StVZO/RearVue 820 light-control registration (`mModelNumber` resets to `null` each connect). Hooking `0x2A29` backfill inside `MyBTLEDevice.readNextCharacteristic()` (`L1454`, immediately after `configureServices(gatt)`) uniformly covers **all** 7 BLE device subclasses (including `BTLERadarDevice`) while keeping measurement/CCCD ops first in `mGattQueue` (zero startup telemetry latency and zero interference with Radar 1.5s V2 silence / 3.5s watchdogs or `BTLEHeartRateDeviceTest` `callConfigureServices()` queue assertions).
2. **`onCharacteristicRead` Binder Thread & Failed-Read Stale Bytes**: `MyBTLEDevice.mGattCallback.onCharacteristicRead()` (`L746-761`) executes on Android's Binder thread and calls `characteristicUpdate()` even when `status != GATT_SUCCESS` (`L757-759`). Routing `0x2A29` strictly inside the `status == GATT_SUCCESS && snapshot != null` branch (`L754`) guarantees immutable cloned bytes (`obtainSnapshotCharacteristic`), blocks stale failed-read bytes, and posts `applyBackfilledManufacturerName(gatt, sanitized)` onto `mHandler` so Binder immediately invokes `onGattOperationCompleted()` without blocking on SQLite.
3. **In-Flight Queue Pop & Partitioned Deduplication**: `MyBTLEDevice.processNextGattOperation()` (`L1346`) pops the first op off `mGattQueue` immediately (`mGattOperationPending = true`), so an in-flight read is no longer visible in `mGattQueue`. Strictly partitioning ownership—`MyBTLEDevice` post-`configureServices` owns `0x2A29` only, `BTLEHeartRateDevice` owns missing Polar `0x2A24`/`0x2A25`, and `BTLERadarDevice` owns per-connect Radar `0x2A24`—plus a belt-and-suspenders `mGattQueue` UUID scan guarantees zero duplicate reads.
4. **Cold-Start Polar Alias Hydration (`PolarOfflineGattCoordinator.kt:139`)**: `deviceAliases` is an in-memory `ConcurrentHashMap`. When `BTLEHeartRateDevice` skips a redundant `0x2A25` read because `PolarOfflineCapabilityStore.getPolarDeviceId(ctx, mac)` is already populated, it MUST still call `PolarOfflineGattCoordinator.registerDeviceAliases(existingPolarId, mac)` so SDK callbacks match across process restarts.

## 3. Scope Grounding, Non-Goals & Complexity/Tier Audit
- **In Scope**: New dedicated helper `BleDisReconnectBackfillHelper.kt` (`com.atrainingtracker.banalservice.devices.bluetooth_le`); minimal `+3` LoC delegation in `MyBTLEDevice.java` (`1,494 -> 1,497/1,500` LoC); routing `BTLEHeartRateDevice.configureServices()` Polar `0x2A24`/`0x2A25` checks through the helper (shrinking `BTLEHeartRateDevice.java` `597 -> ~583` LoC); reusing `BleDisStringSanitizer` (`ATT-8996`), `MyDevice.getManufacturerName()`/`setManufacturerName()`, and `DevicesDatabaseManager` untouched (`1,665/1,671` LoC); updating `docs/architecture/detailed_design/my_btle_device.md` (`REQ-PRO-114`) & `docs/architecture.md`; targeted unit tests.
- **Out of Scope**: Re-implementing `BleDisStringSanitizer` or `Devices.db` schema changes (already done in `ATT-8996`, `DB_VERSION = 15`); persisting `modelNumber`/`serialNumber` columns in `Devices.db` (no columns exist; non-Polar HRMs must never pollute `PolarOfflineCapabilityStore` per `REQ-CON-049.2`); UI/Compose/localization edits (`N/A - 0 string changes`).
- **Sizing & Tier Check**: `2 SP` (canonical Fibonacci `<= 5 SP`, no split needed); `tier-a` confirmed (core `MyBTLEDevice` BLE GATT queue & reconnect lifecycle).
