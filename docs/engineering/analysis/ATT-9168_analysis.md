# Stage 1 Analysis: ATT-9168 — Fix Invisible Off-Screen Snapshot `WorkoutHeader` Intercepting Clicks

- **Ticket**: `ATT-9168` (`1 SP`, Major Bug, Epic `ATT-68`, Branch `feature/ATT-9168` from `sprint/2026-11-20_01_Früh` @ `49a2f16a`)
- **Problem**: On Workout Details `Übersicht` tab (`MODE_A_CARD_SCROLL`, `showHeader = false`), tapping **`Sichtbare Diagramme`** or the **`Tempo` (Pace/Speed) multi-source layers icon** plays the tap sound without opening either menu. Note: `ATT-9066` describes the same symptom on the `Übersicht` Speed layers icon (noted for context; out-of-scope beyond `ATT-9168`).

## 1. Forensic Root Cause & Call-Site Audit
- **Hit-Test & Semantics Occlusion (`MapDetailLayout.kt:653-711`)**: All 3 tabbed modes in `WorkoutDetailTabbedContent.kt` (`:339`, `:374`, `:473`) pass `showHeader = false` and `header = snapshotHeader` (`WorkoutHeader` at `:219-233`). In `MapDetailLayout.kt:692-711`, the `showHeader == false` branch lives inside the upper `Column` with `.zIndex(1f)` (`:656`) and uses `.layout { ... layout(0, 0) { placeable.place(0, 0) } }` wrapping `Modifier.drawWithContent { headerLayer.record { this@drawWithContent.drawContent() } }`.
- Because `drawWithContent` omits `drawContent()`, `WorkoutHeader` is invisible—yet `placeable.place(0, 0)` inside `.zIndex(1f)` leaves its full `width x headerHeight` pointer hit-boxes and accessibility semantics sitting directly atop the upper viewport (`Sichtbare Diagramme` & `Tempo` layers icon).
- **Why Clicks Play Sound & Do Nothing (`WorkoutHeader.kt:398, 512`)**: Even though `snapshotHeader` passes `onClusterClick = null`, `WorkoutHeader` still attaches `clickable(onClick = { onClusterClick?.invoke(data.clusterId) })` on its route-cluster chip, consuming taps with a no-op handler and duplicating TalkBack nodes. (In `Karte & Diagramme`, the Map occupies the top viewport, so `Sichtbare Diagramme`/`Tempo` sit below the invisible header bounds.)
- **Target File LoCs**: `MapDetailLayout.kt` `1,062 / 1,500` LoC; `WorkoutDetailTabbedContent.kt` `1,102 / 1,500` LoC; `WorkoutHeader.kt` (`0` edits needed).

## 2. Independent Peer Review & Verification
- **Confirmed**: Ticket RCA at `MapDetailLayout.kt:692-711` (`layout(0,0)` + `place(0,0)` inside `.zIndex(1f)`) and duplicate accessibility tree pollution are 100% accurate.
- **Critical Compose `GraphicsLayer` Frame-Timing & Isolation Findings**:
  1. **On-Demand Composition Frame-Timing Race (`ATrainingTrackerMap.kt:241-256`, `MapDetailLayout.kt:195-199, 370-379`)**: If `snapshotHeader` is composed strictly when `isSharing || externalSnapshotTrigger` is `true`, and `shouldTakeSnapshot = isSharing` triggers `MapEffect` in the same composition where `isSharing` becomes `true` (e.g., floating Share button or `WorkoutShareBottomSheet.onSelectMapSnapshot = { isSharing = true }`), `map.snapshot {}` can invoke `onSnapshotReady` before Compose's draw pass executes `headerLayer.record { drawContent() }`, leaving `headerLayer.size == (0, 0)` (null/blank header bitmap!).
     - **Fix Requirement**: Synchronize capture with Compose's draw frame — e.g. track `isHeaderLayerRecorded` (or await `withFrameNanos {}` before enabling `shouldTakeSnapshot` / inside `captureHeader()` when `!showHeader && headerLayer.size.width == 0`) so `headerLayer.toImageBitmap()` always runs after `headerLayer.record { ... }` has drawn at least once.
  2. **Guaranteed Zero Hit-Testing & Zero Accessibility Leak Even During Capture**: Gate `snapshotHeader` on `isSharing || externalSnapshotTrigger`, move it **out** of the `.zIndex(1f)` `Column` onto a `.zIndex(-1f)` background layer behind opaque content (or place off-viewport `placeable.place(0, -placeable.height - 1000)`), and attach `.clearAndSetSemantics {}` so it can neither intercept pointers nor expose duplicate TalkBack nodes at any time.
- **Scope & Complexity**: `1 SP`, `LOW` risk, confined to `MapDetailLayout.kt` + Robolectric `createComposeRule()` UI & snapshot tests (`ATT-9066` shares root cause; not expanded here).
