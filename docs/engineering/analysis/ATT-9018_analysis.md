# Stage 1 Analysis: ATT-9018 - Fix Bulk Strava Import OOM from Climbs.db Double-Deserialization & Per-Workout Reloads

**Ticket**: `ATT-9018` (`3 SP`, `Bug`, `severity-critical`) | **Parent Epic**: `ATT-235` | **Target Release**: `V5.0.0`  
**Active Sprint**: `2026-11-19_01_Früh` | **Branch**: `feature/ATT-9018` (base `9f8567e2`) | **Author**: AI Agent 1 (`Pro`) | **Date**: 2026-11-19

## 1. Problem Statement & Motivation
* During a Strava bulk archive import (`3,287` rows in `activities.csv`, ~201 new workouts) on Pixel 10 (`com.atrainingtracker.debug`), Java heap hit `509 / 512 MB` (`<1%` free after GC), crashing the main thread in `DevicesDatabaseManager.getLastActiveString()` (`DateFormat.getDateTimeInstance()` -> `ZoneInfo.clone()`) and failing `LegacyImportEngine.recalculateStats` in `ClimbsDatabaseManager.deserializePathPoints` (`String.split`).
* **Expected**: Deduplicating/loading `Climbs.db` uses zero-split parsing and lazy `path_polyline` loading, bulk imports defer repository/climb/cluster refreshes to a single post-batch pass with zero duplicate `reloadWorkoutData`, and `getLastActiveString()` reuses cached formatters.

## 2. Root Cause Analysis & Independent Hypothesis Verification
* **4 Verified Heap Churn Contributors on `sprint/2026-11-19_01_Früh`**:
  1. **Eager `Climbs.db` Deserialization & `String.split` Churn (`ClimbsDatabaseManager.kt:139, 162, 257, 386-462`)**: `insertClimbWithDeduplication`, `insertClimbsWithDeduplicationBatch`, and `deduplicateExistingClimbs` all call `getAllClimbsInternal()`, loading all `5.5 MB` of `Climbs.db` `path_polyline` strings and running `str.split(";")` + `item.split(",")` on every row (~140k 13-field `PathPoint` objects + `ArrayList`/`String` garbage per workout), even though >99% fail endpoint/heading/gain pre-filters.
  2. **Double Load, Copy & Per-Workout Refresh (`WorkoutRepository.kt:4564-4570` -> `LiveClimbsRepository.kt:120-146`)**: Each workout with climbs invokes `LiveClimbsRepository.refreshClimbs()`, triggering a **2nd** full `getAllClimbs()`, `.map { it.copy(...) }` (`:127`), `ClimbDeduplicator.deduplicateForDisplay` (`:128`), and when `activeRouteId == null`, a redundant 2nd `.map { it.copy(...) }` (`:135`) allocating separate `_allStoredClimbs` and `_allClimbs` lists; `backfillHistoricalClimbs()` (`:3148, :3158`) repeats the same per-workout refresh.
  3. **Duplicate `reloadWorkoutData` & Per-Workout Cascade (`LegacyImportEngine.kt:1349-1360` -> `WorkoutRepository.kt:1882-1895, 4464-4520`)**: `recalculateStats` calls `workoutRepo.reloadWorkoutData(workoutId)` (`:1350`) AND `WorkoutClusterRepository.refreshClusters()` (`:1351`), then broadcasts `WORKOUT_UPDATED_INTENT` (`:1358`) to `WorkoutRepository.workoutUpdateReceiver` (`:1887`, the sole main-source listener), queuing a **2nd** `reloadWorkoutData(workoutId)` (`mapper.fromCursor` 40+ queries, `PolyUtil.decode`, `_allWorkouts` clone/sort, `PeriodsRepository`).
  4. **Main-Thread `DateFormat` Instantiation (`DevicesDatabaseManager.java:877-882`)**: `getLastActiveString()` calls `DateFormat.getDateTimeInstance().format(new Date())` on every `setLastActive()` (`:550, :601, :759`), allocating `SimpleDateFormat` and cloning `ZoneInfo` (`2+ KB`) repeatedly on UI/sensor threads.
* **Independent Peer Review & Verification (Blind Spots, Line Corrections & Constraints)**:
  * **Curved-Climb Bounding-Box Blind Spot (`Climb.kt:197-211`)**: `Climb.boundingBox` iterates `pathPoints`. Lazy metadata rows lacking `pathPoints` MUST pad `[start, end]` by triangle-inequality ellipse slack $\frac{1}{2}\sqrt{\max(0, L^2 - d_{se}^2)} + \text{threshold}$ before rejecting Step 4 corridor overlap; endpoint matches (`startDist, endDist <= effThreshold`) resolve without ever loading `path_polyline`.
  * **`ClimbDetector` SubList Pinning (`ClimbDetector.kt:189`)**: `points.subList(startIdx, peakIdx + 1)` pins the full workout `validPoints` list if retained; `.toList()` detaches the slice.
  * **Bulk Reconciliation & `MockK` Arity**: `BackupRestoreViewModel.importStravaArchive` (`:646-683`) lacks post-batch `loadAllWorkouts` / `syncPeriodsIfDiscrepancy` / `refreshClusters` / `refreshClimbs` once per-workout reload is deferred. Keep `persistParsedWorkout`, `bulkRecoverFromDropbox`, `bulkRecoverFromGoogleDrive` parameter arities unchanged (`BackupRestoreViewModelFormatScopingTest`, `StravaBulkExportImporterTest`) via coroutine-scoped `BulkImportBatchContext`.
  * **Monolith LoC Ceilings (`ArchitectureConformanceContractTest.kt:118, 130`)**: `WorkoutRepository.kt` is `4,973` LoC (must remain `<= 4,973` via helper delegation) and `DevicesDatabaseManager.java` is at exact cap `1,671 / 1,671` LoC (must extract formatter helper or stay `<= 1,671`). `ClimbsDatabaseManagerTest.kt:155, 212, 293, 357` stubs `mockDb.query(..., null, ...)` and must align with projected metadata queries. `SpeedAndLocationDevice_ATTFused.kt` now calls `setLastActive()` at `:190, :208, :262, :569, :645` (`9f8567e2`).

## 3. Scope Grounding & Non-Goals (`3 SP` Verified — No Split Required)
* **In-Scope (`3 SP`)**: (1) Zero-split `deserializePathPoints` + projected metadata & lazy `path_polyline` loading in `ClimbsDatabaseManager` (`insertClimbWithDeduplication`, `insertClimbsWithDeduplicationBatch`, `deduplicateExistingClimbs`) + `subList().toList()` in `ClimbDetector`; (2) Deduplicate/share `_allStoredClimbs` & `_allClimbs` when `activeRouteId == null` and serialize `refreshClimbs` in `LiveClimbsRepository`; (3) Remove duplicate `WORKOUT_UPDATED_INTENT` after direct `reloadWorkoutData` in `LegacyImportEngine`, defer per-workout `reloadWorkoutData` / `refreshClusters` / `refreshClimbs` across bulk paths (`StravaBulkExportImporter`, `BackupRestoreViewModel` multi-file/SAF/Strava, `bulkRecoverFromDropbox`, `bulkRecoverFromGoogleDrive`, `AutoImportManager`, `backfillHistoricalClimbs`) via helper extraction (`WorkoutRepository.kt <= 4,973` LoC) + single post-batch reconciliation; (4) `ThreadLocal` `DateFormat` cache preserving `DevicesDatabaseManager.java <= 1,671` LoC.
* **Out-of-Scope**: `Climbs.db` v1 schema changes, `ClimbDetector` math/thresholds, `ATT-9013` silent cluster creation, `ATT-8999` 1-Hz `TrackerService` cascade, and `PathPoint` class layout changes.
