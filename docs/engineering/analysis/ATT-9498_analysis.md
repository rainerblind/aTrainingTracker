## 1. Forensic Root Cause Analysis (`b22f95be`)
Audit of `docs/engineering/emulator_sweeps/2026-11-21_sweep.md` (`8/12` FAIL: `7` `ForegroundServiceDidNotStartInTimeException` crashes across `Pixel_5_Android_12` `en` & `Pixel_8_Android_15` `en/de/fr/it/nl/pl`, plus `Pixel_7_Android_36` `/sdcard/` dump failure) and all `startForegroundService()` callers in `app/src/main/` (strictly `TrainingApplication.java:1806` & `WorkoutPostProcessingService.kt:163`; `BANALService` is bound-only) identified **three distinct lifecycle defects**:

1. **Root Cause 1 — `WorkoutPostProcessingService` Fast-Drain vs `stopService()` FGS Race (Primary Crash Driver)**:
   - On stop, `TrackerService.endWorkout()` enqueues `WorkoutPostProcessingCoordinator.enqueue()` (`:328`), which calls `WorkoutPostProcessingService.startForPostProcessing()` $\rightarrow$ `ContextCompat.startForegroundService()` (`WorkoutPostProcessingService.kt:163`, setting AMS `fgRequired = true`) and immediately launches `drainQueue()` on `Dispatchers.IO` (`:332`).
   - For short/non-Polar workouts (`MultiLocaleUiSweepAndroidTest`), `drainQueue()` completes in ~10–30 ms — *before* the Main Looper dispatches `WorkoutPostProcessingService.onStartCommand()` — and `finally` (`:383`) calls `WorkoutPostProcessingService.stopIfRunning()` $\rightarrow$ `appContext.stopService(...)` (`:191`). Calling `stopService()` while `fgRequired == true && !isForeground` deterministically throws `ForegroundServiceDidNotStartInTimeException`.
   - Additionally, `WorkoutPostProcessingService.onStartCommand()` (`:79–83`) handles `ACTION_STOP` by calling `demoteForeground(); performStopSelf()` without promoting first if a pending `startForegroundService()` contract has not yet been satisfied.
2. **Root Cause 2 — `TrainingApplication.startTracking()` vs Rapid `stopTracking()` & Late `TrackerService.performStartForeground()` Race**:
   - `TrainingApplication.startTracking()` (`TrainingApplication.java:1806,1841`) invokes `ContextCompat.startForegroundService(this, TrackerService)` and synchronously flips `cTrackingMode = TrackingMode.TRACKING` before `TrackerService.onCreate()` sets `sInstance`.
   - If `REQUEST_STOP_TRACKING` arrives before `TrackerService.onCreate()` runs (e.g. `MultiLocaleUiSweepAndroidTest.kt:107–125` exits its wait loop immediately on `isTracking() == true`), `TrainingApplication.stopTracking()` (`:1938–1945`) sees `!TrackerService.isRunning()` and calls `stopService(TrackerService)` (`:1944`) on a pending `fgRequired` service $\rightarrow$ `ForegroundServiceDidNotStartInTimeException`.
   - Inside `TrackerService.onStartCommand()`, `performStartForeground()` (`:1379`) executes *after* `mDbExecutor.submit(...)` (`:1279`, whose error path calls `performStopSelf()` at `:1307`), and `handleActionStop()` (`:1471–1474`) can call `performStopSelf()` without satisfying a pending FGS start.
   - Furthermore, when `ACTION_STOP` arrives before FIFO `createNewWorkout()` completes on `mDbExecutor`, `enqueueAsyncFinalization()` (`:1544`) snapshots stale `stoppingWorkoutId = mWorkoutID` (`<= 0`), so `endWorkout()` never commits `FINISHED = 1`, leaving ghost unfinished workouts (`"Training unterbrochen"` dialog observed in all 4 passing KW47 PNGs).
3. **Root Cause 3 — Manifest Blind Spot (`tools/baseline_manager.py:168–188`)**:
   - `_collect_open_risks_and_deviations()` parses only `docs/releases/<baseline>/verification_summary.md`, ignoring `docs/engineering/emulator_sweeps/YYYY-MM-DD_sweep.md`. Consequently, Sprint 467–471 manifests reported `Open Release Deviations: 0` despite `2026-11-21_sweep.md` carrying `**Verdict**: \`FAIL\`` (`8/12` failures).
