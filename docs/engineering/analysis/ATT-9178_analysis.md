# Stage 1 Analysis: ATT-9178 — Limit Periodic Re-Search to Lost/MIA Sensors & Tighten Period Presets

**Ticket**: `ATT-9178` (`3 SP`, `tier-a`, `severity-major`, Epic `ATT-5910`) | **Target Release**: `V5.0.0` | **Branch**: `feature/ATT-9178` | **Date**: 2026-11-24

## 1. Problem Statement & Observed On-Device Defect
During PO acceptance of `ATT-8965` (`5.0.0-dev-f4ab0955` on Pixel 10), paired sensors that were never powered on or present (`12:9B`, `64:21`, `67:AA`) entered indefinite periodic re-search on the main `READY` screen once initial search tries expired. Additionally, the `ATT-8965` steady-state period presets (`1m / 2m / 5m / 10m`, default `5m`) are too coarse for recovering genuine mid-session drops (e.g., bakery stop, swim) and must tighten to `15s / 30s / 1m / 2m` (default `1m`).

## 2. Forensic Root Cause Analysis & Independent Peer Review / Verification
Auditing `sprint/2026-11-24_02_Spät` confirms the ticket's root pointer and uncovers four coupled gaps:
1. **Unconditional Periodic Retry on Never-Connected Sensors (`DeviceSearchPeriodicRetryCoordinator.kt:99-125`)**: When `tries <= 1` and `!current.shouldKeepAliveOnSearchTimeout()`, `handleSearchStoppedForCurrentDevice()` calls `scheduleRetryIfEnabled()` unconditionally without checking whether `current` ever connected in the current session. Absent sensors in `READY` therefore stay in `mMyRemoteDevices` and loop forever instead of invoking `detachAndGiveUpDevice` (`shutDown()` + removal).
2. **Missing Session-Connected Contract on `MyRemoteDevice` (`MyRemoteDevice.java:40-159`, `MyANTDevice.java:138-181`)**: Only `MyBTLEDevice.hasConnectedInSession()` (`L1166`) and private `PolarOnlineStreamingBridge.hasConnectedInSession` (`L193`) track prior connection; `MyRemoteDevice` and `MyANTDevice` expose neither `hasConnectedInSession()` nor `resetSessionConnectionState()`. Note: `MyBTLEDevice.mHasConnectedInSession` MUST remain a declared field on `MyBTLEDevice` for `DetailedDesignParityContractTest.kt:191`.
3. **Never-Connected Polar Live-IMU Active Reconnect Loops (`PolarOnlineStreamingBridge.kt:388,575-595,637,709,745,883`)**: `resumeAfterOfflineSync()` (`L388`) and `scheduleBackoffReconnect()` (`L588`) bypass session gating via `|| SensorSearchSettings.isPeriodicResearchEnabled(mContext)`, and `isMidSessionOrWorkoutActive()` (`L575-580`) returns `true` during `TRACKING`/`PAUSED` even when `hasConnectedInSession == false`. Unlike `MyBTLEDevice` (which converges to zero-scan passive `autoConnect = true` per `REQ-SET-123`), Polar SDK's `connectToDevice()` triggers active search watchdogs and backoff loops for absent sensors.
4. **Missing Workout-End Reset & `READY` GATT-133 Stall (`DeviceManager.java:220-229`, `MyBTLEDevice.java:694-705`)**:
   - When a workout ends (`TRACKING`/`PAUSED -> READY`/`IDLE`), `DeviceManager.mTrackingStateChangedReceiver` calls `startSearchForPairedDevices()` without clearing `hasConnectedInSession` or cancelling background `mReconnectRunnable`/`reconnectJob` on disconnected (`!isReceivingData()`) MIA devices from the ended workout—leaving them looping indefinitely in `READY` while actively connected (`isReceivingData() == true`) sensors must remain undisturbed.
   - In `MyBTLEDevice.onConnectionStateChange(STATE_DISCONNECTED)` (`L694-705`), if an absent never-connected sensor in `READY` (`!mHasConnectedInSession && !isMidSessionOrWorkoutActive() && isSearching()`) fails with immediate GATT status `133`, `disconnectFromGattInternal` cancels `mSearchTimeoutRunnable` and schedules `mReconnectRunnable` without calling `notifyStopSearching(false)`, risking queue stall.
5. **Preset Range & Legacy Clamping (`SensorSearchSettings.kt:35-45`, `SensorReconnectBackoffPolicy.kt:39`, `SearchSettingsDialog.kt:343-349`, `SensorSearchTuningSection.kt:279-285`, `prefs_search.xml:86-93`, `values*/strings_devices.xml`)**: Still expose `60/120/300/600 s` (default `300 s`); persisted `300`/`600` values must clamp/snap to `120 s` (`2m`) so segmented buttons always highlight a valid preset.
6. **Verified Monolith LoC Headroom (`ArchitectureConformanceContractTest.kt:113-128`)**: `DeviceManager.java` `1,679/1,708`, `MyBTLEDevice.java` `1,483/1,500` (**17 LoC left**), `PolarOnlineStreamingBridge.kt` `1,489/1,500` (**11 LoC left**), `TrainingApplication.java` `1,977/2,050` (untouched).

## 3. Scope Grounding, Non-Goals & Complexity/Tier Audit
- **In Scope**: MIA-only periodic re-search/backoff across `MyRemoteDevice`, `MyANTDevice`, `DeviceSearchPeriodicRetryCoordinator`, `DeviceManager`, `MyBTLEDevice`, `PolarOnlineStreamingBridge`; workout-end session-state reset for disconnected MIA sensors; `15s/30s/1m/2m` (default `1m`) presets + legacy `300`/`600 -> 120` clamping across settings, policy, both Compose UIs, `prefs_search.xml`, all 9 `values*/strings_devices.xml`, SWE.2/SWE.3 docs, and tests.
- **Out of Scope**: Removing `REQ-SET-123` passive OS-managed `autoConnect = true` for never-connected `MyBTLEDevice` during active workouts (zero active scans/timers); changing `MyBTLEDevice.MAX_RECONNECT_DELAY_MS = 16000L`; touching `TrainingApplication.java`, `TrackerService.java`, or SQLite schemas.
- **Sizing & Tier Check**: `3 SP` (canonical Fibonacci `<= 5 SP`, no split needed); `tier-a` confirmed (BLE/ANT+/Polar sensor connectivity & concurrency).

## 4. Requirement Archaeology & Chesterton's Fence Audit (`REQ-PRO-022`)
1. **Original Requirement ID & Target**: `REQ-CON-052` (`REQ-CON-052.1`–`.3`, `req_tracking_cockpit_part3.md`), interacting with `REQ-SET-123` (`req_settings_profiles.md`), `REQ-CON-051`, `REQ-CON-036`, and `SYSREQ-TRK-002`.
2. **Historical Origin & Commit Trace**: `6bb37af4` (`ATT-8965`, `2026-11-19` — extended `1s..5m` backoff & periodic re-search), `ATT-9243` (`REQ-SET-123`, `2026-11-21` — passive `autoConnect = true` convergence for never-connected workout BLE sensors), `d2209175` (`ATT-8998` — `REQ-CON-051` queue release), `3dc19303` (`ATT-7755` — `REQ-CON-036`).
3. **Root Reason for Existing Formulation**: `ATT-8965` aimed to recover dropped sensors after long out-of-range periods and avoid `16 s` retry storms, but scheduled periodic re-search on every `tries <= 1` failure without distinguishing absent paired sensors from previously connected MIA sensors; `ATT-9243` added passive `autoConnect = true` during `TRACKING`/`PAUSED` so sensors turned on mid-ride still attach with zero active scan-assist.
4. **Preservation of Core Invariants**: Preserve `MyBTLEDevice.INITIAL_RECONNECT_DELAY_MS = 1000L` & `MAX_RECONNECT_DELAY_MS = 16000L` (`SYSREQ-TRK-002`), `MyBTLEDevice.mHasConnectedInSession` / `isMidSessionOrWorkoutActive()` reflection parity (`DetailedDesignParityContractTest`), `REQ-SET-123` zero-scan passive `autoConnect = true` during active workouts, `REQ-CON-051` non-blocking queue handoff, `REQ-SET-120` `PolarOfflineGattCoordinator` yield keep-alive (`isOfflineGattYielded()`), and all LoC ceilings (`DeviceManager <= 1,708`, `MyBTLEDevice <= 1,500`, `PolarOnlineStreamingBridge <= 1,500`).
