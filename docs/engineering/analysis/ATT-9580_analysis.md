## 1. Forensic Root Cause Analysis & Independent Peer Review

- **Independent Peer Review & Verification (`ATT-3534`)**: Verified the ticket hypothesis against live `sprint/2026-11-23_03_Nacht` (`c9d98989`). Ticket line citations drifted (`:155-163` / `:279`); actual live locations are `WorkoutClusterRepository.kt:135-147` (`init`), `:154-195` (`loadAllClustersLightweight()`), and `:229-394` (`refreshClusters()`, with `needsEnrichment`/`showProgress` at `:261-262`). Investigation confirmed the hypothesized bug **and uncovered two additional coupled races**:

| # | Defect Mechanism | Live Code Location | Trigger & Impact |
|---|---|---|---|
| **1** | **Progress-Suppression Race** *(confirmed ticket RCA)* | `WorkoutClusterRepository.kt:138-146`, `:261-262` | `init` asynchronously launches `loadAllClustersLightweight()` on `Dispatchers.IO`, hydrating `_allClusters.value` with un-enriched rows (`previewPaths = emptyList()`). `refreshClusters()` computes `showProgress = forceShowProgress || (needsEnrichment && _allClusters.value.isEmpty())`. Whenever `init` finishes first (both under parallel test load and in production when the athlete visits General Map before Favorite Tracks), `_allClusters.value.isEmpty()` is `false` -> `showProgress = false` -> cold preview enrichment emits **zero** `MigrationStatus` updates (`TST-PERF-010` assertion failure). |
| **2** | **Stale Lightweight Overwrite Race** *(newly uncovered)* | `WorkoutClusterRepository.kt:154-195`, `:274-275`, `:389-390`, `:414-447` | `loadAllClustersLightweight()` holds `lightweightLoadMutex`, but neither `refreshClusters()` nor `ATT-9607`'s `syncClusterAfterWorkoutDeletion()` shares it (and `refreshClusters()` recursively calls itself via `recalculateClustersWithProgress()` at `:236` -> `:627`, so a non-reentrant mutex across `refreshClusters()` would deadlock). If `loadAllClustersLightweight()` reads un-enriched rows before `refreshClusters()` (or `syncClusterAfterWorkoutDeletion()`) commits and resumes at `:189`, it overwrites `_allClusters.value` with stale un-enriched / pre-deletion clusters. |
| **3** | **`StateFlow` Conflation Across Hardcoded `Dispatchers.IO`** *(newly uncovered)* | `WorkoutClusterRepository.kt:138,154,229`; `WorkoutClusterPreviewPersistenceTest.kt:138-146`; `WorkoutClusterRepositoryTest.kt:623-638` | `WorkoutClusterRepository` hardcodes `Dispatchers.IO` while test collectors run on `runBlocking`'s `BlockingEventLoop`. Under heavy CPU contention, `refreshClusters()` can execute Loading -> Healing -> Previews -> `null` on `Dispatchers.IO` before the JUnit thread wakes up; `MutableStateFlow` conflates `null -> non-null -> null` back to `null == oldState` and delivers **zero** non-null emissions, causing the exact same `AssertionError`. |

- **ATT-9607 Coexistence Audit (`d7711449`)**: Confirmed `ATT-9607` added synchronous `syncClusterAfterWorkoutDeletion(clusterId)` at `WorkoutClusterRepository.kt:414-447` (invoked by `WorkoutDeletionCoordinator:248`, not an async `WorkoutMutationEvent` collector inside `WorkoutClusterRepository`). ## 2. User Scope Grounding (`ATT-1250`)

- **In-Scope**: Eliminate the `init` lightweight load vs `refreshClusters()` progress race, stale `_allClusters`/`_clusterStats` overwrite race, and `StateFlow` conflation test flakiness in `WorkoutClusterRepository`, `WorkoutClusterPreviewPersistenceTest`, and `WorkoutClusterRepositoryTest`; preserve silent warm-restart reload (`TST-PERF-010`) and silent same-session revisits (`TST-PERF-009`, including indoor clusters with empty `previewPaths`).
- **Out-of-Scope**: SQLite schema changes (`0` migrations), UI/Compose/string edits (`Localization Parity: N/A`), refactoring `WorkoutClusterEngine` or `WorkoutDeletionCoordinator`, or altering `recalculateClustersWithProgress()` progress phases.

## 3. Requirement Archaeology & Chesterton's Fence Audit (`REQ-PRO-022`)

- **Original Requirement ID & Target**: `REQ-PER-006` (*Workout Cluster Migration Progress & Silent Persistent Preview Reload*, `TST-PERF-007`/`009`/`010`), `REQ-PER-003` (`TST-PERF-003`), and `REQ-UI-322.5` (*Fast Lightweight Cluster Hydration*).
- **Historical Origin & Commit Trace**: `663c82c9` (`ATT-441`, Jul 2026) introduced persisted `previewPaths` and `showProgress = forceShowProgress || (needsEnrichment && _allClusters.value.isEmpty())`; `c020fa5c` (`ATT-5074`, Nov 2026) added asynchronous `init { loadAllClustersLightweight() }`.
- **Root Reason for Existing Formulation**: When `ATT-441` was written, only `refreshClusters()` populated `_allClusters`, so `_allClusters.value.isEmpty()` served as a proxy for "first full refresh in this process" (avoiding repeated progress flashes on subsequent visits when un-enrichable indoor clusters keep `previewPaths.isEmpty()`). `ATT-5074` later populated `_allClusters` asynchronously from `init`, breaking that proxy invariant.
- **Preservation of Core Invariants**: Replacing `_allClusters.value.isEmpty()` with an explicit `!hasCompletedFullRefresh.get()` gate preserves all original semantics: (1) cold preview enrichment emits progress even after lightweight hydration, (2) warm restarts with persisted previews stay silent (`needsEnrichment == false`), (3) same-session revisits stay silent even with indoor/no-GPS clusters (`hasCompletedFullRefresh == true`), and (4) `init` lightweight hydration for map overlays stays fast and non-blocking.
