# Stage 1 Analysis: ATT-8895 - Derive Cycling Crank Cadence and Running Stride Cadence from Carriage-Classified Smartphone IMU Oscillations

**Ticket**: `ATT-8895` (`3 SP`, `Feature`) | **Parent Epic**: `ATT-166` | **Target Release**: `V5.0.0`  
**Active Sprint**: `2026-11-18_02_Spät` | **Branch**: `feature/ATT-8895` (base `fee3e805`) | **Author**: AI Agent 1 (Implementer) | **Date**: 2026-11-18

## 1. Problem Statement & Motivation
* When cycling with the smartphone in a front jeans pocket (`BIKE_FRONT_POCKET`) or jersey back pocket (`BIKE_JERSEY_BACK`) or running without a footpod/Polar IMU (`RUN_WAIST_HIP`, `RUN_BICEP_ARM`, `RUN_HANDHELD`), `SensorType.CADENCE` (and `SensorType.STRIDES` for runs) remain unrecorded (`GCData` `'C'` absent) because `Protocol.SMARTPHONE` emits no cadence.
* `ATT-8890` (`fee3e805`) now classifies 1-Hz `PhoneCarriageMode` via `PhoneCarriageClassifier`, enabling high-SNR smartphone IMU cadence extraction while strictly suppressing cadence on `BIKE_HANDLEBAR` mounts (`ATT-166` non-goal invariant).

## 2. Root Cause Analysis & Independent Hypothesis Verification
* **Existing DSP & Priority Infrastructure**:
  * `PolarLiveRunningCadenceEstimator.kt` (`:494-758`) defines `UniformGridResampler`, `BiquadBandPass`, `Vector3BandPass`, `BiquadSection`, `DoubleRingBuffer`, `Vector3RingBuffer`, and `findFundamentalLag()` (`:441-485`) as `private` nested classes expecting Polar units (`mG` `Int`, `deg/s` `Float`). Extracting these primitives into a shared pure-Kotlin DSP core enables zero-duplication reuse by `SmartphoneImuCadenceEstimator` while converting Android SI units (`m/s^2`, `rad/s`).
  * `SpeedAndLocationDevice_ATTFused.kt` (`:233-267`) runs `carriageClassifier` (`:99`) and registers `TYPE_GYROSCOPE`, `TYPE_GAME_ROTATION_VECTOR`/`TYPE_ROTATION_VECTOR`, `TYPE_PRESSURE`, and gated `TYPE_STEP_DETECTOR` in `registerImuSensors()`.
* **Independent Peer Review & Verification (Blind Spots Found in Live Code)**:
  1. **`TYPE_ACCELEROMETER` Rate & Lifecycle Gap (`SpeedAndLocationDevice.java:225-251,429`, `SpeedAndLocationDevice_ATTFused.kt:236,285`)**: `SpeedAndLocationDevice_ATTFused` currently delegates `TYPE_ACCELEROMETER` to `super` (`SpeedAndLocationDevice.registerAccelerometer()`), which only registers after `LocationAvailable()` at `SENSOR_DELAY_UI` (~15 Hz — aliases `1.2–4.0 Hz` impacts) and unregisters on `LocationUnavailable()`. Moreover, `registerImuSensors()` early-returns on `!isEffectiveGyroActive` (`:236`), blocking `ACC` + `TYPE_STEP_DETECTOR` cadence (`RUN_WAIST_HIP`) when a gyro is absent/disabled.
  2. **`GCData` `'C'` Pollution on `BIKE_HANDLEBAR` (`MySensorManager.java:330-361,571-573`)**: Calling `MySensorManager.registerSensor()` adds `SensorType.CADENCE` to `mAccumulatedSensorTypeSet` and permanently flips `GCData[5]` to `'C'`. Like `PolarOnlineStreamingBridge.kt:894-952`, `SpeedAndLocationDevice_ATTFused` must dynamically register `CADENCE` (and `STRIDES` via `MyIntegerAccumulatorSensor` + `accumulate(0)` strictly under `BSportType.RUN`, listening to `SPORT_TYPE_CHANGED_BY_USER_INTENT`) only when non-handlebar cadence is active, never registering on `BIKE_HANDLEBAR`, `UNKNOWN`, or `BIKE` walking dismounts (`WALKING_TRANSITION` while `BSportType.BIKE`).
  3. **Hardcoded `CADENCE_PRIORITY.last() == HRM` Test (`MySensorManager.java:68-75`, `MySensorManagerCadenceArbitrationTest.kt:168-171`)**: `MySensorManagerCadenceArbitrationTest` explicitly asserts `CADENCE_PRIORITY.last() == DeviceType.HRM`. Appending `DeviceType.SPEED_AND_LOCATION_ATT_FUSED` after `HRM` (plus defining `STRIDES_PRIORITY` and adding `SPEED_AND_LOCATION_ATT_FUSED` to `DeviceType.getDeviceTypeList(CADENCE|STRIDES)` at `DeviceType.java:173-184`) requires updating that priority-tail assertion while preserving `RUN_SPEED`/`BIKE_*`/`HRM` precedence.
  4. **Classifier Hysteresis During Coasting (`PhoneCarriageClassifier.kt:68,458-530`)**: `BIKE_FRONT_POCKET` coasting (`< 0.25 rad/s` RMS) triggers the `1.5 s` coasting gate (`0.0 RPM` within `2.0 s`), and after `DEFAULT_MOUNT_HYSTERESIS_MS` (`4,000 ms`) quiet coasting may transition to `BIKE_HANDLEBAR`, which must cleanly suppress/null cadence without phantom RPMs.
