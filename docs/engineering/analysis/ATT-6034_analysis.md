## 1. Problem Domain & Live Code Audit (`0bc45492`)
* **`TrackerService.java` (`3,555 / 3,559` LoC)** and **`TrainingApplication.java` (`2,134 / 2,135` LoC)** sit within 1–4 lines of their monolith ratchet caps (`ArchitectureConformanceContractTest.kt:118,122`).
* **Teilpaket A — Shutdown Deduplication, Type-Safe Lap Extraction & `TrainingApplication` Teardown**:
  1. `TrackerService.handleActionStop()` (`L1477–1560`) and `onDestroy()` (`L1686–1783`) duplicate ~50 lines of controller stop (`RadarLightController`, `PolarH10/VeritySenseOfflineController`, `cancelTrackerHandle`, `mDebugHeapWatchdog`, `mAutoPauseManager.release`, `mBroadcastTracker.reset`, `unregisterTransientReceivers`) and async `mDbExecutor` finalization dispatch. Differences (`onDestroy` cancels `mTableInitializationFuture`, clears `sInstance`, releases `mRadarAlertManager`, shuts down `mScheduler`/`mRrFlushExecutor`/`mDbExecutor`, and has the `ATT-6178` non-blocking `mIsStopping` early return; `handleActionStop` gates `performIdempotentMainThreadTeardown(true)` on `mSessionGeneration == stoppingGeneration && mIsStopping`) require explicit parameters.
  2. Lap telemetry extraction (`LAP_NR`, `TIME_LAP`, `DISTANCE_m_LAP`, `lapSpeed`) is duplicated 3×: `BanalFinalizationSnapshot.capture()` (`TrackerService.java:610–626`, `instanceof Integer` / `Number`), `TrackerService.createNewLap()` (`L2237–2255`, unsafe `(Integer)`/`(Double)` casts), and `BANALService.newLap()` (`BANALService.java:654–677`, unsafe `(Integer)`/`(Double)` casts + display strings). Unifying via Kotlin `LapTelemetryExtractor` (`com.atrainingtracker.banalservice.sensor`) with `instanceof Number` + finiteness guards eliminates `ClassCastException` hazards across all 3 sites.
  3. In `TrainingApplication.java` (`L2010–2093`), `stopTracking()`, `resetTrackingStateOnAbort()` (`static`, `cAppContext != null`), and `onTrackingAborted()` share pause-lock resets (`mWasAutoPaused`, `setManualPauseLock(false, ctx)`, `setAutoPaused(false, ctx)`) and active-tracking resets (`cTrackingMode = READY`, `sActiveWorkoutId = -1`, `clearBreadcrumbs`), while `stopTracking()` requires pause resets **before** `ACTION_STOP`/`stopService` dispatch and active-tracking reset **after**, and `trackingStopped()` (`L2083–2093`) is semantically distinct (`RESET_ACCUMULATORS_INTENT`, `clearBreadcrumbs`, `WorkoutNavigationEvents.triggerEdit`, `mNotificationManager.cancel` — zero pause/mode resets). Two small `private static` helpers (`resetPauseLocks` + `resetActiveTrackingState`) preserve 100% ordering and semantics.
* **Teilpaket B — `PostWorkoutFinalizer` Extraction (`TrackerService.java:3160–3550`, `390` LoC)**:
  * `finalizeLiveSession(...)` (7 fault-isolated stages: map/streams, start/end/extrema/apex, EF/Decoupling/Dynamics/power metrics respecting `mDeferHrPhysiologyToPostProcessing`, `guessCommuteAndTrainer`, identity/clustering/auto-naming/milestones, converged wheel circumferences, diagnostic error JSON) and `guessCommuteAndTrainer(workoutId)` can be extracted into a dedicated Kotlin object `PostWorkoutFinalizer` (`com.atrainingtracker.trainingtracker.tracker`), keeping `TrackerService`'s protected 0-/1-/4-arg `finalizeLiveSession` and 0-/1-arg `guessCommuteAndTrainer` delegates intact (`~360` LoC removed from `TrackerService.java`).
* **Teilpaket C — Strava Sync Preferences & Worker Scheduling (`TrainingApplication.java:1218–1399`, `3 × Strava*SyncWorker.kt`)**:
  * 18 copy-pasted static methods (`Equipment`/`Routes`/`Segments`, each with its own `"never"` string resource) can delegate to a private `StravaSyncPref` enum + 6 parameterized helpers (`~110` LoC removed, preserving all 18 public static signatures and null `cSharedPreferences`/`cAppContext` guards per `coding_standards.md` §5.5).
  * `StravaEquipmentSyncWorker`, `StravaRoutesSyncWorker`, and `StravaSegmentsSyncWorker` duplicate `schedule(context)` (`~40` LoC each) while keeping distinct `doWork()`. A shared `StravaSyncScheduler.schedulePeriodicSync(...)` helper preserving per-worker `tag`, `workName`, and `entityLabel` deduplicates all 3 cleanly (preserving `StravaRoutesSyncWorkerTest.kt:99` log tag assertion).
