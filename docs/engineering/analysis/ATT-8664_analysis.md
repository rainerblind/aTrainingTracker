## 1. Problem Domain, Root Cause Analysis & Codebase Audit
* **Root Cause 1 — Unconditional Extrema-Only Polyline Truncation in `PeriodsViewModel.filterPeriodSummary()` (`PeriodsViewModel.kt:279-358`, `423 / 1,500` LoC)**:
  * `PeriodsRepository.enrich()` (`PeriodsRepository.kt:974-1145`, `1,211 / 1,500` LoC) sets `workoutIdToAllPolylinesMap = emptyMap()` and `workoutIdToPathMap = emptyMap()` (`REQ-PER-039.1`/`.2`), restricts `workoutIdToPolylineMap` to `<= 5` extrema anchors (`trueLongestId`, `northId`, `southId`, `eastId`, `westId`), and puts `<= 8` curated tracks (`MAX_SUMMARY_THUMBNAIL_TRACKS`) into `summary.polylines`.
  * `PeriodsScreen.kt:72, 169` (`210` LoC) always renders `filteredGroupedPeriods`, which unconditionally invokes `filterPeriodSummary(summary, selectedSports)` even under the default `{BIKE, RUN}` filter.
  * Inside `filterPeriodSummary()` (`:289-325`), `polylineSource` and `allPolylineSource` both fall back to `summary.workoutIdToPolylineMap` (the `<= 5` extrema anchors), overwriting `polylines` with ONLY those `<= 5` extrema anchors and silently discarding all non-anchor preview tracks in `summary.polylines` (while also erroneously re-populating `workoutIdToAllPolylinesMap` in the filtered copy).
* **Root Cause 2 — Extrema-Biased Preview Curation & Truncated Region Detection (`PeriodsRepository.kt:981-995`, `PeriodMapUtils.kt:241-379`, `431 / 1,500` LoC)**:
  * Even prior to filtering, `enrich()` prioritizes `anchorWorkouts` (`northId`/`southId`/`eastId`/`westId` — by definition geographic outliers such as a 2-ride vacation in Scotland) ahead of recent home-region tracks.
  * `PeriodMapUtils.prepareCardMapPreviewSync()` (`:300-376`) executes `SpatialRegionEngine.detectRegionsFromPaths(budgetEnforcedPaths)` strictly on the surviving `<= 5` extrema tracks and assigns `primaryRegionPathsCount = activePaths.size` (`:370`), allowing a 2-track outlier region (`northId` + `westId`) to beat a 150+ workout home region and display `Hauptregion: Highland Council (2)`, contradicting `PeriodsViewModel.showPeriodMap()` (`:158`, which runs `SpatialRegionEngine.detectRegions(filteredWorkouts)` across all period workouts).

## 2. Independent Peer Review & Verification (4-Augen-Prinzip — Rules 69 & 70)
1. **Memory-Bounded Sport-Aware Region Summaries (`PeriodData.kt`, `178` LoC; `PeriodsRepository.kt`; `PeriodsViewModel.kt`)**:
   * Storing a compact per-region summary list (`regionSummaries: List<PeriodRegionPreview>`) computed once inside `PeriodsRepository.enrich()` via `SpatialRegionEngine.detectRegions(groupWorkouts)` (which uses `startLatLng` + bounding coordinates — **zero** `PolyUtil.decode()` calls!) solves BOTH default `{BIKE, RUN}` AND any toggled sport filter (`{BIKE}`, `{RUN}`, `{UNKNOWN}`) while keeping `workoutIdToPathMap == emptyMap()`, `workoutIdToAllPolylinesMap == emptyMap()`, `workoutIdToPolylineMap.size <= 5`, and `summary.polylines.size <= MAX_SUMMARY_THUMBNAIL_TRACKS (8)` (`REQ-PER-039`, `PeriodsRepositoryMemoryTest`).
   * Each `PeriodRegionPreview` holds only `center`, `bounds`, per-sport `sportCounts`, `sportDistancesMeters`, `sportMostRecentTimestampS`, and bounded per-sport curated encoded polylines (`<= MAX_SUMMARY_THUMBNAIL_TRACKS`), allowing `filterPeriodSummary(summary, sports)` to rank surviving regions (`filteredCount > 0`) by the **exact** `SpatialRegionEngine.detectRegions()` comparator (`workoutCount DESC`, `totalDistance DESC`, `mostRecentTimestampS DESC`) and pick `<= 8` preview polylines strictly from the winning Primary Region.
2. **Blind Spot — Multi-Region Badge Visibility & True Workout Count (`PeriodMapUtils.kt:300-376`, `PeriodSummaryCard.kt:284-317`, `789` LoC)**:
   * Once `summary.polylines` is curated strictly from the Primary Region (`<= 8` tracks within `< 60 km`), running `detectRegionsFromPaths()` alone would report `regionCount = 1` (hiding the multi-region badge) and `primaryRegionPathsCount <= 8` (instead of e.g. `159`). Propagating authoritative `primaryRegionSummary` (`detectedRegionCount`, `primaryRegionWorkoutCount`, `center`, `bounds`) onto `PeriodSummary` lets `PeriodMapUtils.prepareCardMapPreviewSync()` render the primary region's tracks, set `regionCount = detectedRegionCount`, set `primaryRegionPathsCount = primaryRegionWorkoutCount`, set `activeRegionId = "region_0"`, and geocode from `primaryRegionSummary.center` (matching `PeriodMapScreen` 1:1!), while preserving full legacy fallback (`detectRegionsFromPaths`) when `regionSummaries` is empty (keeping all existing synthetic `PeriodCardMapStateTest` cases green).
3. **Blind Spot — Cache Key & Compose `produceState` Invalidation on Sport Toggle (`PeriodMapUtils.kt:245, 390`; `PeriodSummaryCard.kt:260-264`)**:
   * Toggling `{BIKE, RUN}` -> `{BIKE}` can retain the exact same 8 recent bike polylines while changing `primaryRegionWorkoutCount` (`159 -> 150`) or `detectedRegionCount` (`2 -> 1`). Both `periodCardMapStateCache` key (`PeriodMapUtils.kt:245, 390`) and `produceState` keys (`PeriodSummaryCard.kt:261-263`) MUST include the resolved primary-region summary key so stale badge counts/names never linger.
4. **Blind Spot — `workoutIdToAllPolylinesMap` Retention Leak & Backward Compatibility (`PeriodsViewModel.kt:295-351`)**:
   * `filterPeriodSummary()` currently copies `workoutIdToPolylineMap` into `workoutIdToAllPolylinesMap` when input `workoutIdToAllPolylinesMap` is empty; restricting `filteredAllPolylinesMap` strictly to non-empty input preserves `REQ-PER-039.2` (`emptyMap()`) while keeping `PeriodsViewModelTest.testSymmetricDtoPolylineSportFiltering_TST_PER_032_1` 100% green.
5. **Localization Check**: Verified `workout_periods__primary_named_region_format` and `workout_periods__primary_region_format` already exist across all 9 active locales (`values`, `de/es/fr/it/ja/nl/pl/pt`) -> **`Localization Parity: N/A - no UI strings`**.
