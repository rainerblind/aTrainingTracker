# Stage 1 Analysis: ATT-8690 - PolarBleApi Singleton Collision & Polar Offline/Live Coordination

**Ticket**: `ATT-8690` (`3 SP`, `severity-critical`, Parent `ATT-5910`) | **Target Release**: `V5.0.0` | **Sprint**: `2026-11-17_03_Nacht` | **Branch**: `feature/ATT-8690` | **Date**: 2026-11-17

## 1. Problem Statement & Motivation
* On Pixel 10 (`Android 13+`) with paired Polar Verity Sense (`24:AC:AC:24:82:56`) and Polar H10 (`24:AC:AC:25:0F:A6`), offline backup arming fails with `PolarBleSdkInstanceException` (`PolarVerityOfflineCtrl` at `17:06:21.094`, `PolarH10OfflineCtrl` at `17:06:21.095`), blocking stop-time backfill and Aftermath retry for `ATT-7924`, `ATT-8000`, and `ATT-8001`.
* Expected: All Polar bridges and offline controllers share one process-wide `PolarBleApi` singleton without `PolarBleSdkInstanceException`, callback loss, or unworn-sensor scan contention.

## 2. Root Cause Analysis & Independent Hypothesis Verification
* **Cause 1 — Exact-Set `BDBleApiImpl` Singleton & Destructive `cleanup()`**:
  * `polar-ble-sdk:8.6.0` `BDBleApiImpl$Companion.getInstance(context, features)` checks `Intrinsics.areEqual(instance.getFeatures(), features)`; even strict feature subsets throw `PolarBleSdkInstanceException`. `cleanup()` calls `BleDeviceListener.removeAllSessions()` and clears `telemetryAvailabilityMap` WITHOUT clearing `BDBleApiImpl.instance` (only `shutDown()` clears `instance`).
* **Cause 2 — Four Disjoint Feature Sets Across 4 Production Callers**:
  * `PolarOnlineStreamingBridge.kt:354, 368-383`: 6 features (H10) or 7 features (Verity Sense).
  * `PolarOfflineGattCoordinator.kt:381`: `withGattYieldAndPolarApi` creates a new client when `getActiveSession(polarId)` is `null`.
  * `PolarH10OfflineController.kt:281, 518` (2 features: `H10_EXERCISE_RECORDING`, `DEVICE_TIME_SETUP`): bypasses `withGattYieldAndPolarApi`, duplicating `defaultImplementation(...)` and `api.cleanup()` (`:417, 649`).
  * `PolarVeritySenseOfflineController.kt:94-102, 472, 527, 581, 736, 773`: two 2-feature sets (`OFFLINE_RECORDING` + `DEVICE_TIME_SETUP` or `TRAINING_DATA`).
* **Independent Peer Review & Verification (Live `45465e8f` + SDK Bytecode)**:
  * **Verified**: All 4 `defaultImplementation` sites in `app/src/main/` match the ticket; `getActiveSession(polarId)` (`PolarOfflineGattCoordinator.kt:67-113`) only shares per `polarId`, so any second device or transient reconnect/Aftermath retry collides with `BDBleApiImpl.instance`.
  * **Blind Spot 1 — Global Callback Clobbering**: `BDBleApiImpl.setApiCallback()` holds ONE global `callback` and immediately fires `blePowerStateChanged(listener.bleActive())`. `PolarOnlineStreamingBridge.kt:357` overwrites `api.setApiCallback(sdkCallback)` directly; `PolarOfflineGattCoordinator.awaitFeaturesViaCallback()` (`:286-341`) replaces `api.setApiCallback` globally and restores only `activeSessionCallbacks[normalizeId(polarId)] ?: NoOpPolarCallback()`, dropping concurrent `awaitFeaturesReady` callers and any second bridge. Moreover, `PolarOnlineStreamingBridge.sdkCallback.deviceConnected` (`:266`) / `deviceDisconnected` (`:280`) do not filter by `polarDeviceInfo.deviceId`/`address`.
  * **Blind Spot 2 — `api.cleanup()` Kills Sibling Sessions**: Because `BDBleApiImpl.cleanup()` invokes `listener.removeAllSessions()`, calling `api.cleanup()` in `PolarOnlineStreamingBridge.shutDown()` (`:790`), `PolarOfflineGattCoordinator.kt:394`, or `PolarH10OfflineController.kt:417, 649` tears down ALL live Polar sessions process-wide; a centralized ref-counted singleton must NEVER call `cleanup()`/`shutDown()` while other holders/bridges are active (`apiOverride?.shutDown()` in `:186`/`:266` is test-only).
  * **Blind Spot 3 — Unworn Sensor Scan & ID Mismatch**: `TrackerService.java:1247-1255` invokes both H10 and Verity `onWorkoutStarted()`; `findEnabledPolarDevice()` (`PolarOfflineGattCoordinator.kt:209-219`, `DevicesDatabaseManager.java:126-144`) scans all `allDevicesForCache` rows without checking `DeviceManager` active/receiving HRM state (`DeviceManager.java:994-1014`). Note also `getBtleDeviceByAddress()` (`DeviceManager.java:1017-1030`) skips `PolarOnlineStreamingBridge` (`MyRemoteDevice`, not `MyBTLEDevice`), and `PolarH10OfflineControllerTest`/`PolarVeritySenseOfflineControllerTest` use relaxed DB mocks without stubbing `isPaired()`.
  * **Blind Spot 4 — MAC vs 8-Hex ID Mismatch**: `extractPolarId()` (`PolarOfflineGattCoordinator.kt:161-163`) falls back to MAC when the DB name lacks an 8-hex ID, whereas `BDBleApiImpl` emits `session.getPolarDeviceId()` when non-empty in callbacks—breaking `identifier.equals(polarId)` checks (`PolarOfflineGattCoordinator.kt:306`, `PolarOnlineStreamingBridge.kt:297, 306`) and `activeSessions`/`activeAccOwners` lookups (`:67-69`).

## 3. Scope Grounding & Non-Goals (`ATT-1250`)
* **In-Scope (`3 SP`)**: (1) Centralize process-wide `PolarBleApi` singleton in `PolarOfflineGattCoordinator` using the 8-feature superset (`FEATURE_HR`, `FEATURE_POLAR_ONLINE_STREAMING`, `FEATURE_BATTERY_INFO`, `FEATURE_DEVICE_INFO`, `FEATURE_POLAR_DEVICE_TIME_SETUP`, `FEATURE_POLAR_H10_EXERCISE_RECORDING`, `FEATURE_POLAR_OFFLINE_RECORDING`, `FEATURE_POLAR_TRAINING_DATA`), ref-counted acquisition/release, and a global multiplexed callback dispatcher (no per-caller `cleanup()`/`shutDown()`); (2) Route `PolarOnlineStreamingBridge`, `PolarH10OfflineController` (`stopAndBackfillWorkout` & `syncPendingWorkout` too), and `PolarVeritySenseOfflineController` through the shared coordinator; (3) Skip unworn/disconnected Polar offline arming when another Polar HRM is actively tracking, and match both MAC and 8-hex Polar ID across callbacks/session maps; (4) Unit tests for singleton reuse, ref-counting, callback multiplexing, MAC/hex matching, and unworn-sensor gating.
* **Out-of-Scope**: `Devices.db` schema bumps, `BTLEHeartRateDevice` standard `0x180D` path, Polar SDK version upgrade, physical Pixel 10 execution (deferred to PO/Systemtest per `Rule 7.6`).
