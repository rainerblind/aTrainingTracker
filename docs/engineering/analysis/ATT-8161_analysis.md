## 2. Forensic Code-Grounded Survey & Independent Verification
Audited `ADR-001`, `docs/architecture.md`, `JavaCoreMigrationStrategyContractTest.kt`, `AspiceSweAuditContractTest.kt`, and `app/src/main/` for the 6 core decisions:
1. **ADR-002 — Foreground Tracking Service (`TrackerService`)**: `AndroidManifest.xml` declares `TrackerService` (`foregroundServiceType="location|health"`, `START_STICKY` + `ACCESS_BACKGROUND_LOCATION`), `PARTIAL_WAKE_LOCK` (`aTrainingTracker:TrackingLock`), and `ScheduledExecutorService` (`mScheduler` 1-Hz tick, `mDbExecutor`, `mRrFlushExecutor`). *Alternatives*: `WorkManager` / `JobScheduler` (rejected: deferred/batched by Doze, cannot sustain deterministic 1-Hz sampling) vs Foreground Service + `START_STICKY` (selected).
2. **ADR-003 — Sensor Ingestion Bus (`BANALService` & `BANALServiceRepository`)**: `BANALService` (`location|health` FGS) exposes Local Binder `BANALServiceComm`, `BroadcastReceiver`s, `MySensorManager`, `ProxySensor`, and `FilterManager`; `BANALServiceRepository` bridges `BANALServiceComm` to `StateFlow<List<FilteredSensorData<*>>>` for Compose/ViewModels. *Alternatives*: Global static EventBus or cross-process AIDL (rejected: lifecycle leaks, Binder serialization overhead) vs Local Binder + Repository `StateFlow` bridge (selected).
3. **ADR-004 — Raw SQLite Managers vs Room ORM (`*DatabaseManager`)**: Note ticket cites `TrackPointsDatabaseManager` (absent in code); real persistence uses `SQLiteOpenHelper` managers (`WorkoutSamplesDatabaseManager` with dynamic per-workout 1-Hz tables via `createNewTable`/`makeColumns`, `WorkoutSummariesDatabaseManager`, `LapsDatabaseManager`, `DevicesDatabaseManager`, `WorkoutClusterDatabaseManager`, `HrvReadinessDatabaseManager`, `WorkoutRrDatabaseManager`, WAL + `dbDispatcher`/`mDbExecutor`) encapsulated behind Kotlin repositories (`WorkoutRepository`, `DeviceDataRepository`, `KnownLocationsRepository`). *Alternatives*: Full Room ORM migration (rejected: static `@Entity` schemas cannot cleanly model dynamic per-workout sample tables and risk multi-version upgrade regressions) vs SQLite WAL Managers + Repository encapsulation (selected).
4. **ADR-005 — Hybrid Preferences (`DataStore` vs `SharedPreferences`)**: `TrainingApplication` and legacy/sync callers read `PreferenceManager.getDefaultSharedPreferences`, while reactive UI/tuning/zone settings use `androidx.datastore:datastore-preferences` (`SettingsDataStore` with eager `StateFlow<SettingsSnapshot>`, `TuningPreferencesDataStore`, `MyPreferenceManager`, `AttFusedPreferences`) + `SettingsDataStoreJavaHelper` for Java callers. *Alternatives*: Monolithic `SharedPreferences` (rejected: main-thread XML I/O, no `Flow`) or immediate big-bang DataStore cutover (rejected: legacy Java service hotpath risk) vs Hybrid DataStore-first with Java bridge (selected).
5. **ADR-006 — Incremental Single-Activity Compose Navigation (`MainActivityWithNavigation`)**: `MainActivityWithNavigation` hosts `ATrainingTrackerApp` (`androidx.navigation:navigation-compose` `NavHost`, `AppNavigationDrawer`) and MVI `StateFlow` ViewModels while incrementally replacing legacy XML/fragments (`ConfigViewsActivityClassic`, `ConfigViewsFragment`, `TrackOnMapHelper`). *Alternatives*: Pure multi-Fragment XML or big-bang Compose rewrite (rejected) vs Single-Activity `NavHost` + incremental screen migration (selected).
6. **ADR-007 — Unified BLE & ANT+ Hardware Abstraction (`MyDevice` / `MyRemoteDevice`)**: Note ticket cites `ANTDevice`/`BTLEDevice` (real base classes: `MyDevice` -> `MyRemoteDevice` -> `MyANTDevice` using pinned `ANT-Android-SDKs` `0e8cea71` / `AntPluginPcc` and `MyBTLEDevice` with `BluetoothGatt` + `mGattQueue`, plus `PolarOnlineStreamingBridge` via `polar-ble-sdk`), aggregated by `DeviceManager` into protocol-agnostic `MySensor`/`ProxySensor` (`SensorType`). *Alternatives*: Protocol-specific UI/tracking branches (rejected) vs Unified `MyRemoteDevice` + `SensorType` abstraction (selected).
