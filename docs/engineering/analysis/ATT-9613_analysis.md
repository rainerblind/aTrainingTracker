## 2. Chesterton's Fence Archaeology (`REQ-PRO-022`)

- **Original Requirement ID & Target**: `REQ-DAT-029.4` (in `docs/requirements/req_data_migration_export_part1.md:2936-2940`), `REQ-EXP-044.1` & `REQ-EXP-045.3`/`.4` (`req_data_migration_export_part2.md:759-763, 896-903`).
- **Historical Origin & Commit Trace**: `ExportManager.invalidateWorkoutExport` was created in `ATT-3274` (commit `6ac6e7aa`, 2026-10-14) for pre-crop cache invalidation, hardened with unique-work cancellation in `ATT-3995` (`REQ-DAT-029.4`), well before `FileFormat.RAW_SENSOR` was introduced in `ATT-8020` (`REQ-EXP-044`) and extended to `.phone_raw.csv.gz` in `ATT-9348` (`REQ-EXP-045`).
- **Root Reason for Existing Formulation**: When `ATT-3274` was authored, every local file under `FileFormat.values()` (`CSV`, `GC`, `TCX`, `GPX`, `FIT`, `STRAVA`) was a disposable cache derived from `WorkoutSamples.db`/`WorkoutSummaries.db` that had to be purged so stale pre-crop/pre-backfill files would not be uploaded or shared before regeneration.
- **Preservation of Core Invariants**: Derived export caches (`CSV`, `GC`, `TCX`, `GPX`, `FIT`, `STRAVA`) MUST continue to be deleted on `invalidateWorkoutExport`; Step 1 WorkManager cancellation (`cancelAllWorkByTag`, `cancelUniqueWork("export_" + fileBaseName)`, and `getUniqueWorkName(fileBaseName, format)` for all formats) and Step 3 `ExportStatus.WAITING` DB reset + `broadcastExportStatusChanged` (`REQ-DAT-029.4`) remain 100% preserved so subsequent `exportWorkout` cleanly regenerates derived files and re-exports/uploads intact raw sidecars. `FileFormat.RAW_SENSOR` directory/ending/MIME constants (`"raw_sensor"`, `".polar_raw.csv.gz"`, `"application/gzip"`) and `STANDARD_FILE_FORMATS` remain unchanged.

## Change-Request Impact Analysis

- **Affected Requirements**: Adds `REQ-EXP-048` / `TST-EXP-048` (`Derived (SW-only)`) refining `REQ-DAT-029.4` file-cleanup scope and protecting `REQ-EXP-044.1` / `REQ-EXP-045.3`–`.4` sidecars in `docs/requirements/req_data_migration_export_part2.md` and `docs/tests/tst_data_migration_export.md`. `SYS.2`/`SYS.3` impact: none (no external sensor, HAL, cloud REST API, or SQLite schema changes).
- **Affected Architecture Elements**: `FileFormat.java` (adds `isDerivedExportFile()` enum property), `ExportManager.java` (filters Step 2 cache-file deletion by `format.isDerivedExportFile() && !format.getFileEnding().isEmpty()` with safe `baseDir` guard and updated Javadoc). Zero edits to `RawSensorFileExporter.kt`, `PolarRawTelemetryPruner.kt`, `WorkoutRepository.kt`, SQLite schemas, or UI/strings (`Localization Parity: N/A`).
- **Verification Impact & Test Surface**: Add unit regression tests in `ExportManagerTest.kt` (verifying `FileFormat.isDerivedExportFile()` classification for every enum constant, `invalidateWorkoutExport` deleting all 6 derived caches `CSV`/`GC`/`TCX`/`GPX`/`FIT`/`STRAVA` while preserving `.polar_raw.csv.gz`, `.phone_raw.csv.gz`, and `.tmp` sidecars byte-for-byte + cancelling WorkManager & resetting DB status) and `RawSensorFileExporterTest.kt` (end-to-end `invalidateWorkoutExport` followed by `RawSensorFileExporter.export()` succeeding with both Polar and Phone sidecars intact). Also run existing `ExportManager*Test`, `RawSensorFileExporterTest`, `PolarRawTelemetryPrunerTest`, `BaseExporterDownloadsTest`, and `ArchitectureConformanceContractTest`.
- **Risk Assessment & Invariants**: `HIGH` (`tier-a`) because data loss affects irreplaceable field recordings, while fix surface is minimal and deterministic (`2` small Java files). Mitigated by enum-level `isDerivedExportFile()` exhaustiveness (future `FileFormat` entries must declare classification explicitly) and real temp-directory filesystem assertions in unit tests.
