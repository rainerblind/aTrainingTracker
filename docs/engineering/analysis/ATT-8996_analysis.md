# Stage 1 Analysis: ATT-8996 — BLE DIS (`0x2A29`/`0x2A24`/`0x2A25`) NUL-Byte Sanitization & DB Cleanup

**Ticket**: `ATT-8996` (`2 SP`, `tier-a`, `severity-minor`, Epic `ATT-5910`) | **Target Release**: `V5.0.0` | **Branch**: `feature/ATT-8996` | **Date**: 2026-11-24

## 1. Problem Statement & Observed On-Device Defect
On the Pixel 10 (`Devices.db`), paired BLE sensors (`Polar H10` `_id=25`, `Polar Verity Sense` `_id=28`) persist a trailing C-string NUL byte (`'\u0000'`) in `Devices4.manufacturerName` (`"Polar Electro Oy\u0000"`). Android's `BluetoothGattCharacteristic.getStringValue(0)` copies all payload bytes verbatim—including trailing `0x00` terminators emitted by BLE peripherals—and Kotlin's `CharSequence.trim()` / `isNotBlank()` treats `'\u0000'` as non-whitespace (`'\u0000'.isWhitespace() == false`), allowing NUL bytes to survive into SQLite, `SharedPreferences`, and Polar DIS/model classifiers.

## 2. Forensic Root Cause Analysis & Independent Peer Review / Verification
Auditing `sprint/2026-11-24_02_Spät` (`44ca00f5`) confirms the ticket's root cause and refines the exact production call sites (correcting two hypotheses from the ticket description):
1. **Exact BLE GATT String Read Sites (6 `getStringValue(0)` + 1 GAP Name + 1 Polar SDK Callback)**:
   - `BTSearchForNewDevicesEngine.java`: `L198` (`0x2A29` Manufacturer Name -> `mManufacturerMap`), `L202` (`0x2A24` Model Number -> `PolarOfflineCapabilityStore`), `L208` (`0x2A25` Serial Number -> `isValidCanonicalPolarId` / `recordDisMetadata` / `registerDeviceAliases`), plus `L117` (`gatt.getDevice().getName()` — Android's GAP `0x2A00` / advertising local name -> `mNameMap`).
   - `BTLEHeartRateDevice.java`: `L396` (`0x2A24` Model Number), `L399` (`0x2A25` Serial Number).
   - `BTLERadarDevice.java`: `L783` (`0x2A24` Model Number -> `completeLightControlRegistration`; a NUL-only payload `"\u0000"` passes `!model.isEmpty()` and corrupts `mModelNumber`).
   - `PolarPmdStreamCoordinator.kt`: `L212-236` (`recordDisCharacteristic`, invoked by `PolarOnlineStreamingBridge.kt:811-819,982-987`) calls Kotlin `value.trim()` without stripping `'\u0000'`.
   - **Peer-Review Correction (`MyBTLEDevice.java` & `0x2A00`)**: `MyBTLEDevice.java` (`1,494/1,500` LoC) performs **zero** DIS/GAP string reads today (`onOtherCharacteristicUpdate()` is an empty hook; general reconnect DIS backfill belongs to follow-up `ATT-8723`), and no class reads GATT `0x2A00` directly (`BluetoothDevice.getName()` at `BTSearchForNewDevicesEngine.java:117` is the sole GAP name entry point). Keeping `MyBTLEDevice.java` untouched preserves its `1,500` LoC ceiling.
2. **Kotlin `trim()` / `isNotBlank()` Failure Modes in `PolarOfflineCapabilityStore.kt` & `PolarOfflineGattCoordinator.kt`**:
   - `PolarOfflineCapabilityStore.kt:176,198-199,248,286,346-347,362-363,444,487` uses Kotlin `.trim()`: `"ABCD1234\u0000"` fails `CANONICAL_POLAR_ID_REGEX` (`^[0-9A-Fa-f]{8}$`), silently dropping Polar serial IDs; `"Sense\u0000"` fails exact `lower == "sense"` (`L450`), misclassifying Verity Sense as `UNKNOWN`; and previously persisted dirty SharedPreferences entries remain dirty on read.
   - `PolarOfflineGattCoordinator.kt:1044-1053,1087-1094`: `hasExplicitNonPolarManufacturer("\u0000")` evaluates `"\u0000".isNotBlank() == true`, falsely suppressing legacy Polar heuristics when DIS manufacturer contains only NUL bytes.
3. **Database Persistence & Cursor-Bypass Read Sites (`DevicesDatabaseManager.java`, `RawDeviceDataProvider.kt`, `DeviceDataRepository.kt`)**:
   - `DevicesDatabaseManager.java` (`1,657/1,671` LoC baseline in `ArchitectureConformanceContractTest.kt:126` — **14 LoC headroom**) stores `name` and `manufacturerName` verbatim in `insertNewBluetoothDeviceIntoDB` (`L590-591`), `insertNewAntDeviceIntoDB` (`L539-540`), and `setManufacturerName` (`L747-749`), and reads them unsanitized in `getManufacturerName` (`L726`), `getDeviceName` (`L731`), `getAllDevicesForCache` (`L126`), `getDeviceIdAndNameLists` (`L486-487,498`), `getCriticalBatteryDevices` (`L823`), `getSensorsForSportType` (`L976`), and `getAllRemoteSensors` (`L1016`).
   - `RawDeviceDataProvider.kt:46-47` reads `MANUFACTURER_NAME` and `NAME` directly via `Cursor` (bypassing `DevicesDatabaseManager` getters), and `DeviceDataRepository.kt:588` updates `NAME`. Existing dirty rows in `Devices4` (e.g., Pixel 10 v14 DB or restored `.attbackup`) require an idempotent `DB_VERSION` `14 -> 15` data migration (matching v9–v12 data-only migration precedent) plus read/write sanitization.
