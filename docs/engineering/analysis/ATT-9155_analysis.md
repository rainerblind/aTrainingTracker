## 1. Problem Statement & Field Evidence
Observed on Pixel 10 (`5.0.0-dev-906504b8`, pre-run setup before `2026-11-19_184953`) with **Polar Verity Sense** (`24:AC:AC:24:82:56`):
1. **Silent connected HRM (`--` indefinitely)**: Verity Sense reported as connected in the app yet delivered 0 Heart Rate values.
2. **Invisible to rediscovery after unpair/delete until hardware power-cycle**: Unpairing and scanning to re-pair the Verity Sense returned 0 BLE scan matches until the sensor was physically switched off and back on.

## 2. Independent Peer Review & Verification
Independently audited live `sprint/2026-11-20_02_Spät` @ `392e312c` (post-`ATT-9161`, `ATT-9176`, `ATT-8994`, `Rule 68` side-effect trace):
1. **Verified Root Cause 1 — Incomplete Unpair/Delete Teardown Across Raw GATT & Polar SDK (`MyBTLEDevice.java`, `BTLEHeartRateDevice.java`, `PolarOnlineStreamingBridge.kt`, `PolarOfflineGattCoordinator.kt`, `DeviceDataRepository.kt`, `DeviceManager.java`)**:
   - **`PolarOnlineStreamingBridge.shutDown()` (`L1209-1248`)**: Calls `api.disconnectFromDevice(streamId)` on only **one** identifier (`streamId`), omitting sibling MAC / canonical 8-hex aliases (`coordKey`, `polarId`, `macAddress`), and never clears `PolarOfflineGattCoordinator.connectedDeviceIds`. Because `connectPersistentSession()` (`L627`) enabled `api.setAutomaticReconnection(true)` on the shared `PolarBleApi`, a session keyed under a different alias or held by a non-zero `activeLeaseCount` can keep the Verity Sense ACL-connected (suppressing BLE advertising).
   - **`BTLEHeartRateDevice.shutDown()` (`L343-360`)**: Tears down only raw `BluetoothGatt`; never disconnects lingering `PolarBleApi` sessions for `getAddress()` / canonical Polar ID in `PolarOfflineGattCoordinator` (e.g., after offline PFTP arming/backfill or prior bridge usage).
   - **`MyBTLEDevice.disconnectFromGatt()` (`L887-912`) & `onConnectionStateChange()` (`L560-591`)**: Always defers `gatt.disconnect(); gatt.close();` via `mHandler.post(...)` even when already executing on `mHandler`'s looper; worse, `L561` (`if (mBluetoothGatt != null && gatt != mBluetoothGatt) return`) does **not** check `mIsShutDown` when `mBluetoothGatt` was already nulled, allowing a late in-flight `STATE_CONNECTED` callback after `shutDown()` to leak an open `BluetoothGatt` handle! *(Note: `MyBTLEDeviceLifecycleTest.kt:323-337` asserts `mIsShutDown == false && mBluetoothGatt == null` posts 1 runnable and skips `discoverServices()`, so the late-callback close guard must trigger strictly when `mIsShutDown == true`.)*
   - **`DeviceDataRepository.deleteDevice()` (`L592-598`) & `DeviceManager.pairingChanged()` (`L917-925`)**: `deleteDevice()` broadcasts `PAIRING_CHANGED(false)` and immediately deletes the SQLite row before the async broadcast runs, so if the sensor is absent from `mMyRemoteDevices` (e.g., timed out pre-workout while `sharedApi` stayed open), `pairingChanged()` logs `"BUG: an unpaired device became unpaired"` (`L925`) and performs zero Polar SDK cleanup.
2. **Verified Root Cause 2 — Discovery Engine Ignores Already-Connected GATT Peripherals (`BTSearchForNewDevicesEngine.java`, `573` LoC)**:
   - `startAsyncSearch()` (`L389-437`) only starts `BluetoothLeScanner.startScan(...)`. When a Verity Sense remains GATT-connected (to our app, a lingering Polar SDK handle, or another app such as `fi.polar.polarflow`), it stops advertising and is completely invisible to `ScanCallback`.
   - `BluetoothManager` (`L308`) is not retained and `getConnectedDevices(BluetoothProfile.GATT)` is never enumerated. **Hidden side-effect (`Rule 68`)**: `getConnectedDevices(GATT)` returns *all* connected BLE peripherals (watches, earbuds, radars, already-paired active HRMs). Probing must therefore: (a) first release any unpaired Polar SDK sessions in `PolarOfflineGattCoordinator` when searching `DeviceType.HRM`, (b) skip MACs already paired in `DevicesDatabaseManager` (`isBluetoothDeviceInDB && isPaired`) so active paired sensors are untouched, and (c) verify `gatt.getService(targetServiceUuid) != null` (plus `UUID_SERVICE_GARMIN_MEMBER` for `BIKE_RADAR`, CSC feature for cycling) on connected-GATT probes before emitting `newDeviceFound()`, closing non-matching probe handles immediately.
3. **Verified Root Cause 3 — Silent Connected BLE HRM Without HR Data (`MyBTLEDevice.java`, `BTLEHeartRateDevice.java`, `PolarOnlineStreamingBridge.kt`)**:
   - **Standard GATT path (`MyBTLEDevice.java:616-643, 1204-1271`; `BTLEHeartRateDevice.java:174-223`)**: `readNextCharacteristic()` transitions to `State.CONNECTED_WITH_SERVICE` (`isReceivingData() == true`) and calls `registerSensors()` **before** `configureServices()` runs. If HR CCCD (`0x2A37` / `0x2902`) write returns `false` synchronously (`L1160`), times out (`2,500 ms`, `L228`), or completes with `status != GATT_SUCCESS` (`L712`), it is silently dropped with zero retry and zero watchdog. **Chesterton's Fence constraint (`BTLEHeartRateDeviceTest.kt:561-597`)**: DIS `0x2A24`/`0x2A25` reads MUST remain enqueued before the initial HR CCCD write (`REQ-CON-049`), so hardening must come from `onDescriptorWriteCompleted` failure retry + a bounded silent-HR watchdog (paused/deferred while `isGattPaused()` is true for PFTP yield!).
   - **Polar SDK bridge path (`PolarOnlineStreamingBridge.kt:395-416, 442-503, 744-752`)**: `deviceConnected()` sets `isConnectedFlag = true` (`isReceivingData() == true`) before `FEATURE_HR` or `startHrStreaming()` delivers any sample. If `FEATURE_HR` stalls, `startHrStreaming()` throws (swallowed in `PolarPmdStreamCoordinator.launchStream` `L170`), or `0x2A37` notifications stall with 0 packets, the bridge stays permanently connected showing `--`.
4. **Target File LoC & Monolith Budget Audit (`ArchitectureConformanceContractTest.kt`)**:
   - `DeviceManager.java`: `1,707 / 1,708` LoC (**ONLY 1 LoC headroom** -> target **`+0` net LoC** by replacing `L925` in-place with a 1-line `PolarOfflineGattCoordinator` delegation and putting repository/coordinator logic in Kotlin).
   - `TrackerService.java` (`3,539 / 3,559`) & `DevicesDatabaseManager.java` (`1,669 / 1,671`): **`0` edits**.
   - `MyBTLEDevice.java` (`1,274 / 1,500`), `BTLEHeartRateDevice.java` (`361 / 1,500`), `BTSearchForNewDevicesEngine.java` (`573 / 1,500`), `PolarOfflineGattCoordinator.kt` (`1,020 / 1,500`), `PolarOnlineStreamingBridge.kt` (`1,259 / 1,500`), `PolarPmdStreamCoordinator.kt` (`300 / 1,500`), `DeviceDataRepository.kt` (`770 / 1,500`): all remain well below `1,500` LoC, extracting reusable silent-connection watchdog logic into a new pure-JVM helper `BleHrmSilentConnectionWatchdog.kt`.

## 3. User Scope Grounding (`ATT-1250`) & Complexity Audit (`REQ-PRO-029`)
- **In-Scope (`3 SP` confirmed; no split required)**:
  1. Synchronous & alias-complete teardown of both raw `BluetoothGatt` (including late `mIsShutDown` callback close and same-looper synchronous close) and `PolarBleApi` sessions (`MAC` + canonical 8-hex Polar ID + all registered aliases) on unpair, delete, and device shutdown (`MyBTLEDevice`, `BTLEHeartRateDevice`, `PolarOnlineStreamingBridge`, `PolarOfflineGattCoordinator`, `DeviceDataRepository`, `DeviceManager` `+0` LoC).
  2. Pre-scan release of unpaired Polar SDK sessions + `BluetoothManager.getConnectedDevices(BluetoothProfile.GATT)` enumeration with strict target-service-UUID validation and already-paired-sensor exclusion in `BTSearchForNewDevicesEngine.java`.
  3. Bounded silent-HR watchdog (`12 s`, injectable for deterministic unit tests) across **both** `BTLEHeartRateDevice` (with `onDescriptorWriteCompleted` CCCD failure retry + `isGattPaused` safety) and `PolarOnlineStreamingBridge` (re-subscribing HR slot once, then clean alias disconnect + backoff reconnect if still 0 packets).
- **Out-of-Scope**: New UI screens or localized strings, SQLite schema changes, ANT+ discovery/devices, non-HRM BLE device watchdogs (`BTLERadarDevice` already owns its 3.5 s watchdog), or Polar offline recording protocol refactoring.

## 6. Architectural Strategy & Localization Parity
1. **`BleHrmSilentConnectionWatchdog.kt`**: Pure-JVM state machine (`IDLE -> ARMED_INITIAL -> ARMED_AFTER_RESUBSCRIBE -> RECOVERING`) with configurable timeout (`DEFAULT_WATCHDOG_TIMEOUT_MS = 12_000L`), `onConnected()`, `onHrPacketReceived()`, `onWatchdogElapsed()` returning `Action.REENABLE_CCCD` vs `Action.DISCONNECT_AND_RECONNECT` vs `Action.NONE`, and `reset()`, reused by both `BTLEHeartRateDevice` and `PolarOnlineStreamingBridge`.
2. **Unified Alias-Complete Unpair/Delete Teardown**: Add `PolarOfflineGattCoordinator.forceDisconnectDevice(context, macAddress, polarId)` (disconnecting all known MAC/8-hex aliases on `sharedApi` + clearing `connectedDeviceIds`/`activeAccOwners`/`activeSessions` without disrupting sibling devices) and `disconnectUnpairedSessions(context)`; invoke from `PolarOnlineStreamingBridge.shutDown()`, `BTLEHeartRateDevice.shutDown()`, `DeviceDataRepository.updateDevice()` (unpair) / `deleteDevice()` (capturing MAC pre-delete), and `DeviceManager.pairingChanged()` (`L925`, `+0` LoC); close late `STATE_CONNECTED` GATT callbacks when `MyBTLEDevice.mIsShutDown` is true and run `gatt.disconnect()/close()` synchronously when already on `mHandler`'s looper.
3. **Connected-GATT Discovery Enumeration**: Retain `BluetoothManager` in `BTSearchForNewDevicesEngine`, release unpaired Polar SDK sessions for `DeviceType.HRM`, enumerate `getConnectedDevices(BluetoothProfile.GATT)` (permission-guarded, skipping already-paired DB rows & already-tracked MACs), and gate probe emission on confirmed target service UUID presence.
4. **Localization Parity**: `N/A - no new UI strings`.
