### Requirement Archaeology & Chesterton's Fence Audit

1. **Original Requirement ID & Target**:
   - `REQ-STB-014` (*Simulated Process Exit Reason Injection & Native PyQt6 Desktop Kill Simulator Architecture*, net-new developer tooling requirement, referencing `REQ-STB-012` and `ATT-2469`).
2. **Historical Origin & Commit Trace**:
   - Introduced in Sprint 2026-40.16 (`ATT-2079`, commit `95e0c511`) and Sprint 2026-40.17 (`ATT-2469`, `simulate_kill.py`). Created to allow testing process kill dialogs at the desk without physical device power-cycling or background waiting.
3. **Root Reason for Existing Formulation**:
   - `ProcessExitReasonHelper.kt` relied strictly on Android 11+ `ApplicationExitInfo.getHistoricalProcessExitReasons()`. In Android (AOSP), `ApplicationExitInfo.REASON_LOW_MEMORY` is generated exclusively by the Linux kernel's in-kernel Low Memory Killer daemon (`lmkd`) when the device experiences actual physical RAM exhaustion. User-space ADB commands (`am send-trim-memory` or `kill -9`) produce `REASON_SIGNALED` or `REASON_USER_REQUESTED` in ActivityManagerService, which `ProcessExitReasonHelper` reclassifies as `BATTERY_KILL` when the app is not battery-whitelisted. As a result, testers could not deterministically verify the Low Memory dialog (`"Training unterbrochen: Speicherengpass"`). Furthermore, `simulate_kill.py` initially used an ad-hoc local HTTP browser GUI, whereas the established project standard for developer desktop tools (`tools/replay_workout.py`) is a native PyQt6 desktop application with an obsidian theme.
4. **Preservation of Core Invariants**:
   - Invariant 1: In release builds (`BuildConfig.DEBUG == false`), the simulated exit reason injection channel is 100% disabled/stripped; production code relies exclusively on system `ApplicationExitInfo`.
   - Invariant 2: Recovery dialog contracts (`StartOrResumeInterface`), resumption state machines (`REQ-STB-003`), and battery exemption shortcuts remain unchanged.
   - Invariant 3: Single-use consumption ensures injected simulation keys are cleared immediately upon first evaluation, preventing false positives on subsequent normal launches.
   - Invariant 4: Native PyQt6 GUI falls back gracefully to the interactive terminal menu if PyQt6 is not installed on the developer workstation.

## 1. Problem Statement & Motivation

During desk verification of [ATT-2079](https://rainerblind.atlassian.net/browse/ATT-2079) (Inform Athlete on Process Kill Reasons) using the process kill simulation tool [ATT-2469](https://rainerblind.atlassian.net/browse/ATT-2469) (`tools/simulate_kill.py`), two key operational frictions were identified:

1. **Simulated Low Memory Kill (LMK) Failure**:
   - When triggering `python3 tools/simulate_kill.py --kill lmk`, the app fails to display the expected Low Memory recovery dialog (*"Training unterbrochen: Speicherengpass"*). Instead, the dialog always falls back to *"Training unterbrochen: Akku-Optimierung"*.
   - AOSP architecture prevents user-space tools (including ADB/root) from synthesizing `ApplicationExitInfo.REASON_LOW_MEMORY` without genuine kernel RAM starvation.
   - The app's `ProcessExitReasonHelper` reclassifies unrecognized exit reasons (`REASON_SIGNALED`) as `BATTERY_KILL` whenever the app is not battery-whitelisted.
   - Neither the app nor the simulator provides an injection mechanism to simulate specific kill reasons deterministically.

2. **Tool GUI Architecture Inconsistency**:
   - `tools/simulate_kill.py` currently spawns an HTTP server on port 8088 and opens a browser tab (`--gui`), creating browser dependency and inconsistent window management.
   - The canonical developer GUI architecture established in `tools/replay_workout.py` is a native **PyQt6 Desktop GUI** with an obsidian dark theme.
   - Migrating `tools/simulate_kill.py` to PyQt6 aligns all testing tools under a consistent, responsive native desktop interface.

## 2. Root Cause Analysis (Forensic Investigation)

### 2.1 Low Memory Kill Synthesis in Android
In the Android operating system:
* `ApplicationExitInfo.REASON_LOW_MEMORY` is strictly generated by `ActivityManagerService` when informed by `lmkd` that a process was reaped under memory pressure.
* `am send-trim-memory <pid> COMPLETE` merely dispatches `ComponentCallbacks2.onTrimMemory(TRIM_MEMORY_COMPLETE)` to the app; it does not kill the process.
* The subsequent fallback `kill -9 <pid>` sends `SIGKILL`. Android logs this as `reason=5 (REASON_SIGNALED)` or `reason=10 (REASON_USER_REQUESTED)`.
* In `ProcessExitReasonHelper.kt:79-84`:
  ```kotlin
  detectedReason = when (exitInfo.reason) {
      ApplicationExitInfo.REASON_EXCESSIVE_RESOURCE_USAGE -> KillReason.BATTERY_KILL
      ApplicationExitInfo.REASON_LOW_MEMORY -> KillReason.LOW_MEMORY
      ApplicationExitInfo.REASON_PERMISSION_CHANGE -> KillReason.PERMISSION_REVOKED
      else -> KillReason.GENERIC_UNFINISHED
  }
  ```
* In line 96:
  ```kotlin
  if (detectedReason == KillReason.GENERIC_UNFINISHED && !isIgnoringBattery) {
      detectedReason = KillReason.BATTERY_KILL
  }
  ```
  Because the test device on the desk is typically not battery-whitelisted (`!isIgnoringBattery`), `GENERIC_UNFINISHED` is transformed into `BATTERY_KILL`.

### 2.2 Solution: Debug Simulation Injection Channel
In debug builds only (`BuildConfig.DEBUG`), `ProcessExitReasonHelper` should inspect SharedPreferences for `pref_debug_simulated_kill_reason`:
* Supported values: `"LOW_MEMORY"`, `"PERMISSION_REVOKED"`, `"BATTERY_KILL"`, `"GENERIC"`.
* When present:
  1. Map directly to the corresponding `KillReason`.
  2. Immediately consume and remove the key from SharedPreferences to maintain idempotency.
  3. Release builds (`BuildConfig.DEBUG == false`) completely ignore this key.

### 2.3 PyQt6 Desktop GUI Architecture
`tools/replay_workout.py` provides the blueprint for high-performance desktop tools:
* `QMainWindow` with dark palette (`#121212`, `#1E1E1E`, `#2A2A2A`, `#BB86FC`, `#03DAC6`, `#CF6679`).
* High-glanceability status cards (Package, Connection, Process PIDs, Whitelist, Permissions, Escalation Count, Latest Exit Record).
* One-click action triggers executing simulation commands in background threads without freezing the UI.
* Graceful fallback: If PyQt6 is not installed (`HAS_PYQT6 == False`), log an advisory notice and launch the interactive terminal UI (`TerminalKeyReader`).

## 3. User Scope Grounding (ATT-1250)

* **In-Scope Goals**:
  1. Add debug-only exit reason injection channel in `ProcessExitReasonHelper.kt` (`pref_debug_simulated_kill_reason`) with single-use consumption.
  2. Implement `inject_simulated_kill_reason(reason)` in `tools/simulate_kill.py` via `run-as` SharedPreferences modification.
  3. Wire LMK, Battery, and Permission simulation actions in `tools/simulate_kill.py` to inject the corresponding simulated reason before termination.
  4. Convert `tools/simulate_kill.py --gui` from HTTP server to native PyQt6 desktop application matching `tools/replay_workout.py` styling.
  5. Provide unit tests (`ProcessExitReasonHelperTest.kt`) and tool contract tests (`tools/test_simulate_kill.py`).
* **Out-of-Scope Non-Goals (Scope Bounding)**:
  1. Modifying release build APK logic or production exit reason detection.
  2. Altering `StartOrResumeDialog.kt` UI layout or string resources (already verified in `REQ-UI-329` and `REQ-UI-345`).
  3. Rewriting `tools/replay_workout.py` or changing its features.
