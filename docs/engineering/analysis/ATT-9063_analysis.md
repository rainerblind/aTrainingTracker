## 1. Problem Statement & Motivation
* Pixel 10 field ride `Zum Bäcker #58` (`workoutID = 2411`, `2026-11-19_055904`, `584 s`) showed live `AltitudeAndSlopeDevice_ATTFused` staying anchored at `438.00 -> 438.13 m` (`+21.13 m` / `-21.11 m`), while post-workout `ExtendedRtsAltitudeSlopeSmoother` produced an initial altitude of **`458.48 m`** (`+20.5 m` above `DEM = 438.00 m` and `BARO = 437.19 m`), **`-91%` slope** at `t = 4..31 s`, and **`21.97 m` of phantom initial descent** (`ascent = 18.87 m`, `descent = 36.64 m` on a closed loop).
* Separately, fixed tight carriage slew limits (`BIKE_FRONT_POCKET` `baroMaxSlewRateMps = 0.7 m/s`) clip genuine fast alpine descents (`17–20 m/s` at `-10%` grade = `-1.7..-2.0 m/s`), causing severe growing elevation lag on mountain descents.
* **Expected**: `ExtendedRtsAltitudeSlopeSmoother` enforces physical slope bounds (`±35%`), low-speed slope gain damping (`< 1.2 m/s`), contractive standstill slope decay, DEM grid-step slope decoupling, realistic flat-start slope prior (`p[1][1] = 0.0025`), barometer-free fallback without NaN/overshoot, and speed-coupled barometer slew limiting (`max(profile.baroMaxSlewRateMps, 0.25 * speedMps)`).

## 2. Root Cause Analysis & Independent Hypothesis Verification
* **Verified Root Causes on `sprint/2026-11-19_03_Nacht` (`c33bef19`)**:
  1. **Unclamped DEM Grid-Step Coupling into Slope `x[1]` (`ExtendedRtsAltitudeSlopeSmoother.kt:116, 143-159, 173-238`)**: Initial `p[1][1] = 0.01` (`10%` SD) plus undamped low-speed prediction (`< 1.2 m/s`) builds strong `p[0][1]` over `~5 m` startup movement. When integer `DEM` steps `438 -> 435 m` at `t = 4 s` while barometer stays flat (`437.9 -> 437.5 m`), Step 3 (`:218-222`) applies full `k1 = p[1][0] / sRef` with no DEM-to-slope decoupling and no `±0.35` physical clamp (unlike `KinematicAltitudeSlopeEkf.kt:62-63, 178-188`), driving `x[1]` to `-0.91` (`-91%`).
  2. **Frozen Standstill Slope (`ExtendedRtsAltitudeSlopeSmoother.kt:139-142`)**: During `t = 8..28 s` (`isStandstill = true`), `x[1] = -0.91` and cross-covariances `p[0][1]`, `p[1][2]` remain frozen (`F = I_3`) instead of decaying toward `0.0` (`REQ-FIL-023.2`).
  3. **Backward RTS Integration Amplification (`ExtendedRtsAltitudeSlopeSmoother.kt:143, 257-287`)**: Upon moving at `t = 29..40 s` (`~30 m`), forward predict projects `x[0] += -0.83 * deltaDist` (`~-20 m`) against flat `438 m` measurements; backward RTS ($x_{k|N} = x_{k|k} + C_k(x_{k+1|N} - x_{k+1|k}^-)$) reconciles the `-83%..-91%` slope by pushing `x_{0|N}[0]` up `+20.5 m` to `458.48 m`, and never clamps `smoothedStates[k][1]` to `±0.35`.
  4. **Fixed Non-Speed-Coupled Barometer Slew Ceiling (`BarometricAltitudeFilter.kt:135-177`, `ErtsPostWorkoutRecomputer.kt:399-405`, `PhoneCarriageMode.kt:169`)**: `BIKE_FRONT_POCKET` hard-caps `maxSlewRateMps = 0.7 m/s`, clipping `-1.8 m/s` alpine descents (`18 m/s` at `-10%`) by `1.1 m/s` every second (`66 m` lag in `60 s`).
* **Independent Peer Review & Verification (4-Augen-Prinzip Mathematical Blind Spots & Monolith Audit)**:
  * **Blind Spot 1 (Backward RTS Exponential Blowup under Naive Standstill Decay)**: Copying `KinematicAltitudeSlopeEkf`'s forward decay `F[1][1] = alpha < 1` (`alpha = exp(-dt / 2.5) ≈ 0.67`) with `Q[1][1] = 0` would yield backward RTS gain $C_k[1][1] = 1/\alpha \approx 1.49$ ($1.49^{20} \approx 2,900\times$ backward explosion across a `20 s` stop!). Using a stationary **Ornstein-Uhlenbeck** transition `F[1][1] = alpha` with $Q_{11} = (1 - \alpha^2)\max(\sigma_g^2, P^+_{11})$ (`sigma_g^2 = 0.0025`) matches $P^- = F P^+ F^T + Q$ exactly and guarantees strictly contractive $0 < C_k[1][1] \le \alpha < 1$ in both directions.
  * **Blind Spot 2 (Non-SPD Covariance under Damped/Zeroed `k1`)**: Applying suboptimal/damped gains (`k1 = 0` on DEM or `k1 * gainScale` on low-speed baro) with the simplified `P - K H P` formula breaks symmetry and positive-definiteness of `P_{k|k}`, risking ill-conditioned `invert3x3(P_{k+1|k})` in backward RTS. Using exact 3×3 **Joseph-form** updates $P^+ = (I - K H) P^- (I - K H)^T + K R K^T$ guarantees strictly symmetric SPD covariances for all gains (including standstill bias-only $H = [0, 0, 1]$).
  * **Blind Spot 3 (Barometer-Free Fallback & Leading-Null `0.0 m` Injection)**: (a) Unconditionally setting `k1 = 0` on Step 3 would freeze `slope = 0.0%` on barometer-free callers passing `rawAltitudeM = Double.NaN` + `referenceAltitudeM = DEM/GPS`. Setting `k1 = 0.0` when `hasBaroData` (`samples.any { it.rawAltitudeM.isFinite() }`) and damped `k1 = (p[1][0]/sRef) * gainScale` (clamped `±0.35`) when `!hasBaroData` handles both cleanly. (b) `ErtsPostWorkoutRecomputer.kt:504` passes `rawAltitudeM = row.rawAltitude ?: 0.0`, injecting sea-level `0.0 m` spikes on leading-null rows, and `:183` checks only `row.rawAltitude != null`; fixing to `row.rawAltitude ?: Double.NaN`, `hasAltitudeData = rawRows.any { it.rawAltitude != null || it.referenceAltitude != null }`, and finite-scan `initialAlt` in `ExtendedRtsAltitudeSlopeSmoother` eliminates NaN/0 m startup corruption while preserving `ErtsPostWorkoutRecomputerTest.testVerticalSpeedRecomputation` (`ALTITUDE` + `DEM` without baro column).
  * **Blind Spot 4 (Live `maxSlewRateMps == 0.7` Contract Preservation)**: `AltitudeAndSlopeDevice_ATTFusedTest.kt:850` and `BarometricAltitudeFilterTest.kt:163` assert `baroFilter.maxSlewRateMps == 0.7`. Keeping `maxSlewRateMps` as the base profile rate and adding `@JvmOverloads speedMps: Double = 0.0` to `BarometricAltitudeFilter.filterSlewOnly()` + `computeSpeedCoupledSlewRateMps(base, speed)` (`max(base, 0.25 * speed.coerceIn(0.0, 35.0))`) preserves 100% existing contract compatibility while enabling speed-coupled alpine descent slew in `ErtsPostWorkoutRecomputer.resolveCarriageModesAndFilterBaro()` (and optionally live `AltitudeAndSlopeDevice_ATTFused` — kept untouched unless needed; see Scope).
  * **Monolith LoC Headroom Audit (`ArchitectureConformanceContractTest.kt:116-134`)**: All 3 planned files are well under the `1,500` LoC ceiling (`ExtendedRtsAltitudeSlopeSmoother.kt`: `453 / 1,500`, `1,047` headroom; `ErtsPostWorkoutRecomputer.kt`: `1,051 / 1,500`, `449` headroom; `BarometricAltitudeFilter.kt`: `205 / 1,500`, `1,295` headroom). Protected monoliths remain **0 LoC touched** (`TrackerService.java` `3,559`, `WorkoutSummariesDatabaseManager.java` `3,148`, `WorkoutSamplesDatabaseManager.java` `1,533`, `WorkoutRepository.kt` `5,117`). `ErtsPostWorkoutRecomputer.kt` retains its existing `NumericalEncodingUtils` import so `BASELINE_ALLOWED_DATABASE_UPWARD_UI_IMPORTS` stays intact.
