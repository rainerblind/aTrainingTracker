## 1. Problem Domain, Gap Analysis & Codebase Audit
* **Current State (`EditDeviceDialog.kt:542-661`, `1,843 / 2,004` LoC ratcheted ceiling in `ArchitectureConformanceContractTest.kt:124`)**:
  * `CalibrationSection()` routes `DeviceType.BIKE_SPEED`, `DeviceType.BIKE_SPEED_AND_CADENCE`, and wheel-capable `DeviceType.BIKE_POWER` to `WheelCircumferenceSelector()`, while `DeviceType.RUN_SPEED` uses `RunCalibrationFactorSelector()`.
  * `WheelCircumferenceSelector()` still renders the manual known-distance calculator `IconButton` (`Icons.Default.Calculate`, `:614-620`) and opens `CorrectCalibrationDialog` (`:650-660`), contradicting online GNSS auto-calibration (`ATT-131`, `ATT-7753`).
  * `WheelCircumferenceSelector()` renders a hardcoded English `"Baseline: $baselineMm mm"` label (`:626`) and a standalone `OutlinedButton` (`devices_reset_tire_pressure_baseline`, `:632-647`), without explaining automatic in-ride calibration and without showing the longitudinal `WheelCircumferenceHistoryChart` (currently mounted only in `EditEquipmentDialog.kt:169`).
* **Data Layer (`EquipmentDbHelper.java:89-95, 439, 495-545, 813` & `EquipmentRepository.kt:89-101`)**:
  * `WheelCircumferenceHistory` (`Equipment.db` v5) stores `(equipment_id, timestamp, wheel_position, circumference_mm, source)` with **no `device_id` column**; sensors link to bikes via `Links(EquipmentId, ANTDeviceId, wheel_position)`.
  * `EquipmentDbHelper` already provides `getLinkedEquipmentIdsFromDeviceId(deviceId)`, `getWheelPosition(equipmentId, deviceId)`, `getCircumferenceHistory(equipmentId)`, and `addCircumferenceHistory(...)` — zero SQLite schema changes required.
* **Sibling Boundary (`ATT-8421` Out of Scope)**: `BANALServiceRepository` runtime `getBaselineCircumference` wiring & null-GNSS gating belong strictly to `ATT-8421`; `ATT-8422` replaces the hardcoded `"Baseline: $baselineMm mm"` UI line in `EditDeviceDialog` with localized 9-locale resources while keeping `BANALServiceRepository.kt` untouched.

## 2. Independent Peer Review & Verification (4-Augen-Prinzip — Rules 69 & 70)
1. **Preservation of `CorrectCalibrationDialog` for `RUN_SPEED` (`EditDeviceDialog.kt:665-711`)**: Ticket asks to remove `CorrectCalibrationDialog` from `WheelCircumferenceSelector`. Live audit confirms `RunCalibrationFactorSelector()` (`DeviceType.RUN_SPEED`) STILL invokes `CorrectCalibrationDialog` at `:701`. Therefore `CorrectCalibrationDialog` MUST remain intact for footpods, while only the `Icons.Default.Calculate` button and `CorrectCalibrationDialog` call in `WheelCircumferenceSelector` are removed. Unused bike-only strings (`devices_correct_calibration_factor_title_bike`, `devices_correct_calibration_explanation_bike`) are safe to audit/clean across all 9 locales (`values`, `de`, `es`, `fr`, `it`, `ja`, `nl`, `pl`, `pt`).
2. **`WheelCircumferenceHistoryChart` Blind Spot for `WheelPosition.UNSPECIFIED` (`WheelCircumferenceHistoryChart.kt:132-133`)**: Currently filters strictly `FRONT` and `REAR`. When a wheel sensor has `WheelPosition.UNSPECIFIED` (or records came from `BANALServiceRepository.kt:845` single-estimator fallback), `historyRecords.isNotEmpty()` bypasses the empty-state card and renders a **completely blank Canvas**. Adding an `UNSPECIFIED` series fallback (drawn only when `unspecifiedRecords.isNotEmpty()`, preserving `EditEquipmentDialog` Front/Rear visual parity) plus an optional `emptyStateText` parameter fixes this blind spot cleanly.
3. **Duplicate Baseline Reset Button Avoidance (`EditDeviceDialog.kt:632-647` vs `WheelCircumferenceHistoryChart.kt:221-238`)**: Both `WheelCircumferenceSelector` and `WheelCircumferenceHistoryChart` render a "Freshly pumped / Reset baseline" button. Consolidating onto the chart's single baseline reset button (wired to `EditDeviceViewModel.resetTirePressureBaseline()`, which updates `Devices.db` baseline AND appends `SOURCE_MANUAL_RESET` to linked bikes in `EquipmentRepository` + refreshes `wheelCircumferenceHistory`) prevents duplicate buttons and updates the chart immediately.
4. **Repository Layer & `EditDeviceDialog.kt` LoC Hygiene (`REQ-PRO-050`, `REQ-PRO-129`)**: `EditDeviceViewModel` (`banalservice/ui/devices/editdevice/`) MUST NOT touch `EquipmentDbHelper` directly; expose `getCircumferenceHistoryForDevice(deviceId)` and `recordManualBaselineResetForDevice(deviceId, circumferenceMm)` on `EquipmentRepository`. Extracting the sensor wheel-calibration + chart UI into a dedicated cohesive file `WheelCircumferenceSection.kt` in `banalservice/ui/devices/editdevice/` **shrinks `EditDeviceDialog.kt` below `1,843` LoC** (downward ratchet well under `2,004`).
