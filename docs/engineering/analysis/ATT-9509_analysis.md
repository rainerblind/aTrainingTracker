## Context & Problem Statement
Follow-up from PO on-device testing of `ATT-9175` (Pixel 10, `2026-11-21`). When a Polar Verity Sense or Polar H10 is unpaired (or deleted) before/during post-workout sync, the Aftermath Workout Details retry banner (`PolarPendingRetrySyncSection` / `PolarH10RetrySyncBanner`) still enables **"Jetzt synchronisieren"** (`R.string.polar_h10_retry_sync_action`). Tapping it launches a full BLE/PFTP retry attempt and fails with a generic connection error (`polar_verity_retry_sync_failed` / `polar_h10_retry_sync_failed`) without explaining that the target sensor is unpaired. Once the user re-pairs the sensor, **"Jetzt synchronisieren"** must reactively re-enable and execute normally.

## Root Cause & Forensics
Independent live codebase audit on `b9ba0eea` (`Rules 69 & 70`):
1. **`polarDeviceId` Dropped at Both Aftermath Call Sites**: `WorkoutData` (`WorkoutData.kt:117-119`) already carries `polarSyncPending`, `polarDeviceId`, and `polarExerciseId` (hydrated by `WorkoutDataMapper.kt:507-515,771-773` from `WorkoutSummaries.POLAR_DEVICE_ID`). Neither `TrackOnMapScreen.kt:506-512` nor `WorkoutDetailTabbedContent.kt:731-737` passes `workoutData.polarDeviceId` into `PolarPendingRetrySyncSection`.
2. **No Paired-State Check in Banner or Repository**: `PolarPendingRetrySyncSection` (`PolarH10RetrySyncBanner.kt:81-115`) enables `Button(R.string.polar_h10_retry_sync_action)` solely on `!isSyncing` (`line 264`). In `DevicesDatabaseManager.java`, unpairing sets `DevicesDbHelper.PAIRED = 0` (`DeviceDataRepository.kt:532`) while retaining the row, whereas deleting removes the row (`deleteDevice`, `line 603`). Both states leave `!db.isPaired(dev.id)` or no matching row.
3. **Alias-Aware Polar Identification & Repository Encapsulation (`Rule 8.7`)**: `PolarH10RetrySyncBanner.kt` is in `ui/aftermath/` and is NOT in `ArchitectureConformanceContractTest.BASELINE_ALLOWED_UI_DB_CALLERS` (`line 85-108`), so it MUST NOT import `DevicesDatabaseManager`. Conversely, `DeviceDataRepository` (`777/1,500` LoC, allowlisted) wraps `DevicesDatabaseManager` privately, exposes reactive `allDevices: StateFlow<List<DeviceUiData>>`, and can expose a pure domain query `isPolarRetrySensorPaired(polarDeviceId: String?, isVeritySense: Boolean): Boolean` reusing `PolarOfflineGattCoordinator` alias/type helpers (`matchesDeviceIdentifier`, `extractPolarId`, `PolarOfflineCapabilityStore.getPolarDeviceId`, `isPolarVeritySenseDevice`/`isPolarH10Device`) without exposing `*DatabaseManager` or `Cursor` getters (`Rule 8.7`).
4. **Reactivity & Frame-0 Safety (`docs/coding_standards.md` §5.10)**: `DeviceDataRepository.updateDevice()`/`swapPairedDevice()`/`deleteDevice()`/`handleNewDeviceFound()` update `allDevices: StateFlow<List<DeviceUiData>>`, while `DeviceDataRepository.insertNewBluetoothDeviceIntoDB()` (`DeviceManager.java:311`) may also pair sensors externally. Observing `DeviceDataRepository.allDevices` plus a `Lifecycle.Event.ON_RESUME` refresh tick in `PolarPendingRetrySyncSection` and running `isPolarRetrySensorPaired(...)` via `LaunchedEffect`/`withContext(Dispatchers.IO)` with `initialValue = null` (never treating unhydrated Frame 0 as unpaired) ensures instant reactive updates on re-pair without unmounting `WorkoutDetailTabbedContent` (§5.9).
5. **Monolith LoC Audit (`ArchitectureConformanceContractTest.kt:117-133`)**: `WorkoutRepository.kt` (`4,986/5,117`, `0` edits), `DevicesDatabaseManager.java` (`1,669/1,671`, `0` edits), `PolarVeritySenseOfflineController.kt` (`1,483/1,500`, `0` edits), `PolarH10OfflineController.kt` (`788/1,500`, `0` edits), `PolarOfflineGattCoordinator.kt` (`1,294/1,500`, `0` or minimal edits), `DeviceDataRepository.kt` (`777/1,500`), `PolarH10RetrySyncBanner.kt` (`324/1,500`), `TrackOnMapScreen.kt` (`1,013/1,500`), `WorkoutDetailTabbedContent.kt` (`1,102/1,500`).

- **In Scope**: Pass `workoutData.polarDeviceId` into `PolarPendingRetrySyncSection` from both `TrackOnMapScreen.kt` and `WorkoutDetailTabbedContent.kt`; add encapsulated `DeviceDataRepository.isPolarRetrySensorPaired(polarDeviceId, isVeritySense)` checking `PAIRED > 0` across BLE HRM MAC / `PolarOfflineCapabilityStore` 8-hex ID / `extractPolarId` / name (with family fallback only when `polarDeviceId.isNullOrBlank()`); disable `"Jetzt synchronisieren"` (`enabled = !isSyncing && isSensorPaired`) and show a clear semantic warning/error hint (`docs/design_guidelines.md` §5.4, Material vector icon, zero inline emojis per `ATT-5400`) when unpaired; reactively re-enable on `allDevices` updates and `ON_RESUME`; add 2 localized strings (`polar_h10_retry_sync_unpaired_hint`, `polar_verity_retry_sync_unpaired_hint`) across all 9 `app/src/main/res/values*/strings_devices.xml` (`EN, DE, ES, FR, IT, JA, NL, PL, PT`).
