## 1. Problem Statement & Motivation
`WorkoutSamples.db` records parallel source-qualified streams (`ATT Odometrie-Fusion`, `ATT Fused (Höhe und Steigung)`, `GPS`, `Google Fused`, `Barometer`, `DEM`), yet Workout Details lacks: (1) `ATT_FUSED` in Map `Layers` (plus `showTechnicalTracks` wiring in peek bottom-sheets), (2) multi-source overlay comparison on `ElevationProfile`, `SPEED`/`PACE`, and `SLOPE`, and (3) persisted per-chart visibility toggles (including `Slope`) in `CHARTS`.

## 2. Root Cause Analysis & Independent Hypothesis Verification
* **RCA**: `TrackType` (`MapModels.kt:42-71`) omits `ATT_FUSED`, keeps dead `NETWORK` (`ATT-5492`), and hardcodes `"LATITUDE (GPS)"` / `"LATITUDE (Google Fused)"`. `WorkoutRepository.kt` (`ATT-8096`) only scans `^${type.name} \((.+)\)$` for `HR`/`POWER`/`CADENCE`, rejecting `<= 0` values. `TelemetryMetricType` (`TelemetryMetricGraph.kt:118-127`) omits `SLOPE`, `ElevationProfile.kt` lacks overlay rendering, and `MapDetailLayout.kt:518-803` renders all available charts unconditionally.
* **Independent Peer Review & Verification** (audited on `sprint/2026-11-18_02_Spät` @ `1beb3841`):
  * *`ATT-8096` Reuse (`71fdb559`, `12de9c54`)*: `TelemetrySourcePoint`, `TelemetrySourceSeries`, `discoverNamedSourceColumns`, `discoverMultiSourceOverlayColumns`, `OverlaySeriesAccumulator`, `MultiSensorOverlayControls`, and `OverlayTelemetryChartSection` ALREADY exist for `HR`/`POWER`/`CADENCE` — extend them rather than duplicating.
  * *Exact DB Column Names (`TrackerService.java:2739-2743`, `DevicesDatabaseManager.java:1624-1668`)*: `SpeedAndLocationDevice_ATTFused.getName()` = `"att_fused"` -> `LATITUDE_att_fused`, `LONGITUDE_att_fused`, `SPEED_mps_att_fused`, `ALTITUDE_att_fused`. **Blind spot**: `AltitudeAndSlopeDevice_ATTFused.getName()` = `"att_fused_altitude_slope"` (NOT `"ATT Fused ..."`), yielding `"ALTITUDE (att_fused_altitude_slope)"` / `"SLOPE (att_fused_altitude_slope)"`. Also `SpeedAndLocationDevice_GPS`/`GoogleFused` write localized DB names (`"Phone GPS (Satellite)"`, `"Smartphone GPS (Satellit)"`, `"Google Location (Fused)"`) or legacy `_gps`/`_google_fused` alongside `"LATITUDE (GPS)"` — `TrackType` must resolve all aliases cleanly.
  * *Accumulator Sign & Unit Blind Spots*: `OverlaySeriesAccumulator.record()` (`WorkoutRepository.kt:2017`) rejects `raw <= 0.0`, which drops descents/flats (`SLOPE <= 0%`) and sea-level/below (`ALTITUDE <= 0m`). `SPEED_mps` overlays store `m/s` and need `MyHelper.mps2userUnit` / inverted `PACE` conversion at chart render/mean readout.
  * *LoC Ceilings (`ArchitectureConformanceContractTest.kt:116-134`)*: `TelemetryMetricGraph.kt` is at `1,965 / 1,965` (0 headroom), `WorkoutRepository.kt` at `5,048 / 5,117` (69 headroom), `MapDetailLayout.kt` at `1,425 / 1,500` (75 headroom), `ElevationProfile.kt` at `1,419 / 1,500` (81 headroom). **Mandatory**: extract helpers (`WorkoutMultiSourceSampleDiscovery.kt`, `TelemetryOverlayComponents.kt`, `TelemetryChartStack.kt`, `ElevationProfileOverlayComponents.kt`) and keep `WorkoutRepository$Companion` delegates for `DetailedDesignParityContractTest.kt`.
  * *Caller Audit*: `PeriodMapScreen.kt:238` and `WorkoutClusterHeatmapScreen.kt:389` pass single `TrackType.BEST` tracks without `showTechnicalTracks = true` or `multiSensorOverlays`; `WorkoutClustersScreen.kt:163` sets `showTechnicalTracks = true` but omits `multiSensorOverlays`; `TrackOnMapScreen.kt:730-831` duplicates chart rendering.

## 3. Scope Grounding & Non-Goals (`ATT-1250`, Complexity Audit = `3 SP`)
* **In-Scope Goals**:
  1. `TrackType.ATT_FUSED` (`LATITUDE_att_fused`/`LONGITUDE_att_fused`), alias-aware `GPS`/`FUSED` resolution, remove obsolete `TrackType.NETWORK`, and wire `showTechnicalTracks = true` + multi-track/overlay loading in `PeriodMapScreen.kt`, `WorkoutClusterHeatmapScreen.kt`, and `WorkoutClustersScreen.kt`.
  2. Generic discovery (`<SENSOR> (<name>)` + `_(gps|google_fused|att_fused)`) in extracted helper for `ALTITUDE`, `SPEED_mps`, `SLOPE` (+ existing `HR`/`POWER`/`CADENCE`), friendly labels for technical suffixes, metric-aware validity (`SLOPE`/`ALTITUDE` allow `<= 0`), `TelemetryMetricType.SLOPE` (`TelemetryGraphColorPreferences`), and `ElevationProfile` / `SPEED`/`PACE` / `SLOPE` overlays with synchronized scrubbing & `Rule 64` alignment.

* **Out-of-Scope Non-Goals**: `TrackerService.java` / `CSVFileWriter.java` / DB schema changes, `TrackOnMapHelper.java` legacy fragment, or `SYS.2`/`SYS.3` hardware changes. **Complexity**: Confirmed **`3 SP`** (no split needed per `REQ-PRO-029` because `ATT-8096` already built the core overlay infrastructure).
