## 1. Problem Statement & Gap Analysis
Manual UI verification currently relies on the PO's single physical **Pixel 10**, while `app/src/androidTest/` has only 4 files (`AppSmokeAndroidTest.kt`, `PolarRetrySyncBannerAndroidTest.kt`, `SwimWorkoutAdjustCardAndroidTest.kt`, `EditDevicePolarBackupAndroidTest.kt`). `app/build.gradle` targets `minSdk 26` / `targetSdk 37`, exposing OS-level risks (`POST_NOTIFICATIONS` on API 33+, FGS rules on API 34+, Edge-to-Edge insets on API 35–37) and 9-locale (`en`, `de`, `es`, `fr`, `it`, `ja`, `nl`, `pl`, `pt`) runtime truncation/crash risks until late release cycles.

## 2. Independent Peer Review & Call-Site / Skill Audit
Verified directly against live repository & workstation state (treating ticket claims strictly as hypotheses):
1. **Workstation AVDs & System Images**: `emulator -list-avds` reports **`Pixel_5_Android_12`**, **`Pixel_6_Pro_Android_12`**, **`Pixel_7_Android_36`**, and **`Pixel_8_Android_15`**; `$ANDROID_HOME/system-images/` holds `android-31`, `android-35`, `android-36`, and `android-37.0` (`3` distinct OS levels installed as AVDs, plus `android-37.0` image). Thus `tools/run_multi_os_emulator_sweep.py` MUST dynamically resolve installed AVDs (targeting at least 3 distinct API levels, configurable via `--avds`), NEVER hardcoding unavailable API 26/29 AVDs or requiring a physical phone.
2. **Existing Emulator Guardrails (`tools/agent_emulator.py`)**: Already provides `parse_adb_devices()`, `get_adb_devices()`, `resolve_target_device()` (strictly blocking non-`emulator-*` serials in `ATT_AGENT_MODE=1` / `--agent` per `REQ-TST-004`), `find_emulator_binary()`, `get_available_avds()`, `is_boot_completed()`, `tune_emulator_settings()`, and `configure_app()`. The new sweep runner MUST reuse `tools/agent_emulator.py` directly, boot strictly **1 AVD at a time**, pass `-no-snapshot-save` / clean `adb emu kill` shutdown in `finally`, and never touch physical `Pixel 10` (`66020DLCR002FL`).
3. **Governance Directory & Registry Trap (`tools/verify_requirement_governance.py:533`)**: `ALLOWED_ENGINEERING_ENTRIES` does **not** currently include `"emulator_sweeps"`. Adding `docs/engineering/emulator_sweeps/` without updating `ALLOWED_ENGINEERING_ENTRIES` (and registering it in `docs/management/cm_plan.md`) would break `verify_engineering_directory_structure()` (`TST-PRO-061.4`).
4. **Weekly Cadence (`tools/jira_util.py:4326`) & Release Gate (`.agents/skills/release-manager/SKILL.md:87`)**: `ensure_weekly_reviews()` coordinates only Code Review (`ATT-8213`) and ASPICE Audit (`ATT-8212`), while `tools/hoechstmass/tools/jira_util.py` has neither (`0` Höchstmaß parity scope). Adding `is_weekly_emulator_sweep_overdue()` (checking `> 7 days` since latest `YYYY-MM-DD_sweep.md` AND optional `develop` commit delta) + `ensure_weekly_emulator_sweep_ticket()` (deduplicated under `ATT-232`, `rank_top=True`) + updating `docs/management/qa_plan.md` §7 + `.agents/skills/release-manager/SKILL.md` Phase 1 closes the scheduling loop.
5. **9-Locale Switching & Instrumented Click-Through**: `AppCompatDelegate` / `adb shell cmd locale set-app-locales com.atrainingtracker.debug <lang>` (API 33+) or test instrumentation locale configuration enables deterministic 9-language switching; `app/build.gradle` (`L321-324`) includes `androidx.test.ext:junit`, `espresso-core`, `runner`, and `rules` (no `uiautomator` Gradle dep needed when using `adb shell uiautomator dump` + `adb exec-out screencap -p` in Python alongside a focused `androidTest` click-through test compiled with `:app:compileDebugAndroidTestKotlin`).
