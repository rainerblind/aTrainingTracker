## 1. Forensic Codebase Verification & Independent Peer Review

| Component / Call Site | Verified Baseline | Confirmed Root Cause & Side-Effect Finding |
|---|---|---|
| `DeviceManager.java:424-462` | Instantiates `SpeedAndLocationDevice_GPS`, `SpeedAndLocationDevice_GoogleFused`, and `SpeedAndLocationDevice_ATTFused` **concurrently** whenever paired. | Both `SpeedAndLocationDevice_GPS` (`:56`) and `SpeedAndLocationDevice_ATTFused` (`:280`) subscribe independently to `LocationManager.GPS_PROVIDER` (`"gps"`), receiving two Binder copies of every 1-Hz GPS fix with identical `elapsedRealtimeNanos`, `time`, and coordinates. |
| `SpeedAndLocationDevice.java:570-581` & `SpeedAndLocationDevice_ATTFused.kt:501-504` | `recordsRawLocationDirectly()` (`true` on `ATTFused`, `false` on `GPS` & `GoogleFused`) only prevents `ATTFused` from logging its *own* fix twice. | **Defect 1 (Duplicate GPS rows)**: `GPS` logs the fix via `SpeedAndLocationDevice.java:579` AND `ATTFused` logs the exact same GPS fix via `SpeedAndLocationDevice_ATTFused.kt:504` -> 2 consecutive identical `GNSS` rows/fix. **Defect 2 (Provider mixing)**: `GoogleFused` also enters `SpeedAndLocationDevice.java:579`, writing unnormalized WGS84 ellipsoidal fixes (`~493 m`) into the same untagged `PhoneRawChannel.GNSS` channel as raw GPS (`~476–483 m`). |
| `SmartphoneRawTelemetryRecorder.kt:558-580` | `recordLocation(location, epochMs)` unconditionally emits `PhoneRawChannel.GNSS` with zero deduplication and ignores `location.provider`. | Deleting either call site would break single-device pairings (`GPS`-only, `ATTFused`-only, `GoogleFused`-only) and violate `ATT-9348` pre-EKF raw capture (`SpeedAndLocationDevice_ATTFusedTest:2502,2551`). **Fix must live in `SmartphoneRawTelemetryRecorder` + explicit device-type channel tag.** |
| `PhoneRawTelemetryRow.kt:24-33,114-153`, `PhoneRawSidecarRecovery.kt:127`, `PhoneRawTelemetryReader.kt:139` | 9-column CSV `elapsedRealtimeNs,epochMs,channel,v0..v5` (`schemaVersion=1`), 8 `PhoneRawChannel` values; recovery & reader delegate to `fromCsvLine`. | Adding `PhoneRawChannel.GNSS_FUSED` (same `v0..v5` layout) preserves exact 9-column schema, `schemaVersion=1`, zero extra bytes on 50-Hz IMU rows, automatic crash salvage, and 100% v1 backwards compatibility (`2026-11-22_081402.phone_raw.csv.gz`). |
| `OfflineTelemetryReplayHarness.kt:439-505`, `OfflineReplayModels.kt:38-47`, `OfflineReplayCli.kt`, `app/build.gradle:407-435` | Replays all `PhoneRawChannel.GNSS` rows blindly without provider filtering or legacy duplicate-row suppression. | Adding `ReplayGnssSource` (`AUTO` default: `GNSS` if present else `GNSS_FUSED`; explicit `GPS`/`FUSED`) + exact-duplicate v1 GNSS guard ensures both new and historical v1 sidecars replay cleanly without Google Fused contamination or duplicate GPS timing distortion. |

- **Root Reason for Existing Formulation**: `ATT-9348` added `recordsRawLocationDirectly()` so `ATTFused` records pre-EKF raw GPS fixes (including rejected/coarse fixes and fixes when `isEffectiveGnssActive == false`) before in-place EKF mutation, while keeping `SpeedAndLocationDevice.java:579` active for `GPS`-only and `GoogleFused`-only setups.
- **Preservation of Core Invariants**: Keep BOTH capture hooks intact so every pairing permutation works; deduplicate per channel inside `SmartphoneRawTelemetryRecorder` using a bounded zero-allocation ring buffer (immune to interleaved `GNSS_FUSED` fixes or slight thread skew); tag `GoogleFused` as `GNSS_FUSED` while preserving `v0..v5`, `CSV_HEADER`, `schemaVersion=1`, `SpeedAndLocationDevice_ATTFused.kt <= 1,500` LoC (`1,495/1,500`, `+0` net LoC), and zero allocations when recording is disabled.
