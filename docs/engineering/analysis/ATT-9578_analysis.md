## 2. Chesterton's Fence Archaeology (`REQ-PRO-022`)

- **Original Requirement ID & Target**: `REQ-SET-079` (`ATT-3999`, zero `runBlocking` on DataStore hot paths) and `REQ-EXP-045.1` (`ATT-9348`, cold-start opt-in accuracy for `SmartphoneRawTelemetryRecorder.isEnabled`).
- **Historical Origin & Commit Trace**: `b0bf0bc1` (`ATT-9348`, 2026-11-21) added `runBlocking { recordSmartphoneRawTelemetryFlow.first() }` in `SettingsDataStoreJavaHelper.kt`; `ATT-9569` (KW47 suite) flagged `DataStoreHotPathContractTest` failure; `7b225dee` (`ATT-8136`, 2026-11-23) moved `runBlocking` into `SmartphoneRawTelemetryRecorder.isEnabled()`.
- **Root Reason for Existing Formulation**: On cold process start or post-crash `TrackerService` recreation (`SensorsGpsFilterSectionTest.coldStartFreshInstance_isEnabledImmediatelyReturnsTrueAfterPersistedOptIn_TST_EXP_045_1`), DataStore's async `StateFlow` emits `initialValue = false` before `user_settings.preferences_pb` finishes loading, silently dropping smartphone raw telemetry for the entire workout.
- **Preservation of Core Invariants**: Authoritative persistence remains Jetpack DataStore (`KEY_RECORD_SMARTPHONE_RAW_TELEMETRY`, `ADR-005`). A lightweight dual-write boolean mirror in default `SharedPreferences` (`dataStoreOverride == null` only) seeds both `_tuningConfigStateFlow` and eager `_recordSmartphoneRawTelemetryEnabled` synchronously in the constructor before `init` launches, reconciles automatically on every `editAndSync` and `init` DataStore emission (self-healing upgrades and backup restores with zero steady-state writes), and keeps `dataStoreOverride != null` unit tests hermetically isolated.
