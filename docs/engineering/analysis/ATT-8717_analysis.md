# Stage 1 Analysis: ATT-8717 - Polar Detection & ID via BLE Service UUIDs and DIS Hardware IDs

**Ticket**: `ATT-8717` (`3 SP`, Parent `ATT-5910`) | **Target Release**: `V5.0.0` | **Sprint**: `2026-11-17_03_Nacht` | **Branch**: `feature/ATT-8717` | **Date**: 2026-11-18

## 1. Problem Statement & Motivation
* `PolarOfflineGattCoordinator.kt`, `PolarOnlineStreamingBridge.kt`, `PolarH10OfflineController.kt`, `PolarVeritySenseOfflineController.kt`, `DeviceDataRepository.kt`, and `EditDeviceDialog.kt` rely on user-editable display-name string matching (`isPolarH10Name`, `isPolarVeritySenseName`, `POLAR_ID_REGEX`) to classify Polar H10 vs. Verity Sense/OH1 and extract the 8-hex Polar ID.
* Renaming a paired sensor breaks H10 detection, breaks `POLAR_ID_REGEX` extraction (falling back to MAC), and misroutes/hides offline backup and live IMU controls.
* Expected: Persist and evaluate GATT Service UUIDs (`UUID_SERVICE_POLAR_PMD`, `UUID_SERVICE_POLAR_PFTP`), DIS Hardware Model (`0x2A24`) and Serial/Device ID (`0x2A25` / `PolarDeviceInfo.deviceId`), and Polar SDK feature readiness (`FEATURE_POLAR_H10_EXERCISE_RECORDING` vs. `FEATURE_POLAR_OFFLINE_RECORDING`), keeping legacy name fallback strictly for un-reconnected existing rows.

## 2. Root Cause Analysis & Independent Hypothesis Verification
* **Cause 1 — Name-Regex ID & Model Heuristics**:
  * `PolarOfflineGattCoordinator.kt:61,496-539`: `extractPolarId` uses `POLAR_ID_REGEX`; `isPolarH10Name` checks `"polar h10"`/`"h10"`; `isPolarVeritySenseDevice` checks `VERITY_MODEL_TOKENS` plus boolean `PolarOfflineCapabilityStore` (`offline_rec_<MAC>`).
  * `PolarH10OfflineController.kt:258-260,659-661` ignores MAC completely and passes only `name` to `isPolarH10Name(name)`; `syncPendingWorkout` (`:482`) matches `mac == targetId || name.contains(targetId)`.
  * `DeviceDataRepository.kt:652-662`, `PolarOnlineStreamingBridge.kt:188-192`, `EditDeviceDialog.kt:1738-1757` all inherit the name heuristics.
* **Independent Peer Review & Verification (Live `b08c779e` Codebase Audit)**:
  * **Verified**: Ticket line references match `PolarOfflineGattCoordinator.kt` prior to `ATT-8690` (`34b78941`), which shifted lines to `:496-539` (and already added `registerDeviceAliases`, `matchesDeviceIdentifier`, `ALL_POLAR_FEATURES` with `FEATURE_DEVICE_INFO`, and `disInformationReceived` forwarding in `multiplexerCallback:232-246`).
  * **Blind Spot 1 — Renamed H10 Misclassification Hazard**: `BTSearchForNewDevicesEngine.java:503-506` ALREADY sets `PolarOfflineCapabilityStore.markOfflineRecordingCapable(mContext, address)` whenever `UUID_SERVICE_POLAR_PFTP` (`0000feee-...`) is present—including on Polar H10! Today, only `!isPolarH10Name(name)` in `PolarOfflineGattCoordinator.kt:538` prevents H10 from matching `isPolarVeritySenseDevice`. Once renamed, an H10 with `offline_rec_<MAC>=true` is actively **misclassified as Verity Sense** (wrong offline API, wrong IMU `VERITY_SENSE_ARM` + `GYRO`, wrong `RR_PRIORITY_PPG`).
  * **Blind Spot 2 — Missing DIS `0x2A25` & Reconnect Hydration**: `BluetoothConstants.java:48-49,75-78` defines `UUID_CHARACTERISTIC_MODEL_NUMBER` (`0x2A24`), `UUID_SERVICE_POLAR_PFTP`, `UUID_SERVICE_POLAR_PMD`, but lacks `UUID_CHARACTERISTIC_SERIAL_NUMBER` (`0x2A25`). `BTSearchForNewDevicesEngine.java:133-150` reads only `0x2A29` + `0x2A19` (never `0x2A24`/`0x2A25`, never `UUID_SERVICE_POLAR_PMD`). `MyBTLEDevice.java:602-628` / `BTLEHeartRateDevice.java` never reads DIS or caches PMD/PFTP on reconnect, and `PolarOnlineStreamingBridge.sdkCallback.disInformationReceived` (`:318-320`) is a no-op stub.
  * **Blind Spot 3 — `Devices.db` vs. `PolarOfflineCapabilityStore`**: `DevicesDatabaseManager.java:1158` is at `DB_VERSION = 14`, with `DevicesDatabaseManagerMigrationV14Test.kt:55` asserting `assertEquals(14, DB_VERSION)`. Extending `PolarOfflineCapabilityStore` (MAC-keyed `SharedPreferences` + `ConcurrentHashMap`, established by `ATT-7923`) avoids a `Devices.db` v15 migration/backup-compat blast radius and is auto-rehydrated on first reconnect via GATT/DIS.

## 3. Scope Grounding & Non-Goals (`ATT-1250`)
* **In-Scope (`3 SP`)**: (1) Extend `PolarOfflineCapabilityStore` with `hasPmdService`, `hasPftpService`, hardware `modelNumber` (`0x2A24`), canonical `polarDeviceId` (`0x2A25` / `PolarDeviceInfo.deviceId`), and resolved `PolarDeviceType` (`H10`, `VERITY_SENSE`, `UNKNOWN`); (2) Discover/persist PMD/PFTP UUIDs + DIS `0x2A24`/`0x2A25` during pairing (`BTSearchForNewDevicesEngine`), standard BLE HRM reconnect (`BTLEHeartRateDevice`), and Polar SDK sessions (`PolarOnlineStreamingBridge` + offline controllers via `FEATURE_POLAR_H10_EXERCISE_RECORDING` / `FEATURE_POLAR_OFFLINE_RECORDING` / `deviceConnected` / `disInformationReceived`); (3) Replace name/regex checks in `PolarOfflineGattCoordinator`, `PolarH10OfflineController`, `PolarVeritySenseOfflineController`, `PolarOnlineStreamingBridge`, `DeviceDataRepository`, `EditDeviceDialog`, keeping legacy name fallback strictly when hardware metadata is absent (before first reconnect); (4) Seed `ATT-8690` `registerDeviceAliases(polarDeviceId, mac)` from persisted hardware ID at startup.
* **Out-of-Scope**: `Devices.db` v15 schema bump, Polar SDK version upgrade, UI redesign or new `strings*.xml` copy, physical hardware testing (deferred per `Rule 7.6`).

## 5. System Invariants & Design Strategy
* **Disambiguation Precedence**: (1) Persisted DIS Model `0x2A24` (`"H10"` vs. `"Verity Sense"`/`"Sense"`/`"OH1"`) or SDK feature (`FEATURE_POLAR_H10_EXERCISE_RECORDING` vs. `FEATURE_POLAR_OFFLINE_RECORDING`) -> `PolarDeviceType`; (2) Only if `PolarDeviceType == UNKNOWN` and both `PMD`+`PFTP` (or legacy `offline_rec`) exist, fall back to name heuristics (`isPolarH10Name`/`isPolarVeritySenseName`) for un-reconnected rows, never blindly classifying `PFTP`-only unknown Polar devices as Verity Sense if H10 cues exist; (3) Resolve canonical Polar ID from persisted `0x2A25` / `PolarDeviceInfo.deviceId` -> `POLAR_ID_REGEX` -> `macAddress`, registering aliases in `PolarOfflineGattCoordinator`.
* **Risk Rating**: **MEDIUM** — Touches BLE GATT discovery, Polar SDK callbacks, and UI/repository eligibility, but requires zero SQLite schema changes and preserves all `ATT-8690` invariants.
