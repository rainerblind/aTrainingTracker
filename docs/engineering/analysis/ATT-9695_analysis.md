### Requirement Archaeology & Chesterton's Fence Audit

1. **Original Requirement ID & Target**: Net-new `REQ-FIL-046` refining `REQ-FIL-029.2`/`.3` (`ATT-8895`), `REQ-FIL-030.2`/`.3` (`ATT-8891`), and `REQ-EXP-046` (`ATT-9349`) across `BANALService.java`, `TrackerService.java`, `SmartphoneImuCadenceEstimator.kt`, and `SpeedAndLocationDevice_ATTFused.kt`.
2. **Historical Origin & Commit Trace**: `a3a5942a` (`ATT-8895`) gated `WALKING_TRANSITION` & `STRIDES` on `BSportType.RUN` to block cycling bakery stops (`BIKE_HANDLEBAR`/`CYCLING` zero-stride rule from `ATT-166`); `ATT-8891` (`REQ-FIL-030`) added Tier 3 kinematic `RUN`/`BIKE` inference and anti-circular `getAuthoritativeBSportType()` isolation while intentionally keeping `WALKING_TRANSITION` neutral in `KinematicSportTypeDiscriminator`.
3. **Root Reason for Existing Formulation**: Cycling stops enter `WALKING_TRANSITION`; suppressing non-`RUN` `WALKING_TRANSITION` prevented bike rides from recording walking strides, and isolating `getAuthoritativeBSportType()` prevented positive-feedback carriage latching.
4. **Preservation of Core Invariants**: `PhoneCarriageClassifier` continues consuming strictly `getAuthoritativeBSportType()` (Tier 1+2 only); `BANALService.getBSportType()` retains exact `REQ-FIL-030.3` 4-tier precedence for `BanalFinalizationSnapshot`/finalization; Tier 1 explicit user `OTHER` (`mHaveUserSelectedSportType && UNKNOWN`) and active `CYCLING` (any tier) keep `WALKING_TRANSITION` strictly `SUPPRESSED` (`0` strides); `BIKE_HANDLEBAR` stays suppressed; zero per-sample SQLite queries; zero `SPORT_TYPE_CHANGED_BY_USER_INTENT` on auto-resolution; all monolith LoC caps upheld.
