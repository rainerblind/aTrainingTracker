## 1. Problem Statement & Motivation
Polar Verity Sense does not transmit beat-to-beat RR intervals over standard BLE Heart Rate Service (`0x2A37`), blocking slip-on morning resting HRV checks (`ATT-9177`). `polar-ble-sdk:8.6.0` exposes optical Pulse-to-Pulse Intervals (`PolarOnlineStreamingApi.startPpiStreaming`), which are valid for still resting `rMSSD` but unsuitable for exercise `DFA α1` due to PPG pulse-wave smoothing and motion artifacts.

## 2. Independent Peer Review & Verification
Audited live `sprint/2026-11-20_01_Früh` @ `cdc565c0` + `javap` on cached `polar-ble-sdk-8.6.0-api.jar` (`Rule 68` side-effect trace):
1. **Already Completed by `ATT-9177` (`b899a864`, `REQ-HRV-049`) — Zero Duplicate Edits**: `RrBeatEvent.kt` already carries `@JvmOverloads val isOpticalPpi: Boolean = false` + 6-arg Java `copy()`; `DeviceManager.java:538-542` already assigns Verity Sense `PolarOnlineStreamingBridge` `RR_PRIORITY_PPG (2)` behind `ECG (0)` and `ANT+ (1)`; `MorningHrvCheckViewModel.kt` and `HrvSignalQualityAnalyzer.kt` already consume `isOpticalPpi`.
2. **Verified `polar-ble-sdk:8.6.0` PPI API (`javap`)**: `PolarOnlineStreamingApi.getAvailableOnlineStreamDataTypes(id)` (`suspend`), `startPpiStreaming(id): Flow<PolarPpiData>`, `stopStreaming(id, PmdMeasurementType.PPI)`, `PolarBleApi.PolarDeviceDataType.PPI`, and `PolarPpiSample(ppi: Int, errorEstimate: Int, hr: Int, blockerBit: Boolean, skinContactStatus: Boolean, skinContactSupported: Boolean, timeStamp: ULong)`.
3. **Verified Gap 1 — Missing PPI Stream & 3-Entry Startup (`PolarOnlineStreamingBridge.kt`, `1,228/1,500` LoC)**: Currently starts only `HR`, `ACC`, and `GYRO`. Must start `PPI` for `isVeritySense == true` across all 3 readiness paths (`bleSdkFeatureReady(FEATURE_POLAR_ONLINE_STREAMING)`, `syncAlreadyOpenSessionIfReady`, and `maybeStartVerityStreamsIfReady` after DIS model or `FEATURE_POLAR_OFFLINE_RECORDING`), guarded against re-entrancy/PMD `ERROR_ALREADY_IN_STATE` and cleanly cancelled/stopped (`PmdMeasurementType.PPI`) on disconnect/`blePowerStateChanged(false)`/`shutDown()`. Verified scope boundary: `PolarOnlineStreamingBridge` remains gated on `DeviceDataRepository.isPolarLiveImuBridgeEligible` (`L670-678`, Android 13+ opt-in).
4. **Hidden Side-Effect A — Hardware Artifact Preservation in `RrArtifactFilter.kt:312-315`**: `isGapOrOutOfPhysiologicalRange` preserves only `ARTIFACT_GAP` (and out-of-range RR); other pre-set flags are overwritten by `classifyBeat()`. Therefore `ppi <= 0` samples MUST be dropped, while `ppi > 0` samples with `blockerBit == true` or `(skinContactSupported && !skinContactStatus)` MUST be stamped `artifactFlag = RrBeatEvent.ARTIFACT_GAP` (preserving timeline monotonicity via `RrBeatNormalization`, excluding adjacent pairs from bias-free `rMSSD`, and keeping hardware-flagged motion/contact loss visible to `HIGH_ARTIFACTS > 5%`).
5. **Hidden Side-Effect B — Dual Live Engine Synergy (`HrvRollingEngine.kt`, `274` LoC)**: Because `ATT-8990` (`cdc565c0`) unified `HRVMetricsDevice` (`157` LoC) and `PerDeviceHrvController` (`330` LoC) on `HrvRollingEngine`, checking `activeWindowHasOpticalPpi = allBeats.any { it.beatTimestampMs >= dfaCutoff && it.isOpticalPpi }` inside `HrvRollingEngine.evaluate()` suppresses `HRV_DFA_A1` (`null`, non-sticky: resumes once optical beats age out of 120s window) AND forwards `isOpticalPpi` to `HrvSignalQualityAnalyzer.analyzeBeats(...)` for **both** global `"Bester Sensor"` and pinned per-device Verity Sense tiles simultaneously!
6. **Hidden Side-Effect C — `WorkoutRr.db` / `HrvPostWorkoutRecomputer` Pollution (`TrackerService.java:293`)**: `TrackerService.mRrBeatListener` (`L290-313`) persists all arbitrated `RrBeatEvent`s during `AutoPauseState.TRACKING && mWorkoutID > 0` into `WorkoutRr.db` (which has no `is_optical_ppi` column), causing `HrvPostWorkoutRecomputer.kt` (`486` LoC) to plot optical `DFA α1` curves on Verity-only workouts. **Zero-LoC-growth fix**: replace `L293` in-place with `if (!event.isOpticalPpi() && mAutoPauseManager.getCurrentState() == AutoPauseState.TRACKING && mWorkoutID > 0)` (**`+0` net LoC**, `TrackerService.java` stays `3,538/3,559`; alternative of skipping `rrBeatListeners` in bridge during `TRACKING` would break live `HRVMetricsDevice` `rMSSD` & `PolarRawTelemetryRecorder`).
7. **Target File LoC Audit (`ArchitectureConformanceContractTest.kt`)**: `DeviceManager.java` (`1,707/1,708`, **0 edits**), `DevicesDatabaseManager.java` (`1,669/1,671`, **0 edits**), `TrackerService.java` (`3,538/3,559`, **+0 net LoC** 1-line guard), `PolarOnlineStreamingBridge.kt` (`1,228/1,500`, target `<= 1,310` via new pure-JVM `PolarPpiStreamProcessor.kt`), `HrvRollingEngine.kt` (`274`, `+8` LoC), `PolarVeritySenseOfflineController.kt` (`1,473`, **0 edits** — offline HR uses `PolarDeviceDataType.HR` independently of PMD `PPI`).

## 6. Architectural Strategy & Localization Parity
1. **`PolarPpiStreamProcessor.kt`**: Pure-JVM stateful helper filtering `ppi <= 0` drops, stamping `blockerBit || (skinContactSupported && !skinContactStatus)` as `RrBeatEvent.ARTIFACT_GAP`, reconstructing monotonic UTC timestamps via `RrBeatNormalization`, emitting `RrBeatEvent(..., isOpticalPpi = true)`, with `reset()` on disconnect/`onAccumulatorsReset()`.
2. **`PolarOnlineStreamingBridge.kt`**: Add `ppiJob`/`isPpiStreamingActive`, check `getAvailableOnlineStreamDataTypes(sessionId).contains(PolarDeviceDataType.PPI)` when `isVeritySense`, collect `api.startPpiStreaming(sessionId)` -> `processPpiData(...)` across all 3 Verity readiness hooks, cancel in `cancelActiveStreamJobs()`, stop `PmdMeasurementType.PPI` in `shutDown()`.
3. **`HrvRollingEngine.kt` & `TrackerService.java:293`**: Suppress `alpha1Value = null` and pass `isOpticalPpi = activeWindowHasOpticalPpi` to `HrvSignalQualityAnalyzer.analyzeBeats(...)` in `HrvRollingEngine.evaluate()`; ignore `event.isOpticalPpi()` in `TrackerService.mRrBeatListener` (`+0` net LoC) so `WorkoutRr.db` & `HrvPostWorkoutRecomputer` stay ECG-only.
