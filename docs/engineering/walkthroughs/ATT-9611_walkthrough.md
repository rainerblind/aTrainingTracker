## 1. Summary of Changes & Gate 3 Guardrail Compliance
- **`PolarOfflineHrTimestampAligner.kt` (new pure-JVM, `266` LoC, `0` `android.*` imports, `0` warnings)**:
  - `resolveHrOfflineAnchorMs()` strictly converts Polar BLE SDK `8.6.0` `HrOfflineRecording.startTime` (parsed as UTC by `OfflineRecordingData.parseStartTime`) via `ZoneOffset.UTC` (falling back to `fallbackAnchorMs` ONLY when null, `< 2020`, or `<= 0L`), eliminating the `-1 h` CET / `-2 h` CEST / `+5 h` EST shift (`REQ-SET-130.1`).
  - `parsePbLocalDateTimeMs()` honors `Types.PbLocalDateTime.timeZoneOffset` strictly within `-1080..1080` (guarding against `DateTimeException` on malformed protobuf bytes, else `fallbackZone`).
  - `selectMatchingHrEntry()` evaluates all valid local offsets (`zoneId.rules.getValidOffsets(entry.date)` for DST fall-back 2-offset overlap hours) before falling back to UTC path matching only when zero local matches exist in a non-UTC timezone (`REQ-SET-130.1`).
  - `alignHrSamples()`, `alignIntHrSamples()`, `extractTurnTimestamps()`, and `formatBackfillDiagnostics()` centralize 1-Hz HR alignment and structured diagnostics (`REQ-SET-130.3`).
- **`WorkoutSamplesDatabaseManager.java` (`1,478 / 1,500` LoC, unchanged pinned JVM signature)**:
  - Added `public static final long MAX_HR_MATCH_TOLERANCE_MS = 5_000L` and enforced strict bounded nearest-sample matching in `patchMissingHeartRateSamples()` so out-of-window rows (`> 5_000 ms`) are skipped rather than flat-line clamped to boundary samples (`106 bpm`), while preserving live HR/GPS/Power rows and the `totalRows == 0` empty-table swim insert path (`REQ-SET-130.2`).
- **`PolarVeritySenseOfflineController.kt` (`1,476 / 1,500` LoC, `-16` LoC vs baseline) & `PolarH10OfflineController.kt` (`936 / 1,500` LoC)**:
  - Delegated anchor/entry/sample/turn helpers to `PolarOfflineHrTimestampAligner`.
  - Added symmetric zero-gap fast path in `executePendingSyncSession()` for already-complete HR (`!shouldBackfill`, preserving `swimSession` full backfill): skips `getOfflineRecord` and redundant `reexportUpdatedWorkout()`, logs `Log.i` (`alreadyCompleteHr=true`), clears `polarSyncPending`, removes matched flash entry, and refreshes workout (`REQ-SET-130.3`).
  - Hardened `applyBackfillAndCommit()` defense-in-depth: rejects (`Log.w`, returns `false`, preserves flash & pending state) strictly when `baseFileName.isNullOrEmpty() || hrPairs.isEmpty() || (patchedCount <= 0 && hasMissingHeartRateSamples(baseFileName))`, while cleanly clearing pending & removing flash without livelock when `patchedCount == 0 && !hasMissingHeartRateSamples(baseFileName)`.
  - Added structured `Log.i`/`Log.w` backfill diagnostics across both Verity Sense and H10 controllers (preserving H10 RR-only backfill when `intervals.isNotEmpty()`, zero `WorkoutRr.db` writes on Verity Sense, and `0` edits to `PolarOfflineGattCoordinator.kt`, `PolarOnlineStreamingBridge.kt`, `TrackerService.java`, `strings*.xml`).
