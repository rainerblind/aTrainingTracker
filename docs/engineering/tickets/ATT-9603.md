# Ticket Deliverable: ATT-9603 — Eliminate 150-lines-per-second LiveSegmentsRepository logcat flood during active workouts

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-431`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**: During a 10-minute workout (`2026-11-22_081402`, `Zum Bäcker #60`, `PID 25837`), `LiveSegmentsRepository` emitted `92,339` `I/LiveSegmentsRepository` logcat lines (`~150 lines/sec`). In `app/src/main/java/com/atrainingtracker/trainingtracker/segments/LiveSegmentsRepository.kt`, `DEBUG` resolves to `BuildConfig.DEBUG` (`true` in debug builds) and `updateLiveSegments()` (line 207) plus `processLiveSegmentUpdate()` (lines 222, 250–257, 368) execute unconditional `Log.i(TAG, ...)` calls on every 1-Hz GNSS fix for every saved Strava segment—even unchanged `FAR_FAR_AWAY` segments 450 km away—wasting CPU/allocations and evicting diagnostic warnings/errors from Android's `logcat` ring buffer.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*: Remove the per-tick `Log.i` calls in `updateLiveSegments()` (line 207) and `processLiveSegmentUpdate()` (lines 222, 250–257, 368) in `LiveSegmentsRepository.kt`; restrict `DEBUG` `Log.i` logging strictly to actual `LiveSegmentStatus` transitions (`FAR_FAR_AWAY <-> APPROACHING <-> ON_SEGMENT <-> ON_SEGMENT_CLOSE_TO_FINISH <-> FINISHED`); add `REQ-LIV-006` / `TST-LIV-002` and targeted unit tests in `LiveSegmentsRepositoryTest.kt`.
  * *Out-of-Scope*: No changes to Strava segment sync (`SegmentsRepository.kt`), SQLite schemas (`SegmentsDatabaseManager.java`), polyline gate/projection math (`PolylineProgressTracker`), `LiveSegmentData` / `LiveSegmentMath` models, or Compose UI / localized strings.
* **Chesterton's Fence / Impact**: Preserves `REQ-LIV-001`..`REQ-LIV-005` and `REQ-MAP-065` invariants (`_liveSegments.update { ... }` atomic CAS updates, immutable `LiveSegmentMath`, 45° bearing alignment, orthogonal projection, PR delta math, and `BuildConfig.DEBUG` release dead-code stripping). `SYS.2`/`SYS.3`: `SYSREQ-TRK-004` (unchanged).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**: Keep `val DEBUG = com.atrainingtracker.BuildConfig.DEBUG` so release builds continue to strip diagnostic logs cleanly, while eliminating all per-tick `Log.i` calls inside `updateLiveSegments()` and `processLiveSegmentUpdate()` (`"updateLiveSegments ..."`, `"  checking segment: ..."`, `"  distanceToStart: ..., distanceToEnd: ..."`, `"  start_cross_loc: ..., end_cross_loc: ..."`, `"  we are on this segment.  Thus, we update it ..."`). Emit `if (DEBUG) Log.i(TAG, ...)` exclusively when a segment's `LiveSegmentStatus` transitions (covering `FAR_FAR_AWAY -> APPROACHING`, `APPROACHING -> ON_SEGMENT`, `APPROACHING -> FAR_FAR_AWAY`, `ON_SEGMENT -> ON_SEGMENT_CLOSE_TO_FINISH`, `ON_SEGMENT -> FAR_FAR_AWAY`, `ON_SEGMENT_CLOSE_TO_FINISH -> FINISHED`, `ON_SEGMENT_CLOSE_TO_FINISH -> FAR_FAR_AWAY`, and `FINISHED -> FAR_FAR_AWAY`).
* **SWE.2 Architecture / Files Touched**:
  * Production: `app/src/main/java/com/atrainingtracker/trainingtracker/segments/LiveSegmentsRepository.kt`.
  * Tests: `app/src/test/java/com/atrainingtracker/trainingtracker/segments/LiveSegmentsRepositoryTest.kt`.
  * Living Docs: `docs/requirements/req_process_stability_part1.md`, `docs/tests/tst_process_stability_part1.md` (plus synced master indexes).
  * `docs/architecture.md`: No structural change (internal logging hygiene inside existing `LiveSegmentsRepository`).

## 4. Implementation Plan
1. Remove per-tick `Log.i` calls in `LiveSegmentsRepository.updateLiveSegments()` and `processLiveSegmentUpdate()`, retaining/completing `if (DEBUG) Log.i(...)` strictly on `LiveSegmentStatus` transitions.
2. Add targeted unit tests in `LiveSegmentsRepositoryTest.kt` verifying: (a) `0` `Log.*` calls across repeated 1-Hz updates for `>= 50` unchanged `FAR_FAR_AWAY` segments (and steady-state `APPROACHING`/`ON_SEGMENT`/`FINISHED` ticks), and (b) `Log.i` fires only on actual `LiveSegmentStatus` transitions while all existing gate/progress/PR tests remain identical.
3. Add `REQ-LIV-006` and `TST-LIV-002` to living docs, promote to `[Verified]`, sync indexes, and run targeted `:app:testDebugUnitTest`, `verify_requirement_governance.py`, and `auto_gate.py --write-bundle --advance-jira`.
