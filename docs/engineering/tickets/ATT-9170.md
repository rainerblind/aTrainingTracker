# Ticket Deliverable: ATT-9170 — Dotted Grey Average Reference Line & `Ø` Y-Axis Label on All TelemetryMetricGraph Charts

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-68`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Value Proposition**:
  * Athletes reviewing telemetry graphs (`TelemetryMetricGraph`) in both **Workout Summary** (`WorkoutSummary.kt`) and **Workout Details** (`TelemetryChartStack.kt` / `MapDetailLayout.kt`) currently see only top/bottom Y-axis extrema (and `DFA α1` threshold markers), with no visual reference line indicating the workout's overall average.
  * Rendering a horizontal dotted grey average reference line paired with a `Ø`-prefixed Y-axis label lets athletes instantly judge how each segment of the session compares against the entire workout's overall average across Speed, Pace, Slope, Heart Rate, Power, Cadence, W'bal, DFA α1, and rMSSD.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*:
    1. Pure-JVM entire-workout average math (`TelemetryMetricUtils.computeWorkoutAverage`) covering all `TelemetryMetricType` metrics rendered in `TelemetryMetricGraph`:
       - `PACE`: harmonic / speed-derived average pace from overall mean positive finite speed (`1000 / mean(speed_mps) / 60` in `METRIC`, `METER_PER_MILE / mean(speed_mps) / 60` in `IMPERIAL`), preventing slow stops or walking breaks from skewing the average line.
       - `SPEED`, `HEART_RATE`, `POWER`, `CADENCE`, `SLOPE`, `ALTITUDE`, `W_PRIME_BAL`, `HRV_DFA_A1`, `HRV_RMSSD`: mean across valid finite samples of the entire workout (`HRV_DFA_A1` and `HRV_RMSSD` exclude high-artifact samples `hrvArtifactRate > 5.0` when clean samples exist, matching plotted-curve semantics).
       - Constant reference anchor across zoom/pan (`pathPoints` is never viewport-sliced); cleanly omitted when no valid finite average exists or when the average falls outside `[dataMin, dataMax]`.
    2. Y-axis label formatter (`TelemetryMetricUtils.formatAverageYAxisLabel` / `formatYAxisValue`) using `Ø` prefix + metric's standard Y-axis format (`Ø155`, `Ø8:15`, `Ø0,83`, `Ø235`, `Ø1%`), locale-aware decimal formatting, and `-0%` suppression.
    3. Pure-JVM priority-based Y-axis label layout & collision-avoidance engine (`TelemetryChartCanvasHelpers.kt`: `resolveTelemetryYAxisLabels`, `drawAverageReferenceLine`) placing `Ø<val>` right-aligned inside the `50.dp` left gutter (`startPaddingPx - 4.dp`) with auto-fit width scaling so it never clips into the plot area, and enforcing strict top priority for `Ø` (`PRIORITY_AVERAGE > PRIORITY_THRESHOLD > PRIORITY_EXTREMA`) so colliding min/max, `DFA α1` threshold, or future `ATT-9164` zone boundary labels are cleanly suppressed.
    4. Dotted grey horizontal reference line (`colorScheme.onSurfaceVariant` at `0.60f` alpha, crisp rounded-dot `PathEffect` distinct from existing `6.dp / 6.dp` dashed lines, `StrokeCap.Round`) across `[startPaddingPx, startPaddingPx + chartWidthPx]` with narrow-canvas (`plotWidth <= 0f`) guard.
    5. Automatic coverage of every `TelemetryMetricGraph` instance in both `WorkoutSummary.kt` and `TelemetryChartStack.kt` / `MapDetailLayout.kt` (Portrait and Landscape).
    6. Pure-JVM unit tests + Robolectric Compose UI & Light/Dark/AMOLED `Rule 8.5` PNG screenshot verification.
  * *Out-of-Scope*: `ElevationProfile.kt` (explicitly excluded and untouched), `ATT-9164` HR/Power zone-colored curve & zone boundary labels (coordinated via reusable priority levels in `resolveTelemetryYAxisLabels`), database schema, and string XMLs (`Ø` is a language-neutral mathematical symbol; `0` new XML string keys).
* **Chesterton's Fence / Impact**:
  * Preserves `REQ-UI-206` (`ATT-1740`, `TelemetryMetricGraph`), `REQ-UI-219` (Pace `mm:ss` formatting), `REQ-UI-230` (dashed zone threshold lines `6.dp/6.dp`), `REQ-HRV-046` (inverted `PACE` & `HRV_DFA_A1` Y-axis), `REQ-HRV-047` (`HRV_RMSSD` dynamic Y-axis & formatter), `Rule 64` (`startPadding = 50.dp`, portrait `52.dp` / landscape `0.72f` plot alignment), `ElevationProfile.kt` untouched, and `TelemetryMetricGraph.kt <= 1,965` LoC (`ArchitectureConformanceContractTest`).
  * `SYS.2`/`SYS.3` impact: `NONE` (SW-only post-workout Compose canvas visualization inside `TelemetryMetricGraph`).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * Keep all averaging math and Y-axis formatting in `TelemetryMetricUtils.kt` and all Y-axis priority collision layout + dotted reference line Canvas helpers in `TelemetryChartCanvasHelpers.kt`. This keeps `TelemetryMetricGraph.kt` lean (~+35 lines, staying well below its `1,965` LoC ceiling) and makes all math, collision priority, and boundary guards directly pure-JVM unit-testable.
  * Use priority tiers (`PRIORITY_AVERAGE = 100`, `PRIORITY_THRESHOLD = 50`, `PRIORITY_EXTREMA = 20`) inside `resolveTelemetryYAxisLabels` so `Ø` always wins over any colliding label today (min/max, `DFA α1` thresholds) and seamlessly integrates with upcoming `ATT-9164` HR/Power zone boundary labels without rework.
  * Render the dotted grey average line (`strokeWidth = 1.5.dp`, `dashPathEffect(floatArrayOf(0.5.dp, 4.5.dp))`, `StrokeCap.Round`, `onSurfaceVariant @ 0.60f`) right after the curve/overlays (before the scrubbing cursor) so dot contrast remains crisp and uniform over both shaded zone bands and curve area fills without obscuring the solid `2.dp` telemetry stroke.
* **SWE.2 Architecture / Files Touched**:
  * Production:
    * `app/src/main/java/com/atrainingtracker/trainingtracker/ui/map/TelemetryMetricUtils.kt`
    * `app/src/main/java/com/atrainingtracker/trainingtracker/ui/map/TelemetryChartCanvasHelpers.kt`
    * `app/src/main/java/com/atrainingtracker/trainingtracker/ui/map/TelemetryMetricGraph.kt`
  * Tests:
    * `app/src/test/java/com/atrainingtracker/trainingtracker/ui/map/TelemetryMetricGraphAverageLineTest.kt` (new pure-JVM + Robolectric Compose UI & Light/Dark/AMOLED PNG verification suite)
  * `ElevationProfile.kt` & `docs/architecture.md`: untouched (`ElevationProfile` explicitly excluded; no new subsystem/service/DB/prefix family).
