# Ticket Deliverable: ATT-9174 — EditWorkoutScreen: Show Polar pending retry sync banner directly after stopping a workout

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-5910`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**: After stopping a workout while a Polar Verity Sense or Polar H10 sensor is disconnected, stop-time fast-fail (`ATT-8969`) opens `EditWorkoutScreen` directly. However, `PolarPendingRetrySyncSection` was mounted only in `TrackOnMapScreen.kt` and `WorkoutDetailTabbedContent.kt`, not in `EditWorkoutScreen.kt`, forcing the user to close Edit Workout and navigate into Workout Details before seeing the retry sync banner.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*: Mount `PolarPendingRetrySyncSection` in `EditWorkoutDialog` (`EditWorkoutScreen.kt`) whenever `workoutData.polarSyncPending == true`; wire `dismissPolarSyncPending()` and `PolarRetrySyncCoordinator.completedWorkoutEvents` refresh in `EditWorkoutViewModel.kt`; add optional `outerPadding` parameter to `PolarPendingRetrySyncSection` / `PolarH10RetrySyncBanner` so the banner aligns flush inside `AppModalBottomSheet`.
  * *Out-of-Scope*: No changes to BLE/PFTP sync protocols, SQLite schema, `WorkoutRepository.kt`, or localized string tables (all 9-locale Polar retry/unpaired strings already exist in `strings_devices.xml`).
* **Chesterton's Fence / Impact**: Preserves `PolarRetrySyncCoordinator` non-composition scope (`REQ-SET-119.1`), `ATT-9509` unpaired-sensor guard & reactive re-pairing (`REQ-SET-125`), 19-field user-edit preservation during async telemetry refresh (`REQ-TRK-091.2`), `WorkoutPostProcessingCoordinator` / controller export gating, and default `16.dp`/`8.dp` padding on `TrackOnMapScreen` and `WorkoutDetailTabbedContent`. `SYS.2`/`SYS.3`: `SYSREQ-DEX-007` (unchanged).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**: Reuse `PolarPendingRetrySyncSection` directly at the top of `EditWorkoutDialog` (below the optional Diagnostic Warning Card, above Workout Name) with `outerPadding = PaddingValues(0.dp)` so it aligns 1:1 flush with `EditWorkoutDialog`'s form controls inside `AppModalBottomSheet` (`20.dp + 4.dp` existing padding). In `EditWorkoutViewModel`, mirror `userClearedRecordingErrors` with `userDismissedPolarSyncPending` so dismissing hides the banner immediately and resists stale `allWorkouts` emissions, while collecting `PolarRetrySyncCoordinator.completedWorkoutEvents` refreshes summary telemetry without overwriting unsaved edits.
* **SWE.2 Architecture / Files Touched**:
  * Production: `app/src/main/java/com/atrainingtracker/trainingtracker/ui/aftermath/editworkout/EditWorkoutScreen.kt`, `app/src/main/java/com/atrainingtracker/trainingtracker/ui/aftermath/editworkout/EditWorkoutViewModel.kt`, `app/src/main/java/com/atrainingtracker/trainingtracker/ui/aftermath/PolarH10RetrySyncBanner.kt`.
  * Tests: `app/src/test/java/com/atrainingtracker/trainingtracker/ui/aftermath/editworkout/EditWorkoutPolarRetrySyncUiTest.kt`, `app/src/test/java/com/atrainingtracker/trainingtracker/ui/aftermath/editworkout/EditWorkoutViewModelTest.kt`.
  * `docs/architecture.md`: No structural change (reuses existing `PolarRetrySyncCoordinator` & `PolarPendingRetrySyncSection`).
