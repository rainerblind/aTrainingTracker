## 1. Problem, Scope & Change-Request Impact Analysis

### Problem / Root Cause
* `ATT-8991` (`REQ-CON-057`) already added `DeviceType.HRM` to `DeviceType.getDeviceTypeList(CADENCE | STRIDES)`, introduced `HrmSensorCapabilityHelper.isSensorSupported(...)`, and wired it into `SensorSourceDialog.sortNotConnectedDevices()` and `DevicesDatabaseManager.getDeviceIdAndNameLists()`.
* However, `HrmSensorCapabilityHelper.isSensorSupported(...)` (`app/src/main/java/com/atrainingtracker/banalservice/devices/HrmSensorCapabilityHelper.kt:42-67`) omits **both**:
  1. the persisted `polarLiveImuEnabled` opt-in check (`DevicesDbHelper.POLAR_LIVE_IMU_ENABLED == 1`, `DeviceUiData.polarLiveImuEnabled`, `REQ-SET-112` / `ATT-8016` / `ATT-8017` — default `0` in `Devices.db`), and
  2. the Android 13+ (`Build.VERSION.SDK_INT >= Build.VERSION_CODES.TIRAMISU`) OS gate (where plain-JVM unit tests execute with `SDK_INT == 0`).
* Consequently, paired Polar H10 / Verity Sense BLE straps with `polarLiveImuEnabled == false` (default) or on Android `< 13` are spuriously listed under "Nicht verbundene Sensoren" in `SensorSourceDialog` (and in `DevicesDatabaseManager.getDeviceIdAndNameLists()`) for `CADENCE` / `STRIDES` / `VERTICAL_OSCILLATION` / `GROUND_CONTACT_TIME`, even though `PolarOnlineStreamingBridge` / `DeviceManager.polarLiveImuChanged()` only emit IMU telemetry when `polarLiveImuEnabled == true` on Android 13+. Furthermore, `SensorSourceDialog.sortNotConnectedDevices()` did not enforce `device.isPaired` on `DeviceType.HRM` Live-IMU candidates (`allDevices` originates from `getCursorForAllDevices()`).

### In-Scope / Out-of-Scope
* **In-Scope**:
  * Shared opt-in (`polarLiveImuEnabled`), Android 13+ (`sdkInt == 0 || sdkInt >= TIRAMISU`), and hardware-grounded capability gating in `HrmSensorCapabilityHelper.kt`.
  * Disconnected `SensorSourceDialog` filtering (`device.isPaired` + `device.polarLiveImuEnabled`) and `MySensorManager` (`CADENCE_PRIORITY` / `STRIDES_PRIORITY`) ordering in `SensorSourceDialog.kt`.
  * Consistent DB query gating in `DevicesDatabaseManager.getDeviceIdAndNameLists()` reading `POLAR_LIVE_IMU_ENABLED`.
  * Unit tests, Robolectric Compose behavioral tests (`SensorSourceDialog`), and live `emulator-5554` verification.
* **Out-of-Scope**:
  * **Zero edits to `EditDeviceDialog.kt`** (strict lane isolation with `ATT-166`). Live reconnect/teardown when `polarLiveImuEnabled` toggles is already implemented by `DeviceManager.polarLiveImuChanged()` (`REQ-CON-050.1`).
  * **Zero UI string edits** (`Localization Parity: N/A - 0 string changes`) and **zero DB schema changes**.

### Requirement Archaeology & Chesterton's Fence Audit
1. **Original Requirement ID & Target**: Net-new `REQ-CON-064` refining `REQ-CON-057` (`ATT-8991`), `REQ-SET-112` (`ATT-8016`), `REQ-CON-049` (`ATT-8949`), `REQ-FIL-029` (`CADENCE_PRIORITY`), and `REQ-HRV-050.1` (`HR`/`RR_INTERVAL`/`HRV_*`) across `HrmSensorCapabilityHelper.kt`, `SensorSourceDialog.kt`, and `DevicesDatabaseManager.java`.
2. **Historical Origin & Commit Trace**: `ATT-8016` introduced `POLAR_LIVE_IMU_ENABLED` (default `0`, gated behind Android 13+ SDK compatibility in `PolarLiveImu` feature rollout); `ATT-8991` (`REQ-CON-057`) grounded HRM source lists in Polar hardware metadata (`H10` vs `Verity Sense`) while omitting the user opt-in flag and Android 13+ check.
3. **Root Reason for Existing Formulation**: Polar Live-IMU acceleration/gyro streaming incurs extra BLE PMD/battery load and requires Android 13+ Polar BLE SDK behavior, so `polarLiveImuEnabled` defaults to `false` unless explicitly enabled in `EditDeviceDialog`.
4. **Preservation of Core Invariants**:
   * All HR / RR / HRV (`HR`, `RR_INTERVAL`, `HRV_RMSSD`, `HRV_DFA_A1`, `HRV_ARTIFACT_RATE`, `HRV_SDNN`) HRM source selection remains unconditional for all paired/stored HRMs regardless of `polarLiveImuEnabled`, `Protocol`, or `SDK_INT` (`REQ-HRV-050.1`).
   * Connected active `CADENCE` / `STRIDES` / `VO` / `GCT` telemetry continues to appear in "Verbunden" naturally via `allTelemetry`, and `MySensorManager.CADENCE_PRIORITY` (`RUN_SPEED > BIKE_CADENCE > BIKE_SPEED_AND_CADENCE > BIKE_POWER > HRM > SPEED_AND_LOCATION_ATT_FUSED`) and `STRIDES_PRIORITY` stay unmodified.
   * Monolith ceilings stay compliant (`DevicesDatabaseManager.java <= 1,671`, `SensorSourceDialog.kt <= 1,500`, `HrmSensorCapabilityHelper.kt <= 1,500`).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**: Centralize `polarLiveImuEnabled: Boolean = false` and `sdkInt: Int = Build.VERSION.SDK_INT` (`@JvmOverloads`) inside `HrmSensorCapabilityHelper.isSensorSupported(...)` alongside `requiresPolarLiveImu(sensorType)` rather than duplicating opt-in/OS checks separately in Compose UI and SQLite code. Plain-JVM tests (`Build.VERSION.SDK_INT == 0`) remain deterministic via `sdkInt == 0 || sdkInt >= Build.VERSION_CODES.TIRAMISU`, while Robolectric (`@Config(sdk = [31])` vs `@Config(sdk = [34])`) and explicit `sdkInt` unit tests prove API `< 33` suppression.
* **SWE.2 Architecture / Files Touched**:
  * Production:
    * `app/src/main/java/com/atrainingtracker/banalservice/devices/HrmSensorCapabilityHelper.kt`
    * `app/src/main/java/com/atrainingtracker/trainingtracker/ui/tracking/controltracking/SensorSourceDialog.kt`
    * `app/src/main/java/com/atrainingtracker/banalservice/database/DevicesDatabaseManager.java`
  * Tests:
    * `app/src/test/java/com/atrainingtracker/banalservice/devices/HrmSensorCapabilityHelperTest.kt`
    * `app/src/test/java/com/atrainingtracker/trainingtracker/ui/tracking/controltracking/SensorSourceDialogPriorityTest.kt`

    * `app/src/test/java/com/atrainingtracker/banalservice/database/DevicesDatabaseManagerTest.kt`
  * `docs/architecture.md`: Unchanged (existing component helper pattern preserved).
