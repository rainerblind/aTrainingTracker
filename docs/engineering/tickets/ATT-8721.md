# Ticket Deliverable: ATT-8721 — Workout Summary -> Details: Open the matching tab when clicking a summary section (Resilient to renamed/reordered/deleted tabs)

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-68`
* **Status**: Verified (`REQ-UI-2805`, `TST-UI-2805`)

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**:
  * In `app/src/main/java/com/atrainingtracker/trainingtracker/ui/aftermath/workoutlist/WorkoutSummary.kt`, tapping summary sections (`WorkoutDetails`, `WorkoutDescription`, `WorkoutExtrema`, `WorkoutPathPreviewMap`, `ElevationProfile`, `TelemetryMetricGraph`, `HeartRateZoneDistributionCard`, `PowerZoneDistributionCard`, `GradeZoneDistributionCard`) invokes a parameterless `onMapClick: () -> Unit`, while `WorkoutRpeFeelSection` and `WorkoutLaps` header/card areas have no section navigation callback.
  * In `WorkoutDetailTabbedContent.kt` (line 161), `rememberPagerState(initialPage = 0, ...)` unconditionally opens tab `0` regardless of which summary section the athlete tapped.
  * Because athletes can rename, reorder, or delete Workout Details tabs via `WorkoutDetailTabConfig` (`SettingsDataStore`), hardcoding tab indices or matching tab titles would break whenever tabs are customized.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*:
    * Propagate tapped `WorkoutSectionType` via optional `onSectionClick: ((WorkoutSectionType) -> Unit)? = null` in `WorkoutSummary.kt`, `WorkoutList.kt`, and `WorkoutTabsScreen.kt`, mapped via `WorkoutSectionType.toWorkoutDetailSectionType()` (`WorkoutDetailTabConfig.kt`) into `initialSection: WorkoutDetailSectionType? = null` in `WorkoutSummariesTabbedScreen.kt`, `WorkoutClustersScreen.kt`, and `TrackOnMapScreen.kt`.
    * Add pure dynamic tab-resolution helpers (`resolveTabIndexForSectionOrNull`, `resolveTabIndexForSection`) on `WorkoutDetailTabConfig` matching strictly by `targetSection in tab.normalizedSections` and `WorkoutDetailSectionAvailability.isSectionActive(...)`, safely falling back to tab `0` when absent or unavailable.
    * Resolve `initialSection` asynchronously in `TrackOnMapScreen.kt` + `WorkoutDetailTabbedContent.kt` once persisted `WorkoutDetailTabConfig` (`workoutDetailTabsOrderFlow` collected with `initial = null`) and `TrackOnMapAftermathViewModel` (`AftermathMapUIState.isLoading`) finish loading, and scroll to the target section inside multi-section tabs or single-page mode (`visibleTabs.size == 1`) across both pure `Column` and `MapDetailLayout` (`lowerScrollState`).
  * *Out-of-Scope*: Changing `WorkoutDetailTabConfig` serialization format (`v4|`), altering `StravaActivitySection` external link click, `ExportStatus` inline expand/collapse, `WorkoutPhotoStrip` photo preview/add actions, or modifying `strings*.xml` (`Localization Parity: N/A - 0 new or modified UI strings`).
* **Chesterton's Fence / Impact**:
  * Refines `REQ-UI-408` / `REQ-UI-499` / `REQ-UI-2795` while preserving: `WorkoutHeader` click (`initialSection = null` -> tab `0`), `WorkoutSummaryCompact` click, `pendingAutoShare` snapshot flow (`ATT-9168`), `WorkoutLaps` per-row/visualizer/split/move-boundary actions, `StravaHelper.openActivity`, `ExportStatus` expand/collapse, `WorkoutPhotoStrip` preview/add, `HorizontalPager` gesture isolation (`REQ-UI-408.4`), and pinned `InterfaceSignatureDriftContractTest` signatures.
  * `SYS.2`/`SYS.3` impact: `NONE` (UI navigation & section-membership lookup only).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * **Membership-Based Resolution Over Title/Index**: Matching strictly on `targetSection in tab.normalizedSections` + `availability.isSectionActive` is completely invariant to tab renaming (`customTitle`), tab reordering, custom tab creation, and deletion.
  * **Async-Safe Hydration (`Rule 82`)**: Collecting `workoutDetailTabsOrderFlow` with `initial = null` in `TrackOnMapScreen.kt` and tracking `isLoading` on `AftermathMapUIState` ensures `WorkoutDetailTabbedContent` does not prematurely discard `initialSection` on Frame 0 before DataStore custom tabs and telemetry/zones (`hasZones`, `hasHrv`, `hasCharts`) finish loading.
  * **Unified Intra-Tab & Single-Page Section Scrolling**: Passing an optional `lowerScrollState` + `onLowerScrollViewportPositioned` into `MapDetailLayout.kt` and tagging/measuring each rendered section in `RenderWorkoutDetailCardSections` allows scrolling the target section cleanly to the top of the viewport in both multi-section tabs (`MODE_A_CARD_SCROLL`, `MODE_B_SPLIT_MAP`) and single-page mode (`visibleTabs.size == 1`).
* **SWE.2 Architecture / Files Touched**:
  * Production: `WorkoutDetailTabConfig.kt`, `WorkoutDetailTabbedContent.kt`, `TrackOnMapScreen.kt`, `MapDetailLayout.kt`, `TrackOnMapAftermathViewModel.kt`, `WorkoutLaps.kt`, `WorkoutSummary.kt`, `WorkoutList.kt`, `WorkoutTabsScreen.kt`, `WorkoutSummariesTabbedScreen.kt`, `WorkoutClustersScreen.kt`.
  * Tests: `WorkoutDetailTabsTest.kt`, `WorkoutDetailSectionNavigationUiTest.kt` (new Robolectric `createComposeRule()` UI + `WorkoutSummary` click tests).
  * Living Docs: `docs/requirements/req_ui_design_system_part6.md`, `docs/tests/tst_ui_design_system_part3.md` (+ synced master indexes); `docs/architecture.md` unchanged.

## 4. Implementation Plan
1. Add `resolveTabIndexForSectionOrNull` and `resolveTabIndexForSection` to `WorkoutDetailTabConfig.kt`.
2. Add optional `lowerScrollState` and `onLowerScrollViewportPositioned` to `MapDetailLayout.kt` and `isLoading: Boolean = false` to `AftermathMapUIState` (`TrackOnMapAftermathViewModel.kt`).
3. Update `WorkoutDetailTabbedContent.kt` and `TrackOnMapScreen.kt` to accept `initialSection: WorkoutDetailSectionType? = null`, wait safely for async DataStore tab config + aftermath telemetry loading, jump to the resolved tab index, and scroll to the target section in both multi-tab and single-page (`visibleTabs.size == 1`) layouts.
4. Wire `onSectionClick: ((WorkoutSectionType) -> Unit)? = null` through `WorkoutSummary.kt`, `WorkoutList.kt`, `WorkoutTabsScreen.kt`, `WorkoutSummariesTabbedScreen.kt`, and `WorkoutClustersScreen.kt` while keeping `WorkoutHeader`, `StravaActivitySection`, `ExportStatus`, `WorkoutPhotoStrip`, and `WorkoutLaps` row actions intact.
5. Add unit & Robolectric Compose UI tests in `WorkoutDetailTabsTest.kt` and `WorkoutDetailSectionNavigationUiTest.kt`, run Tier-1 tests, verify live on `emulator-5554` with `read_file` PNG inspection, update living docs to `[Verified]`, and run `tools/auto_gate.py --write-bundle --advance-jira`.
