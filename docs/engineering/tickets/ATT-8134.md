# Ticket Deliverable: ATT-8134 — Decouple Telemetry Charts, MapDetailLayout & AthleteProfileViewModel

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**:
  1. `ElevationProfile.kt` supports 2-finger pinch-zoom and double-tap reset (using linear `indexOfLast` scrub search), whereas `TelemetryMetricGraph.kt` duplicates drag/tap scrubbing without pinch-zoom or double-tap reset and rebuilds curve `Path`/`Brush`/`PathEffect` objects across all unfiltered raw points on every 16-ms scrub frame. `TelemetryMetricUtils.formatValue()` and `TelemetryOverlayComponents.formatPrimaryActiveValueText()` round-trip speed (`m/s -> userUnit -> m/s -> userUnit`) and pace (`min/unit -> sec/m -> min/unit`).
  2. `MapDetailLayout.kt` repeats 4 lower-viewport layout blocks and 8 identical `GlobalTelemetryZoomToolbar` calls across 44 parameters; `TelemetryChartStack.kt` repeats 8 verbose graph blocks and computes `isTrackless || activeTelemetryDomain == ProfileXAxisDomain.TIME` instead of `ProfileDomainMath.isEffectiveTimeDomain(...)`, diverging from `ElevationProfile` when `totalTimeSec == 0L`.
  3. `AthleteProfileViewModel.kt` merges 14 flows across all 4 Fitness & Physiology tabs into one monolithic `combine`, recomputing Banister PMC (`PowerPhysiologyCalculator.computePerformanceManagementChart`) on unrelated filter-chip clicks; `_hrMaxBpm` is read statically via `.value` instead of reactively (`Rule 39`), and `AthleteProfileScreen.kt` invokes both `onSelectPmcTimeRange`/`onSelectCardioTimeRange` and `onSelectTimeRange`, mutating time-range state twice.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*: Extract shared `Modifier.telemetryChartGestures` + O(log N) floor/nearest lookup (`TelemetryChartGestures.kt`), add viewport min-max downsampling and `Modifier.drawWithCache` path caching (`TelemetryChartCacheHelpers.kt`) for `TelemetryMetricGraph` and `ElevationProfile`, remove speed/pace unit round-trips (`SpeedFormatter`, `PaceFormatter`, `TelemetryMetricUtils`, `TelemetryOverlayComponents`); deduplicate `MapDetailLayout.kt` (cohesive state/config models, unified `MapDetailLowerViewport` + `MapDetailZoomToolbar`, consistent `ProfileDomainMath.isEffectiveTimeDomain`) and `TelemetryChartStack.kt`; split `AthleteProfileViewModel.kt` into 4 independent tab-specific `StateFlow`s (`bodyUiState`, `pmcUiState`, `hrvUiState`, `cardioUiState`) with reactive `_hrMaxBpm` and deduplicated `onSelectTimeRange` in `AthleteProfileScreen.kt`; ratchet `TelemetryMetricGraph.kt` in `ArchitectureConformanceContractTest` if `<= 1,500` LoC.
  * *Out-of-Scope*: Climb badge Paint/Path hoisting (`ATT-6037` already complete), marginal histogram / X-axis `DrawScope` helpers & `PathPreviewMap` (`ATT-6041` already complete), `ATT-9168` offscreen snapshot header semantics (preserved unchanged), new UI strings (`0` `strings*.xml` edits).
* **Chesterton's Fence / Impact**: Preserves `REQ-UI-192`, `REQ-UI-206`, `REQ-UI-226`, `REQ-UI-232`, `REQ-UI-234`, `REQ-UI-260`, `REQ-UI-261`, `REQ-UI-513.4`, `REQ-UI-2789`, `REQ-UI-2793`, `REQ-UI-2795`, `REQ-UI-2797`, `REQ-UI-2798`, `REQ-REV-015`, `REQ-STB-020.4`, and `AndroidViewModelReflectionContractTest` `@JvmOverloads`. `SYS.2`/`SYS.3`: Derived (SW-only UI/ViewModel consolidation).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * **Shared Gestures (`TelemetryChartGestures.kt`)**: Single `Modifier.telemetryChartGestures` supporting 2-finger centroid-anchored pinch-zoom + pan, `ChartGestureDisambiguator` horizontal/vertical disambiguation, drag/tap scrub, double-tap reset (`350 ms`), and O(log N) binary search preserving `FLOOR` (`ElevationProfile`) vs `NEAREST` + trackless (`TelemetryMetricGraph`) semantics.
  * **Cached Curves (`TelemetryChartCacheHelpers.kt` + `drawWithCache`)**: `Modifier.drawWithCache(cacheBuilder)` keyed strictly on non-scrub inputs so 60-Hz `currentDistance` updates replay pre-built viewport-downsampled `Path`/`Brush`/`PathEffect` objects with zero per-frame allocations while preserving HRV artifact gap breaks and zoom-edge anchors.
  * **Single-Pass Formatting**: `SpeedFormatter.formatUserUnitWithUnits` and `PaceFormatter.formatPaceMinutesWithUnits` format extracted display values directly once.
  * **Unified `MapDetailLayout` & `TelemetryChartStack`**: Bundle layout/viewport config into cohesive data classes (retaining backward-compatible parameter overload), collapse 4 viewport blocks + 8 `GlobalTelemetryZoomToolbar` calls into `MapDetailLowerViewport` + `MapDetailZoomToolbar`, drive `TelemetryChartStack` via shared `TelemetryChartViewport` + `ProfileDomainMath.isEffectiveTimeDomain`.
  * **Tab-Isolated `AthleteProfileViewModel`**: Separate `bodyUiState`, `pmcUiState` (with `pmcSummaryFlow` keyed only on `_workoutLoadSamples`, distinct `(ftp, hrRest)`, and reactive `_hrMaxBpm`), `hrvUiState`, and `cardioUiState`; derive `uiState` via zero-recomputation `combine` of the 4 tab flows; remove duplicate callback writes in `AthleteProfileScreen.kt`.
* **SWE.2 Architecture / Files Touched**:
  * Production: `ui/map/TelemetryChartGestures.kt` (new), `ui/map/TelemetryChartCacheHelpers.kt` (new), `ui/map/ElevationProfile.kt`, `ui/map/TelemetryMetricGraph.kt`, `ui/map/TelemetryMetricUtils.kt`, `ui/map/TelemetryOverlayComponents.kt`, `ui/map/MapDetailLayout.kt`, `ui/map/TelemetryChartStack.kt`, `banalservice/sensor/formater/SpeedFormatter.kt`, `banalservice/sensor/formater/PaceFormatter.kt`, `ui/athleteprofile/AthleteProfileViewModel.kt`, `ui/athleteprofile/AthleteProfileScreen.kt`.
  * Tests: New `TelemetryChartGesturesAndCacheTest.kt`, `MapDetailLayoutViewportConsolidationUiTest.kt`, `AthleteProfileTabFlowIsolationTest.kt`, plus existing map/athleteprofile/build contract suites.
  * `docs/architecture.md`: No new subsystem or repository (internal refactoring inside existing `ui/map` and `ui/athleteprofile`).
