# Ticket Deliverable: ATT-9065 — AntMissingAdapterDialog reappears repeatedly after clicking 'Verstanden' when ANT+ dongle is removed

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-5910`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**:
  * **Root Cause 1 — Cancelled inner `CoroutineScope` (`ATrainingTrackerApp.kt:834-846`)**: Inside `is AntDialogState.MissingAdapter ->`, `val scope = rememberCoroutineScope()` and `val tuningDataStore = remember { TuningPreferencesDataStore.getInstance(activity) }` were scoped to the `MissingAdapter` branch itself. In `onDismiss`, `activity.antDialogState = null` triggers recomposition before `tuningDataStore.setSuppressAntMissingAdapterDialog(true)` completes its DataStore write, causing the `MissingAdapter` branch to leave composition and cancel `scope`. Consequently, `tuning_suppress_ant_missing_adapter_dialog` was never persisted.
  * **Root Cause 2 — Synchronous in-memory race window (`MainActivityWithNavigation.kt:284, 306-311` & `ATrainingTrackerApp.kt:841-846`)**: `isAntMissingAdapterDialogSuppressed` waited for an asynchronous emission from `suppressAntMissingAdapterDialogFlow` instead of updating synchronously on dismissal. Because `MyANTDevice.onResultReceived` (`ADAPTER_NOT_DETECTED`) emits one broadcast per paired ANT+ sensor, back-to-back broadcasts arriving between `antDialogState = null` and DataStore emission saw `isAntMissingAdapterDialogSuppressed == false` and reopened the dialog.
  * **Root Cause 3 — Cold-start hydration race (`MainActivityWithNavigation.kt:284, 520-526, 555`)**: `isAntMissingAdapterDialogSuppressed` initialized to `false` before `suppressAntMissingAdapterDialogFlow` delivered its first persisted emission from disk. An `ADAPTER_NOT_DETECTED` broadcast arriving right after `onResume()` registers `mAntAdapterMissingReceiver` bypassed persisted `true` suppression.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*:
    * Use the long-lived outer `ATrainingTrackerApp` `scope` and `tuningDataStore` (with `NonCancellable` protection around `setSuppressAntMissingAdapterDialog(true)`) so DataStore persistence survives `MissingAdapter` leaving composition.
    * Add synchronous `MainActivityWithNavigation.onAntMissingAdapterDialogDismissed()` to immediately set `isAntMissingAdapterDialogSuppressed = true`, clear `antDialogState = null`, and shield against stale in-flight `false` DataStore emissions while the `true` write is pending.
    * Guard cold-start broadcasts before initial `suppressAntMissingAdapterDialogFlow` hydration via `isAntMissingAdapterSuppressionLoaded` + `hasPendingAntAdapterMissingBroadcast` (discarding deferred broadcasts if persisted `true`, flushing `showANTAdapterMissingDialog()` if persisted `false`).
    * Preserve `onViewStatus` (`"ANT+ Status anzeigen"`) behavior: set `showAntStatusSheet = true` and clear `antDialogState = null` without mutating DataStore suppression (`REQ-UI-353`).
    * Expand unit, Robolectric Activity cold-start/broadcast, and Compose `createComposeRule()` UI regression tests in `AntMissingAdapterDialogSuppressionTest.kt` and `AntMissingAdapterDialogComposeTest.kt`, plus live `emulator-5554` smoke verification.
  * *Out-of-Scope*: Altering `MyANTDevice.java` broadcast emission, `AntMissingDependencyDialog`, `AntServicesStatusSheet.kt`, `TuningPreferencesDataStore` key schema, or `strings*.xml` (`Localization Parity: N/A - 0 new or modified UI strings`).
* **Chesterton's Fence / Impact**:
  * Refines `REQ-UI-353` (`ATT-3220`, `ATT-3454`) and preserves `REQ-UI-323` (`ATT-2939`).
  * Preserves: clean-install dialog visibility (`SUPPRESS_ANT_MISSING_ADAPTER_DIALOG = false`), Advanced Tuning re-enablement toggle in `SensorSearchTuningSection.kt` / `AdvancedTuningScreen.kt`, `onViewStatus` opening `AntServicesStatusSheet` without persisting suppression, `AntAlertDialogContractTest` structural assertions, and `ArchitectureConformanceContractTest` LoC ceilings (`MainActivityWithNavigation.kt` and `ATrainingTrackerApp.kt` `< 1,500` LoC).
  * `SYS.2`/`SYS.3` impact: `NONE` (internal UI/Activity state & DataStore coordination only).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * Reuse `ATrainingTrackerApp`'s outer `scope` and `tuningDataStore` (matching `PermissionOnboardingSheet` in the same file) instead of an inner branch-scoped `rememberCoroutineScope()`, avoiding unnecessary `MainActivityWithNavigation` scope proliferation and preserving `AntAlertDialogContractTest` / `AntMissingAdapterDialogSuppressionTest` structural contracts.
  * Keep `var isAntMissingAdapterDialogSuppressed: Boolean = false` as a plain `Boolean` field on `MainActivityWithNavigation` (preserving reflection-based contract tests) paired with `isAntMissingAdapterSuppressionLoaded`, `hasPendingAntAdapterMissingBroadcast`, and `isPersistingAntMissingAdapterSuppression` handled in `applyAntMissingAdapterSuppressionState(suppressed)` and `onAntMissingAdapterDialogDismissed()`.
  * Buffer an early pre-hydration broadcast (`hasPendingAntAdapterMissingBroadcast = true`) rather than dropping it unconditionally, so clean-install users still see the alert once DataStore confirms `suppressed == false`, while returning users with persisted `suppressed == true` never see a spurious cold-start popup.
* **SWE.2 Architecture / Files Touched**:
  * Production: `ATrainingTrackerApp.kt`, `MainActivityWithNavigation.kt`.
  * Tests: `AntMissingAdapterDialogSuppressionTest.kt`, `AntMissingAdapterDialogComposeTest.kt`.
  * Living Docs: `docs/requirements/req_ui_design_system_part3.md`, `docs/tests/tst_ui_design_system_part2.md` (plus synced master indexes).
  * `docs/architecture.md`: unchanged (no new subsystem, service, DB, or prefix family).
