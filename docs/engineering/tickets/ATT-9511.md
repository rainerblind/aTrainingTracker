# Ticket Deliverable: ATT-9511 — Tracking Cockpit: Re-localize default SQLite tracking tab names on device locale change

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-5908`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**:
  * Observed during the 2026-KW47 9-language emulator sweep (`ATT-9386`, `docs/engineering/emulator_sweeps/2026-11-21_sweep.md`) on `Pixel_8_Android_15` (`es`, `ja`, `pt` locales): when the device/app locale changes after `FlexibleGenericView.db` has already been initialized under another language (e.g. German), Cockpit Tab 1 localizes (`Inicio`, `スタート`, `Iniciar`) because `TrackingTabsScreen.getControlTabTitle()` resolves `stringResource(R.string.tab_start)`, whereas Tabs 2–4 remain stuck in the initial persisted SQLite strings (`"Standard"`, `"Karte"`, `"Runden"`).
  * `TrackingViewsDatabaseManager.TrackingViewsDbHelper.onCreate()` (lines 1615–1628) persists `mContext.getString(R.string.text_default)`, `R.string.tab_power`, `R.string.tab_map`, and `R.string.tab_laps` directly into `ViewsTable.Name` at initial DB creation. `TrackingViewsRepository.toTrackingViewInfo()` reads `ViewsTable.Name` verbatim without re-resolving default tab names, and `TrackingTabsViewModel.trackingViews` (`stateIn(..., WhileSubscribed(5000))`) survives `Activity` recreation on locale configuration changes while `TrackingTabsScreen`, `TrackingTabPreviewHeader`, and `TrackingTabConfigHeader` render `view.name` directly.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*: Introduce `DefaultTrackingTabKey` & `TrackingTabTitleResolver` mapping all 9 supported languages' default tab titles (`R.string.text_default`, `R.string.tab_power`, `R.string.tab_map`, `R.string.tab_laps`) dynamically to the active locale without any SQLite schema migration; integrate resolution in `TrackingViewsRepository.toTrackingViewInfo()` (repository layer) AND Compose UI (`resolveTrackingTabTitle()` in `TrackingTabsScreen.kt`, `TrackingTabPreviewHeader.kt`, `TrackingTabConfigHeader.kt` via `stringResource(...)` so locale switches take effect immediately even across retained `ViewModel` state); add thorough JVM + Robolectric Compose + 9-language parity tests and live `emulator-5554` locale-switch verification (`Rule 8.5`).
  * *Out-of-Scope*: SQLite `ViewsTable` schema changes (`DB_VERSION` remains `22`), `TrackingViewsDatabaseManager.ensurePowerTabExistsForBikePower()` query signature (`BikePowerCockpitDefaultsAndGatingTest`), user-added numeric empty tab names (`addEmptyTabView` stores `newLayoutNr`), `WorkoutDetailTabConfig` (`WorkoutDetailTabsConfigSheet` already localizes presets), and `strings*.xml` edits (`Localization Parity: N/A - 0 new or modified UI strings`).
* **Chesterton's Fence / Impact**:
  * Preserves `TrackingViewsDatabaseManager.DB_VERSION = 22`, `DatabaseSchemaRegistry`, `BikePowerCockpitDefaultsAndGatingTest` (`addDefaultTab` & `ensurePowerTabExistsForBikePower` expectations), `TrackingTabConfigHeader` smooth-typing local state (`remember(viewInfo.tabViewId, currentLocale)`), user-renamed custom tab names (e.g., `"Intervalle"`, `"Race Cockpit"`), numeric empty tabs (`"4"`), existing `TrackingTabsScreen.kt <= 1,500` LoC ceiling (`1,459` baseline), and `0` string resource changes.
  * `SYS.2`/`SYS.3` impact: `NONE` (SWE presentation/repository localization fix linked to `SYSREQ-TRK-006`).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * Add a single shared `TrackingTabTitleResolver` (`DefaultTrackingTabKey`: `DEFAULT -> R.string.text_default`, `POWER -> R.string.tab_power`, `MAP -> R.string.tab_map`, `LAPS -> R.string.tab_laps`) in `com.atrainingtracker.trainingtracker.ui.tracking`:
    1. `resolveDefaultTabKey(persistedName: String?): DefaultTrackingTabKey?` maps any exact unmodified default tab title from any of the 9 supported locales (`en`, `de`, `es`, `fr`, `it`, `ja`, `nl`, `pl`, `pt`) to its `DefaultTrackingTabKey`, returning `null` for any custom user-renamed title or numeric title. Because the 4 sets across all 9 locales are mutually disjoint, lookup is `O(1)`, deterministic, idempotent, and handles both newly created tabs and legacy persisted SQLite rows with zero DB migration.
    2. `resolveTitle(context: Context, persistedName: String): String` resolves `context.getString(key.titleResId)` when `persistedName` matches a default key (falling back safely to `persistedName` if `getString` returns empty/throws in MockK unit tests), used by `TrackingViewsRepository.toTrackingViewInfo()`.
    3. `@Composable fun resolveTrackingTabTitle(name: String): String` resolves `stringResource(key.titleResId)` in `TrackingTabsScreen.kt`, `TrackingTabPreviewHeader.kt`, and `TrackingTabConfigHeader.kt`, guaranteeing immediate Compose recomposition on `LocalConfiguration` / Activity locale changes even when `TrackingTabsViewModel.trackingViews` (`WhileSubscribed(5000)`) is retained across configuration changes.
  * In `TrackingTabConfigHeader.kt`, initialize `localName` with `remember(viewInfo.tabViewId, currentLocale) { mutableStateOf(displayTitle) }` so entering config mode displays the active-locale title while preserving smooth typing and saving custom edits via `TrackingTabsViewModel.onUpdateTabName`.
* **SWE.2 Architecture / Files Touched**:
  * Production: `TrackingTabTitleResolver.kt` (new), `TrackingViewsRepository.kt`, `TrackingTabsScreen.kt`, `TrackingTabPreviewHeader.kt`, `TrackingTabConfigHeader.kt`.
  * Tests: `TrackingTabTitleResolverTest.kt` (new: 9-locale `LocalizationTestCache` parity, cross-locale matrix, custom title preservation, legacy SQLite + Robolectric Compose locale-switch UI verification).
  * `docs/architecture.md`: unchanged (no new subsystem/service/DB/prefix family).
