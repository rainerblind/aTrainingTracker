# Ticket Deliverable: ATT-9610 — SensorSourceDialog (ATT-9345 Follow-up): Order HR Active Backups and Not Connected sensors by health and modality priority

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-5910`

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**:
  * In `app/src/main/java/com/atrainingtracker/trainingtracker/ui/tracking/controltracking/SensorSourceDialog.kt` (lines 89–112), tapping `SensorType.HR` in `SensorStatus` opens `SensorSourceDialog` showing (1) **Active Primary Source** (already driven by `PrimaryHrSensorArbitrator` via `sensorSourceMapping[SensorType.HR]`), (2) **Active Backups**, and (3) **Not Connected**.
  * Both `activeBackups` and `notConnected` currently sort exclusively by `MySensorManager.getPriorityRank(sensorType, deviceType)` $\to$ `deviceName` $\to$ `id`. Because every Heart Rate monitor shares `DeviceType.HRM`, `MySensorManager.getPriorityRank(SensorType.HR, DeviceType.HRM)` returns the identical rank (`0`) for all HR sensors, collapsing `SensorSourceDialog` ordering to alphabetical `deviceName` (e.g. placing a disconnected or degraded optical `"Armband Optical"` ahead of an ECG `"Polar H10"` chest strap or an ANT+ HRM), diverging from `PrimaryHrSensorArbitrator` (`REQ-SET-126.3`, `ATT-9345`).
* **In-Scope / Out-of-Scope**:
  * *In-Scope*:
    * Reuse `PrimaryHrSensorArbitrator` (`resolveModality` and `resolveHealthTier`) by adding a shared persisted-metadata `resolveModality(protocol, deviceType, deviceName, manufacturer, macAddress, context)` overload and exposing `resolveHealthTier(...)` publicly in `PrimaryHrSensorArbitrator.kt`.
    * Propagate `btAddress` through `DeviceRawData` (`RawDeviceDataProvider.kt`, `DeviceData.kt`) so `raw2UiDeviceData` and `SensorSourceDialog` resolve persisted `HrModality` (including `PolarOfflineCapabilityStore` DIS/GATT metadata for renamed sensors) into `DeviceUiData.hrModality`.
    * Propagate live `hrHealthTier: HrHealthTier?` and `hrModality: HrModality?` from `PrimaryHrSensorArbitrator` through `DeviceTelemetry` in `BANALServiceRepository.kt`.
    * Extract pure internal sorting helpers in `SensorSourceDialog.kt` so when `sensorType == SensorType.HR`:
      * **Active Backups** order by `(healthTier [HEALTHY < DEGRADED < STALE_OR_NULL], modalityTier [ECG < ANT+ < Optical PPG < Other], deviceName, deviceId)`.
      * **Not Connected** order by `(modalityTier [ECG < ANT+ < Optical PPG < Other], deviceName, deviceId)` using persisted protocol/capability metadata.
      * Non-HR sensor types preserve `MySensorManager.getPriorityRank(sensorType, deviceType)` $\to$ `deviceName` $\to$ `deviceId` unchanged.
    * Add unit & Robolectric `createComposeRule()` tests covering ECG / ANT+ / Optical PPG / Other and Healthy / Degraded / Stale-or-Null HR ordering (including anti-alphabetical names like `"Armband Optical"` vs. `"Polar H10"`), plus live `emulator-5554` screenshot verification.
  * *Out-of-Scope*: Changing `PrimaryHrSensorArbitrator.selectBestHrSensor` arbitration rules (`REQ-SET-126.3`), modifying `MySensorManager.java` or BLE/ANT+ device drivers, changing `Devices.db` SQLite schema, or adding/modifying `strings*.xml` (`Localization Parity: N/A - 0 new or modified UI strings`).
* **Chesterton's Fence / Impact**:
  * Refines `REQ-UI-268.5` (`ATT-4375`) and aligns UI ordering with `REQ-SET-126.3` (`ATT-9345`) and `REQ-CON-049.4` (`PolarOfflineGattCoordinator.isPolarVeritySenseDevice`).
  * Preserves all non-HR sensor sorting (`SPEED_mps`, `LATITUDE`, `ALTITUDE`, `POWER`, `CADENCE`, `RADAR_THREAT_COUNT`), conditional dividers (`REQ-UI-2781`), altitude calibration (`REQ-TRK-047`), truthful `(verfügbar)` / `(nicht verbunden)` status rows (`REQ-UI-268`), `InterfaceSignatureDriftContractTest` pinned signatures on `BANALServiceRepository` (zero changed/removed methods; `DeviceTelemetry` and `DeviceUiData` add strictly optional defaulted parameters), and `SensorSourceDialog` public signature.
  * `SYS.2`/`SYS.3` impact: `NONE` (UI presentation & repository DTO projection reusing existing `PrimaryHrSensorArbitrator`).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * Rather than duplicating BLE/ANT+/Polar Verity Sense classification inside UI code, `PrimaryHrSensorArbitrator` becomes the single source of truth for both live `MyDevice` and persisted `DeviceRawData`/`DeviceUiData` modality resolution (`resolveModality(protocol, deviceType, deviceName, manufacturer, macAddress, context)`).
  * `BANALServiceRepository` computes `hrModality` and `hrHealthTier` for active devices carrying `SensorType.HR` using `PrimaryHrSensorArbitrator` on its 1-Hz telemetry snapshot, exposing them on `DeviceTelemetry` with default `null` values for full backward compatibility.
  * `RawDeviceDataProvider` reads `DevicesDbHelper.BT_ADDRESS` safely (`getSafeString`) into `DeviceRawData.btAddress` (without extra DB queries on `SELECT *` cursors and without breaking mock cursors that omit `BT_ADDRESS`), and `DeviceUiData` carries optional `hrModality: HrModality? = null` and `btAddress: String? = null` so renamed optical Polar sensors (`PolarOfflineCapabilityStore`) classify accurately even before connecting.
  * `SensorSourceDialog.kt` extracts `internal fun sortActiveBackupTelemetries(...)` and `internal fun sortNotConnectedDevices(...)` so both production rendering and unit/Compose tests execute the exact same comparator logic without duplicating code in tests.
* **SWE.2 Architecture / Files Touched**:
  * Production: `PrimaryHrSensorArbitrator.kt`, `DeviceData.kt`, `RawDeviceDataProvider.kt`, `BANALServiceRepository.kt`, `SensorSourceDialog.kt`.
  * Tests: `SensorSourceDialogPriorityTest.kt`, `SensorSourceDialogContractTest.kt`, `PrimaryHrSensorArbitratorTest.kt`.
  * Living Docs: `docs/requirements/req_ui_design_system_part6.md`, `docs/requirements/req_ui_design_system_part2.md` (`REQ-UI-268.5` note), `docs/tests/tst_ui_design_system_part3.md` (plus synced master indexes).
  * `docs/architecture.md`: unchanged (no new subsystem, service, DB, or prefix family).
