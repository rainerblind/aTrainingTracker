# Ticket Deliverable: ATT-9030 — Add collapsible metric scrubber graph and bidirectional position sync to full-screen workout map

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-68`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**: Full-screen workout map mode (`ATT-9029` / `REQ-MAP-069`) gives athletes an edge-to-edge geographic map with spatial and base-map layer toggles, but provides no way to scrub along the route telemetry or inspect effort metrics (Elevation, Heart Rate, Power, Speed/Pace, Cadence, Slope, W'bal, HRV) directly on the full-screen map. Furthermore, scrubbing position is currently local to `MapDetailLayout.kt` and neither initializes full-screen mode on open nor syncs back to Workout Details on close.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*:
    1. Collapsible bottom metric scrubber panel docked inside `FullScreenWorkoutMapContent` (reusing `ElevationProfile`, `TelemetryMetricGraph`, `PathPoint`, and `TelemetryChartGestures` primitives) with a **Collapse / Expand** toggle (collapsing leaves a minimal bottom pill for unobstructed map viewing and restores the graph on tap).
    2. **Dynamic Metric Selector**: Horizontal scrollable compact chip selector listing strictly metrics present in `activeScrubPath` (`Elevation`, `Heart Rate`, `Power`, `Speed`/`Pace`, `Cadence`, `Slope`, `W'bal`, `HRV DFA a1`, `HRV rMSSD`), defaulting to `Elevation` when present or else the first available stream, and hiding cleanly when no plottable telemetry stream exists.
    3. **Live Floating Scrub Readout Pill**: Centered directly above the expanded graph while a scrub position is selected, displaying `Distance · Time · Selected Metric` (including zone tag where configured) plus key available secondary context (`HR / Power / Elevation & Grade / Speed or Pace / Cadence` without duplicating the selected metric), synchronized 1:1 with the map position marker (`ATrainingTrackerMap` `ScrubMarkerLayer` + `ScrubberController`) and a subtle clear (`×`) action.
    4. **Bidirectional Scrub Position Sync** (`TrackOnMapScreen.kt`, `WorkoutDetailTabbedContent.kt`, `MapDetailLayout.kt`): Initialize full-screen scrub distance from Workout Details' current scrub position (rendering the marker and readout immediately on open), preserve drag-end scrub positions in full-screen (`clearSelectionOnDragEnd = false`), and propagate the final full-screen scrub distance back to Workout Details upon closing.
    5. 9-language localization parity in `app/src/main/res/values*/strings_workout_details.xml`.
  * *Out-of-Scope*: Adding new sensor columns or database schema migrations (e.g. ambient temperature is not stored on `PathPoint`), altering `MapDetailLayout`'s existing chart drag-end behavior (`clearSelectionOnDragEnd = true` default preserved), or modifying `MapScreenWithTrack`.
* **Chesterton's Fence / Impact**: Preserves `MapDetailLayout.kt` well below the `1,500` LoC monolith ceiling (`+10` LoC only for `onScrubDistanceChange`), preserves `LiveSegmentSheetContractTest`'s exact `LaunchedEffect(externalScrubDistance)` block verbatim, preserves `ElevationProfile` adaptive height invariant (`calculateElevationProfileHeight(range)`, `Design Guidelines §2.3` — zero hardcoded fixed height), preserves existing `FullScreenWorkoutMapOverlay` `bottomOverlay` slot compatibility (`ATT-9029`), and preserves `TelemetryChartGestures` default `clearSelectionOnDragEnd = true` for all existing charts. `SYS.2`/`SYS.3`: `Derived (SW-only)` refining `SYSREQ-TRK-004` (unchanged).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * **Modular Separation (`FullScreenWorkoutScrubberModels.kt` + `FullScreenWorkoutMapScrubberPanel.kt`)**: Keep pure metric availability resolution, default selection, altitude interpolation, and scrub readout formatting in `ui/map/FullScreenWorkoutScrubberModels.kt` (plain JVM unit-testable) and the Compose panel/readout UI in `ui/aftermath/FullScreenWorkoutMapScrubberPanel.kt` so `FullScreenWorkoutMapOverlay.kt` and `MapDetailLayout.kt` stay concise and cohesive.
  * **Persistent Drag-End Scrub Selection in Full-Screen (`clearSelectionOnDragEnd = false`)**: Existing `telemetryChartGestures` clears selection on drag-end (`onDistanceSelected(null)`) for stacked charts. Adding an opt-in `clearSelectionOnDragEnd: Boolean = true` parameter (default `true` preserving all existing charts) allows the full-screen scrubber to retain the athlete's final dragged position (e.g. `21.5 km`) when lifting their finger to inspect the map, read the floating pill, or tap Close (`X`) to sync `21.5 km` back to Workout Details.
  * **Consistent Distance X-Axis Domain**: On a GPS workout map, plotting all selectable scrubber metrics against `ProfileXAxisDomain.DISTANCE` aligns 1:1 with the physical route polyline so switching between `Elevation`, `Power`, and `Heart Rate` keeps the vertical scrub cursor anchored at the exact same horizontal coordinate.
  * **Adaptive Map Bottom Padding**: Update `ATrainingTrackerMap.contentPadding` with the measured bottom scrubber height when expanded (reverting to navigation-bar inset height when collapsed) so the Google watermark, initial `FIT_PRIMARY` bounds, and `ScrubberController` viewport clamping remain strictly above the docked scrubber panel.
  * **UI Guidelines Compliance**: `RoundedCornerShape(12.dp)` docked surface (`§5.3`), compact single-line scrollable metric chips (`maxLines = 1`, `softWrap = false`, `§5.6`), `44.dp+` collapse/expand touch targets, canonical `calculateElevationProfileHeight(range)` for `ElevationProfile` (`§2.3`), and Light/Dark/AMOLED `MaterialTheme.colorScheme` tokens (`§5.4`).
