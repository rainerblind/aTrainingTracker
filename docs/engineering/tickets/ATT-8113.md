# Ticket Deliverable: ATT-8113 — Schalter für Post-Workout ERTS-Glättung in EditDeviceDialog der Fused-Sensoren integrieren

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-166`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**: Post-workout Extended Rauch-Tung-Striebel (`ERTS`) smoothing (`REQ-FIL-017.5`, persisted under `TuningPreferencesDataStore.KEY_POST_WORKOUT_ERTS_SMOOTHING`, defaulting to `false`) is currently only configurable deep inside *Experteneinstellungen* (`AdvancedTuningScreen.kt` -> `SensorsGpsFilterSection.kt`). Athletes configuring either virtual ATT Fused sensor (`SpeedAndLocationDevice_ATTFused` / `DeviceType.SPEED_AND_LOCATION_ATT_FUSED` or `AltitudeAndSlopeDevice_ATTFused` / `DeviceType.ALTITUDE_AND_SLOPE_ATT_FUSED`) in `EditDeviceDialog.kt` have no direct toggle for post-workout ERTS smoothing where they expect sensor-fusion controls. In addition, `TuningPreferencesDataStore.updatePostWorkoutErtsSmoothingEnabled()` currently calls `dataStore.edit { ... }` instead of `editAndSync { ... }`, leaving a brief cache-sync window before `_tuningConfigStateFlow` (`getTuningConfig()`) reflects single-key updates.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*: Add a dedicated `PostWorkoutErtsSmoothingCard` toggle inside `EditDeviceDialog.kt` gated exclusively via `shouldShowPostWorkoutErtsToggle(deviceType)` to `DeviceType.SPEED_AND_LOCATION_ATT_FUSED` and `DeviceType.ALTITUDE_AND_SLOPE_ATT_FUSED`; stage draft changes in `EditDeviceViewModel.kt` (preserving `REQ-UI-2799.2` Save-only persistence, rotation survival, and Cancel zero-write invariants); persist to and observe `TuningPreferencesDataStore.KEY_POST_WORKOUT_ERTS_SMOOTHING` so changes sync bidirectionally with `AdvancedTuningScreen.kt` / `SensorsGpsFilterSection.kt` and `TrackerService.java`; upgrade `TuningPreferencesDataStore.updatePostWorkoutErtsSmoothingEnabled()` to `editAndSync`; reuse existing 9-language localized strings (`tuning_post_workout_erts_smoothing_title`, `tuning_post_workout_erts_smoothing_desc`); add unit & Compose UI tests (`EditDeviceDialogErtsSmoothingTest.kt`) and live emulator verification.
  * *Out-of-Scope*: No changes to ERTS Kalman/RTS math (`ExtendedRtsOdometrySmoother.kt`, `ExtendedRtsAltitudeSlopeSmoother.kt`, `ErtsPostWorkoutRecomputer.kt`), `TrackerService.java` finalization trigger, `Devices.db` schema, or existing `SensorsGpsFilterSection.kt` layout.
* **Chesterton's Fence / Impact**: Preserves `REQ-SEN-028.4` (4 guarded odometry source toggles), `REQ-FIL-016.5` (4 guarded altitude source toggles), `REQ-FIL-017.5` (`false` default & `KEY_POST_WORKOUT_ERTS_SMOOTHING` single source of truth), `REQ-UI-2799.2` (Save-only persistence / Cancel zero-write / rotation draft survival), `AndroidViewModelReflectionContractTest` (`EditDeviceViewModel(Application)` public constructor), and `ArchitectureConformanceContractTest` (`EditDeviceDialog.kt <= 2,004` LoC). `SYS.2`/`SYS.3`: `SYSREQ-TRK-003`, `SYSREQ-TRK-004` (unchanged).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  1. **Single Shared Card Below Input-Source Guards**: Render `PostWorkoutErtsSmoothingCard` (`OutlinedCard`, `RoundedCornerShape(12.dp)`, `surface` container, `outlineVariant` border, M3 `Switch` + title + summary) via `shouldShowPostWorkoutErtsToggle(data.deviceType)` directly after `AttFusedConfigSection` / `AttFusedAltitudeConfigSection`. This separates post-workout processing from live sensor input-source toggles, avoids duplicating UI across both Fused sections, and keeps `EditDeviceDialog.kt` well below the `2,004` LoC architecture cap.
  2. **Unified Persistence & Draft-Safe Sync**: `EditDeviceViewModel` injects an optional `tuningPreferencesDataStore: TuningPreferencesDataStore? = null` on its `internal constructor` (preserving all existing test call sites and the public `EditDeviceViewModel(Application)` constructor), observes `postWorkoutErtsSmoothingFlow` reactively into `postWorkoutErtsPersisted`, stages edits in `postWorkoutErtsDraft`, discards on `Cancel` (`discardDraft()`), and persists via `updatePostWorkoutErtsSmoothingEnabled(enabled)` on `Save` (`saveChanges()`). Upgrading `updatePostWorkoutErtsSmoothingEnabled()` to `editAndSync` guarantees immediate synchronous updates to `tuningConfigStateFlow`, `getTuningConfig()`, `postWorkoutErtsSmoothingFlow`, and `SettingsDataStoreJavaHelper.isPostWorkoutErtsSmoothingEnabled(context)`.
  3. **9-Language Localization Parity**: Reuses `R.string.tuning_post_workout_erts_smoothing_title` and `R.string.tuning_post_workout_erts_smoothing_desc` (already localized across all 9 supported languages: `en`, `de`, `es`, `fr`, `it`, `ja`, `nl`, `pl`, `pt`), ensuring identical terminology between `EditDeviceDialog` and *Experteneinstellungen* (`0` new/modified string resources required).
* **SWE.2 Architecture / Files Touched**:
  * Production: `app/src/main/java/com/atrainingtracker/trainingtracker/settings/TuningPreferencesDataStore.kt`, `app/src/main/java/com/atrainingtracker/banalservice/ui/devices/editdevice/EditDeviceViewModel.kt`, `app/src/main/java/com/atrainingtracker/banalservice/ui/devices/editdevice/EditDeviceDialog.kt`.
  * Tests: `app/src/test/java/com/atrainingtracker/banalservice/ui/devices/editdevice/EditDeviceDialogErtsSmoothingTest.kt`.
  * Living Docs: `docs/requirements/req_tracking_cockpit_part2.md`, `docs/tests/tst_tracking_cockpit_part2.md` (plus synced master indexes).
  * `docs/architecture.md`: No structural change (reuses existing `EditDeviceViewModel` and `TuningPreferencesDataStore` boundaries).
