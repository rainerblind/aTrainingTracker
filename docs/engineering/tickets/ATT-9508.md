# Ticket Deliverable: ATT-9508 — Workout Details: Respect configured tab section order for CHARTS and ELEVATION

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-68`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**:
  * Observed during PO on-device review (Pixel 10, build `5.0.0-dev-c9b5619a`) while testing `ATT-9066`: moving *Telemetrie-Diagramme* (`WorkoutDetailSectionType.CHARTS`) or *Höhenprofil* (`WorkoutDetailSectionType.ELEVATION`) in the Workout Details tab-outline editor (`WorkoutDetailTabsConfigSheet`) had no effect on rendered section order — both always rendered at the very top of the scrollable content (`ELEVATION` then `CHARTS`, above all other cards).
  * In `app/src/main/java/com/atrainingtracker/trainingtracker/ui/aftermath/WorkoutDetailTabbedContent.kt` (lines 318–326, 376–397, 464–493, 1090–1094), `nonMapNonGraphSections` filtered out `MAP`, `ELEVATION`, and `CHARTS`, passing only booleans `showElevationProfile = tabHasElevation` and `showTelemetryCharts = tabHasCharts` to `MapDetailLayout`, while `RenderWorkoutDetailCardSections` treated `ELEVATION` and `CHARTS` as no-ops. Inside `MapDetailLayout.kt` (lines 521–656), `ElevationProfile` and `TelemetryChartStack` were hardcoded at fixed top slots above `analyticsContent`.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*: Add an optional scoped slot `customLowerContent: (@Composable MapDetailLowerContentScope.() -> Unit)? = null` to `MapDetailLayout.kt` exposing `ElevationProfileSection(...)` and `TelemetryChartsSection(...)` bound to the single shared scrubbing/zoom/overlay/gesture-isolation state; update `WorkoutDetailTabbedContent.kt` (`MODE_A_CARD_SCROLL` and `MODE_B_SPLIT_MAP`) to iterate `orderedLowerSections = activeSections.filter { it != MAP && (it != ELEVATION || hasAltitudeData) }` in exact `tab.normalizedSections` order; add Robolectric Compose UI tests + Light/Dark PNG and live `emulator-5554` verification.
  * *Out-of-Scope*: `MAP` split-pane pinning at index `0` in `MODE_B_SPLIT_MAP` (`REQ-UI-408.3`, intentionally preserved), `WorkoutDetailTabsConfigSheet.kt` (already persists arbitrary non-`MAP` section order), legacy `TrackOnMapScreen` single-page fallback (`useTabbedLayout = false`), `RouteOnMapScreen`/`SegmentOnMapScreen`/`ClimbOnMapScreen`/`LiveSegmentSheet`/`WorkoutClusterHeatmapScreen` (`customLowerContent = null`), and `strings*.xml` (`Localization Parity: N/A - 0 new or modified UI strings`).
* **Chesterton's Fence / Impact**:
  * Preserves `MapDetailLayout` default backward compatibility (`customLowerContent = null`), `MAP` top split-pane pinning (`REQ-UI-408.3`), synchronized scrubbing (`selectedDistance` across Map, `ElevationProfile`, `TelemetryChartStack`, and `scrubbingOverlay`), shared zoom/pan viewport (`profileZoomScale`, `viewportStartFraction`, `isPanMode`), multi-sensor overlays, chart visibility toggles (`hiddenCharts`, `onToggleChartVisibility`), `HorizontalPager` region-aware & edge-gutter gesture isolation (`REQ-UI-408.4` / `ATT-5826`), offscreen share snapshot capture (`elevationLayer` / `REQ-REV-015`), `navigationBarsPadding()` (`Rule 41`), and file LoC limits (`<= 1,500` LoC per `ArchitectureConformanceContractTest`).
  * `SYS.2`/`SYS.3` impact: `NONE` (SWE UI rendering-order bugfix within existing `REQ-UI-408` architecture).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * Introduce `interface MapDetailLowerContentScope` in `MapDetailLayout.kt` with `ElevationProfileSection(modifier: Modifier = Modifier)` and `TelemetryChartsSection(modifier: Modifier = Modifier, applyLandscapeToolbarTopPadding: Boolean = false)` and an optional `customLowerContent: (@Composable MapDetailLowerContentScope.() -> Unit)? = null` parameter on `MapDetailLayout`.
  * Extract internal composable helpers inside `MapDetailLayout` so both the legacy path (`customLowerContent == null`) and the custom-ordered path (`customLowerContent != null`) share the exact same `ElevationProfile`, `TelemetryChartStack`, `chartInteractiveTouchDetector`, scrubbing state (`selectedDistance`), zoom/pan viewport (`profileZoomScale`, `viewportStartFraction`, `isPanMode`), and multi-sensor altitude overlay state with zero duplication.
  * In `customLowerContent != null`, wrap the ordered lower column in `Surface(Modifier.fillMaxWidth().navigationBarsPadding())` recorded by `elevationLayer` (preserving share snapshots and Rule 41 bottom inset clearance) and keep `lowerColumn`'s `PointerEventPass.Initial` reset (`onInteractiveCanvasTouch(false)`) so card sections allow `HorizontalPager` swiping while child `chartInteractiveTouchDetector` plot areas continue to isolate horizontal scrubbing (`PointerEventPass.Initial` runs top-down).
  * In `WorkoutDetailTabbedContent.kt`, pass `orderedLowerSections` through a single deduplicated `RenderWorkoutDetailCardSections(..., lowerContentScope = this)` call in `MODE_B_SPLIT_MAP` and `MODE_A_CARD_SCROLL`, passing `applyLandscapeToolbarTopPadding = (sectionIndex == 0)` for `CHARTS` so landscape's floating `GlobalTelemetryZoomToolbar` never overlaps `ChartVisibilityHeaderBar` when `CHARTS` is ordered first.
* **SWE.2 Architecture / Files Touched**:
  * Production: `app/src/main/java/com/atrainingtracker/trainingtracker/ui/map/MapDetailLayout.kt`, `app/src/main/java/com/atrainingtracker/trainingtracker/ui/aftermath/WorkoutDetailTabbedContent.kt`.
  * Tests: `app/src/test/java/com/atrainingtracker/trainingtracker/ui/aftermath/WorkoutDetailSectionOrderUiTest.kt` (new behavioral Compose UI + scrubbing + Light/Dark PNG verification).
  * `docs/architecture.md`: unchanged (no new subsystem/service/DB/prefix family).
