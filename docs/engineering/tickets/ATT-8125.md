# Ticket Deliverable: ATT-8125 — PeriodsScreen, EditDeviceDialog & BottomSheets: Legacy-Fragment-Overlay, Komma-Locale-Eingabe & doppelte Window-Insets beheben

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-8119`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**:
  1. **Legacy Fragment Overlay in `PeriodsScreen.kt` (`PeriodsScreen.kt:90-149`)**: While `ATrainingTrackerApp.kt:383-387` wires `onStartWorkoutList` for period-level Compose navigation (`MainActivityWithNavigation.startWorkoutSummaryListFromPeriod` -> `NavRoutes.workouts(pushed = true)`), `handleDayClick` bypasses `onStartWorkoutList` and executes `(context as? FragmentActivity)?.supportFragmentManager?.beginTransaction()?.add(android.R.id.content, WorkoutSummariesListFragment.newInstance(...))?.addToBackStack(null)?.commit()`, sticking a legacy `Fragment` directly over the Compose `NavHost` root (and the unused fallback in `handleStartWorkoutList` repeats the same `android.R.id.content` transaction).
  2. **Rotation Data Loss, Broken `de_DE` Comma Decimal Input & Immediate Persistence Ignoring `Cancel` in `EditDeviceDialog` (`EditDeviceDialog.kt`, `EditDeviceViewModel.kt`, `DevicesTabbedScreen.kt:105`)**:
     * `DevicesTabbedScreen.kt:105` holds `editingDeviceId` in `remember` instead of `rememberSaveable`, and `EditDeviceDialog.kt:91-93` calls `viewModel.loadInitialDeviceData(deviceId)` unconditionally on every `LaunchedEffect(deviceId)` recreation, overwriting dirty unsaved user edits in `_deviceSnapshot` across configuration changes.
     * `RunCalibrationFactorContent` (`EditDeviceDialog.kt:613-621`) formats the calibration factor with `Locale.getDefault()` (producing `"1,0000"` in `de_DE`) while parsing keystrokes via `it.toDoubleOrNull()` (which rejects `','` and returns `null`, discarding edits); `CorrectCalibrationDialog` (`EditDeviceDialog.kt:664-665`) has the identical `toDoubleOrNull()` comma bug.
     * `AttFusedConfigSection` (`EditDeviceDialog.kt:969-1020`) and `AttFusedAltitudeConfigSection` (`EditDeviceDialog.kt:1137-1188`) write immediately to `AttFusedPreferences` / `AttFusedAltitudePreferences` on toggle click (and lose local `remember` state on rotation); `EditDeviceViewModel.resetTirePressureBaseline()` (`EditDeviceViewModel.kt:390-407`) immediately writes to `Devices.db` and `Equipment.db`; `RadarLightControlSection` (`EditDeviceDialog.kt:1299-1300`) immediately calls `RadarLightController.setAutoMode()` / `setManualLightMode()` (writing `TuningPreferencesDataStore`) — all bypassing `Save`/`Cancel`.
  3. **Duplicate / Missing Window Insets in BottomSheets (`ATrainingTrackerApp.kt:788-793`, `FilterBottomSheetScaffold.kt:93-97`)**:
     * `ATrainingTrackerApp.kt:792` applies `modifier = Modifier.windowInsetsPadding(WindowInsets.ime.union(WindowInsets.navigationBars))` on the outer `ModalBottomSheet` hosting all 10 Settings dialogs, every one of which already renders `AppBottomSheetContent` -> `AppBottomSheetBody` with `.navigationBarsPadding().imePadding()` (`AppModalBottomSheet.kt:201-206`), causing doubled bottom inset spacing.
     * Conversely, `FilterBottomSheetScaffold.kt:93-97` applies only `.navigationBarsPadding()` without `.imePadding()`, so the soft keyboard obscures text inputs in filter sheets (`WorkoutFilterBottomSheet`, `RouteFilterBottomSheet`, `SegmentFilterBottomSheet`, `ClusterFilterBottomSheet`, `KnownLocationsFilterBottomSheet`, `DeviceFilterBottomSheet`).
* **In-Scope / Out-of-Scope**:
  * *In-Scope*: Pure Compose day-click routing via `onStartWorkoutList` & removal of `FragmentActivity`/`WorkoutSummariesListFragment`/`android.R.id.content` from `PeriodsScreen.kt`; rotation-safe dirty-draft preservation in `EditDeviceViewModel` + `rememberSaveable` for `editingDeviceId` in `DevicesTabbedScreen.kt` + fresh reload on reopen/clean state (`TST-UI-216.3`); local text buffer supporting `.` and `,` in `RunCalibrationFactorContent` & `CorrectCalibrationDialog`; staging ATT Odometry Fusion, ATT Altitude Fusion, TPMS baseline reset, and `EditDeviceDialog` Radar tail light edits in `EditDeviceViewModel` draft state (persisting strictly on `saveChanges()`, discarding cleanly on `Cancel`/`discardDraft()`); removing duplicate outer `windowInsetsPadding` in `ATrainingTrackerApp.kt:792` and adding `.imePadding()` in `FilterBottomSheetScaffold.kt`; behavioral Compose UI & ViewModel tests and `Rule 8.5` Light/Dark PNG + `emulator-5554` verification.
  * *Out-of-Scope*: Legacy `PeriodsFragment.kt` (`TST-PER-009`), `RadarLightQuickSwitchSheet` live cockpit quick-switch (intentionally immediate without Save/Cancel), Fused sensor UI toggle expansions (`ATT-8112`/`ATT-8113`), DB schema changes, and `strings*.xml` (`Localization Parity: N/A - 0 new or modified UI strings`).
* **Chesterton's Fence / Impact**:
  * Preserves `TST-UI-216.3` (`DeviceDataRepositoryEquipmentSyncTest`: unedited/reopened `loadInitialDeviceData(deviceId)` still fetches fresh DB snapshot while dirty in-session edits survive rotation via `hasUnsavedChanges` guard + `discardDraft()` on dismiss).
  * Refines `REQ-CON-031.5` (`ATT-7540`) and `REQ-SEN-033.2` (`ATT-8422`) strictly inside `EditDeviceDialog` (which has explicit `Save`/`Cancel` buttons): radar tail light mode and TPMS baseline reset are staged in `EditDeviceViewModel` draft state until `saveChanges()` and discarded with zero persistence on `Cancel`, while preserving `RadarLightQuickSwitchSheet` immediate cockpit dispatch, `RadarLightController` hardware/DataStore behavior on Save, and `EditDeviceDialog.kt <= 2,004` LoC (`ArchitectureConformanceContractTest`) + `EditDeviceViewModel(Application)` reflection constructor (`AndroidViewModelReflectionContractTest`).
  * `SYS.2`/`SYS.3` impact: `NONE` (SWE UI navigation, dialog state & inset bugfix).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * **Part 1 (`PeriodsScreen.kt`)**: Extract `internal fun buildDayPeriodSummary(date, sport, activity, locale, zoneId)` and route `handleDayClick` through `onStartWorkoutList?.invoke(daySummary, sport, activity.workoutIds.firstOrNull())`. `ATrainingTrackerApp` forwards to `activity.startWorkoutSummaryListFromPeriod(...)` -> `WorkoutFilterCriteria(startDateS = dayStartS, endDateS = dayEndS, bSportType = sport)` + `navController.navigate(NavRoutes.workouts(pushed = true))`, where `WorkoutSummariesTabbedScreen` already provides `BackHandler { onBackClick() }` clearing contextual filter criteria and popping back cleanly to `Periods`. Remove all `FragmentActivity` / `WorkoutSummariesListFragment` / `android.R.id.content` code from `PeriodsScreen.kt`.
  * **Part 2 (`EditDeviceViewModel.kt`, `EditDeviceDialog.kt`, `DevicesTabbedScreen.kt`)**:
    * Guard `loadInitialDeviceData(deviceId)` to return early when `_editingId.value == deviceId && _deviceSnapshot.value != null && hasUnsavedChanges`, preserving unsaved edits across rotation while keeping fresh DB reloads on clean/reopened dialogs (`TST-UI-216.3`) and `discardDraft()` on Cancel/dismiss. Switch `editingDeviceId` in `DevicesTabbedScreen.kt:105` to `rememberSaveable`.
    * Add `internal fun parseLocaleDecimal(input: String): Double?` (trimming and normalizing `','` -> `'.'`, rejecting non-finite/invalid text) and `internal fun formatCalibrationFactor(value: Double?, locale: Locale): String`, backed by a `rememberSaveable` local text buffer in `RunCalibrationFactorContent` (synced only when parsed numeric value differs from external updates like `CorrectCalibrationDialog`, which also uses `parseLocaleDecimal`).
    * Stage `AttFusedDraftConfig`, `AttFusedAltitudeDraftConfig`, `pendingBaselineResetCircumferenceMm`, and `RadarLightDraftSelection` in `EditDeviceViewModel` `StateFlow`s; mutate them only in memory during editing (`hasUnsavedChanges = true`); persist atomically inside `saveChanges()` (`devicesRepository.updateDevice`, `AttFusedPreferences`, `AttFusedAltitudePreferences`, `devicesRepository.resetTirePressureBaseline` + `equipmentRepository.recordManualBaselineResetForDevice`, `RadarLightController.setAutoMode` / `setManualLightMode`); discard cleanly with zero writes in `discardDraft()`.
  * **Part 3 (`ATrainingTrackerApp.kt`, `FilterBottomSheetScaffold.kt`)**:
    * Remove outer `modifier = Modifier.windowInsetsPadding(WindowInsets.ime.union(WindowInsets.navigationBars))` on `ModalBottomSheet` in `ATrainingTrackerApp.kt:792` so all 10 `AppBottomSheetContent` settings dialogs apply `navigationBarsPadding().imePadding()` strictly once inside `AppBottomSheetBody`.
    * Add `.imePadding()` alongside `.navigationBarsPadding()` on the root `Column` in `FilterBottomSheetScaffold.kt` (extracting `internal fun FilterBottomSheetBody(...)` for direct Compose UI + IME inset testing while preserving all `BottomSheetDesign` tokens checked by `BottomSheetVisualContractTest` and `ClusterItemAndFilterPolishTest`).
* **SWE.2 Architecture / Files Touched**:
  * Production: `PeriodsScreen.kt`, `EditDeviceViewModel.kt`, `EditDeviceDialog.kt`, `DevicesTabbedScreen.kt`, `ATrainingTrackerApp.kt`, `FilterBottomSheetScaffold.kt`.
  * Tests: `PeriodsScreenComposeNavigationTest.kt` (new), `EditDeviceDialogDraftLocaleRotationTest.kt` (new), `BottomSheetInsetsComposeTest.kt` (new), `EditDeviceViewModelTest.kt`, `EditDeviceWheelCircumferenceTest.kt`.
  * `docs/architecture.md`: unchanged (no new subsystem, service, DB, or prefix family).
