## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause** (verified against Pixel 10 screenshot `docs/attachments/att8733_device_screenshot.png` and `RadarEdgeOverlay.kt`):
  1. **V1 / Simulator Motorcycle Icon (`RadarEdgeOverlay.kt:442-449`)**: `resolveFullScreenVehicleVisualSpec()` maps `VehicleSizeCategory.UNKNOWN_OR_LIGHT` to `Icons.Filled.TwoWheeler`. Because BLE V1 (`BTLERadarDevice.parseV1ThreatPacket`), ANT+ (`ANTBikeRadarDevice`), and V1 simulator scenarios default targets to `UNKNOWN_OR_LIGHT`, approaching cars render as motorcycles.
  2. **Undersized Badges & Distance Typography (`RadarEdgeOverlay.kt:442-466`)**: Current `54×26` / `60×28` / `70×32 dp` capsules with `11–13.sp` labels (`80m`, `123m`) are visually dwarfed by cockpit tiles (`21,6 km/h`, `78 bpm`, `232 W`) and fail glanceable handlebar legibility.
  3. **Unconditional 3-Lane Dashed Guides in V1 Mode (`RadarEdgeOverlay.kt:520`)**: `RadarFullScreenThreatOverlay` unconditionally composes `RadarFullScreenLaneGuides` across all cockpit tiles even when `!has2DData` (V1 / 1D range-only streams carry no lateral offset).
  4. **Red ↔ Orange Color Oscillation (`RadarEdgeOverlay.kt:313-326`, `:615-626`, `:748` + V1 1m quantization)**: Two compounding causes: (a) `RadarFullScreenVehicleMarker` alpha-pulses `FAST_APPROACHING` fill down to `0.65f + 0.35f * pulseAlpha` (`0.79f`) over warm yellow/light cockpit cards (and `RadarStatusBadgePill` drops to `0.4f`), blending crimson red toward orange/pink; and (b) 1m-quantized 8-Hz V1 packets (`BTLERadarDevice.parseV1ThreatPacket` `dr/dt >= 15 m/s`) for a ~12 m/s vehicle alternate `dr = 1m (8 m/s -> APPROACHING)` and `dr = 2m (16 m/s -> FAST_APPROACHING)` frame-to-frame, flickering markers and the status badge between amber and red without UI threat-level hysteresis.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*:
    1. Map `VehicleSizeCategory.UNKNOWN_OR_LIGHT` to `Icons.Filled.DirectionsCar` (keeping `CAR` as `Icons.Filled.DirectionsCar`, `TRUCK_OR_BUS` as `Icons.Filled.LocalShipping`, removing `Icons.Filled.TwoWheeler`).
    2. Enlarge full-screen marker capsules & typography to handlebar-legible cycling-safety dimensions (`UNKNOWN_OR_LIGHT`: `92×42 dp` / `24.dp` icon / `18.sp`; `CAR`: `100×46 dp` / `26.dp` icon / `19.sp`; `TRUCK_OR_BUS`: `114×52 dp` / `28.dp` icon / `21.sp`; stadium capsule `RoundedCornerShape(percent = 50)`, `2.dp` dark scrim + `1.5.dp` crisp white border) while preserving `.layout` bounds clamping and zero clipping for 2- and 3-digit distances (`15m`, `128m`, `160m`).
    3. Gate `RadarFullScreenLaneGuides` strictly on `RadarOverlayMath.hasFullScreen2DLateralData(radarState)` (`false` in V1 / ANT+ 1D mode; `true` when genuine 2D lateral offsets / non-`UNKNOWN` lanes are present).
    4. Render full-screen vehicle markers and full-screen status badge at 100% solid opaque fill (`alpha = 1.0f`, zero alpha-pulse translucency blending over light/warm cards) AND apply per-target UI threat-level hysteresis (`RadarOverlayMath.stepThreatHysteresis`: immediate initial level, `3` consecutive frames to escalate `APPROACHING -> FAST_APPROACHING`, `4` consecutive frames to de-escalate `FAST_APPROACHING -> APPROACHING`, departed-target pruning) driving both full-screen markers and the full-screen status badge consistently.
  * *Out-of-Scope*: Modifying BLE/ANT+ wire parsers (`BTLERadarDevice.java`, `ANTBikeRadarDevice.kt`, `tier-a` boundary), `RadarAlertManager`, or `LEFT`/`RIGHT` `RadarVerticalRail` dot geometry (`REQ-TRK-073.2`).
* **Chesterton's Fence / Impact**: Refines `REQ-TRK-089` / `TST-TRK-089` (`ATT-8733`) directly per ASPICE `TRB-02` audit guidance, preserving `REQ-TRK-062.3` 100% touch pass-through (`HorizontalPager`, `GoogleMap`, edge back gestures), `ATT-8679` clear-road badge suppression, `REQ-TRK-073.2` edge-rail geometry, centralized `Color.kt` tokens, `private` `@Preview` visibility, `RadarEdgeOverlay.kt <= 1,500` LoC, and 9-locale parity (`0` string edits). `SYS.2`/`SYS.3`: `SYSREQ-TRK-004` (unchanged).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * **Neutral Car Icon for `UNKNOWN_OR_LIGHT`**: Using `Icons.Filled.DirectionsCar` matches cycling-radar reality where V1/ANT+ sensors cannot distinguish vehicle size and almost all approaching road threats are cars, while distinct scaling (`92×42` < `100×46` < `114×52 dp`) and `Icons.Filled.LocalShipping` keep V2 heavy vehicles unmistakably differentiated.
  * **Glanceable Stadium Capsule Geometry**: Scaling font sizes to `18–21.sp` bold tabular numerals (`tnum`) and heights to `42–52.dp` with `RoundedCornerShape(percent = 50)` makes distance pills comparable in visual weight to cockpit metric labels while staying well under half a 360dp viewport width (`~100–120 dp` total width with scrim) so multi-lane targets remain unclipped via existing single-pass `.layout` clamping.
  * **2D-Gated Lane Guides (`hasFullScreen2DLateralData`)**: Suppresses the 3 vertical dashed lines for V1 BLE, V1 simulator (`lateralOffsetMeters == null && laneState == LaneState.UNKNOWN`), and 1D ANT+ (`source == RadarSource.ANT_PLUS` with only default `IN_RIDER_LANE`/`0.0f` center targets), drawing guides only when genuine lateral lane data is present.
  * **Dual Anti-Oscillation (Opaque Fill + Per-Target Frame Hysteresis)**: Eliminating fill alpha modulation in `FULL_SCREEN` mode prevents red-over-yellow blending shifts AND skips unnecessary `rememberInfiniteTransition` wakeups in full-screen mode; pairing it with a pure, identity-guarded `RadarOverlayMath.stepThreatHysteresis()` tracker stops single-frame / alternating 8-Hz `APPROACHING ↔ FAST_APPROACHING` flicker while preserving zero-latency Frame-1 rendering and fast `~250ms` confirmation of sustained high-speed escalation.
* **SWE.2 Architecture / Files Touched**:
  * Production: `app/src/main/java/com/atrainingtracker/trainingtracker/ui/tracking/radar/RadarEdgeOverlay.kt` (no new strings, no `Color.kt` changes needed).
  * Tests: `app/src/test/java/com/atrainingtracker/trainingtracker/ui/tracking/radar/RadarEdgeOverlayTest.kt`.
