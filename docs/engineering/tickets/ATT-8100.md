# Ticket Deliverable: ATT-8100 — Strava Photo Download: Fetch & Import Activity Photos via Strava API v3 (with Strava Settings Option)

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-597`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**: `StravaBulkExportImporter.importActivityPhotos` (`migration/StravaBulkExportImporter.kt`) already imports photos from offline Strava bulk ZIP exports into `WorkoutPhotoManager`, but live API-based photo fetching during `StravaUploader` sync/upload (`exporter/uploader/StravaUploader.kt`) does not exist yet. Furthermore, `StravaActivityParser.minimize()` (`ui/aftermath/StravaActivityData.kt`) strips all third-party `photos` / `photo_count` fields before storing `StravaActivityData` in `StravaUpload.db`, and `StravaSettingsDialog` (`ui/settings/strava/StravaSettingsDialog.kt`) exposes no user setting to opt in to Strava activity photo downloads.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*: Add opt-in preference `downloadStravaPhotos` (`StravaPhotoPreferences.kt`, `prefs_strava.xml`, default `false`) and localized toggle in `StravaSettingsDialog` across all 9 `values*/strings_export.xml` locales; parse Strava photo metadata (`GET /api/v3/activities/{id}/photos?size=2048&photo_sources=true` + `photos_summary` fallback) in `StravaActivityParser`; download & register photos into `WorkoutPhotoManager.getWorkoutPhotosDir(context, workoutId)` + `workout_photos` SQLite table during `StravaUploader.doUpdate` when enabled (with EXIF, timestamp, `[lat, lng]` / trackpoint interpolation, Null-Island rejection, and pre-/post-download deduplication); refresh UI photo strips on export status update; preserve strict privacy discard when disabled; add comprehensive unit/Compose/parity tests.
  * *Out-of-Scope*: Background periodic polling of unrelated historical Strava activities (`athlete/activities`), uploading local photos *to* Strava (unsupported by Strava API v3), SQLite schema changes (`workout_photos` table already exists in v27+), or modifying `StravaActivityParser.minimize()` v2 schema (`REQ-EXP-013`).
* **Chesterton's Fence / Impact**: Preserves `REQ-EXP-013` (`StravaActivityParser.minimize()` continues discarding `"photos"`/`"photo_count"`/`"total_photo_count"` from `StravaUpload.db` v2 JSON; existing `StravaActivitySectionTest` invariants untouched), `REQ-EXT-011.5` (`StravaUploader` `Bearer` token guard; CDN photo downloads omit Strava `Authorization` header), and `REQ-DAT-038` / `REQ-UI-448.4` (`GeoUtils.isValidGpsCoordinate` Null-Island guard and trackpoint interpolation). `SYS.2`/`SYS.3`: `SYSREQ-DEX-003` (unchanged).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * Keep `downloadStravaPhotos` opt-in (`default = false`) so existing privacy behavior (`REQ-EXP-013`) and existing `StravaUploader` tests remain unaffected unless enabled by the athlete.
  * Parse Strava API v3 photo JSON (`/activities/{id}/photos` array and `photos.primary` summary fallback) strictly in-memory in `StravaActivityParser` (`StravaActivityData.kt`), selecting highest-resolution `https://`-only URLs (rejecting cleartext `http://` and non-HTTPS schemes) and validating `[lat, lng]` via `GeoUtils.isValidGpsCoordinate`.
  * Centralize shared file-to-DB photo registration (EXIF extraction, fallback timestamp, coordinate fallback & trackpoint interpolation, Null-Island guard) in `WorkoutPhotoManager.registerPhotoFile(...)` and add `WorkoutPhotoManager.importStravaPhotos(...)` with HTTPS defense-in-depth, 30s per-call timeout (`httpClient.newBuilder().callTimeout(...)`), `uniqueId` + canonical-path traversal guard, `image/*` `Content-Type` verification, and two-stage deduplication: (1) pre-download filename (`strava_<id>.*` / `<id>.*`) & pre-existing local capture timestamp proximity (`<= 2,000 ms`), and (2) post-download SHA-256 content digest & EXIF timestamp proximity against existing local photos.
  * Invoke photo download non-fatally in `StravaUploader.doUpdate` when `StravaPhotoPreferences.isDownloadEnabled(mContext)` is `true`, skipping the `/photos` API request if `activityJSON` explicitly reports `total_photo_count == 0` and `photo_count == 0` and empty `photos` summary.
* **SWE.2 Architecture / Files Touched**:
  * Production: `StravaPhotoPreferences.kt`, `StravaSettingsDialog.kt`, `prefs_strava.xml`, `StravaActivityData.kt`, `WorkoutPhotoManager.kt`, `StravaUploader.kt`, `WorkoutDetailTabbedContent.kt`, `WorkoutSummary.kt`, 9× `values*/strings_export.xml`.
  * Tests: `StravaPhotoDownloadTest.kt`, `StravaSettingsDialogComposeTest.kt`, `StravaSettingsDialogContractTest.kt`, `WorkoutPhotoManagerTest.kt`, `StravaUploader*`, `StravaActivitySectionTest.kt`, `TranslationParityTest.kt`.
  * Living Docs: `docs/requirements/req_data_migration_export_part2.md` (`REQ-EXP-050`), `docs/tests/tst_data_migration_export.md` (`TST-EXP-050`).

## 4. Implementation Plan
1. Add `SP_DOWNLOAD_STRAVA_PHOTOS = "downloadStravaPhotos"` (default `false`), `isDownloadEnabled(context)`, and `setDownloadEnabled(context, enabled)` in `StravaPhotoPreferences.kt`, plus matching `CheckBoxPreference` in `prefs_strava.xml`.
2. Add 9-language localized strings (`strava_activity_photos_section`, `strava_download_photos_title`, `strava_download_photos_desc`) to all 9 `values*/strings_export.xml` files and expose the staged toggle in `StravaSettingsDialog.kt`.
3. Add `StravaActivityPhoto`, `StravaActivityParser.parseActivityPhotos(...)`, `parsePhotosSummary(...)`, and `hasZeroPhotosHint(...)` in `StravaActivityData.kt` while keeping `minimize()` strictly compliant with `REQ-EXP-013`.
4. Add `WorkoutPhotoManager.registerPhotoFile(...)` and `WorkoutPhotoManager.importStravaPhotos(...)` in `WorkoutPhotoManager.kt` with EXIF/timestamp/coordinate fallback + Null-Island guard and pre-/post-download deduplication (ID/filename, SHA-256 hash, timestamp proximity).
5. Wire `getStravaActivityPhotos(...)` and `downloadAndImportStravaPhotos(...)` into `StravaUploader.kt` (`doUpdate`) gated by `StravaPhotoPreferences.isDownloadEnabled(mContext)`, and add `workoutData.exportStatuses` refresh key in `WorkoutDetailTabbedContent.kt` and `WorkoutSummary.kt`.
6. Write unit + Robolectric Compose UI tests (`StravaPhotoDownloadTest.kt`, `StravaSettingsDialogComposeTest.kt`), run targeted tests + `TranslationParityTest`, capture & inspect `emulator-5554` screenshot, promote `REQ-EXP-050`/`TST-EXP-050` to `[Verified]`, and run `verify_requirement_governance.py` + `auto_gate.py --write-bundle --advance-jira`.
