## 1. Problem Domain, Scope & Impact Analysis

### 1.1 Background & Root Cause
- Prior to `ATT-8999` (`REQ-STB-020`), `TrackerService` dispatched `WORKOUT_UPDATED_INTENT` at 1 Hz during active and paused tracking, triggering `WorkoutRepository.refreshSingleWorkout` SQLite queries and cloning the entire `_allWorkouts` list (up to 2,200+ workouts) every second — causing severe GC pressure, `PeriodsRepository` / `AthleteProfileViewModel` / `KnownLocationsViewModel` recalculation storms, and OOM crashes.
- `ATT-8999` eliminated the 1-Hz broadcast storm via `LiveWorkoutBroadcastTracker`, restricting `WORKOUT_UPDATED_INTENT` strictly to discrete lifecycle edges (start/resume, pause/resume edge, lap, sport change, stop).
- As a deliberate consequence of eliminating 1-Hz `_allWorkouts` churn, when a user opens **Workout Summaries** while a workout is actively recording, the unfinished greyed-out active workout card displays frozen start-of-session metrics (e.g., `00:00`, `0.00 km`) until tracking stops or a discrete edge occurs.

### 1.2 Invariants & Scope Boundaries
- **Strict Zero-OOM Invariant (`REQ-STB-020` / `ATT-8999`)**:
  - `0` SQLite reloads per 1-Hz tick.
  - `0` 1-Hz `WORKOUT_UPDATED_INTENT` broadcasts.
  - `0` `_allWorkouts` emissions, list clones, or element mutations during live ticks.
  - `0` downstream recalculations in `PeriodsRepository`, `AthleteProfileViewModel`, or `KnownLocationsViewModel`.
- **Parallel-Lane Isolation**: Zero edits to `TrackerService.java` (currently held near its LoC ceiling by parallel Lane 1 work). All live state hooks attach cleanly in 100% Kotlin at existing per-tick and lifecycle-edge boundaries already invoked by `TrackerService`:
  - `LiveWorkoutBroadcastTracker.onSessionInitialized` / `onPauseStateTick` / `reset`
  - `WorkoutRepository.recordLiveSample` / `updateWorkoutTotalTime` / `saveLap` / `markWorkoutFinished` / `markWorkoutFinishedBlocking`
- **Card-Scoped Compose Collection**:
  - Only unfinished cards (`!workoutData.finished`) whose `id` matches the active snapshot collect live updates via `collectAsStateWithLifecycle`.
  - Finished cards (`finished == true`) never subscribe and never recompose.
  - Non-matching unfinished cards receive `distinctUntilChanged()`-filtered `null` and never recompose.
  - Off-screen/backgrounded Workout Summaries stop collecting automatically via lifecycle awareness.
- **No Unwanted Scope Creep**: Tracking Dashboard (`LiveWorkoutData` / `BANALService`), historical workout persistence, and `TrackerService.java` remain untouched.

## 2. SWE.2 Architecture & Design Decisions

### 2.1 Dedicated O(1) In-Memory State Channel (`LiveWorkoutCardStateStore.kt`)
- Introduce `@Immutable data class LiveWorkoutCardSnapshot`:
  - `workoutId: Long`
  - `activeTimeSec: Long?`, `totalTimeSec: Long?`
  - `distanceM: Double?`, `avgSpeedMps: Double?`
  - `ascentM: Long?`, `descentM: Long?`
  - `avgHeartRateBpm: Double?`, `avgPowerWatts: Double?`, `avgCadenceRpm: Double?`
  - `laps: List<LapData>`
  - `isPaused: Boolean`
- Nullable scalar fields prevent a paused/resumed session from flashing `00:00` / `0.00 km` before the first active tick arrives: any `null` field cleanly falls back to the card's persisted `WorkoutData` value.
- `class LiveWorkoutCardStateStore` (with `companion object { val Default = LiveWorkoutCardStateStore(); val snapshot: StateFlow<LiveWorkoutCardSnapshot?> }`):
  - **Lifecycle gating**: `onSessionStarted(workoutId, isPaused)` arms `activeSessionWorkoutId = workoutId`; `clear()` resets `activeSessionWorkoutId = -1L` and emits `null`. Repository hooks check `activeSessionWorkoutId == workoutId` so queued `mDbExecutor` writes draining after `handleActionStop` (`mBroadcastTracker.reset()`) can never resurrect a cleared snapshot, and non-live DB writes (historical lap splits, imports) never pollute the channel.
  - **O(1) running sensor averages**: Maintains constant-memory `(sum, count)` accumulators for `HR`, `POWER`, and `CADENCE` updated from 1-Hz `samplingValues` and periodically resynced from authoritative `ExtremaUpdate(type, ExtremaType.AVG, value, _, count)` when `count > 0` (preserving pre-resume continuity on resumed workouts).
  - **Lap merging**: `onLapSaved(workoutId, lap)` updates or appends by `lapNr` in O(L) where L is the small active-session lap count, deduplicating cleanly against any laps already in `WorkoutData.laps`.

### 2.2 Pure Overlay Transformation & Card-Scoped Compose Collection
- `applyLiveSnapshot(workoutData, snapshot, extremaLabels, formatters)`:
  - Short-circuits and returns `workoutData` by reference when `snapshot == null || workoutData.finished || snapshot.workoutId != workoutData.id`.
  - Overlays scalar metrics (`activeTimeSec`, `totalTimeSec`, `totalDistance`, `avgSpeedMps`, `ascentMeters`, `descentMeters`), merges `laps` deduplicated by `lapNr`, and updates/appends `ExtremaDataRow` averages for `HR`, `SPEED_mps`, derived `PACE_spm` (for `BSportType.RUN`), `POWER`, and `CADENCE` using canonical `SensorType.*.myFormatter` / `MetricFormatterContext` formatters (zero manual unit math).
- `WorkoutSummary` and `WorkoutSummaryCompact`:
  - Accept optional `liveSnapshotFlow: StateFlow<LiveWorkoutCardSnapshot?> = LiveWorkoutCardStateStore.snapshot` (backward-compatible default, directly injectable in unit/UI tests).
  - Guard collection behind `if (!workoutData.finished)` using `liveSnapshotFlow.map { it?.takeIf { s -> s.workoutId == workoutData.id } }.distinctUntilChanged().collectAsStateWithLifecycle(...)`.
  - Keep existing `0.5f` greyed-out unfinished card styling (`TTAlpha` contrast) and disable delete / mark-finished actions while actively tracked.

  - **`REQ-PER-047.1`**: Dedicated `StateFlow<LiveWorkoutCardSnapshot?>` updated in O(1) memory at ~1 Hz during active/paused tracking and cleared to `null` when tracking stops, tears down, or marks the workout finished, with zero SQLite reloads, zero 1-Hz `WORKOUT_UPDATED_INTENT` broadcasts, zero `_allWorkouts` emissions/clones, and zero downstream `PeriodsRepository` / `AthleteProfileViewModel` / `KnownLocationsViewModel` recalculations.
