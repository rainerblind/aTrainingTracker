# Ticket Deliverable: ATT-9627 — Unified Expert-Gated Threshold Editor in Zones Tabs & Fitness Hub Separation

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-9625`

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**:
  * Following `ATT-9628` (`REQ-SET-135`), sport-specific physiological thresholds (`HRmax`, `LTHR`, `LT1`, `FTP`, `CP`, `W'`, `HRrest`) are stored in `AthleteMetrics.db` with atomic `SettingsDataStore` sync, but threshold editing remains split across `AthleteProfileScreen` (`+` creation dialogs for `HRrest`/`FTP`/`CP`/`W'`) and `ZoneCalculatorDialog` (which only exposes `% HRmax` & Karvonen and couples threshold edits to overwriting custom `Z1..Zn` cutoffs).
  * Athletes cannot edit sport-specific `HRmax`, `LTHR`, or `LT1` directly in **Zones**, nor filter threshold controls by Expert Settings physiology model toggles (`enableCogganPowerMetrics`, `enableCriticalPowerModel`, `enableAerobicEfficiencyModel`, `enablePmcModel`).
* **Change Impact Analysis (4 Dimensions)**:
  1. *Functional / UX*: Consolidates all HR & Power threshold editing into a unified Expert-gated **Physiological Thresholds** card inside `Zones` (`HR Run`, `HR Bike`, `Power Bike`) with decoupled debounced persistence (zero silent `Z1..Zn` overwrite), an embedded **2-Point CP & W' Estimator**, and an upgraded **"Recalculate Zones from Thresholds"** dialog (`Coggan 7-Zone`, `% HRmax`, `Karvonen`, `LTHR-anchored`, `Threshold-anchored LT1+LTHR`) recording `zone_history` snapshots. Separates **Fitness & Physiology** (`AthleteProfileScreen`, Option 1) to keep Body Weight directly editable, preserve all historical trends (`Weight`, `HRrest`, `FTP`, `W/kg`, `CP`, `W'`, `HRmax`, `LTHR`) and history backdating/deletion, and replace duplicate threshold `+` editors with **"Edit in Zones"** navigation directly to the matching Zones tab.
  2. *Architecture / State*: Adds debounced threshold persistence & `zone_history` snapshot helpers to `ZonesSettingsViewModel`; extracts `PhysiologicalThresholdsCard.kt` & `CpWPrimeEstimatorDialog` under `ui/settings/zones/` (keeping `ZoneSettingsScreen.kt` and `AthleteProfileScreen.kt` well within LoC ceilings); extends `ZoneCalculationMath` (`calculateLthrAnchoredHeartRateZones`), `ZoneValidator` (`validatePhysiologicalThresholds`), and `ZoneCalculatorDialog` (`HrMethod.LTHR`, `HrMethod.THRESHOLD_ANCHORED`); wires `onNavigateToZones(initialTab)` from `ATrainingTrackerApp.kt` to `AthleteProfileScreen`.
  3. *Persistence / Data Safety*: Zero SQLite schema changes (`AthleteMetrics.db` stays `DB_VERSION = 2`); all threshold edits persist via `AthleteMetricsRepository.addEntry` (SQLite -> DataStore SSoT) preserving `ATT-9628` upgrade-seeding invariants.
  4. *Localization / Contracts*: Full 9-locale parity in `app/src/main/res/values*/strings_athlete_thresholds.xml` (`Rule 9.4`); preserves `ZonesSettingsHeaderContractTest`, `ZonesSettingsPreviewPillsContractTest` (zero `FilterChip` in `ZoneSettingsScreen.kt`), `ZoneCalculatorDialogContractTest`, `PhysiologyModelsVisibilityContractTest`, and `AthleteProfileContractAndLocalizationTest`.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*: `PhysiologicalThresholdsCard.kt`, `ZonesSettingsViewModel.kt`, `ZoneSettingsScreen.kt`, `ZoneCalculatorDialog.kt`, `ZoneCalculationMath.kt`, `ZoneValidator.kt`, `AthleteMetricsPlotMath.kt`, `AthleteProfileViewModel.kt`, `AthleteProfileScreen.kt`, `ATrainingTrackerApp.kt`, 9-locale `strings_athlete_thresholds.xml`, unit/Compose tests, live `emulator-5554` verification.
  * *Out-of-Scope*: Graphical threshold markers on `ZoneGaugeBar` (`showThresholdMarkers`, next ticket in `ATT-9625`), `SettingsDataStore` schema changes, or Intervals.icu / Polar Loop cloud sync.
* **Chesterton's Fence / Impact**:
  * Extends `REQ-UI-373` (Zone Calculator), `REQ-UI-391` / `REQ-UI-399` / `REQ-UI-403` (Athlete Profile & CP/W' estimator), `REQ-SET-082` (`zone_history`), and `REQ-SET-135` (`ATT-9628`). Preserves `ZonesSettingsHeaderContractTest` (compact Calculate/History header `IconButton`s, no `TextButton`), `ZonesSettingsPreviewPillsContractTest`, `AthleteProfileContractAndLocalizationTest` (`WindowInsets.navigationBars`, `Locale.getDefault()`, `bodyTabIndex` top-bar `+` for Body Weight), and `PhysiologyModelsVisibilityContractTest` (`resolveVisiblePlotMetrics` default behavior).
  * `SYS.2`/`SYS.3` impact: `NONE` (`Derived (SW-only)` UI & settings workflow).

## 2. Decision & Architecture Impact
* **Design Decisions**:
  * Extract `PhysiologicalThresholdsCard.kt` (including pure `resolveVisibleThresholdFields(zoneType, tuningConfig)` and `CpWPrimeEstimatorDialog`) under `ui/settings/zones/` so `ZoneSettingsScreen.kt` stays compact and `FilterChip`-free.
  * Decouple threshold edits from zone cutoffs: `ZonesSettingsViewModel.savePhysiologicalThreshold()` writes validated values via `AthleteMetricsRepository.addEntry()` (debounced `350 ms`) without calling `saveZoneProfile()` or mutating `Z1..Zn`.
  * Upgrade `ZoneCalculatorDialog` (`HrMethod`: `MAX_HR`, `KARVONEN`, `LTHR`, `THRESHOLD_ANCHORED`) using a clean 2x2 selectable pill grid (`maxLines = 1`, `TextOverflow.Ellipsis`), pre-filling from sport-specific DataStore flows, preserving overwrite confirmation when `isCustomized == true`, and recording a `zone_history` snapshot via `ZonesSettingsViewModel.saveRecalculatedZonesSnapshot()` on apply.
  * In `AthleteProfileScreen` (Option 1), keep Body Weight `+` editable, keep history backdating/edit/delete intact, add `HR_MAX_RUN`/`HR_MAX_BIKE`/`LTHR_RUN`/`LTHR_BIKE` trend inspection + summary cards, and replace duplicate threshold `+` triggers with direct **"Edit in Zones"** navigation (`NavRoutes.trainingZones(initialTab, pushed = true)`).
* **Files Touched**:
  * Production: `ZoneCalculationMath.kt`, `ZoneValidator.kt`, `ZonesSettingsViewModel.kt`, `PhysiologicalThresholdsCard.kt` (new), `ZoneSettingsScreen.kt`, `ZoneCalculatorDialog.kt`, `AthleteMetricsPlotMath.kt`, `AthleteProfileViewModel.kt`, `AthleteProfileScreen.kt`, `ATrainingTrackerApp.kt`, 9-locale `strings_athlete_thresholds.xml`.
  * Tests: `ZoneCalculationMathTest.kt`, `ZoneCalculatorDialogContractTest.kt`, `PhysiologicalThresholdsCardTest.kt` (new), `AthleteProfileThresholdsSeparationTest.kt` (new).
  * Living Docs: `docs/requirements/req_settings_profiles.md`, `docs/tests/tst_settings_profiles.md`, synced `docs/requirements.md` & `docs/tests.md`.
