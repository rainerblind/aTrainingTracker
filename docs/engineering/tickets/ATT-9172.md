# Ticket Deliverable: ATT-9172 — Synchronized Activity & Carriage Mode Bar Below Map in Karte & Diagramme

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-68`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Value Proposition**:
  * Athletes reviewing a workout in `Karte & Diagramme` currently see `ActivityCarriageTimelineCard` only as a static duration summary card inside `DETAILS` (`tab_overview`, `REQ-PER-045`), with no spatially synchronized bar aligned below the map and telemetry graphs in `Karte & Diagramme`.
  * Adding a synchronized, color-coded Activity & Carriage Mode segmented bar directly below the map — coupled 1:1 with the scrubbing cursor (`selectedDistance`), map marker, zoom/pan viewport (`profileZoomScale`, `viewportStartFraction`), and `DISTANCE`/`TIME` X-axis domains — lets athletes correlate cycling, running, walking, and stationary phases pixel-for-pixel against the map and telemetry curves.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*:
    1. Create `ActivityCarriageSyncBar.kt` (`ui/map/`) containing pure-JVM `ActivityCarriageBarMath` (domain projection across `DISTANCE` & `TIME`, zero-distance stop marker preservation, zoom/pan clipping, active scrubbed `PhoneCarriageMode` lookup) and `@Composable ActivityCarriageSyncBar` with exact `Rule 64` plot bounds (`startPaddingPx = 50.dp`, portrait `endPaddingPx = 52.dp` when aligned with histograms, landscape `0.72f`/`0.28f` split), canonical `TTColor.getCarriageModeColor` & `carriageModeIcon`, compact active-mode scrub readout chip, bidirectional scrub/pan gestures via `ChartGestureDisambiguator`, and Light/Dark/AMOLED `@Preview`s.
    2. Wire optional `activityCarriageTimeline` + `showActivityCarriageBar` + `MapDetailLowerContentScope.ActivityCarriageBarSection()` into `MapDetailLayout.kt` (keeping `MapDetailLayout.kt <= 1,500` LoC and all existing callers 100% backward-compatible).
    3. Add configurable `WorkoutDetailSectionType.ACTIVITY_CARRIAGE_BAR` (`15`th detail-only section; `toWorkoutSectionTypeOrNull() -> null`, keeping `WorkoutSectionType` at `14` for `WorkoutSummary.kt`), default placement `[MAP, ACTIVITY_CARRIAGE_BAR, ELEVATION, CHARTS]` in `tab_map_graphs`, `v3|` -> `v4|` auto-migration preserving user removals on `v4|`, automatic omission when `activityCarriageTimeline == null || segments.isEmpty()`, and `HorizontalPager` gesture isolation + pointer-up unlock.
    4. Add 9-locale `workout_detail_section_activity_carriage_bar` in `values*/strings_workout_details.xml` and behavioral Compose UI + unit + `TranslationParityTest` + `Rule 8.5` PNG verification.
  * *Out-of-Scope*: `ActivityCarriageTimelineCalculator` / `PhoneCarriageClassifier` accuracy (`ATT-9157`/`ATT-9062` already `Erledigt`), `WorkoutSummary.kt` (`14` `WorkoutSectionType` entries unchanged), `ActivityCarriageTimelineCard` in `DETAILS` (preserved intact), and `WorkoutSamples.db` schema.
* **Chesterton's Fence / Impact**:
  * Preserves `WorkoutDetailSectionType.ELEVATION` (*Höhenprofil*) independently configurable alongside or instead of `ACTIVITY_CARRIAGE_BAR`, preserves `WorkoutSectionType` (`14` entries) and `WorkoutSummary.kt`, preserves `MapDetailLayout` default signatures, `Rule 64` horizontal plot alignment, `REQ-UI-2795` custom tab section ordering, `Rule 41` `navigationBarsPadding()`, and `<= 1,500` LoC ceilings.
  * `SYS.2`/`SYS.3` impact: `NONE` (SW-only post-workout Compose UI visualization of existing `ACTIVITY_AND_CARRIAGE_MODE` telemetry).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * Isolate all domain projection math and Canvas rendering in a dedicated `ui/map/ActivityCarriageSyncBar.kt` module so `MapDetailLayout.kt` stays well under `1,500` LoC (`~1,225` LoC) and math functions (`projectSegmentsToDomain`, `resolveModeAtDomainPosition`, `resolveScrubbedMode`) are pure-JVM unit-testable.
  * Reuse `TTColor.getCarriageModeColor(mode)` and expose `carriageModeIcon(mode)` from `ActivityCarriageTimelineCard.kt` for 100% visual consistency (zero duplicated color/icon tables).
  * Expose `WorkoutDetailSectionType.ACTIVITY_CARRIAGE_BAR` as a configurable section in `WorkoutDetailTabConfig.kt` (with `v4|` schema prefix and automatic pre-`v4|` migration inserting `ACTIVITY_CARRIAGE_BAR` directly after `MAP` in `tab_map_graphs`) so users can toggle or reorder it independently of `ELEVATION` in `WorkoutDetailTabsConfigSheet` while `v4|` respects explicit user removal (`REQ-UI-2787.1`).
  * In `ActivityCarriageSyncBar`, mirror `TelemetryMetricGraph`'s exact horizontal geometry (`startPaddingPx = 50.dp`, portrait `endPaddingPx = 52.dp` when aligned with histograms, landscape `0.72f` weight), `ElevationProfileZoomMath` viewport clamping, `ChartGestureDisambiguator` horizontal/vertical disambiguation, and `chartInteractiveTouchDetector` pointer-up unlock.
* **SWE.2 Architecture / Files Touched**:
  * Production: `app/src/main/java/com/atrainingtracker/trainingtracker/ui/map/ActivityCarriageSyncBar.kt` (new), `app/src/main/java/com/atrainingtracker/trainingtracker/ui/map/MapDetailLayout.kt`, `app/src/main/java/com/atrainingtracker/trainingtracker/ui/aftermath/ActivityCarriageTimelineCard.kt`, `app/src/main/java/com/atrainingtracker/trainingtracker/ui/aftermath/WorkoutDetailTabConfig.kt`, `app/src/main/java/com/atrainingtracker/trainingtracker/ui/aftermath/WorkoutDetailTabbedContent.kt`, `app/src/main/java/com/atrainingtracker/trainingtracker/ui/aftermath/TrackOnMapScreen.kt`, `app/src/main/res/values*/strings_workout_details.xml` (9 locales).
  * Tests: `app/src/test/java/com/atrainingtracker/trainingtracker/ui/map/ActivityCarriageSyncBarUiTest.kt` (new), `app/src/test/java/com/atrainingtracker/trainingtracker/ui/aftermath/WorkoutDetailTabsTest.kt`, `app/src/test/java/com/atrainingtracker/trainingtracker/ui/settings/tuning/AdvancedTuningAccordionTest.kt`.
  * `docs/architecture.md`: unchanged (no new subsystem/service/DB/prefix family).
