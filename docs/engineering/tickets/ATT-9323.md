# Ticket Deliverable: ATT-9323 — MorningHrvCheckScreen: Prevent starting HRV measurement when no HR sensor is available and show clear status guidance

* **Risk Tier**: `tier-b` | **Target Release**: `V5.0.0` | **Parent Epic**: `ATT-3539` | **Localization Parity**: `9/9 locales (values*/strings_hrv.xml: morning_hrv_state_no_sensor, morning_hrv_no_sensor_hint)`

---

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**: In `MorningHrvCheckScreen.kt` (`ActionButtonsSection`, `:905-921`), the primary `morning_hrv_start_button` (*Start Measurement* / *Messung starten*) omits any `enabled` gate, and `MorningHrvCheckViewModel.kt` (`startMeasurement()`, `:285-289`) only checks `phase` without verifying HR/HRV sensor availability. Meanwhile `MeasurementPacingCard` (`:550-582`) unconditionally displays `"Ready to Measure"` even when no heart rate / RR / optical PPI sensor is connected (`currentHeartRateBpm == null`, no active `SensorType.HR`/`SensorType.RR_INTERVAL` in `BANALServiceRepository`). Unlike `HrvRampTestScreen` (`enabled = uiState.canStartTest`), tapping *Start Measurement* without a sensor runs an entire empty countdown and only fails at completion with `morning_hrv_error_no_rr`.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*:
    1. Track live compatible HR/HRV sensor availability (`isHrSensorAvailable`) and derived `canStartMeasurement` in `MorningHrvUiState` & `MorningHrvCheckViewModel`, combining `BANALServiceRepository.activeSensors` (`SensorType.HR`, `SensorType.RR_INTERVAL`), live `SensorType.HR` telemetry from `BANALServiceRepository.allFilteredSensorData`, and direct `RrBeatListener` (`handleRrBeat`) events (ECG chest straps and optical PPI sensors), clearing availability and stale `READY` heart-rate state cleanly upon sensor disconnect.
    2. Enforce defense-in-depth inside `MorningHrvCheckViewModel.startMeasurement()` so no measurement transitions out of `READY` when `!canStartMeasurement`.
    3. Gate `morning_hrv_start_button` on `enabled = uiState.canStartMeasurement` in `MorningHrvCheckScreen.kt`.
    4. When `phase == MorningHrvPhase.READY && !uiState.isHrSensorAvailable`, replace the misleading `"Ready to Measure"` badge in `MeasurementPacingCard` with a semantic `errorContainer` / `onErrorContainer` status badge (`R.string.morning_hrv_state_no_sensor`) and render clear connection guidance (`R.string.morning_hrv_no_sensor_hint`, `testTag("morning_hrv_no_sensor_guidance")`) while dimming the heart icon cleanly (`MaterialTheme.colorScheme.outline`).
    5. Preserve standalone saving of **Morning Sleep & Wellness** (`onSaveStandaloneWellness`, both secondary button in Full HRV mode and primary button in Pure Wellness mode) 100% enabled and functional without any HR sensor connected.
    6. Add 9-language localization parity for `morning_hrv_state_no_sensor` and `morning_hrv_no_sensor_hint` across all `values*/strings_hrv.xml` files.
  * *Out-of-Scope*: Reordering cards in `MorningHrvCheckScreen` (tracked separately in `ATT-9318`), modifying `HrvRampTestScreen`, or changing `BANALServiceRepository` polling/arbitration internals.
* **Chesterton's Fence / Impact**: Preserves `REQ-PER-032` waking protocol, `REQ-HRV-040`/`REQ-HRV-043` standalone & pure wellness modes, `REQ-HRV-045` `forceFullHrv` route override (including `MorningHrvUiState(currentHeartRateBpm = 54)` defaulting `isHrSensorAvailable = currentHeartRateBpm != null` so existing Compose previews and tests stay backward-compatible), `REQ-HRV-049` Polar Verity Sense optical PPI non-sticky modality handling, zero-workout invariant, and `MorningHrvCheckScreen.kt <= 1,500` LoC ceiling. `SYS.2`/`SYS.3`: Refines `SYSREQ-TRK-012` (unchanged).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * **Unified Sensor Availability Signal (`MorningHrvUiState.isHrSensorAvailable` & `canStartMeasurement`)**: Combining `banalServiceRepository.activeSensors` (`SensorType.HR` / `SensorType.RR_INTERVAL`), `banalServiceRepository.allFilteredSensorData` (positive `SensorType.HR`), and `handleRrBeat(event)` (`event.rrMs > 0.0`) covers all supported Morning HRV hardware paths (BLE ECG `0x2A37`, ANT+ HRM, Polar Verity Sense optical PPI). Tracking `hadActiveHrSensorInRepo` ensures that a live sensor disconnect while in `READY` immediately clears `isHrSensorAvailable`, `currentHeartRateBpm`, and `isOpticalPpiSession` without breaking direct `handleRrBeat` unit tests.
  * **Defense-in-Depth ViewModel Guard**: `startMeasurement()` checks `if (!_uiState.value.canStartMeasurement) return`, mirroring `HrvRampTestViewModel.startProtocol()` (`if (!currentState.canStartTest) return`) so neither UI bugs nor programmatic callers can launch an empty countdown.
  * **UI Consistency (`docs/design_guidelines.md` §5.4)**: Uses Material 3 `errorContainer`/`onErrorContainer` semantic warning tokens for the disconnected status pill and `Icons.Default.WarningAmber` + `onSurfaceVariant` guidance text inside `MeasurementPacingCard`, preserving Light/Dark/AMOLED contrast without hardcoded colors or new custom surfaces.
* **SWE.2 Architecture / Files Touched**:
  * Production: `MorningHrvCheckViewModel.kt`, `MorningHrvCheckScreen.kt`, `app/src/main/res/values*/strings_hrv.xml` (9 locales).
  * Tests: `MorningHrvCheckViewModelTest.kt`, `MorningHrvCheckScreenTest.kt` (plus `MorningHrvOpticalPpiUiTest.kt`, `TranslationParityTest`, `ArchitectureConformanceContractTest` verification).
  * Living Docs: `docs/requirements/req_aftermath_periods.md` (`REQ-HRV-052`), `docs/tests/tst_aftermath_periods.md` (`TST-HRV-052`), master indexes (`docs/requirements.md`, `docs/tests.md`).
