## 1. Problem, Scope & Change-Request Impact Analysis

### Problem / Root Cause
* When the user activates *Swimming* in *Expert Settings* (`AdvancedTuningScreen.kt:255-259` -> `SportTypesRepository.getInstance(context).ensureSwimSportTypeExists()`), `SportTypeDatabaseManager.ensureSwimSportTypeExists()` writes the localized `SWIM` row (`minSpeed = 0.0`, `maxSpeed = 0.0`, `stravaName = "Swim"`, `gcName = "swim"`) into `SportType.db`.
* However, the newly created Swimming entry does not appear in the *Sport Types* screen (`SportTypesTabsScreen.kt`, which replaced the decommissioned `SportTypeListFragment.kt` in `ATT-8129` and is hosted via `NavRoutes.SPORT_TYPES` in `ATrainingTrackerApp.kt:581-590`) or in cached sport-type pickers until an app restart:
  1. `SportTypeViewModel` (`ATrainingTrackerApp.kt:582`) is Activity-scoped (`viewModel(activity)`), calls `loadSportTypes()` only in `init`, `saveSportType()`, `deleteSportType()`, and `workoutRepository.workoutMutationEvents`, and observes no change signal from `SportTypesRepository` / `SportTypeDatabaseManager`.
  2. `SportTypesTabsScreen` (`SportTypesTabsScreen.kt:110-125`) lacks a `Lifecycle.Event.ON_RESUME` observer (`DisposableEffect(lifecycleOwner)`) to trigger `viewModel.loadSportTypes()` when navigated back to or resumed.
  3. Neither `SportTypesRepository` nor `SportTypeDatabaseManager` emits a reactive change signal (`SharedFlow`) when `ensureSwimSportTypeExists()`, `updateSportType()`, `delete()`, or `SportTypeReconciliationHelper` mutates `SportType.db`.
  4. Downstream sport-type pickers/consumers cache sport-type lists across mutations: `EditWorkoutViewModel.kt:81` stores `private val sportTypesList` once at init without observing repository mutations; `EquipmentViewModel.kt:130-131` stores `bikeSportTypes`/`runSportTypes` `by lazy` on an Activity-scoped ViewModel and does not reload `linkedSportTypeNames` on sport-type changes; and `EditWorkoutClusterIdentityDialog` (`WorkoutClusterHeatmapScreen.kt:1207`), `ManualClusterScreen.kt:62`, and `ImportBackupTabsScreen.kt:1048` memoize `SportTypesRepository.sportTypesList` / `getSportTypes(null)` inside unkeyed `remember { ... }`.

### In-Scope / Out-of-Scope
* **In-Scope**:
  * Add a companion-level `sportTypesChanged: SharedFlow<Unit>` + `notifySportTypesChanged()` on `SportTypesRepository` (mirroring `EquipmentRepository.equipmentLinksChanged`) and emit strictly on real `SportType.db` mutations in `SportTypeDatabaseManager` (`ensureSwimSportTypeExists()` on insert, `updateSportType()`, `delete()`) and `SportTypeReconciliationHelper` (`reconcileOrphanSportTypes()` when `insertedCount > 0`, `claimPlaceholder()`, `pruneUnreferencedPlaceholders()` on delete).
  * Update `SportTypeViewModel` (`@JvmOverloads` preserving `(Application)` & `(Application, WorkoutRepository)`) to observe `sportTypesChanged` and update `SportTypesTabsScreen` to reload via `Lifecycle.Event.ON_RESUME`.
  * Propagate live reactivity to downstream pickers: `EditWorkoutViewModel`, `EquipmentViewModel`, and a shared `@Composable fun rememberSportTypesList(...)` helper (`ui/common/SportTypesComposeHelpers.kt`) wired into `EditWorkoutClusterIdentityDialog`, `ManualClusterScreen`, and `ImportBackupTabsScreen`.
  * Add targeted unit & Compose behavioral tests (`SportTypeViewModelRefreshTest`, `EditWorkoutViewModelTest`, `EquipmentViewModelLifecycleTest`, `SportTypesTabsScreenComposeTest`) plus live `emulator-5554` end-to-end verification.
* **Out-of-Scope**:
  * No changes to `SportType.db` schema (`DB_VERSION = 3` unchanged), zero `strings*.xml` edits (`Localization Parity: N/A - 0 string changes`), and no `BSportType` fixed-enum selectors (`SportTypeSelector`, `BatchImportSportTypeDialog`, `EditRouteScreen`).

### Requirement Archaeology & Chesterton's Fence Audit
1. **Original Requirement ID & Target**: Net-new `REQ-SET-134` refining `REQ-SET-107` (`ATT-7999` — `ensureSwimSportTypeExists()` & Expert Settings Swimming activation) and `REQ-UI-257` (`EquipmentRepository.equipmentLinksChanged` reactive repository signal pattern) across `SportTypesRepository.kt`, `SportTypeDatabaseManager.java`, `SportTypeReconciliationHelper.kt`, `SportTypeViewModel.kt`, `SportTypesTabsScreen.kt`, `EditWorkoutViewModel.kt`, `EquipmentViewModel.kt`, `WorkoutClusterHeatmapScreen.kt`, `ManualClusterScreen.kt`, and `ImportBackupTabsScreen.kt`.
2. **Historical Origin & Commit Trace**: `ATT-7999` (`REQ-SET-107`) introduced `ensureSwimSportTypeExists()` so fresh installs keep 5 defaults while Expert Settings activates Swimming on demand; `ATT-8129` (`REQ-UI-2801`) decommissioned legacy `SportTypeListFragment.kt` into pure-Compose `SportTypesTabsScreen.kt` hosted with `viewModel(activity)` in `ATrainingTrackerApp.kt`. Because `SportTypeViewModel` became Activity-scoped without a repository change signal or `ON_RESUME` reload, PO Review (`ATT-7999` on Pixel 10) observed Swimming missing until app restart.
3. **Root Reason for Existing Formulation**: Activity-scoping `SportTypeViewModel` and `EquipmentViewModel` avoided redundant reloads on tab/navigation switches, and `ATT-7999` deferred reactive repository signaling when adding `ensureSwimSportTypeExists()`.
4. **Preservation of Core Invariants**:
   * Fresh `SportType.db` v3 still seeds strictly 5 defaults without Swimming (`REQ-SET-107.1`).
   * `ensureSwimSportTypeExists()` remains idempotent and zero-collision (`minSpeed = 0.0, maxSpeed = 0.0`, `REQ-SET-107.2`) and emits `sportTypesChanged` **only** when inserting a new row (`insertedId != -1L`), not on idempotent no-ops.
   * `@JvmOverloads constructor` on `SportTypeViewModel` preserves `(Application)` for `AndroidViewModelFactory` (`Rule 3.5`) and `(Application, WorkoutRepository)` for existing tests (`SportTypeViewModelRetiredTest`).
   * `RepositoryUiCleanlinessContractTest` invariants (`val sportTypesList: List<SimpleSportTypeInfo>`, `fun getSportTypes(bSportType: BSportType?): List<SimpleSportTypeInfo>`, zero `*DatabaseManager.getInstance(` in `trainingtracker/ui/`) remain 100% intact.

## 2. REQ / TST Specification & Architecture Impact

* **Design Decision & Architecture Impact**:
  * **Repository Change Signal (`SportTypesRepository.sportTypesChanged`)**: Add `MutableSharedFlow<Unit>(replay = 0, extraBufferCapacity = 64, onBufferOverflow = BufferOverflow.DROP_OLDEST)` on `SportTypesRepository.Companion` with `notifySportTypesChanged()` and `resetForTesting()` cleanup. Emit from `SportTypeDatabaseManager` (`ensureSwimSportTypeExists()` on insert, `updateSportType()`, `delete()`) and `SportTypeReconciliationHelper` (`reconcileOrphanSportTypes()` when `insertedCount > 0`, `claimPlaceholder()`, `pruneUnreferencedPlaceholders()` when `deletedCount > 0`), ensuring every mutation path (Expert Settings, Polar Verity Swim backfill, Sport Types UI, backup reconciliation) broadcasts consistently.
  * **UI & ViewModel Propagation**: `SportTypeViewModel` collects `sportTypesChangedFlow` -> `loadSportTypes()`, and `SportTypesTabsScreen` triggers `viewModel.loadSportTypes()` on `Lifecycle.Event.ON_RESUME`. `EditWorkoutViewModel` replaces cached `val sportTypesList` with a live getter (`get() = sportTypesRepository.sportTypesList`) and refreshes `_sportTypeNames` on `sportTypesChanged`. `EquipmentViewModel` replaces `by lazy` `bikeSportTypes`/`runSportTypes` with live getters and reloads equipment on `sportTypesChanged`. Shared `@Composable fun rememberSportTypesList(...)` in `ui/common/SportTypesComposeHelpers.kt` replaces unkeyed `remember { ... }` in `EditWorkoutClusterIdentityDialog`, `ManualClusterScreen`, and `ImportBackupTabsScreen`.
  * **SWE.2 `docs/architecture.md`**: Unchanged (reuses existing `SportTypesRepository` & `SharedFlow` signal pattern from `EquipmentRepository`).
