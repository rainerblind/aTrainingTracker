# Ticket Deliverable: ATT-9320 — Prompt for Front/Rear wheel mounting position via WheelPositionSelectionDialog in EditEquipmentDialog

## 1. Problem, Scope & Change-Request Impact Analysis
* **Problem / Root Cause**: While both `EquipmentSensorMatrixScreen` (`ATT-7752`, `ATT-8859`) and `EditDeviceDialog` (`ATT-8719`) open `WheelPositionSelectionDialog` (`Front Wheel` / `Rear Wheel`, conflict swap hint, `Unlink Sensor`) when linking a wheel speed sensor (`DeviceType.BIKE_SPEED` or `DeviceType.BIKE_SPEED_AND_CADENCE`) to a bike, `EditEquipmentDialog.kt` (`:137-149`, `:231-276`) only toggles `selectedSensorIds` directly without prompting for wheel mounting position or displaying assigned positions. Furthermore, `EquipmentViewModel.addEquipment()` (`:384`), `EquipmentViewModel.updateEquipment()` (`:362`), `EquipmentRepository`, and `EquipmentDbHelper` (`:221`, `:1026`) do not accept draft `wheelPositions: Map<Long, WheelPosition>` on save, causing newly linked wheel sensors to persist as `WheelPosition.UNSPECIFIED`.
* **In-Scope / Out-of-Scope**:
  * *In-Scope*:
    1. In `EditEquipmentDialog.kt` (for bikes `item.frameType > 0`), tapping a wheel speed sensor (`isWheelSpeedSensor(sensor.deviceType)`) in `MultiSelectSensorSpinner` opens the existing `WheelPositionSelectionDialog` with `Front` / `Rear` choices, dynamic draft conflict swap hints (`conflictHints`), and `Unlink Sensor` when already linked.
    2. Display assigned wheel mounting position (`Front Wheel` / `Rear Wheel` / `Unspecified Position`) in both the collapsed sensor summary field (matching `EditDeviceDialog.formatEquipmentSummaryText`) and on each wheel speed sensor row inside the dropdown (subtitle + compact `F`/`R` / `V`/`H` badge pill matching `EditDeviceDialog.kt:498-528`).
    3. Stage draft wheel positions in `EditEquipmentDialog` with conflict-swap resolution mirroring `EquipmentRepository.setWheelSensorLink()` (2-sensor swap, free-opposite move, 3rd-sensor fallback to `UNSPECIFIED`), and persist `linkedDeviceWheelPositions` atomically on Save via backward-compatible overloads in `EquipmentTabsScreen` -> `EquipmentViewModel` -> `EquipmentRepository` -> `EquipmentDbHelper`, preserving untouched positions of already-linked sensors.
    4. Keep non-wheel-speed sensors (HR, Power, Cadence-only, Radar, etc.) and shoe equipment (`item.frameType <= 0`) on unchanged 1-tap checkbox toggle without prompting.
    5. Reuse existing 9-locale `strings_equipment.xml` resources (`0` new strings).
  * *Out-of-Scope*: Changing `WheelPositionSelectionDialog` options (`ATT-8859`), adding SQLite schema migrations (`WHEEL_POSITION` column already exists), or modifying `EquipmentSensorMatrixScreen` / `EditDeviceDialog`.
* **Chesterton's Fence / Impact**: Preserves `EditEquipmentDialogContractTest` (`compatibleSensors`, `isBikeSensor`/`isSharedSensor`/`isRunSensor`, `allSensors = compatibleSensors`), `EquipmentViewModelRetiredTest` (5-arg `updateEquipment` mock when `linkedDeviceWheelPositions.isEmpty()`), `EquipmentTabsScreenContractTest`, `WheelPositionSelectionDialog` `ATT-8859` Front/Rear-only contract, `EquipmentDbHelper` existing 3-arg `addEquipment` and 5-arg `updateEquipment` signatures, and `<= 1,500` LoC file caps. `SYS.2`/`SYS.3`: Refines `SYSREQ-TRK-001` & `SYSREQ-TRK-003` (unchanged).

## 2. Decision & Architecture Impact
* **Design Decision & Rationale**:
  * **Draft-First State + Atomic Persistence**: Mirror `EditDeviceDialog` (`ATT-8719`) by staging draft `selectedSensorIds` + `draftWheelPositions` inside `EditEquipmentDialog` until the user taps `Save` (canceling discards all draft changes cleanly). Closing the `ExposedDropdownMenu` when launching `WheelPositionSelectionDialog` prevents Compose popup-window focus conflicts with `AlertDialog`.
  * **Zero-Breakage Persistence Overloads**: Add 6-arg `updateEquipment(..., wheelPositions)` and 4-arg `addEquipment(..., wheelPositions)` overloads on `EquipmentDbHelper` and `EquipmentRepository`, delegating existing 5-arg / 3-arg overloads with `null`. In `EquipmentViewModel`, dispatch to the wheel-position overload when `linkedDeviceWheelPositions.isNotEmpty()` and to the existing overload when empty — keeping every legacy caller and Mockito stub (`EquipmentViewModelRetiredTest`) 100% compatible while preserving untouched SQLite wheel positions whenever a device ID is absent from `wheelPositions`.
  * **UI Consistency (`docs/design_guidelines.md`)**: Reuses existing `WheelPositionSelectionDialog`, Material 3 `RoundedCornerShape(4.dp)` `primaryContainer`/`onPrimaryContainer` badge pill (`F`/`R` or `V`/`H`), `MaterialTheme.typography.bodySmall` subtitle, and `MaterialTheme.colorScheme` Light/Dark tokens with `0` new custom components or strings.
* **SWE.2 Architecture / Files Touched**:
  * Production: `EditEquipmentDialog.kt`, `EquipmentTabsScreen.kt`, `EquipmentViewModel.kt`, `EquipmentRepository.kt`, `EquipmentDbHelper.java`.
  * Tests: `EditEquipmentDialogWheelPositionTest.kt` (new Robolectric Compose UI + pure logic tests), `EquipmentRepositoryWheelPositionTest.kt` (new SQLite `addEquipment`/`updateEquipment` wheel-position persistence & preservation tests), `EquipmentViewModelMatrixTest.kt` (ViewModel dispatch tests).
  * Living Docs: `docs/requirements/req_tracking_cockpit_part3.md` (`REQ-SEN-035`), `docs/tests/tst_tracking_cockpit_part2.md` (`TST-SEN-035`), master indexes.
