## 2. Detailed Given-When-Then Test Cases

1. **`TST-DAT-044.1` (Null-Safe `WorkoutSummariesDatabaseManager` Getters)**:
   - *Given* a real Robolectric/SQLite or mocked `Cursor` with SQL `NULL` in `DISTANCE_TOTAL_m`, `TIME_ACTIVE_s`, `CLUSTER_ID`, and `TABLE_EXTREMA_VALUES.VALUE`, *When* `getDouble(baseFileName, col)`, `getInt(workoutId, col)`, `getInt(baseFileName, col)`, `getLong(workoutId, col)`, and `getExtremaValue(db, ...)` are called, *Then* every call returns `null` (never `0`/`0.0`); calling `getInt(null, col)` returns `null`; non-null values (including valid `0`/`0.0`) return exact numeric values.
2. **`TST-DAT-044.2` (`LIMIT 1` Extrema & Single-PRAGMA Crop)**:
   - *Given* a workout samples table with leading/trailing `NULL` values in `ALTITUDE`, *When* `calcExtremaValue(..., START, ALTITUDE)` and `calcExtremaValue(..., END, ALTITUDE)` execute, *Then* `db.query` is called with `columns = ["ALTITUDE"]`, `selection = "ALTITUDE IS NOT NULL"`, `orderBy = "_id ASC"` / `"_id DESC"`, and `limit = "1"`, returning exact first/last non-null samples; `calcExtremaValue(..., AVG, SPEED_mps)` returns `null` when `TIME_ACTIVE_s == 0`; `pruneAndShiftSamples` invokes `PRAGMA table_info(...)` exactly once.
3. **`TST-DAT-044.3` (Devices Cursor Safety, `setInt`, Cross-Locale UTC `lastActive` & `paired = 1`)**:
   - *Given* `DevicesDatabaseManager.getCalibrationFactor` returning an empty or `NULL` first cursor, *When* it falls back to `DEVICE_TYPE`, *Then* BOTH the first and second `Cursor` instances have `.close()` verified (`exactly = 1`) and the device type's default calibration factor is returned.
   - *Given* `setInt` invoked via reflection or helper with an unknown column name, *Then* `IllegalArgumentException` is thrown (while `LAST_BATTERY_PERCENTAGE` succeeds).
   - *Given* `Locale.GERMANY` when `LastActiveDateFormatter.formatEpochMillis(ts)` / `setLastActive` writes, *When* default locale switches to `Locale.US`, *Then* `LastActiveDateFormatter.parseToEpochMillis`, `DeviceSortOrder.parseLastSeenTimestamp`, and `DeviceStatusRow` relative formatting all parse exact `ts`, AND a legacy `DateFormat.getDateTimeInstance().format(Date(ts))` string still parses accurately.
   - *Given* `Devices.db` rows for `Protocol.BLUETOOTH_LE` with both `paired = 1` and `paired = 0`, *When* `DeviceDataRepository.getPairedRemoteDevices(Protocol.BLUETOOTH_LE)` runs, *Then* SQL selection contains `AND paired=1` and only paired devices are returned.
4. **`TST-DAT-044.4` (`RoutesDatabaseManager` Upgrade & Single-Read Duplication)**:
   - *Given* `RoutesDbHelper.onUpgrade(db, 4, 11)`, *When* executed, *Then* `onCreate(db)` runs once and `0` `ALTER TABLE` statements execute afterward.
   - *Given* a route with path points and waypoints, *When* `duplicateRouteAsLocal(routeId)` executes, *Then* `TABLE_ROUTE_POINTS` and `TABLE_ROUTE_WAYPOINTS` are queried once (inside `getRouteById`), not twice, and the duplicated `LOCAL_GPX` route preserves all points and waypoints.
5. **`TST-DAT-044.5` (Numeric `isMinRelevant`, `SensorType` Extrema Matching & Single Cluster Reload)**:
   - *Given* `WorkoutDataMapper.createExtremaRow` under `Locale.GERMANY` and `Locale.US`, *When* `rawMinVal` is `null`, `0.0`, `-1.0`, `Double.NaN`, vs `12.5` for `SPEED_mps`/`CADENCE`/`POWER`, *Then* `isMinRelevant` is `false` for non-positive/non-finite values and `true` for `12.5`, and `ExtremaDataRow.sensorType` equals the source `SensorType` (`PACE_spm` for derived pace).
   - *Given* an in-memory `WorkoutData` whose `ExtremaDataRow` was built with English `"HR"` and `sensorType = SensorType.HR`, *When* `application.getString(SensorType.HR.shortNameId)` returns German `"HF"` and `updateExtremaValueInMemory(id, SensorType.HR, ExtremaType.MAX, 185.0)` runs, *Then* the HR row's `maxValue` updates to `"185"` regardless of the label mismatch; `addOrUpdateWorkout` likewise preserves `minLatLng`/`maxLatLng` by `sensorType`.
   - *Given* `assignClusterToWorkout(workoutId, clusterId)` and `unassignClusterFromWorkout(workoutId)`, *When* executed on `WorkoutRepository`, *Then* `summariesManager.getWorkoutCursor(workoutId)` is invoked **once** per mutation (not twice) AND `_initialWorkoutLoaded` receives the updated `WorkoutData`.
