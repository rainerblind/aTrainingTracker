## 3. Acceptance Criteria (Given-When-Then)

- **Given** a cycling workout starts with phone-handling (`glanceCount >= 1`), a brief `acc > 15 m` GNSS spike, and `0.3–0.8 m/s` bike-pushing with `0` footstrikes (`rows 1..25`), **When** evaluated, **Then** `PhoneCarriageClassifier` never emits `RUN_HANDHELD` and `MultisportTransitionDetector` never locks `RUN` or emits `Laufen -> Rad`.
- **Given** an established `BIKE` session rolls `~50 m` at `2.0–4.0 m/s` for `15–20 s` (or `60 s` uncorroborated + `5 s` noise burst) with `confirmedNoFootstrikes == true` (`rows 310..340`, with/without barometer), **When** evaluated, **Then** `RUN_HANDHELD` is suppressed and `0` phantom `BIKE -> RUN` transitions emit.
- **Given** a cyclist dismounts at `T2` into sustained jogging/running (`>= 2.0 m/s`, `>= 15 s`, `~150–160 spm`, incl. after `15 s` slow ticks or with handheld glance, via hardware steps OR 50-Hz accel, with/without barometer), **When** evaluated, **Then** `BIKE -> TRANSITION -> RUN` confirms accurately with `exitAnchor` intact and `enterAnchor` at the qualifying run start.
- **Given** unit tests reproducing both failure windows, fresh/`Long.MIN_VALUE` footstrike queries, dilution immunity, and Phase 2 slow-start recovery, **When** run, **Then** all new and existing tests pass with `0` phantom `RUN` laps.
