## 1. Requirement Specification (REQ-PRO-072)

### 1.1 Problem Statement & Rationale
ASPICE 4.0 pre-assessment finding S-08 (SYS.5 BP, SUP.8) identified that release decisions and release checklists in `.agents/skills/release-manager/SKILL.md` do not reference system-level evidence (SYS.4 integration verification and SYS.5 system verification protocol). Release decisions must require system integration results and verification records so that no release candidate ships without verified system evidence.

### 1.2 Functional & Technical Requirements
* **REQ-PRO-072.1** (*Mandatory System Evidence Gate Specification*): `.agents/skills/release-manager/SKILL.md` SHALL specify mandatory verification gates requiring:
  1. SYS.4 System Integration Verification results (`docs/releases/<tag>/system_integration_results.json` generated by `tools/run_system_integration_tests.py`).
  2. SYS.5 System Verification Protocol sign-off records (`docs/releases/<tag>/sys_verification_record.md` per `docs/system/sys_verification_protocol.md`).
* **REQ-PRO-072.2** (*Release Tagging Blocking Gate*): The release checklist and step-by-step procedures in `.agents/skills/release-manager/SKILL.md` SHALL explicitly block the creation of release candidate tags (`V<versionName>__<versionCode>`) and distribution if either system verification record is missing, incomplete, or contains failing test verdicts.
* **REQ-PRO-072.3** (*Standardized Release Evidence Directory & Template*): A standardized release evidence directory structure and template (`docs/releases/README.md` and `docs/releases/TEMPLATE.md`) SHALL be established under `docs/releases/`, documenting required artifacts, directory layout `docs/releases/<tag>/`, and cross-references to SYS.4 and SYS.5 sign-off criteria.
* **REQ-PRO-072.4** (*Release Manager System Evidence Contract Testing*): An automated JUnit contract test `ReleaseManagerSystemEvidenceContractTest.kt` SHALL verify that `.agents/skills/release-manager/SKILL.md` and release templates enforce the mandatory SYS.4 and SYS.5 gating criteria and block release candidate creation upon missing/failing evidence.

### 1.3 Acceptance Criteria (Given-When-Then)
* **Criterion 1 (System Evidence Gate in Skill)**: *Given* `.agents/skills/release-manager/SKILL.md`, *When* inspected, *Then* it specifies mandatory gates for `docs/releases/<tag>/system_integration_results.json` and `docs/releases/<tag>/sys_verification_record.md`.
* **Criterion 2 (Blocking Gate on Tag Creation)**: *Given* release preparation, *When* system verification records are missing or failing, *Then* the release procedure explicitly blocks tag creation and production release finalization.
* **Criterion 3 (Release Templates & Documentation)**: *Given* `docs/releases/README.md` and `docs/releases/TEMPLATE.md`, *When* inspected, *Then* they specify the release dossier structure and reference SYS.4 and SYS.5 sign-off criteria.
* **Criterion 4 (Contract Test Execution)**: *Given* `ReleaseManagerSystemEvidenceContractTest.kt`, *When* executed via Gradle, *Then* all contract assertions pass with 100% success.

### Requirement Archaeology & Chesterton's Fence Audit
* **Original Requirement ID & Target**: Net-new requirement `REQ-PRO-072` (*Release Manager System Verification Evidence Integration & Release Gating Governance*), fulfilling ASPICE SYS.5 and SUP.8 under Parent Epic ATT-6142. Targets `.agents/skills/release-manager/SKILL.md`, `docs/releases/`, `docs/architecture.md`, and `ReleaseManagerSystemEvidenceContractTest.kt`.
* **Historical Origin & Commit Trace**: Pre-assessment remediation finding S-08 (SYS.5 / SUP.8); builds upon ATT-6166 (commit `daab754c`, SYS.4 integration tests) and ATT-6167 (commit `0d18ef1a`, SYS.5 verification protocol).
