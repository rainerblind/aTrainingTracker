## 1. Requirement Summary (`REQ-SET-125` [Planned])
- **`REQ-SET-125.1` (Encapsulated Live Paired-State Query)**: `DeviceDataRepository.isPolarRetrySensorPaired(polarDeviceId: String?, isVeritySense: Boolean): Boolean` SHALL perform a live `devicesDatabaseManager` query explicitly verifying `isPaired(dev.id)` (`PAIRED > 0`) on `DeviceType.HRM` + `Protocol.BLUETOOTH_LE` sensors. For non-blank `polarDeviceId`, matching SHALL evaluate MAC address, `PolarOfflineCapabilityStore.getPolarDeviceId`, `PolarOfflineGattCoordinator.extractPolarId`, and device name (preventing sibling H10/Verity Sense masking). Strictly when `polarDeviceId.isNullOrBlank()`, family fallback SHALL pass `manufacturer` to `isPolarVeritySenseDevice`/`isPolarH10Device`. Zero `*DatabaseManager`/`Cursor` getters exposed (`Rule 8.7`); `DevicesDatabaseManager.java` and `WorkoutRepository.kt` remain untouched.
- **`REQ-SET-125.2` (Aftermath Wiring & Reactive Re-Evaluation)**: Both `TrackOnMapScreen.kt:506` and `WorkoutDetailTabbedContent.kt:731` SHALL forward `workoutData.polarDeviceId` to `PolarPendingRetrySyncSection`. `PolarPendingRetrySyncSection` SHALL observe `DeviceDataRepository.allDevices` AND `Lifecycle.Event.ON_RESUME` ticks using `initialValue = null` (preventing Frame-0 false-unpaired flicker before async DB check completes, without unmounting `WorkoutDetailTabbedContent`).
- **`REQ-SET-125.3` (Unpaired Action Guard, Semantic Hint & Recovery)**: While `isSensorPaired == false`, `PolarH10RetrySyncBanner` SHALL disable *"Jetzt synchronisieren"* (`enabled = !isSyncing && isSensorPaired`), keep *"Ignorieren"* (`Dismiss`) enabled (`enabled = !isSyncing`), and display a semantic warning/error unpaired hint (Material vector icon, zero inline emojis) taking precedence over any stale generic `errorMessage`. Upon re-pairing (`allDevices` or `ON_RESUME`), the hint SHALL clear and *"Jetzt synchronisieren"* SHALL re-enable automatically.
- **`REQ-SET-125.4` (9-Locale Parity & Architecture Hygiene)**: Localize `polar_h10_retry_sync_unpaired_hint` and `polar_verity_retry_sync_unpaired_hint` across all 9 `app/src/main/res/values*/strings_devices.xml` locales (`EN, DE, ES, FR, IT, JA, NL, PL, PT`, zero inline emojis); enforce `ArchitectureConformanceContractTest` monolith caps and zero direct DB imports under `ui/aftermath/`.

## 2. Acceptance Criteria (Given-When-Then)
1. **Unpaired / Deleted Sensor**: *Given* a workout with `polarSyncPending == true` whose target Polar Verity Sense or H10 has `PAIRED = 0` or is deleted (even if a sibling Polar model is paired), *When* Workout Details opens, *Then* *"Jetzt synchronisieren"* is disabled, *"Ignorieren"* stays enabled, and the model-specific localized unpaired hint is shown (overriding any stale generic error).
2. **Re-Pair Recovery**: *Given* the unpaired banner is displayed, *When* the user re-pairs the target Polar sensor and returns (`allDevices` emission or `ON_RESUME`), *Then* the unpaired hint clears, *"Jetzt synchronisieren"* re-enables, and tapping it triggers `PolarRetrySyncCoordinator.startSync(...)`.
3. **Frame-0 Stability**: *Given* Workout Details renders before the initial async pairing query resolves (`initialValue = null`), *When* Frame 0 composes, *Then* no false unpaired hint or disabled-button flicker appears.
