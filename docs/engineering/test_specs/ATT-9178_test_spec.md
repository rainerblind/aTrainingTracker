## 1. Requirement Specification Delta (`REQ-CON-052`, `[Planned]`)
- **Attributes**: Priority: `High` | Type: `Functional` | Verification Method: `Unit` | System Requirement(s): `SYSREQ-TRK-002`
- **Refined Sub-Requirements (`REQ-CON-052.1`–`.3`)**:
  1. **`REQ-CON-052.1` (Tighter Extended Backoff Progression & `1m` Default)**: `SensorReconnectBackoffPolicy` SHALL compute lost-sensor reconnect/re-search delays along `1s -> 2s -> 4s -> 8s -> 16s -> 32s -> 64s -> 120s` capped at configured `finalPeriodMs` (`15_000 / 30_000 / 60_000 / 120_000 ms`, default `DEFAULT_FINAL_PERIOD_MS = 60_000 ms`), clamp live reductions immediately via `effectiveDelayMs()`, cap at `LEGACY_FAST_MAX_DELAY_MS = 16_000 ms` when disabled, and reset to `1_000 ms` on connect. `MyBTLEDevice.INITIAL_RECONNECT_DELAY_MS = 1000L` and `MAX_RECONNECT_DELAY_MS = 16000L` MUST remain unchanged (`SYSREQ-TRK-002`).
  2. **`REQ-CON-052.2` (MIA-Only Periodic Re-Search, Clean Give-Up & Session-End Reset)**:
     - `MyRemoteDevice` SHALL expose `hasConnectedInSession()` and `resetSessionConnectionState()` (set `true` on connection across `MyRemoteDevice.notifyStopSearching(true)`, `MyANTDevice` `DeviceState.TRACKING`, `MyBTLEDevice` `STATE_CONNECTED`/`CONNECTED_WITH_SERVICE`, and `PolarOnlineStreamingBridge.markBridgeConnected()`).
     - `DeviceSearchPeriodicRetryCoordinator.handleSearchStoppedForCurrentDevice()` SHALL schedule periodic re-search (`nextPeriodicResearchDelayMs`) ONLY when `current.hasConnectedInSession() == true` and periodic re-search is enabled; when `!current.hasConnectedInSession()` (never connected) and `!current.shouldKeepAliveOnSearchTimeout()` and `tries <= 1`, it MUST cancel device retry state, remove `deviceTries`, and invoke `detachAndGiveUpDevice` (`shutDown()` + removal from `mMyRemoteDevices`) with zero scheduled timers. `enqueueDeviceForPeriodicResearch()` MUST enforce `device === current` identity guard and re-verify `device.hasConnectedInSession()` (clearing `lastScheduledDelayByDeviceId` under `lock` and invoking `detachAndGiveUpDevice` if `false`).
     - `PolarOnlineStreamingBridge` SHALL gate `shouldKeepAliveOnSearchTimeout()` strictly on `!isShutDown && (hasConnectedInSession() || isOfflineGattYielded())`, gate `scheduleBackoffReconnect()` / `resumeAfterOfflineSync()` / `onSearchTimeout()` / `deviceDisconnected()` / `blePowerStateChanged(true)` strictly on `hasConnectedInSession()`, and in `resetSessionConnectionState()` (when `!isReceivingData() && !isSearching && !isOfflineGattYielded()`) also cancel `searchTimeoutJob`, clear `sessionOpenPendingFeatures`, and disconnect any pending `polarApi` session under `gattActionLock` without ever cancelling `searchTimeoutJob` while `isSearching == true`.
     - `MyBTLEDevice` SHALL preserve `REQ-SET-123` passive OS-managed `autoConnect = true` (`0` active scans, `0` `mReconnectRunnable`) for never-connected active-workout sensors, NEVER schedule `mReconnectRunnable` in `onConnectionStateChange(STATE_DISCONNECTED)` when `!mHasConnectedInSession && !isMidSessionOrWorkoutActive()` (calling `notifyStopSearching(false)` outside `mGattLock` if `isSearching()`), and in `resetSessionConnectionState()` abort on `CONNECTED_TO_GATT`/`CONNECTED_WITH_SERVICE`, skip GATT close when `mState == SEARCHING || isSearching()` (preventing search-queue wedge), and call `disconnectFromGattInternal(null, false, true)` strictly when `mState == DISCONNECTED && !isSearching()`.
     - `DeviceManager` SHALL eagerly instantiate `mPeriodicRetryCoordinator` in its constructor and unconditionally call `getPeriodicRetryCoordinator().onTrackingModeChanged(mode, mMyRemoteDevices)` **before** the `READY`/`IDLE` check in `mTrackingStateChangedReceiver` so `TRACKING`/`PAUSED -> READY`/`IDLE` cancels pending retries and calls `resetSessionConnectionState()` on every disconnected (`!isReceivingData()`) device while preserving actively connected sensors and pre-workout `READY` connected sensors.
  3. **`REQ-CON-052.3` (`15s / 30s / 1m / 2m` Presets, Legacy Clamping & 9-Locale Parity)**: `SensorSearchSettings` (`FINAL_PERIOD_OPTIONS_SEC = [15, 30, 60, 120]`, `DEFAULT_FINAL_PERIOD_SEC = 60`, `MIN = 15`, `MAX = 120`) SHALL clamp and snap persisted values (including legacy `ATT-8965` `300`/`600 s` -> `120 s` = `2m`) onto `{15, 30, 60, 120}`. `SearchSettingsDialog.kt`, `SensorSearchTuningSection.kt` (`TuningToggleItem` + `TuningSegmentedButtonRow`), `res/xml/prefs_search.xml` (`min=15, max=120, defaultValue=60`), and all 9 `res/values*/strings_devices.xml` locales SHALL present `15s / 30s / 1m / 2m` with full parity.

## 2. Acceptance Criteria (Given-When-Then) & System Invariants
- *Given* paired sensor A (never connected) and sensor B (previously connected, now MIA) with periodic re-search enabled, *When* search tries exhaust in `DeviceManager`, *Then* sensor A calls `shutDown()` and is removed with `0` periodic timers, while sensor B schedules backoff retries capped at `15s/30s/1m/2m`.
- *Given* sensor B (BLE or Polar Live-IMU) connected in `READY` or `TRACKING` and drops out of range, *When* retries fail, *Then* delays advance `1s -> 2s -> 4s -> 8s -> 16s -> 32s -> 64s -> 120s` capped at configured preset (`60s` default); *When* the workout ends (`TRACKING -> READY`), *Then* disconnected MIA sensor B resets `hasConnectedInSession = false` and cancels retries, while still-connected sensor C (`isReceivingData() == true`) remains connected.
- *Given* legacy SharedPreferences `periodicSensorResearchFinalPeriodSec = 300` or `600`, *When* `SensorSearchSettings`, `SearchSettingsDialog`, or `SensorSearchTuningSection` loads, *Then* it normalizes to `120` (`2m`) and highlights the `2m` segmented button across all 9 locales.
- **Invariants**: `MyBTLEDevice.MAX_RECONNECT_DELAY_MS == 16000L` & `mHasConnectedInSession` / `isMidSessionOrWorkoutActive()` preserved; `DeviceManager.java <= 1,708`, `MyBTLEDevice.java <= 1,500`, `PolarOnlineStreamingBridge.kt <= 1,500`, `TrainingApplication.java` untouched; `REQ-SET-123` passive workout `autoConnect = true` & `ATT-9175` Polar offline yield preserved; `0` new `src/main` test reads (`REQ-PRO-049.1`).
