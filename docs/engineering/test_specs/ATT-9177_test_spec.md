# Stage 2 Requirement & Test Specification — ATT-9177: Polar Verity Sense Optical PPI in Morning HRV Check & Baseline Isolation

- **Jira Ticket**: `ATT-9177` (2 SP, Epic `ATT-3539`)
- **Requirements**: `REQ-HRV-049` (`REQ-HRV-049.1`..`REQ-HRV-049.4`) in `docs/requirements/req_aftermath_periods.md`
- **Test Spec**: `TST-HRV-049` (`TST-HRV-049.1`..`TST-HRV-049.4`) in `docs/tests/tst_aftermath_periods.md`
- **Prerequisite Boundary**: `ATT-9176` (`PolarOnlineStreamingBridge` optical PPI acquisition) is `Zu erledigen`; `ATT-9177` defines the backward-compatible `@JvmOverloads` `RrBeatEvent.isOpticalPpi: Boolean = false` contract so `ATT-9176` plugs straight in without breaking Java callers (`ANTHeartRateDevice.java`).

## 1. Formal Requirements Summary (`REQ-HRV-049`)

- **`REQ-HRV-049.1` — Backward-Compatible Optical PPI Contract & Signal Quality Mode**:
  - `RrBeatEvent` SHALL add `val isOpticalPpi: Boolean = false` via `@JvmOverloads constructor(...)`, preserving binary/source compatibility for all Kotlin and Java (`ANTHeartRateDevice.java`) callers.
  - `HrvSignalQualityAnalyzer.analyze(...)` and `analyzeBeats(...)` SHALL add `@JvmOverloads` with optional `isOpticalPpi: Boolean = false`. When `isOpticalPpi == true`, `INSUFFICIENT_DATA` (`< 30` beats) and `HIGH_ARTIFACTS` (`> 5.0%`) SHALL remain strictly enforced, while ECG-specific `QUANTIZED_SYNTHETIC` (`> 55%` zero-diff) and `SMOOTHED_STREAM` (discordance / TPR) gates SHALL be bypassed (returning `VALID`).
- **`REQ-HRV-049.2` — Non-Sticky Morning HRV Optical UX, Start-Screen Eligibility, 9-Locale Parity & Rule 8.5 PNG**:
  - `MorningHrvCheckViewModel.handleRrBeat(event)` SHALL update `isOpticalPpiSession = event.isOpticalPpi` non-stickily during `READY`/`STABILIZING` (switching Verity Sense -> Polar H10 clears optical mode immediately) and derive `isOpticalPpiSession = bufferedBeats.any { it.isOpticalPpi }` during `MEASURING`/`completeMeasurement()`, passing `isOpticalPpi` to `HrvSignalQualityAnalyzer.analyzeBeats(...)` and storing `HrvSensorModality.OPTICAL_PPI` vs `ECG` on `computedEntry`.
  - `MorningHrvCheckScreen.kt` (`<= 1,450` LoC; extract helpers to `MorningHrvOpticalCards.kt` if needed) SHALL display an optical stillness/snug-contact guidance card when `isOpticalPpiSession == true` (outside pure-wellness mode), display optical armband fit/stillness artifact advice when `highArtifactWarning && isOpticalPpiSession`, and display an `Optical PPI` provenance badge on `ReadinessResultCard` when `entry.sensorModality == HrvSensorModality.OPTICAL_PPI`.
  - `ControlTrackingViewModel` (`0` production edits) eligibility for a paired Polar Verity Sense (`DeviceType.HRM`) + morning completion detection SHALL be verified by unit test.
  - All new UI strings SHALL achieve 100% 9-locale parity (`en`, `de`, `es`, `fr`, `it`, `ja`, `nl`, `pl`, `pt`) in `res/values*/strings_hrv.xml` (`TranslationParityTest`). A Rule 8.5 Light/Dark Compose preview PNG (`docs/engineering/walkthroughs/img/ATT-9177_morning_hrv_optical_ppi.png`) SHALL be captured and inspected (`private fun` `@Preview`, `0` `src/main` reads).
- **`REQ-HRV-049.3` — `HrvSensorModality`, SQLite v2->v3 Migration, `.attbackup` Parity & Per-Modality Primary Isolation**:
  - Introduce `HrvSensorModality` (`ECG`, `OPTICAL_PPI`; `fromNameOrDefault` defaulting to `ECG`).
  - Upgrade `HrvReadinessDbHelper.DB_VERSION` `2 -> 3` adding `sensor_modality TEXT NOT NULL DEFAULT 'ECG'` with exact schema parity across `onCreate (v3)`, `v1 -> v3`, and `v2 -> v3` (`Rule 64`), symmetric `toContentValues`/`fromCursor`/`fromCursorBatch` (`Rule 20`), and automatic `DatabaseSchemaRegistry` (`Rule 62`) / `DatabaseConnectionManager` `.attbackup` backup/restore symmetry (`DatabaseSchemaRegistryHrvTest` updated for `v3`).
  - Scope `HrvReadinessDatabaseManager.recomputePrimaryForDayInternal(...)` by `(date_iso, posture, sensor_modality)` so same-day ECG and optical entries never overwrite each other's `is_primary_for_day`; in `updateEntry(...)`, fetch the pre-update row and recompute the old `(dateIso, posture, sensorModality)` cohort whenever any key field changes; filter `getPrimaryEntriesInWindow(posture, startDateIso, endDateIso, sensorModality: HrvSensorModality? = null)` via `AND sensor_modality = ?` when specified.
- **`REQ-HRV-049.4` — ECG vs Optical SWC Baseline Isolation & `HrvReadinessTrendCard` Segmented Selector**:
  - `HrvReadinessCalculator.calculateReadiness(...)` (`@JvmOverloads`, default `sensorModality = HrvSensorModality.ECG`) and `HrvReadinessRepository.calculateReadiness(...)` SHALL strictly filter by `(posture, sensorModality)` so optical PPI readings never contaminate an ECG 60-day SWC baseline (and vice versa).
  - `HrvReadinessTrendMath.calculateTrendSeries(...)` SHALL isolate ECG vs Optical PPI cohorts, default to an available modality (`OPTICAL_PPI`) for optical-only athletes so charts are never blank, and populate `sensorModality`, `availableModalities`, and `seriesByModality` on `HrvTrendSeries`.
  - `HrvReadinessTrendCard.kt` SHALL display a modality provenance badge when optical data is active and render a `SingleChoiceSegmentedButtonRow` (`icon = {}`, per `docs/design_guidelines.md` §1) whenever both `ECG` and `OPTICAL_PPI` cohorts exist for the active posture, with **`0` edits to `AthleteProfileScreen.kt` (`1,975/1,975` LoC)**.
