## 3. Acceptance Criteria (Given-When-Then)

- **Given** an athlete opens `AthleteProfileScreen` (`AthleteProfileViewModel`) showing a PMC peak from a simulator test ride (even when `WorkoutRepository.allWorkouts` is unhydrated/empty), **When** that workout is deleted via single delete or bulk `deleteOldWorkouts`, **Then** all SQLite rows (including `ActiveDevices.db`) and sidecars (including `.salvage`) are purged, `WorkoutMutationEvent` fires post-commit, and the PMC peak, Cardio-Power point, and HRV training-load bar disappear immediately without app restart.
- **Given** a clustered workout absent from `_allWorkouts`, **When** `deleteWorkout(id)` or `deleteWorkoutCascade(id)` executes, **Then** its pre-delete snapshot is loaded from SQLite before deletion, `WorkoutClusterEngine.onWorkoutDeleted` and `WorkoutClusterRepository.syncClusterAfterWorkoutDeletion` decrement `hitCount` and refresh `_clusterStats`, and `_allWorkouts` / `PeriodsRepository` / `KnownLocationsViewModel` / `EquipmentViewModel` / `SportTypeViewModel` / `SportingJourneyViewModel` / `TrackingViewModel.cachedPowerBenchmarks` all reflect the deletion immediately.
- **Given** 3 old workouts deleted via `deleteOldWorkouts(daysToKeep)`, **When** `deleteOldWorkoutsCascade` returns, **Then** every SQLite row and sidecar for all 3 workouts is already committed as deleted before resync starts, emitting exactly 1 `WorkoutMutationEvent.BulkDeleted`.
