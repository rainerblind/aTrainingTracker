## 3. Acceptance Criteria (Given-When-Then)

- **Given** a 1-Hz sample at `t = confirmTime` (`TIME_TOTAL = 1353 s`) snapshotted `oldLapNr = 4` (or torn `5`), or a delayed sample at `t = 1299 s` / `1320 s`, or a `TIME_TOTAL IS NULL` row with UTC `time`, **When** `onMultisportTransitionIntent()` runs `advanceLapsFn()` and `backfillWorkoutSamplesLapNumbers()` concurrently with `TrackerService.sampleAndWriteToDb()`, **Then** `row(1353).LAP_NR == 6`, `row(1320).LAP_NR == 5`, `row(1299).LAP_NR == 4`, `summaryValues.LAPS == 6` across all three, the `TIME_TOTAL IS NULL` row is tagged `6`, and `row[i].LAP_NR <= row[i+1].LAP_NR` holds across `WorkoutSamples.db`.
- **Given** multiple consecutive multisport transitions (`Run -> T1 -> Bike -> manual lap -> T2 -> Run`) under concurrent 1-Hz writes and rapid Stop/Start or cold-resume (`null` -> non-null `baseFileName`), **When** all transitions complete and `endWorkout()` finishes, **Then** every `[exitS, enterS)` row carries `transitionLapNr`, every `>= enterS` row carries `newLegLapNr` (or higher manual/later lap), and zero orphaned older `LAP_NR` rows exist.
- **Given** deterministic interleaving, Robolectric `TrackerService` wiring, and multi-threaded stress tests reproducing `row 425`, **When** executed, **Then** zero non-monotonic `LAP_NR` anomalies occur, zero deadlocks occur, and main-thread zero-SQLite invariants remain intact.
