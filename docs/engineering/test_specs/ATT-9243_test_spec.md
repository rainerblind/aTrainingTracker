| **`REQ-SET-123.1`** | `MyBTLEDevice.mSearchTimeoutRunnable` SHALL preserve `isMidSessionOrWorkoutActive()` (`DetailedDesignParityContractTest`) and distinguish previously connected (`mHasConnectedInSession == true`) vs. never-connected (`!mHasConnectedInSession && isMidSessionOrWorkoutActive()`) paired BLE devices during `TRACKING`/`PAUSED`. Never-connected workout timeouts SHALL stop scan-assist, set `State.DISCONNECTED`, arm `mIsBackgroundReconnecting = true`, cancel and MUST NOT schedule `mReconnectRunnable`, converge to a single passive OS-managed `connectGatt(..., autoConnect = true, ..., TRANSPORT_LE)` handle (replacing any non-`autoConnect` GATT opened when Try 1 started in `READY` before transitioning to `TRACKING`, while preserving an existing `autoConnect = true` handle), and release `DeviceManager` via `notifyStopSearching(false)`. `READY` (`!isMidSessionOrWorkoutActive()`) SHALL retain `disconnectFromGatt()` + `notifyStopSearching(false)`. Later passive `STATE_CONNECTED (GATT_SUCCESS)` SHALL set `mHasConnectedInSession = true` and reset `mCurrentReconnectDelayMs = 1000L`. |
| **`REQ-SET-123.2`** | `MyBTLEDevice.initiateScanAndConnect(boolean allowScanAssist)` SHALL invoke `startScanAssistance(btAdapter)` only when `allowScanAssist == true`: `startSearching()` SHALL pass `true` (bounded initial discovery scan), while `attemptBackgroundReconnect()` SHALL pass `mHasConnectedInSession` (`0` `sScanTimestamps` consumed by never-connected devices, preserving Android's 4-in-30s scan quota for mid-workout drop recovery and `ATT-9155` `BleHrmSilentConnectionWatchdog` `triggerSilentConnectionReconnect()`). `attemptBackgroundReconnect()` SHALL skip scheduling `mSearchTimeoutRunnable` when `!mHasConnectedInSession && isMidSessionOrWorkoutActive()` (including post-`resumeGattOperations()`), while keeping `mSearchTimeoutRunnable` for `mHasConnectedInSession \|\| !isMidSessionOrWorkoutActive()` (`READY`). On `onConnectionStateChange(STATE_DISCONNECTED)` (or `status != GATT_SUCCESS`) when `!mIsShutDown && !mHasConnectedInSession && isMidSessionOrWorkoutActive()`, reconnect delay SHALL be floored at `>= 60_000 ms`, while preserving `1s -> 2s -> 4s -> ...` backoff for `mHasConnectedInSession == true` and `READY` disconnects. |
| **`REQ-SET-123.3`** | In `DeviceSearchPeriodicRetryCoordinator.handleSearchStoppedForCurrentDevice()`, when `!success`, `current.shouldKeepAliveOnSearchTimeout()` SHALL be checked **before** `tries <= 1`. When `true`, the coordinator SHALL call `deviceTries.remove(current)` and MUST NOT re-enqueue `current` for redundant tries `2..N`, schedule periodic re-search, or invoke `detachAndGiveUpDevice` (`3` absent paired BLE sensors execute `3` initial scans total instead of `9`, strictly `<= 4` in `30 s` with `0` quota throttles). | **`REQ-SET-123.4`** | `DeviceManager.java` (`<= 1,708` LoC) and `PolarOnlineStreamingBridge.kt` (`<= 1,500` LoC) MUST remain strictly untouched; `MyBTLEDevice.MAX_RECONNECT_DELAY_MS == 16000L`, `MAX_SCANS_IN_WINDOW == 4`, and all `DetailedDesignParityContractTest` symbols MUST remain intact; `docs/architecture/detailed_design/my_btle_device.md` SHALL be synchronized in Stage 3/4; `Localization Parity: N/A`. |

## 2. Acceptance Criteria (`Given-When-Then`)
1. **Never-Connected Multi-Sensor Passive Convergence (`REQ-SET-123.1`, `.3`)**: *Given* `3` absent never-connected paired BLE sensors during `TRACKING` or `PAUSED`, *When* initial searches time out across the queue, *Then* `DeviceSearchPeriodicRetryCoordinator` removes each from `deviceTries` without re-enqueueing tries `2..3`, total active scans remain `3 <= 4` (`0` quota throttles), each transitions to `State.DISCONNECTED` (`isSearching == false`, `mIsBackgroundReconnecting == true`) with passive `connectGatt(..., autoConnect = true, ..., TRANSPORT_LE)`, and `0` `mReconnectRunnable` retries are scheduled.
2. **`READY -> TRACKING` Transition Edge (`REQ-SET-123.1`)**: *Given* Try 1 starts in `TrackingMode.READY` (opening `autoConnect = false` GATT) and tracking transitions to `TRACKING` before timeout, *When* `mSearchTimeoutRunnable` runs, *Then* the non-`autoConnect` GATT is replaced cleanly by passive `connectGatt(..., autoConnect = true, ..., TRANSPORT_LE)` with `0` `mReconnectRunnable` scheduled.
3. **Spurious Disconnect Floor & `attemptBackgroundReconnect` Timeout Skip (`REQ-SET-123.2`)**: *Given* a never-connected BLE sensor during `TRACKING`/`PAUSED` receives `STATE_DISCONNECTED` (`status = 133`/`8`), *When* `onConnectionStateChange` and `attemptBackgroundReconnect()` (or `resumeGattOperations()`) run, *Then* delay is floored at `>= 60_000 ms`, `mSearchTimeoutRunnable` and `startScanAssistance()` are skipped (`0` `sScanTimestamps` added), and passive `autoConnect = true` is maintained.
4. **Mid-Workout Drop, Wake-Up Upgrade & Silent-HR Watchdog Preservation (`REQ-SET-123.1`, `.2`)**: *Given* a session-connected sensor (`mHasConnectedInSession == true`, including one initially awakened via passive `autoConnect = true` or `ATT-9155` `BTLEHeartRateDevice` silent-HR watchdog), *When* it disconnects or times out during reconnect, *Then* fast `1s -> 2s -> 4s -> 8s -> 16s -> ...` backoff, `mSearchTimeoutRunnable`, and active `startScanAssistance()` execute cleanly.
5. **`READY` Mode Startup Preservation (`REQ-SET-123.1`, `.2`, `.3`)**: *Given* `TrackingMode.READY` with `!mHasConnectedInSession`, *When* offline sensors time out or disconnect, *Then* tries `2..N`, periodic re-search / `shutDown()` bounds, and `attemptBackgroundReconnect()` `mSearchTimeoutRunnable` remain unchanged.

## 4. Chesterton's Fence Audit (`REQ-PRO-022`) & System Invariants
* **Original Requirement ID & Target**: Historical `ATT-7755`, `ATT-8998`, and `ATT-8965` reconnection contracts (full `REQ-*` cross-refs preserved in `docs/requirements/req_settings_profiles.md`) targeting `MyBTLEDevice.java`, `DeviceSearchPeriodicRetryCoordinator.kt`, and `docs/architecture/detailed_design/my_btle_device.md`.
* **Historical Origin & Commit Trace**: `3dc19303` (`ATT-7755`), `d2209175` (`ATT-8998`), `6bb37af4` (`ATT-8965`), `f7ed7d94` (`ATT-9155`).
* **Root Reason for Existing Formulation**: `ATT-7755` included `TRACKING`/`PAUSED` in `isMidSessionOrWorkoutActive()` so sensors powered on mid-ride could still connect, and `ATT-8998` preserved that branch while unblocking `mSearchQueue`—inadvertently exposing never-connected absent paired devices to active `1s -> 2s -> 4s` scan-assist loops and redundant tries `2..N`.
* **Preservation of Core Invariants**: Session-connected mid-workout drops retain fast `1s -> 2s -> 4s -> 8s -> 16s -> ...` backoff + active scan-assist; never-connected active-workout sensors retain OS-managed passive `autoConnect = true` (zero active scans, zero queue deadlock, automatic upgrade upon mid-ride wake-up); `READY` offline startup bounds, `ATT-9155` silent-HR watchdog, `PolarOfflineGattCoordinator` pause/resume, `DetailedDesignParityContractTest`, and untouched `DeviceManager.java` / `PolarOnlineStreamingBridge.kt` ceilings remain 100% intact.
