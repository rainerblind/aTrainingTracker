## 1. Requirement Specification (`REQ-CON-062`, `[Planned]`)
- **Attributes**: Priority: `Medium` | Type: `Functional` | Verification Method: `Unit` | System Requirement(s): `SYSREQ-TRK-001` | Localization Parity: `N/A - 0 string changes`
- **Sub-Requirements (`REQ-CON-062.1`–`.3`)**:
  1. **`REQ-CON-062.1` (Universal `MyBTLEDevice` `0x2A29` Manufacturer Name Reconnect Backfill)**: A dedicated helper `BleDisReconnectBackfillHelper` (`com.atrainingtracker.banalservice.devices.bluetooth_le`) invoked from `MyBTLEDevice.readNextCharacteristic()` immediately after `configureServices(gatt)` SHALL inspect `UUID_SERVICE_DEVICE_INFORMATION` (`0x180A`) -> `UUID_CHARACTERISTIC_MANUFACTURER_NAME` (`0x2A29`) for **all** `MyBTLEDevice` subclasses (Heart Rate, Radar, Cycling Speed/Cadence/Power, Running Speed) and enqueue a serialized `ReadCharacteristicOp` via `enqueueReadCharacteristic()` strictly when: (a) `!mIsShutDown && !isGattPaused() && deviceId > 0`, (b) `needsManufacturerBackfill(getManufacturerName())` is `true` (value is `null`, blank/whitespace-only, or contains `'\u0000'`), and (c) no `0x2A29` read is already queued in `mGattQueue`. Once `manufacturerName` is cleanly populated (non-null, non-blank, zero `'\u0000'`), subsequent reconnects SHALL enqueue `0` `0x2A29` reads. Missing `0x180A` or `0x2A29` SHALL be a silent no-op.
  2. **`REQ-CON-062.2` (Sanitized, Non-Blocking, Stale-Safe `0x2A29` Read Persistence)**: Inside `MyBTLEDevice.mGattCallback.onCharacteristicRead()`, strictly on `status == BluetoothGatt.GATT_SUCCESS` with a non-null cloned `obtainSnapshotCharacteristic` snapshot, `BleDisReconnectBackfillHelper.onDisCharacteristicRead()` SHALL decode `0x2A29` via `BleDisStringSanitizer.readSanitizedString(snapshot)` and, when non-null, post `applyBackfilledManufacturerName(gatt, sanitized)` onto `mHandler` (returning immediately so Binder calls `onGattOperationCompleted()` without waiting on SQLite). `applyBackfilledManufacturerName()` MUST re-verify `!mIsShutDown && !mIsGattPaused && mBluetoothGatt != null && gatt == mBluetoothGatt` under `mGattLock` before invoking `setManufacturerName(sanitized)` (updating both `mCachedManufacturerName` and `Devices.db`). Failed reads (`status != GATT_SUCCESS`), blank/NUL-only payloads (`"\u0000"`, `"   "`), and stale/superseded GATT handles SHALL NOT overwrite persisted data and SHALL NOT re-enqueue retries within the same connection.
  3. **`REQ-CON-062.3` (Deduplicated Polar `0x2A24`/`0x2A25` Reconnect Backfill & Alias Hydration)**: `BTLEHeartRateDevice.configureServices(gatt)` SHALL delegate Polar DIS (`0x2A24` Model Number, `0x2A25` Serial Number) backfill to `BleDisReconnectBackfillHelper.enqueueMissingPolarDisReads()` (still strictly before `super.configureServices(gatt)` HR CCCD and gated on `hasPmd || hasPftp` so non-Polar HRMs never read or pollute `PolarOfflineCapabilityStore` per `REQ-CON-049.2`): enqueue `0x2A24` only when `PolarOfflineCapabilityStore.getModelNumber(ctx, mac)` is `null`, and enqueue `0x2A25` only when `PolarOfflineCapabilityStore.getPolarDeviceId(ctx, mac)` is `null`. Whenever `existingPolarId != null` causes `0x2A25` to be skipped, the helper SHALL invoke `PolarOfflineGattCoordinator.registerDeviceAliases(existingPolarId, mac)` to preserve in-memory alias matching across cold starts. `BTLERadarDevice` per-connect `0x2A24` registration (`REQ-CON-031.1`) SHALL remain independent with zero duplicate `0x2A24` reads.

## 2. Acceptance Criteria (Given-When-Then) & System Invariants
- *Given* any paired `MyBTLEDevice` (Cycling Speed/Cadence, Power, Footpod, Radar, or HRM) whose persisted `manufacturerName` is `null`, `""`, or `"Wahoo\u0000"`, *When* `onServicesDiscovered` -> `readNextCharacteristic` completes and the peripheral exposes `0x180A`/`0x2A29` returning `"Wahoo Fitness\u0000"`, *Then* `0x2A29` is enqueued *after* `configureServices(gatt)` via `mGattQueue`, `"Wahoo Fitness"` is persisted via `mHandler` (`setManufacturerName`), `mGattOperationPending` clears immediately on Binder, and a subsequent reconnect enqueues `0` `0x2A29` reads.
- *Given* a `0x2A29` read returning `status != GATT_SUCCESS`, a NUL-only payload `"\u0000\u0000"`, or a stale/superseded `BluetoothGatt` handle (or shut-down/paused device), *When* `onCharacteristicRead` fires, *Then* `setManufacturerName` is never called, `mGattQueue` advances cleanly, and no retry loop is enqueued.
- *Given* a Polar BLE HRM (`hasPmd || hasPftp`) reconnecting with (a) empty store, (b) only `modelNumber` populated, or (c) both `modelNumber` and canonical 8-hex `polarDeviceId` populated, *When* `BTLEHeartRateDevice.configureServices(gatt)` runs, *Then* (a) enqueues `0x2A24` + `0x2A25` before HR CCCD, (b) enqueues only `0x2A25` before HR CCCD, and (c) enqueues `0` Polar DIS reads while hydrating `PolarOfflineGattCoordinator.matchesDeviceIdentifier(polarId, mac) == true`.
- **Invariants**: `MyBTLEDevice.java <= 1,500` LoC (`1,494 -> 1,497/1,500`); `DevicesDatabaseManager.java` untouched (`1,665/1,671`); `BTLERadarDevice.java` untouched (`1,333`); `0` duplicate DIS reads; `0` UI/string changes (`N/A - 0 string changes`); `0` `src/main` test reads (`REQ-PRO-049.1`); `REQ-CON-049` non-Polar isolation & `REQ-CON-031` Radar StVZO preserved; `docs/architecture/detailed_design/my_btle_device.md` updated (`REQ-PRO-114`).
