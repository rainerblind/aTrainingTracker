## 2. Detailed Test Cases (Given-When-Then)
1. **`TST-UI-2800.1` (Repository Dispatchers, Conflation, Sparkline/W'bal Liveness & Concurrency)**:
   * *Given* default `BANALServiceRepository`, `WorkoutRepository`, `EquipmentRepository`, and `SportTypesRepository`, *When* inspecting their coroutine dispatchers, *Then* none uses `Dispatchers.Main` (`BANALServiceRepository`/`WorkoutRepository` = `Dispatchers.Default`; `EquipmentRepository`/`SportTypesRepository` = `Dispatchers.IO`).
   * *Given* two `FilteredSensorData` snapshots with identical `(sensorType, value, stringValue, deviceName, deviceId, filterType, filterConstant)` including `Double.NaN` values and differing `mTimestamp`, *When* compared and emitted into `_allFilteredSensorData`, *Then* `a == b`, `a.hashCode() == b.hashCode()`, `_allFilteredSensorData` conflates without extra emission, steady-value `showGraph` sparklines still advance via `_sparklineTick`, and steady numeric `W_PRIME_BAL` refreshes `scheduleWPrimeStaleCheck()` via `_wPrimeTelemetryHeartbeat` without falsely flipping STALE (while dropping `W_PRIME_BAL` still marks STALE after `STALE_TIMEOUT_MS`).
   * *Given* `bindToBANALService()` returning `false`/throwing OR followed by `unbindFromBANALService()`/`forceUnbindFromBANALService()` before `onServiceConnected`, *When* unbound or late `onServiceConnected`/`onServiceDisconnected` fires, *Then* `connectionLock` keeps state consistent (`isBinding == false`, `isBoundToBanalService == false`, `_serviceBinder.value == null`) with zero leaked connections; concurrent `applyRetroactiveAltitudeCorrection`, `loadAndApplyItpmsBaseline`, and `persistConvergedCircumferences` preserve `trackLock`/`itpmsLock` invariants.
2. **`TST-UI-2800.2` (`RrArtifactFilter` `O(N)` Equivalence, 92-Element Causal Window & Thread Safety)**:
   * *Given* a 300-beat RR window (exceeding `QD_WINDOW_SIZE + 1 == 92` for `filterLiveCausal` `[i - 86, i + 6)`) containing normal, ectopic, missed, short, and gap beats, *When* running `filterLiveCausal` and `filterBidirectionalBeats` (including concurrent multi-thread invocations on one shared `RrArtifactFilter` instance), *Then* outputs match reference classification bit-for-bit with zero `ArrayIndexOutOfBoundsException`, zero shared mutable scratch fields, and 50 consecutive 300-beat runs finish `< 250 ms` on JVM.
3. **`TST-UI-2800.3` (`ProxySensor`, `FilterManager` Single Push & End-to-End Device Rename Survival)**:
   * *Given* a `ProxySensor` wrapping an active `MySensor` holding `150.0` (and concurrent `setSourceSensor` swap), *When* `addSensorListener(listener)` is called, *Then* `listener.newValue` receives `150.0` strictly once (never spurious `null`) and concurrent source swaps re-attach cleanly without holding `mSourceLock`.
   * *Given* a `NumberedMovingAverageFilter` rebound via `FilterManager.rebindFilter` to a sensor holding `200.0`, *When* `100.0` subsequently arrives, *Then* `200.0` is ingested strictly once (`avg == 150.0`).
   * *Given* a pinned device `deviceId = 42L` renamed from `"Old Name"` to `"New Name"`, *When* `rebindExistingFilters()` runs and live telemetry emits, *Then* `FilterData.hashKey` remains `"id:42-..."`, `FilterManager.resolveSensor` returns `getMyDeviceById(42L).getSensor(...)` directly without falling back to `getMyDeviceByName`, `MyFilter.mDeviceName` syncs to `"New Name"`, and both `TrackingViewModel` tiles and `BANALServiceRepository` sparklines continue updating live via `deviceId`.
4. **`TST-UI-2800.4` (Cockpit 1-Hz Recomposition Bounds & Static Contracts)**:
   * *Given* `TrackingTabGridContent` receiving repeated 1-Hz `uiState` updates, *When* recomposing, *Then* `gridActions` maintains strict referential equality (`===`).
   * *Given* `TrackingTabsScreen` under `DisplayBrightnessMode.SYSTEM`, `DisplayBrightnessMode.CUSTOM`, and `DisplayBrightnessMode.AUTO`, *When* `allFilteredSensorData` and `currentLocation` emit 5 consecutive 1-Hz ticks, *Then* `allFilteredSensorData` is NOT collected in `SYSTEM`/`CUSTOM`, `batterySaverController.updateTelemetry` is called `0` times in `SYSTEM`/`CUSTOM` and `5` times in `AUTO`, root `TrackingTabsScreen` recomposes `0` extra times on 1-Hz sensor/GPS ticks, and `beyondViewportPageCount == 0` holds.
   * *Given* all modified files, *When* `ArchitectureConformanceContractTest` runs, *Then* `DeviceManager.java <= 1,708`, `WorkoutRepository.kt <= 5,117`, `TrackingViewsDatabaseManager.java <= 2,631`, and `0` new compiler warnings occur.
