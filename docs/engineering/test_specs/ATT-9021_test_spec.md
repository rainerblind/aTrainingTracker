## 3. Acceptance Criteria (Given-When-Then)

- **Given** an existing `WorkoutSummaries.db` at version `<= 31` lacking the `epic` column, **When** `WorkoutSummariesDbHelper.onUpgrade` runs to version `32`, **Then** the `epic` column exists (`int DEFAULT 0`), all pre-existing workouts read `epic = false` (`0`) without data loss, and schema matches a fresh `onCreate` database.
- **Given** a workout marked as `race = true` (or `commute = true` / `trainer = true`), **When** `EditWorkoutViewModel.updateIsEpic(true)` is called, live telemetry refreshes, and `WorkoutRepository.saveWorkout` persists the workout, **Then** both flags remain `true` simultaneously in memory and across SQLite reload.
- **Given** a workout with `epic = true`, **When** exported to `.fit` via `FitFileWriter` and parsed/imported via `FitWorkoutParser` + `LegacyImportEngine`, **Then** `ParsedWorkoutData.isEpic == true` and the imported SQLite row stores `epic = 1` (`true`); conversely, a legacy or third-party `.fit` file without `is_epic` imports cleanly with `isEpic = false`.
