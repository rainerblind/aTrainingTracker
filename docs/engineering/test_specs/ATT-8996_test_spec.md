# Stage 2: Requirement & Test Specification — ATT-8996

**Ticket**: `ATT-8996` (`2 SP`, `tier-a`, Epic `ATT-5910`) | **Target Release**: `V5.0.0` | **Branch**: `feature/ATT-8996` | **Requirement**: `REQ-CON-060` (`SYSREQ-TRK-001`) | **Test Spec**: `TST-CON-060` | **Date**: 2026-11-24

## 1. Requirement Specification (`REQ-CON-060`, `[Planned]`)
- **Attributes**: Priority: `Medium` | Type: `Functional` | Verification Method: `Unit` | System Requirement(s): `SYSREQ-TRK-001` | Localization Parity: `N/A - 0 string changes`
- **Sub-Requirements (`REQ-CON-060.1`–`.3`)**:
  1. **`REQ-CON-060.1` (Shared BLE GATT/DIS String Sanitizer & All Read Sites)**: A reusable pure-JVM `@JvmStatic` utility `BleDisStringSanitizer` (`com.atrainingtracker.banalservice.devices.bluetooth_le`) SHALL strip all `'\u0000'` bytes (`U+0000` — leading, embedded, and trailing) and trim leading/trailing whitespace via `sanitize(raw: String?): String?` (returning `null` when input is `null`, empty, whitespace-only, or NUL-only), expose `readSanitizedString(characteristic: BluetoothGattCharacteristic?): String?` and `containsNul(value: String?): Boolean`, and preserve UTF-8 non-ASCII characters intact. Every BLE GATT/GAP/Polar DIS string read—`BTSearchForNewDevicesEngine` (`0x2A29` Manufacturer Name, `0x2A24` Model Number, `0x2A25` Serial Number, `gatt.getDevice().getName()`), `BTLEHeartRateDevice` (`0x2A24`, `0x2A25`), `BTLERadarDevice` (`0x2A24`), and `PolarPmdStreamCoordinator.recordDisCharacteristic()` (backing `PolarOnlineStreamingBridge` DIS callbacks)—SHALL decode through `BleDisStringSanitizer` before storage, classification, or alias registration.
  2. **`REQ-CON-060.2` (`PolarOfflineCapabilityStore` & `PolarOfflineGattCoordinator` NUL-Safe Read, Compare & Self-Healing)**: `PolarOfflineCapabilityStore` SHALL sanitize all inputs and persisted reads across `isValidCanonicalPolarId()`, `recordDisMetadata()`, `recordSdkDeviceType()`, `seedLegacyDeviceTypeIfUnknown()`, `classifyModelNumber()`, `getModelNumber()`, `getPolarDeviceId()`, and `normalizeMac()`. When `getModelNumber()` or `getPolarDeviceId()` reads a legacy SharedPreferences value containing `'\u0000'` or unnormalized whitespace, it SHALL return the sanitized value (or `null` if blank/invalid) and self-heal the SharedPreferences key (overwriting with the clean value or removing blank/invalid entries). `PolarOfflineGattCoordinator` SHALL sanitize `name` and `manufacturer` in `isPolarH10Name()`, `isPolarVeritySenseName()`, and `hasExplicitNonPolarManufacturer()` so NUL-only `"\u0000"` is treated as blank rather than an explicit non-Polar manufacturer.
  3. **`REQ-CON-060.3` (`Devices.db` Write/Read Sanitization & Idempotent v14->v15 Migration)**: `DevicesDatabaseManager` SHALL sanitize `name` and `manufacturerName` on writes (`insertNewBluetoothDeviceIntoDB`, `insertNewAntDeviceIntoDB`, `setManufacturerName`) and reads (`getManufacturerName`, `getDeviceName`, `getAllDevicesForCache`, `getDeviceIdAndNameLists`, `getCriticalBatteryDevices`, `getSensorsForSportType`, `getAllRemoteSensors`); `RawDeviceDataProvider.getDeviceData()` and `DeviceDataRepository.createContentValuesForUpdate()` SHALL sanitize `MANUFACTURER_NAME` and `NAME`. `DevicesDbHelper` SHALL increment `DB_VERSION` from `14` to `15` (preserving identical `onCreate`/`onUpgrade` table schema and `DatabaseSchemaRegistry` parity) and execute idempotent `BleDisStringSanitizer.sanitizeExistingDevicesTable(db)` in `onUpgrade(oldVersion <= 14 && newVersion >= 15)` to strip `'\u0000'` bytes and surrounding whitespace from existing `Devices4.manufacturerName` and `Devices4.name` rows (setting NUL-only values to SQL `NULL` while leaving already-clean rows untouched).

## 2. Acceptance Criteria (Given-When-Then) & System Invariants
- *Given* BLE GATT characteristics returning `"Polar Electro Oy\u0000"`, `"Sense\u0000"`, `"A1B2C3D4\u0000"`, `"RTL516\u0000"`, or `"\u0000\u0000"`, *When* read by `BTSearchForNewDevicesEngine`, `BTLEHeartRateDevice`, `BTLERadarDevice`, or `PolarPmdStreamCoordinator`, *Then* stored/classified values contain zero `'\u0000'` bytes (`"Polar Electro Oy"`, `"Sense"` -> `VERITY_SENSE` with Polar services, `"A1B2C3D4"` valid canonical Polar ID, `"RTL516"` -> StVZO `true`, and `"\u0000\u0000"` -> `null`).
- *Given* legacy `SharedPreferences` in `PolarOfflineCapabilityStore` pre-seeded with `model_num_<MAC> = "Sense\u0000"` and `polar_id_<MAC> = "abcd1234\u0000"`, *When* `getModelNumber()`, `getPolarDeviceId()`, or `getDeviceType()` is called, *Then* sanitized `"Sense"` / `"ABCD1234"` / `VERITY_SENSE` are returned and the persisted SharedPreferences entries are rewritten cleanly without `'\u0000'`.
- *Given* an existing v14 `Devices.db` containing `("Polar H10 12345678\u0000", "Polar Electro Oy\u0000")`, `("Clean Sensor", "Garmin")`, and `("Bad\u0000", "\u0000")`, *When* `DevicesDbHelper.onUpgrade(db, 14, 15)` runs (including repeated idempotent calls), *Then* dirty rows become `("Polar H10 12345678", "Polar Electro Oy")` and `("Bad", NULL)`, clean rows remain untouched, and fresh `onCreate` and upgraded `onUpgrade` schemas are 100% identical with `DatabaseSchemaRegistry.getMaxSupportedVersion("Devices.db") == 15`.
- **Invariants**: `MyBTLEDevice.java` untouched (`1,494/1,500` LoC); `DevicesDatabaseManager.java <= 1,671` LoC; `PolarOfflineGattCoordinator.kt <= 1,500` LoC; `0` UI/string changes (`N/A - 0 string changes`); `0` `src/main` test reads (`REQ-PRO-049.1`); all `REQ-CON-049` Polar hardware-precedence & `REQ-CON-031` StVZO radar invariants preserved.
