# Test Specification & Requirement Synchronization - ATT-1472: Theme-Aware Post-Workout Share Snapshot Canvas and Footer

## 1. Feature / Bug Overview & Test Scope

* **Issue Key**: `ATT-1472` (Parent) / `ATT-1476` (Stage 2: Test-Spec)
* **Parent Epic**: `ATT-1157` (*Optimize dark mode*)
* **Target Version**: `V4.9.38` (Sprint `2026-39.3`)
* **Related Requirements**: `REQ-UI-177` (*Theme-Aware Post-Workout & Period Share Snapshot Canvas and Footer*), refining `REQ-UI-059` (*Robust & Asynchronous Workout Sharing*) and `REQ-UI-101` (*Neutral Backgrounds*)
* **Related Tests**: `TST-UI-129` (*Theme-Aware Share Snapshot Color Harmonization Verification*)

### Objective
Ensure that post-workout and period summary share snapshots generated by `ShareUtils.kt` dynamically adapt their canvas clear color and branding footer background/text colors based on the active theme (Dark Mode vs. Light Mode). Eliminate jarring white canvas seams and bright light-gray footer bars in Dark Mode while guaranteeing 100% visual and functional preservation of historical Light Mode behavior.

---

## 2. Requirement Archaeology & Chesterton's Fence Audit

1. **Original Requirement ID & Target**: `REQ-UI-059` (*Robust & Asynchronous Workout Sharing*) and `REQ-UI-101` (*Neutral Backgrounds*) in `docs/requirements.md`, targeting `ShareUtils.kt`, `MapDetailLayout.kt`, and `PeriodMapScreen.kt`.
2. **Historical Origin & Commit Trace**: Introduced during initial implementation of the workout sharing pipeline to stitch map and header snapshots with a clean, branded footer.
3. **Root Reason for Existing Formulation**: When `ShareUtils.kt` was originally authored, aTrainingTracker operated strictly in Light Mode; hardcoding `Color.WHITE` for the canvas background and `#F5F5F5` for the footer background with `Color.DKGRAY` text was standard. Following the introduction of Dark Mode and AMOLED Pure Black under Epic `ATT-1157`, these hardcoded light constants produce visual seams and a jarring bright white footer bar below dark workout graphics.
4. **Preservation of Core Invariants**: Historical Light Mode styling (`Color.WHITE`, `#F5F5F5`, `Color.DKGRAY`) is 100% preserved; binary and source compatibility for all callers is guaranteed via default argument `isDark`; FileProvider security, caching logic, and branding geometry remain unchanged.

## 3. Requirement Specification (`REQ-UI-177`)

### REQ-UI-177: Theme-Aware Post-Workout & Period Share Snapshot Canvas and Footer

The system SHALL adapt the composite image canvas background and branding footer colors to the active theme (Dark Mode vs. Light Mode) when generating shared workout and period snapshots (ATT-1472):

1. **Decoupled Theme Color Token Resolution (`ShareThemeColors` / `ShareThemeResolver`)**:
   - In `ShareUtils.kt`, the system SHALL resolve composite colors via `ShareThemeResolver.resolveColors(isDark: Boolean)` returning `ShareThemeColors`:
     - *Light Mode* (`isDark == false`): `canvasBackground = Color.WHITE`, `footerBackground = Color.parseColor("#F5F5F5")`, and `footerTextColor = Color.DKGRAY` (`#444444`).
     - *Dark Mode* (`isDark == true`): `canvasBackground = Color.BLACK` (`#000000`), `footerBackground = Color.parseColor("#1E1E1E")`, and `footerTextColor = Color.parseColor("#E0E0E0")`.
2. **Context-Aware Night Mode Detection & Call-Site Compatibility**:
   - The system SHALL provide `ShareThemeResolver.isNightMode(context: Context): Boolean` evaluating `(context.resources.configuration.uiMode and Configuration.UI_MODE_NIGHT_MASK) == Configuration.UI_MODE_NIGHT_YES`.
   - `combineAndShare` and `combineWorkoutAndShare` SHALL expose `isDark: Boolean = ShareThemeResolver.isNightMode(context)`, preserving 100% binary and source compatibility for existing callers (`MapDetailLayout.kt`, `PeriodMapScreen.kt`) while enabling explicit programmatic overrides.
3. **Contrast & WCAG 2.1 AAA Compliance**:
   - In Dark Mode, footer text (`#E0E0E0`) on footer background (`#1E1E1E`) SHALL achieve a contrast ratio $\ge 7:1$ (measured 13.5:1), fully satisfying WCAG 2.1 Level AAA.
   - In Light Mode, footer text (`Color.DKGRAY`) on footer background (`#F5F5F5`) SHALL maintain contrast ratio $\ge 7:1$ (measured 9.0:1), satisfying WCAG 2.1 Level AAA.
   - Canvas background in Dark Mode SHALL be `Color.BLACK` (`#000000`), seamlessly matching AMOLED dark map tiles and dark card containers without white border artifacts.
4. **Sharing Pipeline & Geometry Invariants**:
   - The system SHALL preserve footer height (125px), logo dimension ($80\times 80$), horizontal margin (24f), and text size (42f).
   - PNG compression (100% quality), cache file directory (`context.cacheDir/images`), `FileProvider` URI generation, and intent dispatch on `Dispatchers.Main` MUST NOT be altered.

#### Acceptance Criteria (Given-When-Then)

* **AC-1 (Light Mode Snapshot Color Fidelity)**:
  - *Given* an active application session operating in Light Mode,
  - *When* the user shares a workout summary (`combineWorkoutAndShare`) or period summary (`combineAndShare`),
  - *Then* the composite canvas background SHALL clear to `Color.WHITE`, the footer background SHALL be `#F5F5F5`, and the footer text SHALL be `Color.DKGRAY`.
* **AC-2 (Dark Mode Snapshot Color Harmonization)**:
  - *Given* an active application session operating in Dark Mode (or AMOLED mode),
  - *When* the user shares a workout summary or period summary,
  - *Then* the composite canvas background SHALL clear to `Color.BLACK`, the footer background SHALL be `#1E1E1E`, and the footer text SHALL be `#E0E0E0`.
* **AC-3 (Call-Site Backward Compatibility & Dynamic Resolution)**:
  - *Given* any caller invoking `combineWorkoutAndShare(context, hBmp, mapBitmap, eBmp)` without specifying `isDark`,
  - *Then* the function SHALL automatically evaluate `ShareThemeResolver.isNightMode(context)` and render the corresponding theme colors without error.
* **AC-4 (WCAG 2.1 AAA Contrast Compliance)**:
  - *Given* the resolved footer colors for both Light Mode and Dark Mode,
  - *When* contrast ratios are computed between footer text and footer background,
  - *Then* both configurations SHALL achieve a contrast ratio $\ge 7:1$.

## 4. Test Design & Test Cases (`TST-UI-129`)

### 4.1 Unit Test Suite: `ShareThemeResolverTest.kt`

A dedicated unit test file `app/src/test/java/com/atrainingtracker/trainingtracker/helpers/ShareThemeResolverTest.kt` will verify:

1. **`testLightModeColors_matchHistoricalDesignConstants`**:
   - Verify `ShareThemeResolver.resolveColors(isDark = false)` produces:
     - `canvasBackground == Color.WHITE`
     - `footerBackground == Color.parseColor("#F5F5F5")`
     - `footerTextColor == Color.DKGRAY`
2. **`testDarkModeColors_matchDarkThemeSpecification`**:
   - Verify `ShareThemeResolver.resolveColors(isDark = true)` produces:
     - `canvasBackground == Color.BLACK` (`0xFF000000.toInt()`)
     - `footerBackground == Color.parseColor("#1E1E1E")`
     - `footerTextColor == Color.parseColor("#E0E0E0")`
3. **`testWcagContrastRatios_exceedLevelAaaStandards`**:
   - Compute relative luminance and contrast ratio for Light Mode: `#444444` on `#F5F5F5` $\ge 7.0:1$ (measured ~9.0:1).
   - Compute relative luminance and contrast ratio for Dark Mode: `#E0E0E0` on `#1E1E1E` $\ge 7.0:1$ (measured ~13.5:1).
4. **`testNightModeDetection_evaluatesUiModeCorrectly`**:
   - Mock Android `Context` and `Configuration`.
   - Verify `Configuration.UI_MODE_NIGHT_YES` returns `true`.
   - Verify `Configuration.UI_MODE_NIGHT_NO` returns `false`.
   - Verify uninitialized/undefined flags default cleanly to `false`.

### 4.2 On-Device Verification (Google Pixel 10)

1. **Dark Mode Verification**:
   - Ensure Pixel 10 is configured in Dark Mode (`adb shell cmd uimode night yes`).
   - Navigate to workout map view (`MapDetailLayout`).
   - Tap Share icon -> Trigger image generation.
   - Inspect resulting image: Canvas background is pitch black, footer is dark (`#1E1E1E`), text is clear light gray (`#E0E0E0`), zero white seams.
2. **Light Mode Verification**:
   - Ensure Pixel 10 is configured in Light Mode (`adb shell cmd uimode night no`).
   - Open workout map view and share snapshot.
   - Inspect resulting image: Canvas background is white, footer is `#F5F5F5`, text is dark gray.
3. **Restore Ambient State**:
   - Restore device to default Light Mode (`Night mode: no`).
