## 1. Requirement Specification (`REQ-TRK-091`)

### 1.1 Attributes & System Traceability
- **System Requirement(s)**: `SYSREQ-TRK-005` (Background Foreground Service Execution & Power Management — minor `SYS.2`/`SYS.3` refinement adding `FOREGROUND_SERVICE_TYPE_SHORT_SERVICE` post-workout execution with zero new manifest permissions) & `SYSREQ-DEX-007` (Polar BLE PFTP/PMD Offline Recording & Post-Workout Backfill — asynchronous foreground-protected backfill prior to `ExportManager` export generation); bidirectional parity synced in `docs/system/sysreq_live_tracking.md`, `docs/system/sysreq_data_exchange.md`, `docs/system/system_software_traceability.md`, and `docs/system/system_architecture.md` (net-new Kotlin filenames deferred from `docs/system/` until Stage 4 per Rule 81).
- **Priority**: High | **Type**: Functional | **Verification Method**: Unit, Integration
- **Localization Parity**: 6 new notification strings across all 9 locales (`values/`, `de`, `es`, `fr`, `it`, `ja`, `nl`, `pl`, `pt`), `0` emojis, identical format specifiers.

### 1.2 Functional & Architectural Requirements
1. **`REQ-TRK-091.1` (Non-Blocking Stop Finalization, Armed-State Isolation & Asynchronous Post-Processing Pipeline)**:
   - `TrackerService.endWorkout()` SHALL persist `FINISHED = 1` first (`REQ-TRK-030.1`), save active devices, flush live RR intervals, save accumulated sensors & auxiliary metadata, run `finalizeLiveSession()`, close `PolarRawTelemetryRecorder.stopActiveSession()`, and synchronously capture a per-workout post-processing snapshot (`workoutId`, `baseFileName`, `h10Armed`, `h10StartMs`, `h10ArmedToken`, `verityArmed`, `verityStartMs`, `verityArmedToken`, `ertsEnabled`).
   - `TrackerService.endWorkout()` SHALL enqueue the snapshot onto `WorkoutPostProcessingCoordinator` and immediately broadcast `TRACKING_FINISHED_INTENT` (system + `LocalBroadcastManager`) so `EditWorkoutScreen` opens in `< 1 s` without blocking on Polar BLE PFTP transfers, HRV/ERTS recomputation, or `ExportManager.workoutFinished()`.
   - **Back-to-Back Armed-State Isolation**: `PolarH10OfflineController` and `PolarVeritySenseOfflineController` SHALL track a monotonic armed session token/generation (incremented on arming) so an earlier workout's async `stopAndBackfillWorkout()` `finally` block clears `isArmed` / armed metadata **strictly** when the active token still matches the stopping workout, never disarming a newly started subsequent workout.
   - `WorkoutPostProcessingCoordinator` SHALL execute stages sequentially per workout on a process-wide `SupervisorJob() + Dispatchers.IO` serialized queue with fault isolation per stage: (1) Polar H10 backfill (`showOwnNotification = false`, suppressing duplicate `8045`), (2) Polar Verity Sense backfill (`showOwnNotification = false`, suppressing duplicate `8046`), (3) `HrvPostWorkoutRecomputer` + optional `ErtsPostWorkoutRecomputer` followed by `WorkoutRepository.refreshWorkout(workoutId)`, (4) `ExportManager.workoutFinished(baseFileName)` followed by deferred `ExportManager.exportWorkout(freshWorkoutFromDb)` if requested.
2. **`REQ-TRK-091.2` (Atomic Export Deferral Lock & Edit-Safe Reactive Refresh)**:
   - `WorkoutPostProcessingCoordinator` SHALL guard `activeWorkouts` and `deferredExportWorkouts` under a **single synchronization lock** (`synchronized(stateLock)`): `deferExportIfPostProcessing(workoutId)` atomically marks `workoutId` for deferred export iff `workoutId in activeWorkouts` (returning `true`), and `completePostProcessing(workoutId)` atomically removes `workoutId` from `activeWorkouts` and returns whether deferred export was requested (zero check-then-act race).
   - `WorkoutRepository.saveWorkout(userEditedWorkout)` SHALL immediately persist editable fields (`summariesManager.updateWorkoutData`) and update `_allWorkouts` in memory (including `rpe` and `feel`). If `deferExportIfPostProcessing(workoutId)` returns `true`, `saveWorkout()` SHALL skip premature `exportManager.exportWorkout(...)`; upon pipeline completion, the coordinator SHALL reload the fresh `WorkoutData` from SQLite and invoke `exportManager.exportWorkout(freshWorkout)` so FIT/TCX/GPX/CSV/Strava/Health Connect exports contain **both** backfilled/smoothed telemetry and user-saved metadata. If post-processing is inactive, `saveWorkout()` SHALL trigger `exportManager.exportWorkout(...)` immediately as before.
   - `EditWorkoutViewModel` SHALL collect `repository.allWorkouts` filtered to `workoutId` and merge strictly **telemetry/derived fields** (distance, speed, ascent/descent, altitudes, polyline/streams, lat/lng bounds, HR/HRV metrics, `polarSyncPending`, `recordingErrors`) while strictly preserving **all** user-editable fields (`workoutName`, `sportId`, `sportName`, `bSportType`, `stravaSportName`, `equipmentId`, `equipmentName`, `clusterId`, `clusterName`, `rpe`, `feel`, `description`, `goal`, `method`, `commute`, `trainer`, `race`, `uploadToStrava`, `syncToHealthConnect`) and WITHOUT re-running initial sport/equipment suggestion rewrites (`suggestedSportTypeName`, `suggestedEquipmentName`, `currentBSportType`).
3. **`REQ-TRK-091.3` (`shortService` Foreground Host, Progress Notification `ID 8047` & 9-Locale Parity)**:
   - Declare `WorkoutPostProcessingService` in `AndroidManifest.xml` with `android:foregroundServiceType="shortService"` and **zero** new manifest permissions (`FOREGROUND_SERVICE_CONNECTED_DEVICE` / `"connectedDevice"` strictly absent per `MergedManifestFgsAuditTest`).
   - On API 34+, promote via `ServiceInfo.FOREGROUND_SERVICE_TYPE_SHORT_SERVICE` and implement `onTimeout(startId, fgsType)` to stop foreground cleanly without `RemoteServiceException`. On `ForegroundServiceStartNotAllowedException` / `IllegalStateException`, fall back cleanly to in-process coroutine execution + `NotificationManagerCompat`.
   - `WorkoutPostProcessingNotificationManager` (`NOTIFICATION_ID_POST_PROCESSING = 8047`, channel `TrainingApplication.NOTIFICATION_CHANNEL__EXPORT`, `CATEGORY_PROGRESS`, `PRIORITY_LOW`, `setProgress(totalSteps, currentStep, false)`) SHALL update localized stage copy (Polar H10 sync, Polar Verity Sense sync, HRV/track recompute, export finalization), enforce API 33+ `POST_NOTIFICATIONS` permission gating, cancel cleanly on normal completion, and post an auto-cancel non-ongoing warning on failure.
4. **`REQ-TRK-091.4` (Monolith Ceilings & Governance Invariants)**:
   - `TrackerService.java` MUST shrink (`< 3,539 / 3,559` LoC); `WorkoutRepository.kt <= 5,117` LoC; `PolarVeritySenseOfflineController.kt <= 1,500` LoC; `0` edits to `DeviceManager.java` & `DevicesDatabaseManager.java`; `0` SQLite schema migrations; `0` new `src/main` reads (`SourceTextReadingAuditContractTest`).

## 2. Requirement Archaeology & Chesterton's Fence Audit (`REQ-PRO-022`)
- **Original Requirement ID & Target**: `REQ-TRK-030` / `REQ-TRK-033` (`TrackerService.java`), `REQ-TRK-022` (`AndroidManifest.xml`, `MergedManifestFgsAuditTest.kt`), `REQ-SET-105` (`PolarH10OfflineController.kt`), `REQ-SET-109` (`PolarVeritySenseOfflineController.kt`), `REQ-SET-119` (`PolarOfflineGattCoordinator.kt`), `REQ-UI-211` (`EditWorkoutViewModel.kt`).
- **Historical Origin & Commit Trace**: `ATT-3986`/`ATT-4006`/`ATT-4099` (`aa0e9097`) moved `endWorkout()` onto FIFO `mDbExecutor` with isolated `FINISHED = 1` commit; `ATT-3567` purged `FOREGROUND_SERVICE_CONNECTED_DEVICE` (`REQ-TRK-022`); `ATT-7918` (`60ec5c3b`) and `ATT-7924` added synchronous Polar backfill & HRV/ERTS recompute before `ExportManager.workoutFinished()`; `ATT-8969` (`8e44039d`) added disconnected fast-fail & `5 s` connect timeout.
- **Root Reason for Existing Formulation**: Synchronous ordering in `endWorkout()` guaranteed Polar backfill and HRV/ERTS smoothing finished prior to `ExportManager` serialization.
- **Preservation of Core Invariants**: Preserves minimal `FINISHED = 1` commit first (`REQ-TRK-030.1`), Polar zero-gap fast paths & `5 s` connect timeout / disconnected fast-fail (`REQ-SET-105.1`, `REQ-SET-109.1`, `REQ-SET-119.3`), optical Verity Sense `WorkoutRr.db` isolation (`REQ-SET-109.2`), strict export ordering AFTER backfill + HRV + ERTS (`REQ-SET-105.5`), strict omission of `FOREGROUND_SERVICE_CONNECTED_DEVICE` (`REQ-TRK-022`), and `EditWorkout` hidden-field preservation (`REQ-UI-211`).

## 3. Acceptance Criteria (Given-When-Then)
- *Given* an active workout with Polar H10 and/or Verity Sense offline recording armed, *When* Stop is tapped, *Then* `TrackerService.endWorkout()` commits `FINISHED = 1`, captures armed tokens, enqueues `WorkoutPostProcessingCoordinator`, and broadcasts `TRACKING_FINISHED_INTENT` immediately (`< 1 s`), while async Polar backfill runs with `showOwnNotification = false` (no duplicate `8045`/`8046`) and an earlier async backfill exit never disarms a subsequent workout's newer armed token.
- *Given* background post-processing is active and the user edits name/RPE/Feel/notes/sport/equipment/flags on `EditWorkoutScreen` and taps Save early, *When* `WorkoutRepository.saveWorkout()` and `refreshWorkout(workoutId)` execute concurrently, *Then* unsaved/saved user edits are never overwritten, `rpe`/`feel` stay intact in `_allWorkouts`, premature exports are atomically deferred, and final exports run strictly after backfill + HRV + ERTS + `workoutFinished()` using the fresh SQLite row containing both backfilled/smoothed telemetry and saved metadata.
- *Given* post-processing runs after Stop (foreground or phone pocketed), *When* `WorkoutPostProcessingService` (`shortService`) executes stages, *Then* Progress Notification `8047` on `NOTIFICATION_CHANNEL__EXPORT` updates localized stage progress (permission-gated on API 33+), clears on completion (or updates to auto-cancel warning on failure), handles `onTimeout()` cleanly, and falls back to in-process coroutine + `NotificationManagerCompat` on `ForegroundServiceStartNotAllowedException`.
- *Given* static contract & parity tests run, *When* verified, *Then* `AndroidManifest.xml` declares `shortService` with `0` new permissions and no `connectedDevice`, all 6 strings match across all 9 locales (`0` emojis), and all monolith LoC caps hold.

- **`TST-TRK-091.4` (`ArchitectureConformanceContractTest.kt`, `SystemLiveTrackingRequirementsContractTest.kt`, `SystemDataExchangeRequirementsContractTest.kt`, `SourceTextReadingAuditContractTest.kt`)**: Verify `TrackerService.java < 3,539 / 3,559`, `WorkoutRepository.kt <= 5,117`, `PolarVeritySenseOfflineController.kt <= 1,500`, `0` edits to `DeviceManager.java`/`DevicesDatabaseManager.java`, `0` new `src/main` reads, and full governance parity.
