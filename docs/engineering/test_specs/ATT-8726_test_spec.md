## 1. Requirement Specification (`REQ-TRK-073.1` Refinement, `[Planned]`)
- **Attributes**: Priority: `High` | Type: `Functional` | Verification Method: `Unit` | System Requirement(s): `SYSREQ-TRK-006` | Localization Parity: `N/A - 0 string changes`
- **Refined `REQ-TRK-073.1` (*Dynamic 175m Rail Scaling with Monotonic Per-Approach Latch*)**:
  1. **Stateless Resolution Preserved**: `RadarOverlayMath.resolveRailMaxRange(radarState)` SHALL continue to return `175.0f` (`MAX_RADAR_RANGE_V2_METERS`) when any target has `rangeMeters > 140.0f` (`MAX_RADAR_RANGE_METERS`), `vehicleSizeCategory != VehicleSizeCategory.UNKNOWN_OR_LIGHT`, or `lateralOffsetMeters != null`, and `140.0f` otherwise.
  2. **Monotonic Active-Threat Latch**: `RadarOverlayMath.resolveLatchedRailMaxRange(previousMaxRangeMeters, radarState)` SHALL enforce upward-only scaling during continuous active threats:
     - When `radarState.connectionState != RadarConnectionState.CONNECTED` or `radarState.targets.isEmpty()` (All Clear), it SHALL reset immediately to `140.0f` (`MAX_RADAR_RANGE_METERS`).
     - When `radarState.connectionState == RadarConnectionState.CONNECTED` and `radarState.targets.isNotEmpty()`, once the active range reaches `175.0f` (`previousMaxRangeMeters > MAX_RADAR_RANGE_METERS` or `resolveRailMaxRange(radarState) >= MAX_RADAR_RANGE_V2_METERS`), it SHALL remain latched at `175.0f` across all subsequent active threat frames (including when a V1/ANT+ target crosses `<= 140.0 m` or a closer V2 target clears while a V1 target remains).
     - Expanding from `140.0f` to `175.0f` mid-approach when a newly detected target enters at `> 140.0 m` (or carries V2 metadata) SHALL take effect immediately; shrinking `175.0f -> 140.0f` MUST wait strictly until All Clear (`targets.isEmpty()`) or disconnect (`connectionState != CONNECTED`).
  3. **Unified Overlay Consumption**: `RadarEdgeOverlay` SHALL host a single non-Compose session latch (`RadarRangeLatchSession`, zero snapshot state writes during composition per `coding_standards.md` §1.10) and supply the resolved `maxRangeMeters` identically to both `RadarVerticalRail` (`LEFT`/`RIGHT`) and `RadarFullScreenThreatOverlay` (`COMPACT_BADGE` & `TOP_DOWN_VEHICLES`).

- **Historical Origin & Commit Trace**: Introduced in `ATT-5096` (`f2c2e15e`) and reused by `FULL_SCREEN` modes in `ATT-7537` (`3206a504`), `ATT-8733` (`22853065`), `ATT-8958` (`5e26c348`), and `ATT-8959` (`1b62150e`).
- **Root Reason for Existing Formulation**: `ATT-5096` dynamically scaled to `175.0 m` for RearVue 820 / distant targets while preserving `140.0 m` vertical resolution for legacy V1/ANT+ streams, without specifying per-approach hysteresis across the `140.0 m` boundary.
- **Preservation of Core Invariants**: Preserves stateless `resolveRailMaxRange(radarState)`, `140.0 m` default resolution for standard V1/ANT+ approaches (`<= 140 m`) and post-All-Clear resets, 100% gesture pass-through (`REQ-TRK-062.3`), `LEFT`/`RIGHT` dot geometry (`REQ-TRK-073.2`), `FULL_SCREEN` marker layout & threat hysteresis (`REQ-TRK-089`, `REQ-TRK-098`), and zero DB/decoder/string regressions.

## 2. Acceptance Criteria (Given-When-Then) & System Invariants
- **AC-1 (No Backward Jump Crossing 140m on V1/ANT+)**: *Given* a `CONNECTED` V1/ANT+ radar stream (`UNKNOWN_OR_LIGHT`, `lateralOffsetMeters = null`) with a target approaching `160 m -> 141 m -> 140 m -> 135 m -> 50 m -> 5 m`, *When* `RadarEdgeOverlay` renders consecutive frames in `LEFT`, `RIGHT`, and `FULL_SCREEN` (`COMPACT_BADGE` & `TOP_DOWN_VEHICLES`) modes, *Then* `maxRangeMeters` remains latched at `175.0f` throughout and the target's `normalizedY` and rendered top Y-coordinate decrease monotonically toward `0` with zero backward jump.
- **AC-2 (All Clear & Disconnect Reset to 140m)**: *Given* the latch is held at `175.0f`, *When* `targets` becomes empty (All Clear) OR `connectionState` transitions to `DISCONNECTED_ERROR` / `DISCONNECTED` / `CONNECTING`, and a subsequent `CONNECTED` V1 target appears at `<= 140 m` (e.g. `120 m`), *Then* `maxRangeMeters` resets to `140.0f` (`normalizedY = 120 / 140 = 0.857f`).
- **AC-3 (Multi-Target Upward Expansion & Non-Shrink)**: *Given* a V1 target approaching at `90 m` on the `140.0f` scale, *When* a second V1 target enters at `155 m` (`140 -> 175`), then drops to `138 m` while both targets remain active (or the first target passes), *Then* `maxRangeMeters` expands immediately to `175.0f` and stays latched at `175.0f` until all targets clear.
- **AC-4 (Stateless `TST-TRK-073.1` Contract Preserved)**: *Given* existing `RadarEdgeOverlayTest.resolveRailMaxRange_returnsExpectedBoundaries`, *When* targeted tests execute, *Then* all existing `TST-TRK-073` / `TST-TRK-062` / `TST-TRK-089` / `TST-TRK-098` tests pass alongside new latch tests.
- **Invariants**: `RadarEdgeOverlay.kt <= 1,500` LoC; `0` Compose snapshot state writes during composition (`coding_standards.md` §1.10); `0` clickable/pointer modifiers added to rail/overlay/markers (`REQ-TRK-062.3`); `0` `src/main/` test file reads (`REQ-PRO-049.1`); `0` string/color/DB changes.
