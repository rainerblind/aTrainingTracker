## 2. Key Retrospective Learnings & Root Cause Analysis

### Learning 1: Prohibition of Naive Polygon Auto-Tracing for Vector Assets (`ATT-2859`)
- **Observation**: The vector icons generated by `tools/generate_all_vectors.py` looked jagged and broken on device.
- **Root Cause**:
  1. The script traced pixel color masks using marching squares + Ramer-Douglas-Peucker (`L` straight line segments only) instead of geometric primitives (circles, arcs `A`, rounded strokes).
  2. It omitted `android:fillType="evenOdd"`, causing inner holes in wheels, stopwatch rings, hearts, and letters (`R`, `P`, `D`, `B`) to fill solid under Android's default `nonZero` winding rule.
  3. It traced only visible pixels per color without reconstructing occluded layers, leaving large chunks missing from the black bicycle wheel and red frame where the blue cyclist's leg overlapped them.
- **Countermeasure (Rule 37 / `docs/design_guidelines.md` Sec 5.5)**:
  - Strictly prohibit naive pixel-polygon auto-tracing (`M...L...Z`) for icon vectorization.
  - Construct vector icons from true geometric primitives (circles, arcs, rounded strokes in back-to-front Z-order, and `evenOdd` compound paths for glyphs) and visually verify rendered output 1:1 against the `xxxhdpi` reference PNG before committing.

### Learning 2: Prevent Text Wrapping in Dense Horizontal `FilterChip` and `SegmentedButton` Rows (`ATT-3184`, `ATT-3676`)
- **Observation**:
  - In `ZonesSettingsActivity`, placing 7 Material 3 `FilterChip`s (each with a `leadingIcon` dot) in a single `Row` (`Modifier.weight(1f)`) left only ~11dp for text, wrapping `"Z1"` into `"Z\n1"`.
  - In `ZoneDistributionCard` / `AdvancedSettingsScreen`, the German label `"Histogramm"` wrapped inside a 3-way `SingleChoiceSegmentedButtonRow`.
- **Countermeasure (Rule 38 / `docs/design_guidelines.md` Sec 5.6)**:
  - Never pack 5–7 Material 3 `FilterChip`s with `leadingIcon`s into a single `Row` using `Modifier.weight(1f)`. Use compact custom zone-tinted bordered pills without `leadingIcon` padding overhead, and enforce `maxLines = 1, softWrap = false` across all 9 locales.

### Learning 3: Reactive Flow Subscription Over Static `.value` Reads in `combine(...)` (`ATT-3581`)
- **Observation**: Follow-Me speed-dependent zoom did not update during movement when tested on device.
- **Root Cause**: `TrackingViewModel.observeMapState()` combined only 4 static DataStore preference flows and read `currentSpeed.value` / `currentBearing.value` snapshot properties inside the lambda. Because preference flows only emit when settings change, speed and bearing changes never triggered `MapState` updates.
- **Countermeasure (Rule 39 / `docs/coding_standards.md` Sec 1.5)**:
  - Any live telemetry state (`currentSpeed`, `currentBearing`) used to compute derived UI/camera state inside a reactive `combine(...)` pipeline MUST be subscribed as an active flow input to `combine(...)`, never read lazily via `.value` inside a preference-only observer.

### Learning 4: Growing Warm-Up Window ($1\text{..}29\text{ s}$) Over 30-Second Blank `"--"` Delay (`ATT-1290`, `ATT-1291`)
- **Observation**: Waiting a full 30 seconds showing `"--"` for Normalized Power (NP), Intensity Factor (IF), and TSS makes the user think the sensor is not transmitting.
- **Countermeasure (Rule 40 / `docs/coding_standards.md` Sec 1.6)**:
  - Rolling-window metrics must compute over the growing window ($1 \le k < 30$) during the initial warm-up phase so live values appear immediately from second 1, transitioning seamlessly into the full 30-second window at $t = 30\text{ s}$.
