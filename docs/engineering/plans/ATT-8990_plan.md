## 1. Problem Description & Background
Athletes comparing concurrent HR sensors (e.g., Polar H10 ECG vs. Polar Verity Sense PPG) in the cockpit cannot select a source device for `HRV_DFA_A1`, `HRV_RMSSD`, `HRV_ARTIFACT_RATE`, or `HRV_SDNN` because `DeviceType.getDeviceTypeList()` maps them to virtual `DeviceType.HRV_METRICS` (omitting `HRV_SDNN`) and only global `HRVMetricsDevice` computes live HRV from the arbitrated primary RR stream. Stage 4 maps all 4 HRV metrics to `DeviceType.HRM`, guards `"Bester Sensor"` via `MySensorManager.HRV_PRIORITY`, extracts a shared rolling engine with live `HRV_SDNN`, attaches lazy per-device HRV controllers to all 3 `RrBeatSource` HRM classes, and isolates cockpit/ramp-test lookup.

## 4. Proposed Architectural Changes (SWE.2 Boundaries & Threading)
- **Pure DSP & Lookup Layer (`banalservice/devices/hrv/`)**:
  - `HrvRollingEngine` (`@JvmOverloads`): `@Synchronized` beat queue (`WINDOW_FILTER_CONTEXT_MS = 180_000L`), `onRrBeat()`, `resetSession()`, and `evaluate(nowMs)` returning `HrvMetricsSnapshot(rmssdMs, dfaAlpha1, artifactRatePercent, sdnnMs, signalQualityResult, isDrained)`. Live `HRV_SDNN` computes unbiased sample SD ($\sqrt{\sum (nn_i - \bar{nn})^2 / (N - 1)}$) over non-artifact beats (`!isArtifact`, `correctedRrMs`) in active `120 s` `dfaWindowBeats`, returning `null` if `validBeats.size < 10` (`MIN_SDNN_VALID_BEATS = 10`) or `artifactRate > effectiveGateThreshold` (`[3.0, 5.0]%`) or drained (`> 120 s`).
  - `HrvTelemetryProvider` + `HrvDeviceLookup`: Interface exposing `signalQualityResult: HrvSignalQualityResult` and `latestArtifactRatePercent: Double?`; `HrvDeviceLookup.resolveProvider(deviceManager, deviceName)` resolves `(deviceManager?.getMyDeviceByName(deviceName) as? HrvTelemetryProvider)` when `deviceName != null`, else `deviceManager?.hrvMetricsDevice` (`0` edits to `DeviceManager.java`).
  - `HRVMetricsDevice` implements `HrvTelemetryProvider`, delegates rolling math to `HrvRollingEngine`, and adds `mHrvSdnnSensor` (`getHrvSdnnSensor()`), preserving its exact `@JvmOverloads` constructor and public API.
- **Per-Device Controller & Host-Callback Bridge (`PerDeviceHrvController.kt`)**:
  - Accepts `hostDevice: MyDevice`, `HostCallbacks` (Java-friendly interface: `addAndRegisterSensors(List<MySensor<*>>)`, `unregisterSensor(MySensor<*>)`, `removeSensor(SensorType)`, `notifySensorsChanged()`), injectable `TimeProvider`, and `startScheduler: Boolean = true` (`@JvmOverloads`).
  - Single-lock (`lock`) synchronization across GATT/ANT+/Polar beat threads, 5s `ScheduledExecutorService` task (lazily started via `scheduleWithFixedDelay` on first RR beat, cancelled via `ScheduledFuture.cancel(false)` on disconnect/reset/shutdown; executor shut down cleanly on `shutDown()`), and volatile snapshot reads from UI thread.
  - On first RR beat (`Rule 52`): creates all 4 `MySensor<Double>` instances (`HRV_RMSSD`, `HRV_DFA_A1`, `HRV_ARTIFACT_RATE`, `HRV_SDNN`) bound to `hostDevice`, batch-registers via one `addAndRegisterSensors(list)` call (single `SENSORS_CHANGED`), and arms scheduler.
  - On `clearAndDetach()` (`unregisterSensors()` / `shutDown()`) and `resetSession()` (`onAccumulatorsReset()` overridden on all 3 HRM devices per `Rule 51`): cancels scheduler task, pushes `newValue(null)` to all 4 sensors **while still `mActivated == true`** *before* `deactivateSensor()` -> `unregisterSensor()` -> `removeSensor()`, clears rolling queue & `latestArtifactRatePercent = null` & `signalQualityResult = INSUFFICIENT_DATA`, and re-arms cleanly on reconnect.
- **Source Mapping, Priority & Cockpit Isolation**:
  - `DeviceType.java`: move `HRV_RMSSD`, `HRV_DFA_A1`, `HRV_ARTIFACT_RATE`, `HRV_SDNN` to `DeviceType.HRM` case.
  - `MySensorManager.java`: add `HRV_PRIORITY = new DeviceType[]{ DeviceType.HRV_METRICS, DeviceType.HRM }` in constructor `setPriorityList(...)` and `getPriorityArray(...)` for all 4 `HRV_*` types.
  - `SensorFieldState.kt` / `TrackingViewModel.kt` / `EditSensorFieldDialog.kt` / `SensorFieldView.kt` / `HrvRampTestViewModel.kt`: propagate `sourceDeviceName: String? = null`; replace `latestArtifactRate` with `latestArtifactRateByDevice: MutableMap<String?, Double?>` + fallback to `HrvDeviceLookup.resolveProvider(dm, deviceName)?.latestArtifactRatePercent`; resolve `signalQualityStatus` per `deviceName` (in `EditSensorFieldDialog.kt:660`: `if (uiState.selectedDeviceId == -1L) null else deviceList.find { it.first == uiState.selectedDeviceId }?.second`); add `SensorType.HRV_SDNN` to `isHrvMetric`; skip `data.deviceName != null` in `HrvRampTestViewModel`.
- **UI Consistency (`docs/design_guidelines.md`)**: `N/A — zero layout, component-type, or string changes; reuses existing Source Spinner and HrvInfoBottomSheet`.
