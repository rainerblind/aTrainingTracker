## 1. SWE.2 Architectural Decomposition, Threading & Upgrade Behavior

- **Canonical Bounds & Storage (`ZoneCalculationMath.kt`, `AthleteMetricsDatabaseManager.kt`)**: Define `MIN_LTHR = 80`, `MAX_LTHR = 230`, `MIN_LT1_HR = 60`, `MAX_LT1_HR = 220`, `MIN_LT1_PWR = 30`, `MAX_LT1_PWR = 500` in `ZoneCalculationMath`. Add the 7 `AthleteMetricType` entries referencing those constants; use `safeEnumValueOfOrNull<AthleteMetricType>(name)` in `fromNameOrNull()`. Keep `DB_VERSION = 2` so `onCreate`/`onUpgrade` parity and forward-compatibility (`fromCursorBatch` skipping unknown tokens) hold without migration risk.
- **DataStore Projection & Non-Blocking Snapshot (`SettingsDataStore.kt`)**: Add 7 sport preference keys (`hr_max_run`, `hr_max_bike`, `lthr_run`, `lthr_bike`, `lt1_hr_run`, `lt1_hr_bike`, `lt1_pwr_bike`) + `sport_hr_max_seeded`, `Flow<Int?>` accessors, compact bounded setter helper (`setBoundedIntPref`), and `SettingsSnapshot` nullable fields + $O(1)$ sync getters (zero `runBlocking`). `hrMaxFlow` computes `listOfNotNull(prefs[KEY_HR_MAX_RUN], prefs[KEY_HR_MAX_BIKE]).filter { it > 0 }.maxOrNull() ?: prefs[KEY_HR_MAX]?.takeIf { it > 0 }`; `setHrMaxRun`/`setHrMaxBike` and `saveCalculatedHeartRateZones` atomically keep `KEY_HR_MAX` synced to `max(hr_max_run, hr_max_bike)` inside a single `dataStore.edit { }` block.
- **Unidirectional Repository SSoT & Historical Lookup (`AthleteMetricsRepository.kt`)**: Add `getEntryEffectiveAt(metricType, timestampMs)` to `AthleteMetricsDataSource` (`SqliteAthleteMetricsDataSource` delegates to `dbManager`). Inside `ensureSeededLocked()` (serialized under `mutex` on `ioDispatcher`): preserve existing `!athleteMetricsSeededFlow.first()` block, then run an independent `!sportHrMaxSeededFlow.first()` block that seeds missing `HR_MAX_RUN_BPM`/`HR_MAX_BIKE_BPM` from legacy `KEY_HR_MAX` in a single transaction, projects them to `SettingsDataStore`, and marks `KEY_SPORT_HR_MAX_SEEDED = true`. Extend `syncLatestToDataStoreLocked()` for all 12 types and add `EffectivePhysiologicalThresholds` + `getEffectiveThresholdsAt(sportType: BSportType, timestampMs: Long)` (falling back to DataStore snapshot for `hrMax`/`hrRest`/`ftp` and strictly returning `null` for `lthrBpm` when unset).
- **Pure-Domain `hrTSS` & Historical PMC (`PowerPhysiologyCalculator.kt`, `WorkoutSummariesDatabaseManager.java`, `AthleteProfileViewModel.kt`)**: Add `bSportType: BSportType = BSportType.UNKNOWN` to `WorkoutTrainingLoadSample` (populated from `w.bSport` in `getWorkoutTrainingLoadRecords()`). Add `lthrBpm: Double? = null` to `calculateHrTss` and `resolveWorkoutTrainingLoad`: use `thresholdHrr = (lthrBpm - safeHrRest) / hrSpan` when `lthrBpm` is finite and in `(safeHrRest, safeHrMax]`, else execute the exact existing `LTHR_HR_RESERVE_FRACTION` (`0.85`) branch for bit-for-bit parity. Add `WorkoutThresholds` + optional `thresholdResolver: ((BSportType, Long) -> WorkoutThresholds?)? = null` to `computePerformanceManagementChart`. In `AthleteProfileViewModel`, project only PMC-relevant `AthleteMetricType` entries (`FTP_WATTS`, `HR_REST_BPM`, `HR_MAX_RUN_BPM`, `HR_MAX_BIKE_BPM`, `LTHR_RUN_BPM`, `LTHR_BIKE_BPM`) with `distinctUntilChanged()` so PMC resolves per-workout `(sportType, timestampMs)` in-memory with 0 extra DB queries and 0 recomputations on `WEIGHT_KG` or tab toggles.
- **Aftermath Sync & Exhaustive UI Handling**: Update `TrackOnMapAftermathViewModel.updateHrZones(newHrvt1, newHrvt2, recalculateZones = true)`, `updateFtp(newFtp, lt1PowerWatts = null, recalculateZones = true)`, `TrackOnMapScreen` fallbacks, `HrvThresholdSummaryCard` (`onUpdatePowerThresholds` preserving `onUpdateFtp`), and `ZoneSettingsScreen` HR calculator save to persist thresholds via `AthleteMetricsRepository`. Update the 5 exhaustive `when` blocks in `AthleteProfileScreen.kt` using 9-locale `strings_athlete_thresholds.xml`.
- **Upgrade-Path Behavior for Existing Users (`docs/coding_standards.md` §5.6)**: Existing users with `KEY_HR_MAX = X` (including those with `athlete_metrics_seeded = true`) automatically receive one-shot seeded `HR_MAX_RUN_BPM = X` and `HR_MAX_BIKE_BPM = X` with zero data loss and identical `hrMaxFlow == X`; because `LTHR` remains unset until explicitly configured, historical `hrTSS`/PMC values stay bit-for-bit identical post-upgrade.
