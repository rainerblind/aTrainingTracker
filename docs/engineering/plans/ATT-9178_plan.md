  - `PolarOnlineStreamingBridge.kt`: remove `isMidSessionOrWorkoutActive()`, override `hasConnectedInSession()` & `resetSessionConnectionState()` (abort if `isReceivingData()`; clear `hasConnectedInSession`, reset `currentReconnectDelayMs`, `cancelReconnectJob()`; strictly when `!isReceivingData() && !isSearching && !isOfflineGattYielded()`, under `gattActionLock` re-check guards, `cancelSearchTimeoutWatchdog()`, clear `sessionOpenPendingFeatures`, `polarApi?.disconnectFromDevice(sdkSessionId)`, `PolarOfflineGattCoordinator.clearConnectingState(sdkSessionId, macAddress)` — NEVER cancel `searchTimeoutJob` when `isSearching`), gate `shouldKeepAliveOnSearchTimeout()` strictly on `!isShutDown.get() && (hasConnectedInSession.get() || isOfflineGattYielded())`, and gate all 6 reconnect triggers strictly on `hasConnectedInSession.get()`.

  - Eagerly instantiate `mPeriodicRetryCoordinator = new DeviceSearchPeriodicRetryCoordinator(mContext)` in `DeviceManager` constructor so `lastTrackingMode` captures `TrainingApplication.getTrackingMode()` even if constructed/rebound mid-workout (`+1` LoC; keep null-safe `getPeriodicRetryCoordinator()` fallback).   - In `handleSearchStoppedForCurrentDevice()` (`!success && !shouldKeepAliveOnSearchTimeout() && tries <= 1`): if `!current.hasConnectedInSession()`, call `cancelDevice(deviceId)`, `deviceTries.remove(current)`, and `detachAndGiveUpDevice.run()` (`0` timers). - **Lock-Order DAG & Thread-Safety**: Acyclic order `mSearchQueue -> coordinator.lock` (never reversed; `coordinator.lock` never held across `resetSessionConnectionState()`/`detachAndGiveUpDevice`); `MyBTLEDevice.mGattLock` released before `notifyStopSearching(false)`/`disconnectFromGattInternal`; `PolarOnlineStreamingBridge` obeys `gattActionLock -> {offlineYieldLock, apiLock, searchTimeoutLock, reconnectLock}` (`my_btle_device.md:92`).
