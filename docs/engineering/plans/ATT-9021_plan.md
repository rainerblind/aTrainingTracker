## 1. SWE.2 Architectural Decomposition & Upgrade-Path Behavior

- **SQLite Persistence Layer (`database/WorkoutSummariesDatabaseManager.java`)**:
  - Add `WorkoutSummaries.EPIC = "epic"` (`int DEFAULT 0`), increment `WorkoutSummariesDbHelper.DB_VERSION = 32`.
  - Add `WorkoutSummaries.EPIC + " int DEFAULT 0"` symmetrically to `CREATE_TABLE` (`onCreate`) and `if (oldVersion < 32) { addColumnIfNotExists(db, WorkoutSummaries.TABLE, WorkoutSummaries.EPIC, "int", "0"); }` (`onUpgrade`).
  - Persist `values.put(WorkoutSummaries.EPIC, workoutData.getEpic() ? 1 : 0)` inside `updateWorkoutData(WorkoutData)`.
  - **Existing-User Upgrade-Path Behavior (`Coding Standards §5.6`)**: Existing workouts keep all data unchanged and receive `epic = 0` (`false`) via `DEFAULT 0`, reproducing prior behavior identically until the athlete tags a workout as `Epic` (in `ATT-9022`) or imports a FIT file with `is_epic = 1`.
- **Domain Model, Symmetric Mapper, Repository & ViewModel (`ui/aftermath/`)**:
  - `WorkoutData.kt` & `WorkoutExportHeader.kt`: add `val epic: Boolean = false` next to `race`.
  - `WorkoutDataMapper.kt`: add `val epic: Boolean = false` to `RawCursorSnapshot`, read `!cursor.isNull(it) && cursor.getInt(it) == 1` (safe default `false` when column absent) in `readCursorSnapshot`, and pass `epic = snapshot.epic` in `fromSnapshot` (guarantees single-item `fromCursor` and batch `fromCursor(cursor, batch)` symmetry per `Rule 20`).
  - `WorkoutRepository.kt`: read `WorkoutSummaries.EPIC` into `WorkoutExportHeader.epic` (`getWorkoutExportHeader`); add `isEpic: Boolean = false` to `insertImportedWorkout` (putting `EPIC = 1` when `true`); merge `epic = userEditedWorkout.epic` into `_allWorkouts.update` in `saveWorkout`. Keep all SQLite/cursor access private inside `WorkoutRepository` (`Rule 81` / `§2.5`).
  - `EditWorkoutViewModel.kt`: add `fun updateIsEpic(isChecked: Boolean) { _workoutData.update { it?.copy(epic = isChecked) } }` (independent of `commute`/`trainer`/`race`) and preserve `epic = current.epic` in `mergeTelemetryPreservingUserEdits`.
- **Garmin FIT 2.0 Export/Import Layer (`exporter/writer/`, `migration/`)**:
  - `FitFileWriter.kt`: under `APP_METADATA_DEVELOPER_DATA_ID` (`developerDataIndex = 1`), register `isEpicDesc` (`fieldDefinitionNumber = 8.toShort()`, `Fit.BASE_TYPE_UINT8.toShort()`, `"is_epic"`) after `isRaceDesc` (`7`) and write `DeveloperField(isEpicDesc, metaDevDataIdMesg)` (`1`/`0`) on `sessionMesg`.
  - `ParsedWorkoutData.kt`: add `val isEpic: Boolean = false`.
  - `FitWorkoutParser.kt`: inside `matchesAppId(devField, devDataAppIds, FitFileWriter.APP_METADATA_DEVELOPER_DATA_ID)`, decode `else if (fieldName == "is_epic" || num == 8)` into `metaIsEpic` (`(raw ?: 0) > 0`) and populate `ParsedWorkoutData.isEpic`.
  - `LegacyImportEngine.kt`: forward `isEpic = parsedWorkout.isEpic` to `workoutRepo.insertImportedWorkout(...)`.
- **Threading & Concurrency**: Zero new threads/coroutines; DB writes execute on existing `Dispatchers.IO` (`WorkoutRepository.saveWorkout`, `LegacyImportEngine`) and ViewModel state updates remain atomic via `_workoutData.update { ... }`.
