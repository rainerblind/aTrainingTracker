## 1. Problem Description & Traceability
When an unbonded V2-capable BLE radar (`6a4e3204`) falls back to legacy V1 (`6a4e3203`), cyclists get no UI guidance or pairing action. This plan implements **`REQ-CON-061`** (`REQ-CON-061.1`–`.4`, linked to `SYSREQ-TRK-002`) and verifies it via **`TST-CON-061`** (`TST-CON-061.1`–`.4`).

## 2. System Invariants, Concurrency & LoC Budgets
1. **Strict Gating & SSoT (Zero 4–8 Hz Resurrection)**: `v2Char == null` (RTL515/516/RVR315) and `radar_v1_only_override == true` MUST keep `isV2BondingRequired == false`. `RadarStateRepository` (under leaf `threatLock`) is the **single source of truth** — `BTLERadarDevice` holds NO cached `mIsV2BondingRequired` flag. `updateThreatLocked()` preserves `sourceStates[BLE]`'s `(isV2BondingRequired, v2BondingDeviceAddress)` across `CONNECTED` BLE frames (unless explicitly set `true`) and auto-clears both + resets the one-shot prompt latch on `DISCONNECTED`/`DISCONNECTED_ERROR`/`CONNECTING`, eliminating ~125 ms resurrection after external `ALREADY_BONDED` clears.
2. **Thread-Safe Receiver Lifecycle & Full Disconnect/Shutdown Teardown**: Dedicated `mBondReceiverLock` in `BTLERadarDevice` guards `mBondReceiverRegistered` + `!mIsShutDown` across lazy `ContextCompat.registerReceiver(..., RECEIVER_EXPORTED)` (`Build.VERSION.SDK_INT == 0` guarded) and `LifecycleUtils.safeUnregisterReceiver`. `setV2BondingRequiredState(false)` (clearing repo + unregistering receiver) runs on: start of `configureServices()`, V2 packet receipt, trimmed case-insensitive matching `BOND_BONDED`, `mWatchdogRunnable`, `resetConnectionState()` (`disconnectFromGatt()` & `shutDown()`), AND overridden `unregisterSensors()` (closing `MyBTLEDevice.java` L685 remote `STATE_DISCONNECTED` path).
3. **Android 12+/13+ Permission & Task-Safe Intent Fallback**: API 31+ `BLUETOOTH_CONNECT` check + `SecurityException` catch; API 33+ `getRemoteLeDevice(mac, ADDRESS_TYPE_RANDOM|PUBLIC)` via `MyBTLEDevice.isRandomStaticAddress`; `Settings.ACTION_BLUETOOTH_SETTINGS` adds `Intent.FLAG_ACTIVITY_NEW_TASK` strictly whenever `context !is Activity` (preventing `AndroidRuntimeException` on `applicationContext`).
4. **Live Tracking & Lane 2 Isolation**: Zero modal dialogs or snackbars during `TRACKING`/`PAUSED`. `BTLERadarDevice.java` edits stay at L101–350 & L621–675 (untouched near L788 `0x2A24` for Lane 2 `ATT-8996`). Zero `MyBTLEDevice.java` or SQLite schema edits (`docs/architecture.md` & `my_btle_device.md` unchanged).
5. **LoC Ceilings**: `BTLERadarDevice.java` `1,333 -> ~1,385/1,500`, `EditDeviceDialog.kt` `1,827 -> ~1,842/2,004`, `TrackingTabsScreen.kt` `1,456 -> ~1,460/1,500`, `DevicesTabbedScreen.kt` `813 -> ~815/1,500`, `RadarStateRepository.kt` `269 -> ~310/1,500`.

## 3. UI Consistency (`docs/design_guidelines.md`)
* **Component & Shape (§5.1, §5.3)**: Extract stateless `RadarV2BondingHintCard.kt` using `OutlinedCard(shape = RoundedCornerShape(12.dp))`, `16.dp` padding, `8.dp` spacing (matching `WheelSensorGuidanceCard`/`PolarFeatureToggleCard`).
* **Color Tokens (§5.4)**: Detect theme via `val isDark = MaterialTheme.colorScheme.surface.luminance() < 0.5f`; apply existing WCAG AAA `LightWarning*`/`DarkWarning*` tokens from `ui/theme/Color.kt` (zero hardcoded hex, zero primary-blue warning misuse, Light/Dark/AMOLED `@Preview`s).
* **Typography, Icons & Copy (§2.8, §4, §5.5)**: Leading `Icons.Default.Bluetooth` vector icon (zero emojis); full-width primary `Button(Modifier.fillMaxWidth())` with `maxLines = 1, softWrap = false, overflow = TextOverflow.Ellipsis` (single-line German fit at 360dp); hint & initiated copy transparently state V2 activates once paired / on next connection.
* **Non-Interrupting Discovery**: `RadarV2BondingSnackbarEffect(snackbarHostState, isAllowedToShow)` keys `LaunchedEffect(snackbarHostState, isAllowedToShow)`, checks `isAllowedToShow` BEFORE calling `consumeV2BondingPromptIfPending(mac)` (dismissing any active snackbar when entering `TRACKING`/`PAUSED` without burning the latch), and mounts in `DevicesTabbedScreen` (`true`) and `TrackingTabsScreen` (`trackingMode == TrackingMode.READY`).
