## 1. SWE.2 Architectural Decomposition & Threading Model

- **Immutable Post-Commit Domain Event (`ui/aftermath/WorkoutMutationEvent.kt`)**: Zero DB imports; sealed class `WorkoutMutationEvent` with `Deleted(workoutId, clusterId, equipmentId, sportId, wasFinished)`, `BulkDeleted(workoutIds)`, and `Finalized(workoutId)`. Exposed on `WorkoutRepository` via bounded `MutableSharedFlow(replay = 0, extraBufferCapacity = 64, onBufferOverflow = BufferOverflow.DROP_OLDEST)` (`REQ-PRO-130.1`), emitted strictly post-commit (never on 1-Hz unfinished ticks, `REQ-STB-020.4`).
- **Extracted Cascade Orchestrator (`repositories/WorkoutDeletionCoordinator.kt`)**: Placed in `repositories/` (outside both `ui/` and `database/` so `BASELINE_ALLOWED_UI_DB_CALLERS` & `BASELINE_ALLOWED_DATABASE_UPWARD_UI_IMPORTS` stay unchanged). Coordinates on `Dispatchers.IO`:
  1. Authoritative pre-delete snapshot via `getWorkoutDataDirect(workoutId)` (in-memory `_allWorkouts` first, SQLite cursor fallback before deletion) + `summariesManager.getBaseFileName(workoutId)`.
  2. Complete persistence purge: transactional `summariesManager.deleteWorkout(workoutId)` (5 tables + `workout_photos/<id>`), `lapsDatabaseManager.deleteWorkout(workoutId)`, `WorkoutRrRepository.deleteWorkoutBlocking(workoutId)`, `ActiveDevicesDbHelper.deleteWorkout(workoutId)`, WorkManager cancellation, `samplesManager.deleteWorkout(fileBaseName)`, `ExportStatusRepository.deleteExportWorkout(fileBaseName)`, `PolarRawTelemetryPruner.deleteSidecar(application, fileBaseName)` (now including `.salvage`), and `stravaUploadDbHelper.deleteWorkout(fileBaseName)`.
  3. Post-commit in-memory cleanup: evicts `recentHrvThresholdsCache`, `ineligibleCardioPowerWorkoutIds`, tombstones `deletedDuringLoadIds` when loading, clears `LiveWorkoutCardStateStore` if active ID matches, and updates `_allWorkouts` (`filterNot`).
  4. Single delete: invokes `WorkoutClusterEngine.onWorkoutDeleted` (using authoritative pre-delete snapshot when `clusterId != -1L`) + `WorkoutClusterRepository.syncClusterAfterWorkoutDeletion(clusterId)`, then emits **1** `WorkoutMutationEvent.Deleted`.
  5. Bulk `deleteOldWorkoutsCascade`: loops synchronously over `oldWorkoutIds` (zero fire-and-forget `launch`!), invokes `progressCallback`, executes synchronous per-item DB/sidecar/cache purge (suppressing per-item cluster sync & events), batch-filters `_allWorkouts` once, and emits **1** `WorkoutMutationEvent.BulkDeleted(deletedIds)` strictly after all deletions commit.
- **Test-Mock Parity & Rule 74 (`WorkoutRepository.kt`)**: `deleteWorkout(id)` continues invoking `deletionHelper.deleteWorkout(id)` (preserving `WorkoutDeletionHelperTest` & `WorkoutRepositoryConcurrencyTest`). A per-call `ThreadLocal<Boolean>` / flag detects whether `deleteWorkoutCascade(id)` already performed post-commit reconciliation; when `deletionHelper` is mocked in tests and returns `true`, `deleteWorkout(id)` performs the same `_allWorkouts` removal, cluster sync, and single `WorkoutMutationEvent.Deleted` emission while keeping `_deletionProgress = Idle` strictly before `deleteFinishedEvent` (`REQ-STB-018.4`). `reloadWorkoutDataInternal` / `saveWorkout` / `cropWorkout` emit `WorkoutMutationEvent.Finalized(id)` strictly when `finished == true`.
- **Reactive Downstream Consumers**:
  - `WorkoutClusterRepository.syncClusterAfterWorkoutDeletion(clusterId)`: reloads the affected `WorkoutCluster` from `clusterDb`, updates `_allClusters` in-place (sorted by `hitCount DESC`), and refreshes that cluster's entry in `_clusterStats` via `summariesManager.getWorkoutClusterStats(clusterId)` (removing entry if `hitCount <= 0`). Automatically updates `KnownLocationsViewModel` (`clusterRepository.allClusters`).
  - `AthleteProfileViewModel`: adds a conflated `MutableSharedFlow<Unit>(extraBufferCapacity = 1, DROP_OLDEST)` analytics-refresh channel collected sequentially on `ioDispatcher` executing BOTH `getCardioPowerDynamicsFitnessTrendSamples(0.50)` and `getWorkoutTrainingLoadRecords()` (eliminating the racing unawaited `launch` in `loadCardioTrendSamples()`), triggered by BOTH the existing `allWorkouts` finished-key flow (`REQ-STB-020.4`) AND `workoutRepository.workoutMutationEvents`.
  - `TrackingViewModel` (`cachedPowerBenchmarks`), `EquipmentViewModel` (`loadEquipment()`), `SportTypeViewModel` (`loadSportTypes()`), and `SportingJourneyViewModel` (`loadData()`, keeping `@JvmOverloads` 1-arg `(Application)` constructor): collect `workoutRepository.workoutMutationEvents` on `Dispatchers.IO` and refresh their derived caches.
