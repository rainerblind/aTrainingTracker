## 1. SWE.2 Architectural Decomposition, Upgrade Path & Formal Lock-Hierarchy Proof

- **Canonical Radar-Light Preferences & One-Time `DataMigration<Preferences>` (`TuningPreferencesDataStore.kt`, `SettingsDataStore.kt`)**:
  - Canonical persisted keys (strictly 2): `KEY_RADAR_LIGHT_CONTROL_MODE` (default `RadarLightControlMode.SMART_AUTOMATION`) and `KEY_RADAR_LIGHT_DEFAULT_MODE` (default `RadarLightMode.DAY_FLASH`). `TuningConfig` stores both and exposes `radarLightAutoMode`, `radarAutoLightControl`, and `radarSmartLightAutomation` as pure derived read-only getters.
  - Switch `TuningPreferencesDataStore.kt:1219-1225` (`mapPreferencesToConfig`) cluster fallbacks from `TrainingApplication.getClusterTol*()` to pure `TuningPreferencesDefaults.CLUSTER_*` constants (breaking circular `TuningPreferencesDataStore <-> TrainingApplication` re-entry). Eagerly hydrate `tuningConfigStateFlow` in `init` via a single collector (replacing `by lazy` + duplicate `tuningConfigFlow.collect`), updating `SmartBrakeLightDetector.isEnabled` and `RadarLightController.onPreferencesUpdated(cfg)`.
  - One-time `TuningPreferencesMigration(context)` (`DataMigration<Preferences>` on `SettingsDataStore.backingDataStore`):
    - **`shouldMigrate`**: `true` iff any legacy radar/map key exists in DataStore OR any legacy `SP_CLUSTER_*` key exists in `SharedPreferences` while its DataStore key is absent.
    - **`migrate` (`Coding Standards §5.6`)**: preserves exact prior effective mode (`KEY_RADAR_LIGHT_CONTROL_MODE` > `KEY_RADAR_LIGHT_AUTO_MODE` > `KEY_RADAR_SMART_LIGHT_AUTOMATION == true` -> `SMART_AUTOMATION`, falling through when `false` to `KEY_RADAR_AUTO_LIGHT_CONTROL`: `true`/absent -> `FIXED_WORKOUT_MODE`, `false` -> `MANUAL`; `MANUAL` without explicit default mode -> `RadarLightMode.OFF`), removes the 3 obsolete radar-light keys + `LEGACY_MAP_CAMERA_KEYS`, and copies absent `SP_CLUSTER_*` values into DataStore. Fresh installs get unified `SMART_AUTOMATION` + `DAY_FLASH`.
    - **`cleanUp` (post-commit)**: deletes migrated `SP_CLUSTER_*` keys from `SharedPreferences` so `shouldMigrate` converges to `false` and `resetToDefaults()` cannot resurrect legacy `SharedPreferences` on next boot.
  - Delete `purgeLegacyMapCameraPreferences()` (including `AdvancedTuningScreen.kt:156` & `init` launch), per-save `LEGACY_MAP_CAMERA_KEYS` loop, and all 7 `TrainingApplication.setClusterTol*` mirrors. Route `TrainingApplication.getClusterTol*()` to `TuningPreferencesDataStore.getInstance(cContext).getTuningConfig()` when initialized (fallback `cSharedPreferences`/defaults for JVM mocks); add `suspend fun updateClusterTuning(...)` updating in-memory state before returning, awaited by `WorkoutClustersViewModel.saveTuningParameters()` (`:414-433`) prior to `recalculateClustersWithProgress()`.
- **Zero Stale Caches (`RadarLightController.kt`, `TrackerService.java`)**:
  - Delete `RadarLightController.cached*`, `hasLoadedInitialPreferences`, and both `updateCachedPreferences` overloads. Read `TuningPreferencesDataStore.getInstance(ctx).getTuningConfig()` directly in `resolveActiveConfig(ctx)` (internal `_controlMode`/`_preferredMode` `MutableStateFlow`s used strictly as headless JVM fallback when `!hasInitializedInstance()`). Execute `persistSelectionAsync` on one long-lived `persistenceScope = CoroutineScope(SupervisorJob() + Dispatchers.IO)`.
  - Delete `TrackerService.mCachedAutoPauseConfig`, `mLastAutoPauseConfigFetchMs`, `AUTO_PAUSE_CONFIG_CACHE_TTL_MS`, `invalidateAutoPauseCache()`, and `invalidateAutoPauseConfigCache()`. `TrackerService.getAutoPauseConfig()` delegates directly to `SettingsDataStoreJavaHelper.getAutoPauseConfig(this)` (O(1) in-RAM `StateFlow.value`, zero `runBlocking`). Remove all 14 `TrackerService.invalidateAutoPauseCache()` calls in `TuningPreferencesDataStore.kt`.
- **3 Orthogonal `StateFlow`s (`RadarState.kt`, `RadarAudioSnoozeState.kt`, `RadarStateRepository.kt`, `RadarSnoozeController.kt`)**:
  - Split into `threatState: StateFlow<RadarThreatState>` (arbitrating `sourceStates <= 4`, `BLE > ANT_PLUS > SIMULATOR`, `CONNECTED > CONNECTING`), `lightState: StateFlow<RadarLightState>`, and `snoozeState: StateFlow<RadarAudioSnoozeState>` with monotonic `snoozeUntilElapsedRealtimeMs: Long?` + `remainingSecondsAt(nowMs)`. Lock-free CAS `_lightState.update` / `_snoozeState.update`; cold `observeCombinedState(): Flow<RadarState>` + on-demand `getState()`.
  - `RadarSnoozeController` replaces its 1-Hz loop with a one-shot `snoozeExpiryJob` that **cancels and reschedules** on every `snooze(...)` call (e.g., `SNOOZE_15M` -> `SNOOZE_30M`) and re-verifies `timeProvider() >= endMs` on wakeup (re-delaying remaining delta if woken early by Doze/drift).
  - `SmartRadarLightEngine` collects ONLY `threatState`; `RadarAlertManager` collects `threatState` and `lightState.map { it.lightMode }.distinctUntilChanged()` (zero `snoozeState` subscription). UI combines via `observeCombinedState()`; `RadarEdgeOverlay` formats badge minutes locally from `snoozeUntilElapsedRealtimeMs`.
- **Formal Lock-Hierarchy Proof (`RadarLightController` <-> `SmartBrakeLightDetector`)**:
  - Let $L_A$ = `RadarLightController.controllerLock`, $L_B$ = `SmartBrakeLightDetector.detectorLock`.
  - `SmartBrakeLightDetector.isEnabled` and `isAutoBypassed` backed by lock-free `AtomicBoolean`.
  - `SmartBrakeLightDetector` (`onLinearAccelerationChanged`, `stopListening`, `resetMotionState` `:346`, `reset` `:367`) captures its transition/brake-release flag inside $L_B$, **releases $L_B$**, then invokes `stopListening()` / `RadarLightController.triggerBrakeLight(...)` strictly **outside** $L_B$ using JVM-safe `safeElapsedRealtime()`.
  - `RadarLightController` (`registerRadarDevice`, `unregisterRadarDevice`, `triggerBrakeLight`, `checkAndRestorePreBrakeMode`) updates internal fields and increments a monotonic `brakeEpoch` inside $L_A$, **releases $L_A$**, then invokes `SmartBrakeLightDetector` (including ALL `isAutoBypassed`/`isEnabled` writes), `setLightMode` (re-checking `brakeEpoch` / `isBrakeActive` so concurrent `onWorkoutPaused()`/`onWorkoutStopped()` is never stomped), `SmartRadarLightEngine`, or `RadarStateRepository`.
  - Directed edges between monitors: $E(L_A \to L_B) = \emptyset$ and $E(L_B \to L_A) = \emptyset$ -> **AB-BA deadlock mathematically impossible**.
