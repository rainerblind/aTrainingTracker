## 1. SWE.2 Architectural Decomposition & Threading Model

- **New Package `com.atrainingtracker.banalservice.devices.raw`**: Pure-Kotlin/minimal-Android data models & bounded IO engines (`PhoneRawMetadata.kt`, `PhoneRawTelemetryRow.kt`, `PhoneRawSidecarRecovery.kt`, `PhoneRawTelemetryReader.kt`, `SmartphoneRawTelemetryRecorder.kt`, `RawSensorSidecarFiles.kt`).
- **Threading & Backpressure**: Sensor/location threads call non-blocking `Channel.trySend` (`capacity = 8192`, `BufferOverflow.DROP_OLDEST`, `onUndeliveredElement` drop counter) -> single dedicated `Dispatchers.IO` writer with one reusable `StringBuilder` (`0` `String.format` per row) + periodic `GZIPOutputStream(..., syncFlush = true)` flush (`<= 256` rows / `<= 5 s`) -> `stop()` joins writer, renames `.tmp` atomically, and cancels private `CoroutineScope`.
- **Plain-JVM Test Safety**: `SmartphoneRawTelemetryRecorder` guards DataStore & `context.filesDir` access (`try/catch` + in-memory `@Volatile` opt-in cache) so plain-JVM MockK tests never throw `NullPointerException` or `Unimplemented`.
- **Monolith LoC Budgets (`ArchitectureConformanceContractTest`)**: `SpeedAndLocationDevice_ATTFused.kt <= 1,500` (baseline `1,489`, delta `<= +8`), `TrackerService.java <= 3,559` (baseline `3,537`, delta `<= +8`), `TuningPreferencesDataStore.kt <= 2,410` (baseline `2,146`, delta `<= +30`).
