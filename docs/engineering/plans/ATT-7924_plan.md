# Implementation Plan: ATT-7924

**Ticket**: `ATT-7924` (`[Feature] Backfill Polar Verity Sense stored HR on workout stop and Aftermath retry`, 2 SP)
**Target Release**: `V5.0.0`

## 1. SWE.2 Architecture & Threading Boundaries
- **GATT Arbitration & SDK Layer (`PolarOfflineGattCoordinator`, `PolarVeritySenseOfflineController`)**: All PFTP operations execute on `dispatcher` (`Dispatchers.IO` by default) wrapped in `PolarOfflineGattCoordinator.withGattYieldAndPolarApi(...)` so standard `MyBTLEDevice` GATT yields cleanly and `resumeGattOperations()` runs in `finally`.
- **Service -> Repository/SQLite Sequence (`TrackerService.endWorkout()`)**: Runs synchronously on `mDbExecutor` right after `PolarH10OfflineController.stopAndBackfillWorkoutBlocking(...)` and BEFORE `HrvPostWorkoutRecomputer` / `ExportManager.workoutFinished()`. `PolarVeritySenseOfflineController.onWorkoutStopped()` keeps armed metadata when `isArmed == true`; `stopAndBackfillWorkout()` clears `isArmed` in `finally`.
- **Strict HRV & Schema Invariants**: Zero writes to `WorkoutRr.db` (`WorkoutRrRepository`) and zero calls to `HrvPostWorkoutRecomputer`. Zero SQLite schema bumps (`WorkoutSummaries.db` stays v31 using `"verity:"` prefix in `POLAR_EXERCISE_ID`). Delete only matched flash entry strictly after SQLite commits.
- **UI Consistency (`docs/design_guidelines.md`)**: Reuse `PolarH10RetrySyncBanner` (`SecondaryContainer`, `Sync` icon, filled `Button` primary *Sync Now* + `OutlinedButton` *Dismiss* fitting single-line German labels cleanly; no `FilterChip` or nested `ElevatedCard`), switching title/desc/syncing/failed copy to Blue Sensor Mode instructions when `isVerityPendingSync(polarExerciseId)` is true (9 locales, zero emojis).
