## 1. SWE.2 Architectural Decomposition & Concurrency / Lock-Ordering Model

- **Layer 1 — `MultisportLapCoordinator.kt` (`561 -> ~685 / 1,500` LoC, leaf-only `@Synchronized` monitor)**:
  - Add immutable `internal data class CommittedTransitionWindow(val baseFileName: String?, val exitTotalS: Long, val enterTotalS: Long, val exitEpochS: Long, val enterEpochS: Long, val hasTransition: Boolean, val transitionLapNr: Int, val newLegLapNr: Int)`.
  - Maintain `@Volatile private var hasCommittedTransitions: Boolean = false`, `private val committedTransitions = mutableListOf<CommittedTransitionWindow>()`, and `private val pendingReconciliationByFileName = LinkedHashMap<String, MutableList<CommittedTransitionWindow>>()` (capped at `MAX_PENDING_RECONCILIATION_SESSIONS = 4`, evicting oldest key to bound memory).
  - Update `resetForSession(...)` (`@Synchronized`): clear `committedTransitions` and set `hasCommittedTransitions = false` (leaving `pendingReconciliationByFileName` intact so a rapid Stop -> Start does not abort queued `endWorkout()` reconciliation for the previous workout).
  - Add `@JvmOverloads` optional `baseFileName: String? = null` to `planAndCommitAnchorTransition(context, event, oldLapNr, baseFileName)` (preserving 3-arg callers); pass `baseFileNameProvider()` from `onMultisportTransitionIntent()` BEFORE `advanceLapsFn()` and BEFORE enqueuing `persistTask`. When `lapAdvanceCount > 0`, append the `CommittedTransitionWindow` to `committedTransitions` (`hasCommittedTransitions = true`) and, when `!baseFileName.isNullOrBlank()`, to `pendingReconciliationByFileName[baseFileName]` under the same `@Synchronized` block.
  - Add `@JvmOverloads fun enforceMonotonicLapNr(baseFileName: String?, samplingValues: ContentValues, summaryValues: ContentValues? = null, sampleEpochS: Long = System.currentTimeMillis() / 1000L)`:
    - O(1) lock-free fast path: `if (!hasCommittedTransitions) return`.
    - Snapshot `matchingWindows` under `synchronized(this)` (`w.baseFileName == null || baseFileName == null || w.baseFileName == baseFileName`) and release monitor immediately (leaf lock!); if `matchingWindows.isEmpty()` return.
    - **Decoupled Sample vs. Summary Floors (Gate 3 Catch #1)**:
      1. **Per-sample `samplingValues[LAP_NR]`**: resolve `requiredLapNr` by matching `samplingValues.getAsLong(SensorType.TIME_TOTAL.name)` against `(exitTotalS, enterTotalS)` (falling back to UTC `time` / `sampleEpochS` against `(exitEpochS, enterEpochS)` when `TIME_TOTAL` is absent): `[exit, enter)` -> `transitionLapNr` iff `hasTransition && enter > exit`, `>= enter` -> `newLegLapNr`, taking `maxOf`. Upgrade `samplingValues[LAP_NR]` iff `requiredLapNr != null && (current == null || current < requiredLapNr)` (never downgrading).
      2. **Workout-wide `summaryValues[WorkoutSummaries.LAPS]`**: compute `maxCommittedNewLegLapNr = matchingWindows.maxOf { it.newLegLapNr }`; whenever `summaryValues != null && summaryValues.containsKey(WorkoutSummaries.LAPS)`, upgrade `summaryValues[LAPS]` iff `current == null || current < maxCommittedNewLegLapNr` (never downgrading higher manual laps), so delayed `< exitS` (`t = 1299`) or `[exitS, enterS)` (`t = 1320`) samples flushing out of order can NEVER regress `WorkoutSummaries.LAPS` from `6` back to `4` or `5`.
  - DRY shared SQL helper `applyTransitionWindowsToTable(db, table, windows)` used by BOTH `backfillWorkoutSamplesTable(db, table, plan)` and `reconcileWorkoutSamplesTable(db, table, windows)`:
    - Single SQLite transaction (`beginTransaction` / `setTransactionSuccessful` / `endTransaction`), `PRAGMA table_info` check + `ALTER TABLE ADD COLUMN LAP_NR INTEGER DEFAULT 1` if missing.
    - **Combined `TIME_TOTAL IS NULL`-Safe Predicates (Gate 3 Catch #2)**: Use strict monotonic `($lapNrCol < ? OR $lapNrCol IS NULL)` for BOTH `[exit, enter)` (`transitionLapNr`) and `>= enter` (`newLegLapNr`). When `hasTimeTotal && hasTimeCol`:
      - For `w.hasTransition`: build combined WHERE predicate combining `($timeTotalCol >= ? AND $timeTotalCol < ?)` (when `w.enterTotalS > w.exitTotalS`) OR `($timeTotalCol IS NULL AND CAST(strftime('%s', $timeCol) AS INTEGER) >= ? AND CAST(strftime('%s', $timeCol) AS INTEGER) < ?)` (when `w.enterEpochS > w.exitEpochS`) with `AND ($lapNrCol < ? OR $lapNrCol IS NULL)`.
      - For `newLegLapNr`: `UPDATE $table SET $lapNrCol = ? WHERE ($timeTotalCol >= ? OR ($timeTotalCol IS NULL AND CAST(strftime('%s', $timeCol) AS INTEGER) >= ?)) AND ($lapNrCol < ? OR $lapNrCol IS NULL)`.
      - Preserve single-column branches (`hasTimeTotal && !hasTimeCol`, `!hasTimeTotal && hasTimeCol`) for schema-minimal tables.
  - **Null/Mixed-Window Finalization Reconciliation (Gate 3 Catch #3a)**: Add `fun reconcileWorkoutSamplesOnFinalization(context: Context, baseFileName: String?)`:
    - Short-circuit `if (baseFileName.isNullOrBlank()) return` immediately.
    - Under `synchronized(this)`, merge `pendingReconciliationByFileName.remove(baseFileName).orEmpty()` with any matching `committedTransitions.filter { it.baseFileName == null || it.baseFileName == baseFileName }` into an order-preserving deduplicated `LinkedHashSet<CommittedTransitionWindow>().toList()`, releasing the monitor immediately.
    - If empty return in O(1) (`0` SQLite I/O on single-sport workouts); else execute `applyTransitionWindowsToTable(db, table, windows)` inside `try/catch (t: Throwable)` on `mDbExecutor`.
- **Layer 2 — `TrackerService.java` (`3,184 -> 3,186 / 3,220` LoC, `+2` lines)**:
  - In `sampleAndWriteToDb()` inside `mTableInitializationFuture.thenAcceptAsync(..., mDbExecutor)` right before `getWorkoutRepository().recordLiveSample(...)` (`:2808`): `mMultisportLapCoordinator.enforceMonotonicLapNr(mBaseFileName, samplingValues, summaryValues);`.
  - In `endWorkout(...)` right after `createNewLap(snapshot, workoutId)` (`:2395`, strictly before `finalizeLiveSession()` / `WorkoutPostProcessingCoordinator.enqueue()`): `mMultisportLapCoordinator.reconcileWorkoutSamplesOnFinalization(getSafeContext(), baseFileName);`.
- **Deadlock-Freedom Proof**: `MultisportLapCoordinator` monitor is a pure in-memory leaf lock (never calls `BANALService`, `WorkoutRepository`, or `SQLiteDatabase`). All SQLite writes execute strictly on single-threaded FIFO `mDbExecutor` (zero main-thread SQLite, zero SQLite writer contention).
- **Continuous SWE.3 Maintenance (`REQ-PRO-114`)**: Update `docs/architecture/detailed_design/tracker_service.md` (Sections 3, 4.2, 5, Change History, `v1.0.12 -> v1.0.13`, `3,186 LOC`, citing `TrackerServiceMultisportMonotonicLapTest`) and verify via `DetailedDesignParityContractTest`.
