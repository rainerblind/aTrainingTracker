# Implementation Plan: ATT-9343 - Fix 512 MB Heap OutOfMemoryError During Dual Polar Live-IMU Streaming

**Ticket**: `ATT-9343` (`3 SP`, `Bug`, `high-risk`, `severity-critical`) | **Parent Epic**: `ATT-235` | **Target Release**: `V5.0.0`  
**Active Sprint**: `2026-11-20_03_Nacht` (Sprint 467) | **Branch**: `feature/ATT-9343` (base `ed05d679`) | **Requirements**: `REQ-STB-023.1`–`.5` | **Tests**: `TST-STB-023.1`–`.4`

## 1. Problem Description & SWE.2/SWE.3 Architectural Boundaries
* **Root Cause Summary**: Live Pixel 10 `512 MB` Java heap `OutOfMemoryError` (`<1%` free after GC) at `15 min 17 s` inside `BleLogger.byteArrayToHex` (`binder:24751_7`) stems from: (1) `SpeedAndLocationDevice_ATTFused` constructing `UnicycleOdometryEkf()` with default `recordSnapshots = true` (zero production readers, retaining `~1.2–1.35 KB` per `50–400 Hz` gyro/GNSS step indefinitely in unbounded `snapshotList`) plus `50–400 Hz` `DevicesDatabaseManager.setLastActive()` SQLite `UPDATE`s; (2) `polar-ble-sdk:8.6.0` `BDBleApiImpl` registering `BDBleApiImpl$1` with `BleLogger.setLoggerInterface(...)` even when `logger == null` (`~850 KB/s` Binder-thread hex `String.format`/`Arrays.copyOf` churn + global `BleLogger.mutex` lock contention); and (3) missing explicit `BufferOverflow.DROP_OLDEST` backpressure, `onUndeliveredElement` drop accounting, zero-`String.format` CSV serialization, and `scope.cancel()` on `PolarPmdStreamCoordinator` / `PolarRawTelemetryRecorder`.
* **SWE.2 / SWE.3 Evaluation (`Rule 8.8`, `REQ-PRO-114`)**: Schedule a targeted SWE.2 sync in `docs/architecture.md` (§3.5 line `237` `PolarRawTelemetryRecorder` `DROP_OLDEST` + `onUndeliveredElement` + `scope.cancel()`, `BleLogger.setLoggerInterface(null)` in `PolarOfflineGattCoordinator`, and §4.9 bounded live EKF `recordSnapshots = false` / `MAX_SNAPSHOTS = 4096` heap budget). Zero state-machine or interface changes in `TrackerService`, `BANALService`, `DeviceManager`, or `MyBTLEDevice` -> `docs/architecture/detailed_design/{tracker_service,banal_service,my_btle_device}.md` and `docs/architecture/interfaces.md` remain untouched.
* **Layering, LoC & UI Scope**: Pure `banalservice` odometry/Polar changes; `SpeedAndLocationDevice_ATTFused.kt` (`1,481 -> <=1,488/1,500`) and `PolarOnlineStreamingBridge.kt` (`1,469 -> <=1,475/1,500`) stay strictly under the `1,500`-LoC ceiling (`ArchitectureConformanceContractTest.kt:116`). `UI Consistency: N/A` (`Localization Parity: N/A - no UI strings`).

## 3. System Invariants & Preserved Behavior
* **Constructor & Public API Stability**: Preserve `UnicycleOdometryEkf` `@JvmOverloads` primary constructor (`recordSnapshots: Boolean = true`) so `UnicycleOdometryEkfTest` and `ExtendedRtsOdometrySmoother` remain untouched; preserve all `PolarOnlineStreamingBridge` public signatures (`InterfaceSignatureDriftContractTest.kt:79`).
* **Sidecar & Streaming Parity**: `.polar_raw.csv.gz` header, 11-column schema, `Locale.US` precision (`%.2f` gyro, `%.1f` RR), `NaN`/`Infinity`/`-0.0f` sign/rounding parity, and empty-session file discard (`REQ-SET-117.1`/`.2`) MUST stay byte-compatible. Preserve `PolarOfflineGattCoordinator` singleton ref-counting, `ATT-9175` offline GATT yield, `ATT-9161` PMD `ERROR_ALREADY_IN_STATE` recovery, and `ATT-9176` Verity PPI isolation.
* **Threading**: `UnicycleOdometryEkf` mutations stay synchronized under `ekf`; `BleLogger.setLoggerInterface(null)` runs outside `apiLock` alongside `setApiCallback`; `PolarRawTelemetryRecorder` drains on `Dispatchers.IO` using a single thread-confined `StringBuilder(128)` without blocking GATT callbacks.

## 4. Proposed Architectural Changes
* **`banalservice/odometry/UnicycleOdometryEkf.kt` (`844` LoC)**: Replace unbounded `mutableListOf<OdometrySnapshot>()` with bounded `ArrayDeque<OdometrySnapshot>()` capped at `MAX_SNAPSHOTS = 4096` (drop-oldest via `removeFirst()` when `size >= MAX_SNAPSHOTS`); keep `getSnapshots(): List<OdometrySnapshot>` returning an unmodifiable snapshot list and preserve `@JvmOverloads` (`recordSnapshots: Boolean = true`).
* **`banalservice/devices/SpeedAndLocationDevice_ATTFused.kt` (`1,481 -> ~1,487/1,500` LoC)**: Instantiate `val ekf = UnicycleOdometryEkf(recordSnapshots = false)` at `:107`; add `private var mLastActiveWriteMs: Long = Long.MIN_VALUE` and throttle `setLastActive()` in `processWorldYawStep()` (`:826`) to `>= LAST_ACTIVE_THROTTLE_MS` (`5_000L` ms).
* **`banalservice/devices/bluetooth_le/polar/PolarOfflineGattCoordinator.kt` (`1,283` LoC)**: Add `@VisibleForTesting internal var bleLoggerDisabler: () -> Unit = { BleLogger.setLoggerInterface(null) }` (reset in `resetForTesting()`), invoked inside `try/catch` in `acquirePolarApi()` (`:321-327`) right after constructing a new `PolarBleApi` singleton (outside `apiLock`).
* **`banalservice/devices/bluetooth_le/polar/PolarPmdStreamCoordinator.kt` (`316` LoC) & `PolarOnlineStreamingBridge.kt` (`1,469 -> ~1,472/1,500` LoC)**: Add `PMD_STREAM_BUFFER_CAPACITY = 64` and apply `.buffer(capacity = PMD_STREAM_BUFFER_CAPACITY, onBufferOverflow = BufferOverflow.DROP_OLDEST)` inside `collectPmdWithAlreadyInStateRecovery()` (`:258`) and a shared `collectBounded(flow, onSample)` helper used by `startHrCollection()` (`:942`).
* **`banalservice/devices/bluetooth_le/polar/RawTelemetryRow.kt` (`98` LoC) & `PolarRawTelemetryRecorder.kt` (`443` LoC)**: Add `appendCsvLine(sb: StringBuilder)` on `RawTelemetryRow` (handling `NaN`, `+/-Infinity`, negative zero `-0.0f`/`-0.0` via raw sign bit, and exact half-up/fixed-decimal rounding parity with `String.format(Locale.US, "%.2f"/"%.1f")` plus large-magnitude fallback; `toCsvLine()` delegates to `appendCsvLine`). In `PolarRawTelemetryRecorder`, switch `channel` to `Channel(CHANNEL_CAPACITY, BufferOverflow.DROP_OLDEST, onUndeliveredElement = { droppedFrameCount.incrementAndGet() })`, expose `getDroppedFrameCount(): Long`, log dropped count in `finalizeFile()`, reuse one `StringBuilder(128)` inside the IO drain loop, and call `scope.cancel()` in `stop()` after `writeJob?.join()`.
