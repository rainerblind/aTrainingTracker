## 1. Architectural & Concurrency Design (SWE.2 / SWE.3)
* **1. `TrackerService` & `TrainingApplication` Pending-FGS Handshake (`REQ-TRK-095.1`)**:
  * In `TrackerService.java` (current `3,180 / 3,220` LoC; target `<= 3,210` LoC):
    * Add `private static final AtomicBoolean sFgsStartPending = new AtomicBoolean(false)`, `private static final AtomicBoolean sPendingStopBeforeStart = new AtomicBoolean(false)`, and `private volatile boolean mIsForegroundPromoted = false`.
    * Expose `markForegroundStartRequested()` (clears `sPendingStopBeforeStart`, sets `sFgsStartPending = true`), `requestStopIfForegroundStartPending()` (returns `true` + sets `sPendingStopBeforeStart = true` iff `sFgsStartPending.get()`), and `@VisibleForTesting resetFgsStartStateForTesting()`.
    * Extract private `boolean promoteForegroundIfNeeded()` calling `performStartForeground(TRACKING_NOTIFICATION_ID, notification, determineForegroundServiceType())`, setting `mIsForegroundPromoted = true`, clearing `sFgsStartPending = false`, and catching `SecurityException | IllegalStateException` (clearing `sFgsStartPending`, setting `mTrackingInterrupted = true`, cancelling init/tracker, showing interrupted notification, `performStopSelf()`, returning `false`).
    * In `onStartCommand()`: keep `ACTION_STOP` and `intent == null && !hasBackgroundLocationPermission()` checks at top (`TrackerServiceResilienceTest` invariant), then invoke `promoteForegroundIfNeeded()` **immediately before** `switch (startType)` / `mDbExecutor.submit(...)`! Right after promotion, if `sPendingStopBeforeStart.getAndSet(false)` is `true`, set `mIsStopping = true; mTrackingInterrupted = true`, call `performIdempotentMainThreadTeardown(true)`, and return `Service.START_NOT_STICKY` (0 orphan SQLite row).
    * In `handleActionStop()`: before early `performStopSelf()` (`mWorkoutID <= 0 && mBaseFileName == null`), if `sFgsStartPending.get() && !mIsForegroundPromoted`, call `promoteForegroundIfNeeded()` + `performStopForeground()` first.
    * In `START_NORMAL`: reset `mWorkoutID = -1;` synchronously before `mDbExecutor.submit(...)`. Inside `enqueueAsyncFinalization()`'s `finalizationTask` (running FIFO after `createNewWorkout()` on `mDbExecutor`), resolve `long resolvedWorkoutId = stoppingWorkoutId > 0 ? stoppingWorkoutId : (stoppingBaseFileName != null && stoppingBaseFileName.equals(mBaseFileName) ? mWorkoutID : stoppingWorkoutId);` and pass `resolvedWorkoutId` to `endWorkout(...)`.
    * In `onDestroy()`: clear `mIsForegroundPromoted = false` without clobbering a newer instance's `sFgsStartPending`.
  * In `TrainingApplication.java` (current `2,038 / 2,050` LoC; target `2,041` LoC, `+3` LoC):
    * Call `TrackerService.markForegroundStartRequested();` immediately after `ContextCompat.startForegroundService(this, intent);` (`:1806`).
    * In `stopTracking()` `else` branch (`:1944`): guard `if (!TrackerService.requestStopIfForegroundStartPending()) { stopService(new Intent(this, TrackerService.class)); }`.
* **2. `WorkoutPostProcessingService` Generation-Guarded FGS Lifecycle (`REQ-TRK-095.2`)**:
  * In `WorkoutPostProcessingService.kt` (`companion object`): synchronize `nextGeneration`, `pendingFgsGeneration`, `promotedFgsGeneration`, `stopRequestedForGeneration`, and `activeInstance` under `lifecycleLock`.
  * `startForPostProcessing()`: under `lifecycleLock`, if `promotedFgsGeneration > 0L && activeInstance != null` or `pendingFgsGeneration > 0L`, clear `stopRequestedForGeneration = 0L` and return `true`; else invoke `starter(appContext, intent)` and on success set `pendingFgsGeneration = ++nextGeneration; stopRequestedForGeneration = 0L`.
  * `stopIfRunning(context)`: under `lifecycleLock`, if `pendingFgsGeneration > 0L`, set `stopRequestedForGeneration = pendingFgsGeneration` and return **without calling `appContext.stopService(...)`**; else if `promotedFgsGeneration > 0L`, reset `promotedFgsGeneration = 0L` and invoke `appContext.stopService(...)`.
  * `onStartCommand()`: promote via `promoteForeground(...)` BEFORE checking `stopRequestedForGeneration >= gen || !WorkoutPostProcessingCoordinator.hasActiveWork()` (and on `ACTION_STOP` when `pendingFgsGeneration > 0L`, promote first before `demoteForeground()` + `performStopSelf()`). Clear `activeInstance`/`promotedFgsGeneration` in `handleTimeout()`/`onDestroy()` without wiping a newer `pendingFgsGeneration`. Wire `resetLifecycleStateForTesting()` into `WorkoutPostProcessingCoordinator.resetForTesting()`.
* **3. `MultiLocaleUiSweepAndroidTest.kt` & `tools/baseline_manager.py` (`REQ-TRK-095.3`, `REQ-PRO-138`)**:
  * In `MultiLocaleUiSweepAndroidTest.kt`: refresh `syntheticWorkoutId` right before `REQUEST_STOP_TRACKING` if still `<= 0L`, and after stop wait up to `3000 ms` for `!WorkoutPostProcessingCoordinator.hasActiveWork()` so synthetic workouts and FGS teardown complete cleanly while keeping the rapid Start$\rightarrow$Pause$\rightarrow$Stop stress timing intact.
  * In `tools/baseline_manager.py`: add `_collect_latest_emulator_sweep_deviation(repo_root)` scanning `docs/engineering/emulator_sweeps/YYYY-MM-DD_sweep.md` (lexicographically latest), parsing `**Verdict**: \`(PASS|FAIL)\``, counting failed/total table rows, and appending a `**DEVIATION**:` entry to `open_deviations` on `FAIL` or missing/unparseable verdict (`0` on `PASS` or empty dir).
