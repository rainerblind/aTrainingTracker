## 1. Problem Description & SWE.2/SWE.3 Architectural Boundaries
* **Root Cause (4 Compounding Heap Churn Contributors)**: During bulk Strava archive import (`3,287` rows, ~201 new workouts) against a `5.5 MB` `Climbs.db`, Java heap reached `509 / 512 MB`: (1) `ClimbsDatabaseManager` (`:139, :162, :257`) eagerly ran `getAllClimbsInternal()` + `String.split(";")`/`split(",")` on every row per workout; (2) `WorkoutRepository.extractAndPersistClimbsFromWorkout` (`:4567`) invoked `LiveClimbsRepository.refreshClimbs()` per workout, re-reading `Climbs.db` and duplicating `_allStoredClimbs`/`_allClimbs`; (3) `LegacyImportEngine.recalculateStats` (`:1350-1360`) invoked direct `reloadWorkoutData` + `refreshClusters()` + `WORKOUT_UPDATED_INTENT` (triggering a 2nd `reloadWorkoutData` via `workoutUpdateReceiver`); and (4) `DevicesDatabaseManager.getLastActiveString()` (`:878`) instantiated `DateFormat.getDateTimeInstance()` (`ZoneInfo.clone()`) per `setLastActive()`.
* **SWE.2 / SWE.3 & Layering Alignment (`REQ-PRO-114`, `Rule 8.8`)**: Place `WorkoutClimbIngestionCoordinator` in `climbs/` (outside `ui/` and `database/` so `ArchitectureConformanceContractTest` `BASELINE_ALLOWED_UI_DB_CALLERS == 22` and `BASELINE_ALLOWED_DATABASE_UPWARD_UI_IMPORTS <= 10` remain unchanged) and `LastActiveDateFormatter` in `banalservice/database/` (`0` `.ui.*` imports). Update `docs/architecture.md` (§2) and `docs/architecture/detailed_design/workout_repository.md` (`v1.0.3`, Collaborators, LoC, §5 tests); `docs/architecture/interfaces.md` (`IF-SWE-*`) and `Climbs.db` schema v1 stay unchanged. `UI Consistency: N/A` (`Localization Parity: N/A - no UI strings`).

## 3. System Invariants & Preserved Behavior
* **Single-File & Deduplication Parity**: Single-file imports retain immediate `reloadWorkoutData(workoutId)`, `refreshClusters()`, and `refreshClimbs()` (`TST-MIG-023`, `TST-MAP-066.1`). Lazy metadata pre-filtering pads `[start, end]` by triangle-inequality ellipse slack $\frac{1}{2}\sqrt{\max(0, L^2 - d_{se}^2)} + \text{effThreshold}$ before rejecting corridor overlap and hydrates `COLUMN_PATH_POLYLINE` for both climbs only when Steps 0–3 pass without endpoint match.
* **API, MockK & Schema Stability**: Preserve `Climbs.db` v1 schema, MockK arities of `persistParsedWorkout`, `bulkRecoverFromDropbox`, `bulkRecoverFromGoogleDrive`, and `extractAndPersistClimbsFromWorkout(Long)`, `DeviceStatusRow`/`DeviceSortOrder` timestamp parsing parity, `WorkoutRepository.kt <= 4,973` LoC, `DevicesDatabaseManager.java <= 1,671` LoC, and `0` `src/main/` test reads.

## 4. Proposed Architectural Changes
* **`database/ClimbsDatabaseManager.kt` & `climbs/ClimbDeduplicator.kt` & `climbs/ClimbDetector.kt`**: Zero-allocation `;`/`,` scanner in `deserializePathPoints` (`"null"` altitude fast-path + decimal parser with fallback); `METADATA_COLUMNS` projection excluding `COLUMN_PATH_POLYLINE`; DRY pre-filter helpers on `ClimbDeduplicator`; lazy `getClimbPathPointsById` caching in `insertClimbWithDeduplication`, `insertClimbsWithDeduplicationBatch`, and `deduplicateExistingClimbs`; `subList(...).toList()` in `ClimbDetector.createClimb()`.
* **`climbs/LiveClimbsRepository.kt`**: Add `Mutex` serialization on `refreshClimbs`; conditional `.copy` only when resolved category differs; share single `deduplicatedStored` reference across `_allStoredClimbs` and `_allClimbs` when `activeRouteId == null` (also in `applyFormula`).
* **`climbs/WorkoutClimbIngestionCoordinator.kt` & `ui/aftermath/WorkoutRepository.kt`**: Extract DEM-validated climb ingestion & persistence into `climbs/` helper (`refreshLiveClimbs: Boolean`), reducing `WorkoutRepository.kt` below `4,973` LoC; `backfillHistoricalClimbs` uses `refreshLiveClimbs = false` in-loop.
* **`migration/BulkImportBatchContext.kt`, `LegacyImportEngine.kt`, `StravaBulkExportImporter.kt`, `BackupRestoreViewModel.kt`, `AutoImportManager.kt`**: Drop `WORKOUT_UPDATED_INTENT` after direct `reloadWorkoutData` when `app != null`; install coroutine-scoped `BulkImportBatchContext` across bulk entry points (`importStravaArchive` / `StravaBulkExportImporter`, multi-file `importWorkoutFilesInternal`, `bulkRecoverFrom*`, `AutoImportManager`) keeping method arities unchanged and running single post-batch reconciliation (`loadAllWorkouts`, `syncPeriodsIfDiscrepancy`, `refreshClusters`, conditional `refreshClimbs`, guarded for non-`Application` test `Context`s like `StravaBulkExportImporterTest`).
* **`banalservice/database/LastActiveDateFormatter.kt` & `DevicesDatabaseManager.java`**: `ThreadLocal` `DateFormat.getDateTimeInstance()` cache checking `(Locale.getDefault(), TimeZone.getDefault())` + delegating `getLastActiveString()` (`<= 1,671` LoC).
