## 1. SWE.2 Architectural Decomposition & Concurrency / Cleanup Model

- **Streaming XML Parsers & `WorkoutParser` (`migration/parsers/`, `tcx/parser/`, `routes/parsers/`)**:
  - `TcxParser.parseStreaming(inputStream, listener)` emits activity/course metadata, lap headers, individual trackpoints (zero `List<TcxTrackpoint>` buffer), and course points on a single `XmlPullParser` pass; `TcxParser.parse(inputStream): Result<TcxDocument>` becomes a thin DTO-collecting consumer of `parseStreaming` (`REQ-DAT-040` preserved).
  - `GpxTrackpointParser.parseStreaming(inputStream, listener)` emits metadata, segment boundaries, individual trackpoints (zero `List<RawTrackpoint>` buffer), and waypoints; `GpxTrackpointParser.parse(inputStream)` collects into `ParsedGpxData` via `parseStreaming`.
  - Delete `TcxTrackpointParser.kt`, unused `ParsedTcxData` (`TrackpointModels.kt`), and dead `TCXFileWriter.buildLap(...)`. Wire `TcxWorkoutParser`, `TcxCourseParser`, `GpxWorkoutParser`, and `GpxRouteImporter` directly to `parseStreaming`.
  - Add `interface WorkoutParser` (`formatExtension`, `workoutSource`, `parse(File, Context)`, `parse(InputStream, Context)`, `companion object.forFormat(extOrFormat)`) implemented by `FitWorkoutParser`, `TcxWorkoutParser`, `GpxWorkoutParser`; unify `LegacyImportEngine` (`importFromFileResult` with existing `importFrom*` facade shims) and `StravaBulkExportImporter`.
- **HRV rMSSD Single Source of Truth (`banalservice/devices/hrv/HrvRmssdCalculator.kt`)**:
  - Pure-JVM object exposing `computeBiasFreeRmssd(beats: List<FilteredRrBeat>, minValidPairs: Int): Double?` with named constants (`LIVE_ROLLING_MIN_VALID_PAIRS = 10`, `POST_WORKOUT_MIN_VALID_PAIRS = 3`, `RESTING_CHECK_MIN_VALID_PAIRS = 1`) and `computeRawRmssd(intervals: List<Double>, minValidPairs: Int = 1): Double?`; all 4 callers delegate here.
- **Hardened Shared Cloud & ZIP Ingestion (`migration/CloudWorkoutSourceScanner.kt`, `SecureZipExtractor.kt`)**:
  - Extend `SecureZipExtractor` with `extractWorkoutArchive(zipFile: File, destDir: File): List<File>` reusing the exact same Zip-Slip prefix, null-byte, symlink, atomic-write, `toRealPath`, and zip-bomb checks (`allowedTopLevelDirs = null` for workout ZIPs) while keeping `extractBackupArchive` and `sanitizeDriveFileName` signatures unchanged.
  - `CloudWorkoutSourceScanner` encapsulates Dropbox & Google Drive listing/dedupe/ascending sort, retry with `RateLimitException` backoff (`backoffMillis + 500L`) and transient exponential backoff, `SecureZipExtractor.sanitizeDriveFileName`, and `.zip` safe extraction into isolated per-item staging dirs cleaned in `finally`.
  - Both `AutoImportManager` (closing the `File(tempDir, entry.name)` traversal bug + adding `.zip` Zip-Slip rejection + rate-limit retry) and `LegacyImportEngine.executeBulkCloudRecovery` (3-worker `Channel` on `Dispatchers.IO` with cooperative `ensureActive()` / `CancellationException` rethrow) consume `CloudWorkoutSourceScanner`. Consolidate `BackupRestoreViewModel.bulkRecoverLegacyData` / `bulkRecoverGoogleDriveData` onto one private helper preserving Drive token refresh precheck and `totalScanned == 0` diagnostic.
- **Single-Unzip `.attbackup` Staging & Shared `BackupOrchestrator` (`migration/BackupOrchestrator.kt`, `ImportEngine.kt`, `BackupRestoreViewModel.kt`, `BackupWorker.kt`)**:
  - `ImportEngine` adds `analyzeBackupToStaging(context, backupFile, stagedDir)` (keeps `stagedDir` only on non-empty valid analysis; purges on empty/error/`SecurityException`) and `performIncrementalImportFromStaging(context, stagedDir, sportMapping, equipmentMapping, listener)` (always purges `stagedDir` in `finally`, keeps `BackupManager.acquireLock` + single SQLite `ATTACH` transaction `REQ-MIG-043`). Existing `analyzeBackup` and `performIncrementalImport(File)` delegate to them so external callers & tests remain 100% compatible.
  - `BackupRestoreViewModel` stores `@Volatile private var activeStagedImport: StagedBackupSession?` (URI string, SHA-256 of streamed archive, `stagedDir` inside `cacheDir/import_analysis`), deletes the temporary `.attbackup` file immediately after extraction, reuses `stagedDir` on matching `performIncrementalImport` (falling back safely if missing/mismatched), and cleans `activeStagedImport` in `finally`, `clearState()`, and `onCleared()` (backed by `SecureZipExtractor.purgeStaleStagingDirs` on process crash).
  - `BackupOrchestrator.executeBackupAndUpload(context, requireCloudProvider, onProgress)` unifies lock acquisition, `BackupManager.createBackup` (calling 1-arg overload when `onProgress == null` and 2-arg when non-null for `BackupWorkerTest` / `BackupCloudProviderUnificationTest` compatibility), Dropbox/Google Drive uploads, `formatTargets`, and `last_backup_*` prefs commit across `BackupWorker` and `BackupRestoreViewModel.uploadToCloud`.
